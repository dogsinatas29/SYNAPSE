노드 증발 현상 (Evaporation):
v0.3.11에서 도입한 경로 통합(Unification) 기능으로 인해, 수동 노드(node_manual_...)가 실제 파일 경로와 매칭되면 ID가 파일 경로로 바뀝니다.
이때, load(state) 로직(668행)에서 isManualId는 false가 되는데, 만약 노드의 status가 confirmed로 상태가 변했다면 n.status === 'pending' 체크도 통과하지 못합니다.
결국 hasUserLayer가 확실하게 주입/저장되지 않았다면, 리로드 시 "이 노드는 수동 노드도 아니고 AI가 아직 찾지도 못한(스캔 전) 유령"으로 취급되어 버퍼에서 누락되는 것입니다.
클러스터 배치 오류:
이미 엣지가 있는 노드(Confirmed 상태)들은 nodeDegree > 0이 되어 Reserved Cluster로 강제 배정됩니다.
하지만 사용자님은 새로 만든 노드가 Reserved가 아닌 루트 레벨(혹은 Buffer)에 머물기를 기대하셨을 수 있고, 현재의 자동 분류 규칙이 사용자의 의도와 상관없이 엣지 유무로만 판단하기 때문에 "배치가 꼬였다"고 느끼시는 것입니다.
🛠️ 근본 해결책: "사용자 중심의 영속성(Persistence) 강화"
병합 시 레이어 각인: 수동 노드가 파일과 통합될 때, 해당 노드의 data.layer를 'user'로 확실히 못 박아 저장 시 유실되지 않게 합니다.

Reserved Nodes 명칭 및 성격 변경:
명칭을 Reserved Cluster로 변경합니다.
이 클러스터에 들어가는 노드들은 엣지가 있는 '사용자 노드'들이어야 하며, 당연히 사용자 커스텀(User Layer) 카운트에 포함되어야 합니다.
루트 노드 자유 배치 (Float Rules):
부모 폴더가 없는 루트 폴더의 파일들은 엣지가 있더라도 특정 클러스터에 가두지 않고 캔버스에 자유롭게 펼쳐지게(Float) 합니다.
수동 노드의 폴더 주권 복구:
현재 수동 노드(isUserLayer)는 폴더 구조를 무시하고 Buffer나 Reserved로만 강제 배정되고 있습니다.
이를 수정하여, 파일 경로상 부모 폴더가 있다면 수동 노드도 해당 폴더 클러스터(inputs 등) 안으로 적절히 배치되도록 수정합니다. (__init__이 inputs 폴더로 가지 못했던 결정적 이유입니다.)
🛠️ 수술 계획: "폴더 우선순위 기반의 지능형 배치"
배정 로직 순서 변경:
1순위: 부모 폴더가 있는가? -> 있다면 무조건 폴더 클러스터 행. (레이어 상관없음)
2순위: 부모 폴더가 없는 루트 파일인가? -> 그렇다면 클러스터 없이 플로팅. (엣지가 있어도 가두지 않음)
3순위: 사용자가 명시적으로 생성한 '완전 신규' 노드인가? -> Buffer Cluster 행.
명칭 동기화: sys_cluster_reserved의 표시 이름을 Reserved Cluster로 확실히 고정합니다.
