# v0.3.10 Candidate Generation Strategy

## 1. Goal

Define a deterministic and high-quality candidate generation system for
intent-based scoring.

Scoring is only as good as the candidates it evaluates.

------------------------------------------------------------------------

## 2. Core Principle

The system does not evaluate a single action.\
It evaluates multiple possible outcomes (candidates) and selects the
best one.

------------------------------------------------------------------------

## 3. Architecture Placement

EventHandler\
→ Intent\
→ RuleEngine (validation)\
→ Candidate Generator\
→ ScoringEngine\
→ StateManager

------------------------------------------------------------------------

## 4. Candidate Definition

``` ts
type Candidate<T> = {
  value: T;
  meta?: Record<string, any>;
};
```

------------------------------------------------------------------------

## 5. Intent-Based Candidate Generation

``` ts
type CandidateGenerator = (intent: Intent, context) => Candidate[];
```

------------------------------------------------------------------------

## 6. MOVE_NODE Strategy (v0.3.10 Core)

### 6.1 Minimal Candidate Set

``` ts
candidates = [
  originalPosition,
  snapToGrid(position),
  offset(position, +dx, 0),
  offset(position, -dx, 0),
  offset(position, 0, +dy),
  offset(position, 0, -dy),
];
```

------------------------------------------------------------------------

### 6.2 Grid-Based Approach (Recommended)

``` ts
function generateGridCandidates(position, gridSize) {
  return [
    snapToGrid(position),
    snapToGrid(offset(position, gridSize, 0)),
    snapToGrid(offset(position, -gridSize, 0)),
    snapToGrid(offset(position, 0, gridSize)),
    snapToGrid(offset(position, 0, -gridSize)),
  ];
}
```

------------------------------------------------------------------------

## 7. CONNECT_EDGE Strategy (Optional)

``` ts
candidates = [
  straightLine,
  bezierCurve,
  orthogonalPath,
];
```

------------------------------------------------------------------------

## 8. Determinism Requirement

Candidate generation MUST be deterministic.

Same input → same candidate set

------------------------------------------------------------------------

## 9. Design Constraints

### 9.1 Small Candidate Set

-   Limit to 3--7 candidates
-   Avoid combinatorial explosion

### 9.2 No Randomness

-   No stochastic generation
-   Fully reproducible

### 9.3 Context Awareness

Candidates may depend on: - node density - grid size - zoom level
(optional)

------------------------------------------------------------------------

## 10. Anti-Patterns

### ❌ Random candidate generation

Breaks reproducibility

### ❌ Excessive candidates

Kills performance and stability

### ❌ Scoring without candidates

Invalid design

------------------------------------------------------------------------

## 11. Minimal Implementation (v0.3.10)

Required: - MOVE_NODE candidate generation - Grid + offset strategy

Optional: - CONNECT_EDGE candidates

Excluded: - ADD_NODE candidates (defer)

------------------------------------------------------------------------

------------------------------------------------------------------------

## 13. Core Insight

Candidate quality defines system behavior.\
Scoring only selects from what is available.

Bad candidates → bad system\
Good candidates → stable system
