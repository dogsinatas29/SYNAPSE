# 🚀 v0.3.10 - Legacy Code Extraction Rules

## 📅 Status
Planned

---

## 🎯 Goal

Define strict rules to extract logic from legacy code **without contaminating the new architecture**.

> Extraction is not reuse. It is controlled isolation.

---

# 1. 🧠 Core Principle

Only extract what fits into:

- RuleEngine (logic)
- MutationEngine (state change)

Everything else is discarded.

---

# 2. 🔍 Extraction Target

Work per single Intent:

```text
CREATE_NODE
CONNECT_EDGE
```

Never extract multiple behaviors at once.

---

# 3. 🧩 Classification Rule

Every line of legacy code must be classified:

```text
[1] Rule        → validation logic
[2] Mutation    → state change
[3] Trash       → everything else
```

---

# 4. ✔ Rule Extraction

## Allowed

- existence checks
- validation conditions
- structural constraints

```ts
if (exists(id)) throw Error()
```

→ becomes:

```ts
!state.nodes[id]
```

---

## Forbidden

- phase checks
- runtime flags
- async timing logic

```ts
if (phase < 2) return   ❌
if (!isReady) return    ❌
```

---

# 5. ✔ Mutation Extraction

## Allowed

- object creation
- state insertion
- direct graph updates

```ts
graph.nodes[id] = node
```

---

## Forbidden

- event emission
- logging
- external calls

```ts
emit("nodeCreated")   ❌
api.call(...)         ❌
```

---

# 6. ❌ Trash (Must Remove)

Immediately discard:

- Phase logic
- Event system
- Logging
- Side effects
- Cross-module calls
- Caching logic

---

# 7. 🔧 Transformation Pattern

## Before

```ts
function createNode(id) {
  if (phase < 2) return
  if (exists(id)) throw Error()

  const node = buildNode(id)
  graph.add(node)
  emit("created")
}
```

---

## After

### RuleEngine

```ts
!state.nodes[id]
```

---

### MutationEngine

```ts
nodes[id] = { id }
```

---

# 8. 🧪 Validation Checklist

After extraction:

- No Phase reference
- No global state access
- No side effects
- Pure logic only

---

# 9. 🔁 Iterative Refinement

Extraction is not one-pass:

1. Rough extraction
2. Remove contamination
3. Simplify
4. Re-test

---

# 10. ⚠️ Anti-Patterns

Do NOT:

- Wrap legacy code as-is
- Preserve original structure
- Keep “just in case” logic

---

# 11. 📌 Success Criteria

- Extracted code fits cleanly into pipeline
- Rule and Mutation clearly separated
- No hidden dependencies remain

---

# 12. 🧾 Summary

> Extract less. Remove more.  
> Purity over completeness.
