# v0.3.10 Intent-Aware Priority Override

## 1. Goal

Introduce intent-based priority resolution to replace static priority
hierarchy.

Priority must be determined by: Priority = f(Intent, RuleSource)

------------------------------------------------------------------------

## 2. Core Concept

Static priority is insufficient because different intents require
different dominance:

-   MOVE_NODE → Spatial dominance
-   CONNECT_EDGE → Logic dominance
-   ADD_NODE → Spatial-biased

------------------------------------------------------------------------

## 3. Architecture

### 3.1 PriorityResolver (Separate Module)

``` ts
function resolvePriority(intent: Intent, source: RuleSource): number;
```

RuleEngine MUST NOT contain priority logic.

------------------------------------------------------------------------

## 4. Types

``` ts
type RuleSource = 'visual' | 'spatial' | 'logic';

type PriorityOverrideMap = {
  [K in Intent['type']]?: Partial<Record<RuleSource, number>>;
};
```

------------------------------------------------------------------------

## 5. Base Priority

``` ts
const BASE_PRIORITY = {
  logic: 100,
  spatial: 70,
  visual: 40,
};
```

------------------------------------------------------------------------

## 6. Override Map

``` ts
const PriorityOverrides: PriorityOverrideMap = {
  MOVE_NODE: {
    spatial: 100,
    logic: 90,
    visual: 30,
  },

  CONNECT_EDGE: {
    logic: 120,
    spatial: 80,
    visual: 20,
  },

  ADD_NODE: {
    spatial: 95,
    logic: 85,
  },
};
```

------------------------------------------------------------------------

## 7. Resolution Logic

``` ts
function resolvePriority(intent: Intent, source: RuleSource): number {
  const override = PriorityOverrides[intent.type]?.[source];
  return override ?? BASE_PRIORITY[source];
}
```

------------------------------------------------------------------------

## 8. Verdict Integration

``` ts
function attachPriority(intent, verdict, source) {
  return {
    ...verdict,
    priority: resolvePriority(intent, source),
    source,
  };
}
```

------------------------------------------------------------------------

## 9. RuleEngine Integration

``` ts
function judge(intent): FinalVerdict {
  const verdicts = [
    attachPriority(intent, visual.evaluate(intent), 'visual'),
    attachPriority(intent, spatial.evaluate(intent), 'spatial'),
    attachPriority(intent, logic.evaluate(intent), 'logic'),
  ];

  const veto = applyVeto(verdicts);
  if (veto) return veto;

  const dominant = applyPriority(verdicts);
  const optimal = applyScoring(verdicts);

  return {
    allowed: dominant.allowed,
    selected: optimal,
  };
}
```

------------------------------------------------------------------------

## 10. Design Constraints

### 10.1 Partial Override Only

Overrides MUST fallback to BASE_PRIORITY.

### 10.2 Intent Granularity

Start with: - ADD_NODE - MOVE_NODE - CONNECT_EDGE - DELETE_NODE

### 10.3 Visual Priority Rule

Visual priority MUST remain lowest in most cases.

------------------------------------------------------------------------

## 11. Conflict Resolution Examples

### MOVE_NODE

-   Spatial dominates to maintain layout

### CONNECT_EDGE

-   Logic dominates to ensure validity

------------------------------------------------------------------------

## 12. Non-Goals (v0.3.10)

-   No dynamic/context-based priority
-   No runtime mutation
-   No adaptive weighting

------------------------------------------------------------------------

## 13. Core Principle

Priority is determined by intent, not by engine.

System behavior must adapt to action context, not static hierarchy.
