# v0.3.10 Intent-Based Scoring Strategy

## 1. Goal

Introduce intent-based scoring to select optimal outcomes among valid
candidates.

Scoring determines quality, not validity.

------------------------------------------------------------------------

## 2. Core Principle

RuleEngine → decides if action is allowed\
ScoringEngine → decides best way to execute

------------------------------------------------------------------------

## 3. Architecture

EventHandler\
→ Intent\
→ RuleEngine (validation)\
→ Candidate Generator\
→ ScoringEngine (intent-based)\
→ StateManager

------------------------------------------------------------------------

## 4. Key Concept: Candidate-Based Evaluation

Scoring operates on multiple candidates, not a single action.

### Example: MOVE_NODE

``` ts
candidates = [
  { x: 100, y: 100 },
  { x: 110, y: 100 },
  { x: 100, y: 110 },
];
```

------------------------------------------------------------------------

## 5. Scoring Engine Design

### 5.1 Types

``` ts
type ScoringFunction = (candidate, context) => number;

type IntentScoringMap = {
  [K in Intent['type']]?: ScoringFunction;
};
```

------------------------------------------------------------------------

### 5.2 Scoring Map

``` ts
const ScoringMap = {
  MOVE_NODE: scoreMoveNode,
  CONNECT_EDGE: scoreConnectEdge,
  ADD_NODE: scoreAddNode,
};
```

------------------------------------------------------------------------

## 6. Intent-Specific Scoring

### 6.1 MOVE_NODE

``` ts
function scoreMoveNode(candidate, context) {
  return (
    - overlapPenalty(candidate, context) +
    - edgeCrossPenalty(candidate, context) +
    + gridAlignmentScore(candidate) +
    + spacingScore(candidate)
  );
}
```

------------------------------------------------------------------------

### 6.2 CONNECT_EDGE

``` ts
function scoreConnectEdge(candidate, context) {
  return (
    - invalidConnectionPenalty(candidate) +
    - edgeCrossPenalty(candidate, context) +
    - lengthPenalty(candidate) +
    + readabilityScore(candidate)
  );
}
```

------------------------------------------------------------------------

### 6.3 ADD_NODE

``` ts
function scoreAddNode(candidate, context) {
  return (
    - densityPenalty(candidate) +
    + centralityScore(candidate) +
    + groupingScore(candidate)
  );
}
```

------------------------------------------------------------------------

## 7. Selection Logic

``` ts
function selectBest(intent, candidates, context) {
  const scorer = ScoringMap[intent.type];

  return candidates
    .map(c => ({
      candidate: c,
      score: scorer(c, context),
    }))
    .sort((a, b) => b.score - a.score)[0];
}
```

------------------------------------------------------------------------

## 8. Design Constraints

### 8.1 Validation Separation

Scoring MUST NOT perform validation.

### 8.2 Candidate Requirement

Scoring requires multiple candidates.

### 8.3 Intent Isolation

Each intent MUST have its own scoring function.

------------------------------------------------------------------------

## 9. Anti-Patterns

### ❌ Using scoring for rejection

Do not replace validation with scoring thresholds.

### ❌ Single global scoring function

Breaks intent-specific optimization.

### ❌ No candidate generation

Invalidates scoring purpose.

------------------------------------------------------------------------

## 10. Minimal Implementation (v0.3.10)

Required: - MOVE_NODE scoring - 3--5 candidates

Optional: - CONNECT_EDGE scoring

Excluded: - ADD_NODE scoring (defer)

------------------------------------------------------------------------

## 12. Core Insight

The system does not evaluate actions.\
It evaluates possible outcomes and selects the best one.
