# 🚀 v0.3.10 - Logical Rule Isolation Specification

## 📅 Status
Planned

---

## 🎯 Goal

Ensure complete isolation between:

- Phase System (Execution Control)
- RuleEngine (Logical Validation)

> Prevent Phase contamination inside logical rule evaluation.

---

# 1. 🔥 Core Problem

New rules (creation / reference) naturally drift toward:

"Can this run in current phase?"

This leads to:

❌ RuleEngine referencing Phase  
❌ Hidden execution coupling  
❌ System instability

---

# 2. 🧠 Fundamental Separation

## Phase System

- Determines **WHEN** execution is allowed

## RuleEngine

- Determines **IF** an action is logically valid

---

## Golden Rule

> RuleEngine must NEVER know about Phase

---

# 3. 🏗️ Execution Pipeline

```text
Intent
  ↓
PhaseGate        (execution permission)
  ↓
RuleEngine       (logical validation)
  ↓
StateManager     (state mutation)
  ↓
RenderEngine
```

---

# 4. 🔒 Hard Constraints

## 4.1 Forbidden Dependencies

RuleEngine MUST NOT:

- import PhaseManager
- import Bootstrap modules
- access runtime phase state

---

## 4.2 Forbidden Context

```ts
validate(intent, context)
```

❌ Invalid context:
- context.phase
- context.isReady
- context.tick
- context.runtimeState

✔ Allowed context:
- graph state only

---

## 4.3 Pure Function Requirement

```ts
validate(intent, graphState) => boolean
```

- No side effects
- No external state
- Deterministic

---

# 5. 🛡️ Structural Guards

## 5.1 Dependency Isolation

- Enforce module boundaries
- No cross-import between RuleEngine and Bootstrap layer

---

## 5.2 Runtime Guard (Optional)

```ts
if (typeof phase !== "undefined") {
  throw new Error("Phase access detected in RuleEngine")
}
```

---

## 5.3 Test Enforcement

```ts
test("RuleEngine must not depend on Phase", () => {
  expect(imports).not.toContain("Phase")
})
```

---

# 6. 🧬 Intent Processing Contract

```text
Intent
 → PhaseGate (timing check)
 → RuleEngine (logical check)
```

RuleEngine MUST assume:

- execution is already permitted
- only logical validation remains

---

# 7. ⚠️ Anti-Patterns (Strictly Forbidden)

```ts
// ❌ WRONG
if (currentPhase < 2) return false

// ❌ WRONG
if (!isSystemReady) reject()

// ❌ WRONG
if (phase !== "RENDER") block()
```

---

# 8. 🧩 Design Insight

Mixing Phase into RuleEngine creates:

- circular dependency
- non-testable logic
- hidden execution paths

---

# 9. 📌 Success Criteria

- RuleEngine has zero Phase references
- All execution control handled by PhaseGate
- Logical validation is deterministic

---

# 10. 🔜 Future Integration

- Creation rules (Node / Edge)
- Reference semantics (import / include)
- Scoring / priority systems

All must comply with this isolation.

---

# 11. 🧾 Summary

> Phase = Execution Authority  
> RuleEngine = Logical Authority  

They must remain completely independent.
