# v0.3.10 Merger Strategy --- RuleEngine (Veto / Priority / Scoring)

## 1. Overview

RuleEngine MUST resolve conflicts using a layered strategy:

1.  Veto (critical rejection)
2.  Priority (dominance resolution)
3.  Scoring (optimal selection)

------------------------------------------------------------------------

## 2. RuleVerdict Definition

``` ts
type RuleVerdict = {
  allowed: boolean;
  severity: 'info' | 'warn' | 'critical';
  priority: number;
  score?: number;
  reasons?: string[];
  source: 'visual' | 'spatial' | 'logic';
};
```

------------------------------------------------------------------------

## 3. Stage 1 --- Veto

### Rule

-   If any verdict is:
    -   allowed === false
    -   severity === 'critical' → IMMEDIATE REJECT

``` ts
function applyVeto(verdicts: RuleVerdict[]) {
  const critical = verdicts.find(v => !v.allowed && v.severity === 'critical');
  if (critical) {
    return {
      allowed: false,
      reason: critical.reasons,
      stage: 'veto',
    };
  }
}
```

### Authority

-   Logic: full veto
-   Spatial: limited veto
-   Visual: no veto

------------------------------------------------------------------------

## 4. Stage 2 --- Priority

### Rule

Select highest priority verdict

``` ts
function applyPriority(verdicts: RuleVerdict[]) {
  return verdicts.sort((a, b) => b.priority - a.priority)[0];
}
```

### Default Priority

``` ts
Logic:   100
Spatial: 70
Visual:  40
```

------------------------------------------------------------------------

## 5. Stage 3 --- Scoring

### Rule

Among allowed verdicts, select highest score

``` ts
function applyScoring(verdicts: RuleVerdict[]) {
  return verdicts
    .filter(v => v.allowed)
    .sort((a, b) => (b.score ?? 0) - (a.score ?? 0))[0];
}
```

------------------------------------------------------------------------

## 6. Final Judge Flow

``` ts
function judge(intent): FinalVerdict {
  const verdicts = [
    visual.evaluate(intent),
    spatial.evaluate(intent),
    logic.evaluate(intent),
  ];

  const veto = applyVeto(verdicts);
  if (veto) return veto;

  const dominant = applyPriority(verdicts);
  const optimal = applyScoring(verdicts);

  return {
    allowed: dominant.allowed,
    selected: optimal,
    stage: 'final',
  };
}
```

------------------------------------------------------------------------

## 7. Design Decisions

### 7.1 Deny vs Degrade

-   Use severity 'warn' for degradations
-   Avoid unnecessary hard rejection

### 7.2 Veto Authority

  Engine    Veto
  --------- ---------
  Logic     Yes
  Spatial   Partial
  Visual    No

### 7.3 Scoring Range

-   Use simple 0\~1 scale
-   Avoid complex weighting initially

------------------------------------------------------------------------

## 8. Anti-Patterns

### ❌ All engines can veto

→ system becomes unusable

### ❌ Scoring without priority

→ unsafe decisions

### ❌ Global score aggregation

→ debugging impossible

------------------------------------------------------------------------

## 9. Minimal Implementation (v0.3.10)

Required: - Veto (Logic only) - Priority (fixed)

Optional: - Scoring (later phase)

------------------------------------------------------------------------

## 10. Core Principle

Logic blocks, Spatial organizes, Visual refines.

System stability is enforced by execution order, not rule complexity.
