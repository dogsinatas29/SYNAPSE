# 🚀 v0.3.10 - Phase Contamination Detection (Lint & Test Rules)

## 🎯 Goal

Automatically detect and block any Phase dependency inside RuleEngine.

---

# 1. 🔥 Detection Targets

We must detect:

- Direct imports of Phase modules
- Indirect references (context.phase, isReady, etc.)
- Hidden runtime coupling

---

# 2. 🧪 ESLint Rules (Static Analysis)

## 2.1 Forbidden Imports

```js
module.exports = {
  rules: {
    "no-phase-import-in-ruleengine": {
      create(context) {
        return {
          ImportDeclaration(node) {
            const forbidden = ["Phase", "PhaseManager", "Bootstrap"]
            if (forbidden.some(f => node.source.value.includes(f))) {
              context.report({
                node,
                message: "RuleEngine must not import Phase-related modules"
              })
            }
          }
        }
      }
    }
  }
}
```

---

## 2.2 Forbidden Identifiers

```js
Identifier(node) {
  const forbidden = ["phase", "currentPhase", "isReady"]
  if (forbidden.includes(node.name)) {
    context.report({
      node,
      message: "Phase-related identifier detected in RuleEngine"
    })
  }
}
```

# 4. 🧪 Unit Test Rules

## 4.1 Import Scan Test

```ts
import fs from "fs"

test("RuleEngine has no Phase imports", () => {
  const files = getRuleEngineFiles()

  files.forEach(file => {
    const content = fs.readFileSync(file, "utf-8")
    expect(content).not.toMatch(/Phase|Bootstrap/)
  })
})
```

---

## 4.2 Runtime Leak Detection

```ts
test("RuleEngine does not access phase", () => {
  const proxy = new Proxy({}, {
    get(target, prop) {
      if (prop === "phase") {
        throw new Error("Phase access detected")
      }
    }
  })

  expect(() => validate(intent, proxy)).not.toThrow()
})
```

# 7. ⚠️ Anti-Bypass Strategy

- Indirect import
