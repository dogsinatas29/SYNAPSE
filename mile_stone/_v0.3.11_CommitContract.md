# v0.3.11_CommitContract.md

---

## 1. 정의

> Commit Contract = Interface + Execution + Rollback  
> Commit은 단순 함수가 아니라 트랜잭션 규약이다.

---

## 2. 핵심 개념

- 성공 시: 모든 변경 반영
- 실패 시: 아무것도 남지 않음 (Atomic)
- 모든 사이드 이펙트는 추적 및 복구 가능해야 함

---

## 3. 입력 인터페이스

```ts
type CommitRequest = {
  nodes: NodeDraft[]
  edges: EdgeDraft[]
}
```

---

## 4. 단계 정의 (불변)

```ts
type CommitStage =
  | "VALIDATE"
  | "MATERIALIZE"
  | "GRAPH"
  | "FINALIZE"
```

---

## 5. 실행 구조

```ts
commitCluster(req: CommitRequest): CommitResult {
  const ctx = createContext()

  validate(req)
  materialize(req, ctx)
  syncGraph(ctx)
  return finalize(ctx)
}
```

---

## 6. 결과 인터페이스

```ts
type CommitResult = {
  files: CreatedFile[]
  graph: GraphSnapshot
}
```

---

## 7. 에러 모델

```ts
type CommitError = {
  stage: CommitStage
  code:
    | "VALIDATION_ERROR"
    | "MATERIALIZATION_ERROR"
    | "GRAPH_ERROR"
  message: string
}
```

---

## 8. Transaction Context (Rollback 핵심)

```ts
type CommitContext = {
  createdFiles: string[]
  previousGraph?: GraphSnapshot
}
```

---

## 9. Rollback 규칙

- 실패한 단계 기준으로 이전 단계만 롤백
- validate 단계는 롤백 없음 (side effect 없음)

```ts
function rollback(ctx: CommitContext, failedStage: CommitStage) {
  if (failedStage === "MATERIALIZE" || failedStage === "GRAPH") {
    deleteFiles(ctx.createdFiles)
  }

  if (failedStage === "GRAPH") {
    restoreGraph(ctx.previousGraph)
  }
}
```

---

## 10. 단계별 책임

| 단계 | 역할 | 사이드 이펙트 |
|------|------|---------------|
| validate | 구조 검증 | 없음 |
| materialize | 파일 생성, import 생성 | 파일 시스템 |
| graph | 그래프 재구성 | 메모리 |
| finalize | 상태 전이 | 상태 변경 |

---

## 11. 불변 규칙

- commit 외부에서 writeFile 금지
- edge 연결 시 import 생성 금지
- graph는 materialize 이후에만 갱신
- commit은 단일 진입점만 허용

---

## 12. 테스트 전략

### VALIDATE 실패
- 파일 생성 없음
- 그래프 변화 없음

### MATERIALIZE 실패
- 생성된 파일 모두 삭제

### GRAPH 실패
- 파일 삭제
- 그래프 복원

### 성공
- 파일 생성됨
- 그래프 반영됨
- 상태 RESERVED

---

## 13. 핵심 요약

> Commit은 실행 로직이 아니라 상태를 보장하는 트랜잭션이다.
