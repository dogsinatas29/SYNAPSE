# v0.3.11_CommitPipeline_Freeze.md

---

## 1. 핵심 정의

> Commit Pipeline은 설계 대상이 아니라 고정 대상이다.  
> 단일 실행 경로와 불변 순서를 가진다.

---

## 2. 목표 구조

```ts
commitCluster(cluster) {
  const validated = validate(cluster)
  const material = materialize(validated)
  const graph = syncGraph(material)
  return finalize(graph)
}
```

---

## 3. 단계 순서 (불변)

```
VALIDATE → MATERIALIZE → GRAPH → FINALIZE
```

---

## 4. 단계별 책임

| 단계 | 역할 | 사이드 이펙트 |
|------|------|---------------|
| validate | 구조 검증 | 없음 |
| materialize | 파일 생성, import 생성 | 파일 시스템 |
| graph | 그래프 재구성 | 메모리 |
| finalize | 상태 전이 | 상태 변경 |

---

## 5. 실패 규칙

```
어느 단계든 실패 → 즉시 중단 → 롤백
```

---

## 6. 진입점 규칙

```
commitCluster() 만이 유일한 실행 진입점
```

---

## 7. 금지 규칙

- validate 단계에서 파일 생성 금지
- edge 연결 시 import 생성 금지
- commit 외부에서 writeFile 금지
- graph를 materialize 이전에 갱신 금지

---

## 8. 인터페이스 고정

```ts
type CommitResult = {
  files: File[]
  graph: Graph
}
```

---

## 9. 에러 모델

```ts
type CommitError =
  | "VALIDATION_ERROR"
  | "MATERIALIZATION_ERROR"
  | "GRAPH_ERROR"
```

---

## 10. 상태 전이

```
BUFFER → RESERVED (only via commit)
```

---

## 11. 핵심 요약

> 실행 순서는 절대 변하지 않으며, 모든 사이드 이펙트는 지정된 단계에서만 발생한다.
