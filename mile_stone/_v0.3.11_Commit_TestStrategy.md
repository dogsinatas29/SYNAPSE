# v0.3.11_Commit_TestStrategy.md

---

## 1. 정의

> 테스트는 기능 검증이 아니라 Commit Contract를 강제하는 수단이다.

---

## 2. 테스트 목표

1. Atomic 보장
2. Side effect 격리 보장
3. Rollback 완전성 보장
4. Commit 외부 write 금지 검증

---

## 3. 테스트 계층

### 1) Transaction Test
- 실패 시 시스템 상태가 완전히 동일해야 한다

### 2) Stage Failure Test
- 각 단계별 실패 강제

### 3) Invariant Test
- 절대 발생하면 안 되는 동작 검증

---

## 4. 핵심 테스트 케이스

### CASE 1 — VALIDATE 실패

```ts
it("validate failure → no side effects", () => {
  const before = snapshotSystem()

  expect(() => commitCluster(invalidInput))
    .toThrow("VALIDATION_ERROR")

  const after = snapshotSystem()

  expect(after).toEqual(before)
})
```

---

### CASE 2 — MATERIALIZE 실패

```ts
it("materialize failure → files rolled back", () => {
  mockWriteFileToFail()

  expect(() => commitCluster(validInput))
    .toThrow("MATERIALIZATION_ERROR")

  expect(getAllFiles()).toEqual([])
})
```

---

### CASE 3 — GRAPH 실패

```ts
it("graph failure → files + graph rolled back", () => {
  mockGraphFailure()

  const beforeGraph = getGraph()

  expect(() => commitCluster(validInput))
    .toThrow("GRAPH_ERROR")

  expect(getAllFiles()).toEqual([])
  expect(getGraph()).toEqual(beforeGraph)
})
```

---

### CASE 4 — SUCCESS

```ts
it("success → all changes applied", () => {
  const result = commitCluster(validInput)

  expect(result.files.length).toBeGreaterThan(0)
  expect(getGraph()).toMatchResult(result.graph)
})
```

---

## 5. 핵심 테스트 (Atomicity)

```ts
it("commit is atomic", () => {
  forceFailureAtRandomStage()

  const before = snapshotSystem()

  try {
    commitCluster(validInput)
  } catch {}

  const after = snapshotSystem()

  expect(after).toEqual(before)
})
```
