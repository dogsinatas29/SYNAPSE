# v0.3.11 Core Freeze 설계 (실제 코드 기반)

## 0. 대상 파일

- src/core/GraphModel.ts
- src/core/DataPipeline.ts
- src/core/canvas-engine/StateManager.ts
- src/bootstrap/BootstrapEngine.ts

---

## 1. 현재 구조 분석

### 1.1 GraphModel.ts
역할:
- Node / Edge / Cluster 구조 정의
- addNode(), addEdge()로 그래프 직접 변경

문제:
- mutable 구조 (직접 변경)

---

### 1.2 DataPipeline.ts
역할:
- 파일 스캔 결과 → Node / Edge 생성

문제:
- 생성 + dispatch 혼합
- 순수 함수 아님

---

### 1.3 StateManager.ts
역할:
- ADD_NODE / CONNECT_EDGE 처리
- GraphModel에 최종 반영

문제:
- Core mutation이 UI 이벤트 흐름과 결합됨

---

### 1.4 BootstrapEngine.ts
역할:
- 초기 스캔 및 그래프 생성 orchestration

---

## 2. Core Freeze 목표

- Graph 생성은 단일 함수로 수렴
- Graph는 immutable
- UI / 이벤트 / 상태와 완전 분리

---

## 3. 새로운 구조

### BEFORE

FileScanner → DataPipeline → dispatch → StateManager → GraphModel

### AFTER

FileScanner → buildGraph() → Graph (immutable)

---

## 4. 리팩토링 전략

## Step 1. GraphBuilder 도입

신규 파일:

src/core/graphBuilder.ts

```ts
export function buildGraph(scanResult): Graph {
  const nodes = createNodes(scanResult)
  const edges = createEdges(scanResult)

  return freezeGraph({ nodes, edges })
}
```

---

## Step 2. DataPipeline 분리

### 기존 (문제)

```ts
canvasEngine.dispatch('ADD_NODE', newNode)
```

### 변경

```ts
nodes.push(newNode)
```

→ dispatch 제거

---

## Step 3. Edge 생성도 동일하게 분리

```ts
edges.push(newEdge)
```

---

## Step 4. StateManager 역할 축소

### 기존

- Graph 생성 + mutation 담당

### 변경

- View 상태 관리만 담당
- Graph 생성 관여 금지

---

## Step 5. GraphModel 변경

### 기존

```ts
addNode()
addEdge()
```

### 변경

- 생성 이후 수정 금지
- read-only 구조로 변경

---

## Step 6. Freeze 적용

```ts
function freezeGraph(graph) {
  Object.freeze(graph)
  Object.freeze(graph.nodes)
  Object.freeze(graph.edges)
  return graph
}
```
