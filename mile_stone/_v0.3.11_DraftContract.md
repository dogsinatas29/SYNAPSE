# v0.3.11_DraftContract.md

---

## 1. 정의

> Draft Contract = NodeDraft + EdgeDraft + Validation + Commit Input  
> Draft는 단순 데이터가 아니라 “검증 가능한 실행 입력”이다.

---

## 2. 목표

- 사용자 입력을 단일 구조로 수렴
- validate와 commit이 동일 입력을 공유
- 중간 변환 없이 실행

---

## 3. 루트 타입 (단일 진입 구조)

```ts
type DraftGraph = {
  nodes: NodeDraft[]
  edges: EdgeDraft[]
}
```

---

## 4. NodeDraft

```ts
type NodeDraft = {
  id: string          // tempId
  name: string        // 파일명
  path?: string       // optional
  type: "module" | "config" | "entry"
  content?: string
}
```

---

## 5. EdgeDraft

```ts
type EdgeDraft = {
  from: string
  to: string
  type: "import" | "dependency"
}
```

---

## 6. Validation (Contract에 종속)

```ts
function validateDraft(graph: DraftGraph): void {
  for (const edge of graph.edges) {
    if (!graph.nodes.find(n => n.id === edge.from)) {
      throw new Error("INVALID_EDGE_FROM")
    }
    if (!graph.nodes.find(n => n.id === edge.to)) {
      throw new Error("INVALID_EDGE_TO")
    }
  }

  checkNoCircularDependency(graph)
}
```

---

## 7. Commit 연결 (동일 입력 사용)

```ts
function commitCluster(graph: DraftGraph): CommitResult {
  validateDraft(graph)
  return executeCommit(graph)
}
```

---

## 8. 금지 규칙

- DraftGraph → 다른 구조로 변환 금지
- validate와 commit 입력 분리 금지
- Draft 단계에서 파일 생성 금지
- Draft 단계에서 import 생성 금지

---

## 9. 불변식

```
validate(graph) 통과 → commit(graph) 가능
```

```
edge.from, edge.to ∈ nodes.id
```

---

## 10. 처리 흐름

```
User Action
  ↓
DraftGraph 생성
  ↓
validateDraft(graph)
  ↓
commitCluster(graph)
  ↓
파일 생성 + Graph 생성
```

---

## 11. 핵심 요약

> Draft는 실행 이전의 완전한 입력이며, validate와 commit은 동일한 구조를 공유해야 한다.
