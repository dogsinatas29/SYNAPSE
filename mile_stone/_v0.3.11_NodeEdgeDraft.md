# v0.3.11_NodeEdgeDraft.md

---

## 1. 정의

> Node / Edge Draft는 Commit Pipeline의 입력 데이터 구조이다.  
> 사용자의 모든 작업은 Draft 형태로 표현된다.

---

## 2. 목표

- 사용자 행동 → Draft 생성
- Draft → Commit 입력
- Commit → 실제 파일 및 그래프 생성

---

## 3. NodeDraft

```ts
type NodeDraft = {
  id: string          // tempId
  name: string        // 파일명
  path?: string       // optional (자동 생성 가능)
  type: "module" | "config" | "entry"
  content?: string    // optional (LLM 또는 템플릿)
}
```

---

## 4. EdgeDraft

```ts
type EdgeDraft = {
  from: string        // node id
  to: string          // node id
  type: "import" | "dependency"
}
```

---

## 5. 핵심 규칙

- Edge는 반드시 존재하는 NodeDraft를 참조해야 한다
- Node = 실제 파일
- Edge = import 생성 힌트

---

## 6. Draft 특징

- 불완전 상태 허용
- 점진적 생성 가능
- UI와 직접 연결됨

```ts
content?: string
path?: string
```

---

## 7. Validation 연결

```ts
validate(nodes, edges) {
  checkNodeExists(edge.from)
  checkNodeExists(edge.to)
  checkNoCircularDependency()
}
```

---

## 8. 처리 흐름

```
User Action
  ↓
Node / Edge Draft 생성
  ↓
Commit 입력
  ↓
파일 생성 + Graph 생성
```

---

## 9. 설계 원칙

- 최소 필드 유지 (불필요한 추상화 금지)
- 확장 가능하지만 현재는 단순 유지
- Draft는 “가능성 상태” 유지

---

## 10. 주의사항

- NodeDraft 없이 EdgeDraft 생성 금지
- Draft 단계에서 import 생성 금지
- Commit 이전 파일 생성 금지

---

## 11. 핵심 요약

> Draft는 실행되지 않은 구조이며, Commit을 통해서만 현실화된다.
