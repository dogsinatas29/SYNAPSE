# v0.3.11_VerificationLayer.md

---

## 1. 정의

> Verification Layer는 commit 이후 결과가 올바르게 생성되었는지 보장하는 단계이다.

---

## 2. 목적

- 실행 결과의 신뢰성 확보
- silent failure 방지
- 런타임 오류 사전 차단

---

## 3. 전체 흐름 내 위치

```
DraftGraph
  ↓
validateDraft        (Pre-check)
  ↓
planCommit           (Diff)
  ↓
executeCommit        (Transaction)
  ↓
verifyCommit         (Post-check)
```

---

## 4. 핵심 원칙

```
validate ≠ verify
```

- validate: 입력 검증
- verify: 결과 검증

---

## 5. verifyCommit 구조

```ts
function verifyCommit(result: CommitResult): void {
  verifyFiles(result)
  verifyImports(result)
  verifyDependencies(result)
  verifyBuild(result)
}
```

---

## 6. 검증 항목

### 6.1 파일 존재 검증

```ts
function verifyFiles(result: CommitResult) {
  for (const file of result.files) {
    assertFileExists(file.path)
  }
}
```

---

### 6.2 import 정합성

- 모든 import 경로가 실제 파일을 가리켜야 함
- broken import 금지

---

### 6.3 의존성 완전성

```
DraftGraph edges == 실제 import 관계
```

---

### 6.4 실행 가능성

가능한 경우:

```bash
tsc --noEmit
```

또는:

- AST parse 성공
- syntax error 없음

---

## 7. Round-Trip 검증 (고급)

### 개념

```
DraftGraph → Files → Graph 재구성 → 비교
```

### 목적

- 구조 손실 방지
- import 누락 탐지

---

## 8. 실패 처리

```ts
try {
  executeCommit(graph)
  verifyCommit(result)
} catch (e) {
  rollbackTransaction()
  throw e
}
```

---

## 9. 불변식

```
verify 실패 → 전체 rollback
```

```
verify 성공 → 실행 가능한 상태 보장
```

---

## 10. 성공 기준

- 모든 파일 존재
- import 오류 없음
- 컴파일 성공 (또는 AST parse 성공)
- DraftGraph와 결과 일치

---

## 11. 요약

> Verification Layer는 결과의 정확성과 실행 가능성을 보장하는 최종 방어선이다.
