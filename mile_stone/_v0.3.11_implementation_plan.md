## 🧠 상세 설계 및 로직 (보강)

### 1. Core Freeze (사실 계층 고정)
- **GraphModel 불변화**: `src/core/GraphModel.ts`에서 직접적인 수정을 허용하는 메서드(`addNode`, `addEdge` 등)를 제거하고 읽기 전용으로 전환합니다.
- **GraphBuilder 도입**: 그래프 생성을 순수 함수인 `buildGraph` 하나로 수렴시킵니다.
- **결정론적 정렬 (Deterministic Sorting)**: 파일 생성 및 import 순서의 일관성을 위해 Node는 ID순, Edge는 FROM-TO 순으로 정렬하여 처리합니다.
- **DataPipeline 정화**: `dispatch` 호출을 제거하고 순수 데이터 변환기(`PipelineResult`)로서의 역할만 수행하게 합니다.

### 2. Transactional Commit (Commit Contract) - [Bootstrap Stages]
- **Draft 체계**: 사용자의 요청을 `DraftGraph`로 수집합니다.
- **5단계 실행 파이프라인 (STRICT)**:
    1. **STAGE 1 — Draft Initial**: DraftGraph 객체 구축 (Buffer 상태).
    2. **STAGE 2 — Pre Validation**: `validateDraft(graph)` 실행 (순환 참조, 무효 참조 검사).
    3. **STAGE 3 — Commit Planning**: `planCommit(graph)`을 통해 `ChangeSet` 생성.
    4. **STAGE 4 — Execution**: `executeWithTransaction()`을 통한 원자적 파일 쓰기. 실패 시 전륜 롤백.
    5. **STAGE 5 — Verification**: `verifyCommit()`을 통한 최종 결과물(파일 존재, AST 유효성) 검증.

### 3. Execution & Path Resolution Policy
- **Path Resolution**: `tempId` 기반의 Node를 실제 프로젝트 경로(`/src/...`)로 변환하며, 이름 충돌 시 자동 Suffix 처리를 수행합니다.
- **Auto Import Generation**: EdgeDraft 정보를 기반으로 상대 경로를 계산하여 실제 코드 내 `import` 구문을 자동 생성합니다.

### 4. Projection Layer (해상도 제어)
- **FILE Projection**: 파일 단위의 시각화.
- **FUNCTION Projection**: 함수/내부 로직 단위의 시각화.
- **Node Identity 불변성**: 투영이 바뀌어도 노드의 Identity는 유지하여 렌더링 최적화를 보장합니다.

### 5. Rule Engine (표현 규칙 외부화)
- **Edge Compression**: 고밀도 그래프에서의 엣지 압축 규칙.
- **Layer Isolation**: 계층 간 연결 제한 규칙 (동일 계층 내 연결 권장).
- 코어 엔진은 실행만 담당하며, 규칙은 별도의 데이터셋으로 관리합니다.
