# 🚀 v0.3.11 - Mutation & Execution Model

## 📅 Status
Planned

---

## 🎯 Goal

Define how the system actually **executes and mutates state**.

> This converts the system from static architecture → working engine.

---

# 1. 🧠 Core Principle

Execution must be:

- Deterministic
- Atomic (or clearly staged)
- Observable

---

# 2. 🏗️ Execution Flow

```text
Intent
 → PhaseGate
 → RuleEngine
 → MutationEngine
 → StateCommit
 → Event/Log
```

---

# 3. 🔥 Mutation Engine (핵심)

## 역할

- Intent를 실제 state 변화로 변환
- side-effect 정의

---

## 3.1 Mutation Unit

```ts
type Mutation = {
  type: "CREATE_NODE" | "CONNECT_EDGE" | ...
  payload: any
}
```

---

## 3.2 Execution Contract

```ts
execute(mutation, state) => newState
```

- 순수 함수 권장 (가능한 경우)
- 외부 의존성 금지

---

# 4. 🧱 State Model

## 최소 구조

```ts
type State = {
  nodes: Map<NodeId, Node>
  edges: Map<EdgeId, Edge>
  clusters: Map<ClusterId, Cluster>
  layers: Map<LayerId, Layer>
}
```

---

# 5. 🔄 Mutation Strategy

## 5.1 Atomic Mode (기본)

- 하나의 Intent → 하나의 commit
- 실패 시 rollback 없음 (apply 전 차단)

---

## 5.2 Batch Mode (확장)

```text
Intent → multiple mutations → commit once
```

---

# 6. ⚠️ Conflict Handling

기본 정책:

```text
충돌 발생 → 즉시 실패
```

확장 시:

- last-write-wins
- priority-based

---

# 7. 🧬 Example Flows

## 7.1 CREATE_NODE

```text
Intent: CREATE_NODE

→ RuleEngine 통과
→ Mutation 생성
→ nodes[id] 추가
→ commit
```

---

## 7.2 CONNECT_EDGE

```text
Intent: CONNECT_EDGE

→ RuleEngine 통과
→ source/target 존재 확인
→ edge 생성
→ commit
```

---

# 8. 🔍 Consistency Hooks

Mutation 이후 항상 수행:

- node 존재 검증
- edge dangling 여부
- cluster 내부 무결성

---

# 9. 📡 Observability

모든 실행은 로그 남김:

```ts
{
  intent,
  result: "success" | "fail",
  reason?: string,
  mutations: [...]
}
```

---

# 10. 🧾 Success Criteria

- 하나의 Intent가 end-to-end 실행 가능
- State 변화가 명확히 정의됨
- 실패 조건이 deterministic

---

# 11. 🔚 Summary

> Rule은 가능성을 판단한다  
> Mutation은 현실을 만든다  

이 문서부터 시스템이 “실제로 동작”하기 시작한다.
