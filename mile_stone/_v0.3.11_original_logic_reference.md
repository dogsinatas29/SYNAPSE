# v0.3.11 기존 로직 참조 문서 (Original Logic Reference)

이 문서는 v0.3.11 리팩토링 과정에서 기존의 노드, 엣지, 클러스터 생성 로직이 누락되거나 파괴되지 않도록 보존해야 할 핵심 코드 지점을 정리한 것입니다.

## 1. 노드(Node) 생성 로직
**위치:** `src/core/DataPipeline.ts`
스캔된 파일 정보를 기반으로 Node 객체를 구성하고 엔진에 전달하는 핵심 지점입니다.

```typescript
// 기존 로직 (참조용)
const newNode: Node = {
  id: fileName,
  filePath: item.filePath,
  type: isDoc ? NodeType.DOCUMENTATION : NodeType.FILE,
  label: fileName,
  cluster_id: clusterId,
  degree: 0,
  data: { 
      label: fileName, 
      file: item.filePath, 
      cluster_id: clusterId,
      hiddenOnCanvas: isDoc 
  }
};
// v0.3.11 이전: canvasEngine.dispatch('ADD_NODE', newNode);
// v0.3.11 이후: nodes.push(newNode) -> return PipelineResult
```

## 2. 엣지(Edge) 생성 로직
**위치:** `src/core/DataPipeline.ts`
`FileScanner`를 통해 발견된 참조(`references`)를 Edge로 연결하며, 가중치와 상태를 할당합니다.

```typescript
// 기존 로직 (참조용)
let weight = GraphModel.WEIGHT_UTILITY;
if (ref.type === 'dependency') weight = GraphModel.WEIGHT_DIRECT_INCLUDE;
else if (ref.type === 'api_call') weight = GraphModel.WEIGHT_INTERNAL;

const newEdge: Edge = {
  from: fileName,
  to: targetNodeId,
  type: this.mapEdgeType(ref.type),
  weight: weight,
  status: 'confirmed'
};
// v0.3.11 이전: canvasEngine.dispatch('CONNECT_EDGE', newEdge);
// v0.3.11 이후: edges.push(newEdge) -> return PipelineResult
```

## 3. 클러스터(Cluster) 생성 및 관리
**위치:** `src/core/DataPipeline.ts`
디렉토리 구조를 분석하여 시스템 클러스터(Project Root, Ghost, Doc Shelf) 및 폴더 클러스터를 생성합니다.

```typescript
// 시스템 표준 클러스터
{ id: 'cluster_root', label: '🏠 Project Root', type: 'system' }
{ id: 'cluster_ghosts', label: '👻 External Ghosts', type: 'system' }
{ id: 'doc_shelf', label: '📚 Documentation Shelf', type: 'system', collapsed: true }
```

## 4. 저수준 Mutation (실제 데이터 삽입)
**위치:** `src/core/canvas-engine/StateManager.ts`
전달받은 데이터를 `GraphModel`에 최종 반영하며 좌표 및 UI 데이터를 정규화합니다.

```typescript
// StateManager.ts (v0.3.10 기준)
private mutateAddNode(payload: any): CanvasState {
  const newNode: Node = {
    position: payload.position || { x: Math.random() * 500, y: Math.random() * 500 },
    // ...
  };
  graphModel.addNode(newNode);
  return this.getSnapshot();
}
```

---

## ⚠️ v0.3.11 전환 시 주의사항
- **ID 기반 매칭**: 노드와 엣지의 ID 생성 규칙이 변경되지 않아야 함 (파일명 기반 등).
- **좌표 보존**: `bufferNodes`로 관리될 때도 초기 좌표 할당(`Math.random()`) 및 이동 데이터가 소실되지 않아야 함.
- **클러스터 소속**: 노드가 생성될 때 할당된 `cluster_id`가 실제 렌더링 시에도 유효해야 함.
