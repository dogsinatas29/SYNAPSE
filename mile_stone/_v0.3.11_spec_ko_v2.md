# 🛡️ v0.3.11 명세서 — Projection 기반 해상도 제어

---

## 📌 개요

v0.3.11은 기능 추가가 아니라 **엔진 규칙 고정 단계**다.

SYNAPSE를 단일 레벨 시각화 도구에서 벗어나  
**다중 해상도 상태 머신**으로 전환하는 것이 목적이다.

---

## 🎯 목표

1. 그래프 폭발 방지
2. File ↔ Function 해상도 전환의 결정론 확보
3. Projection 간 상태 일관성 유지
4. 고밀도 그래프 안정성 확보

---

## 🧠 핵심 원칙

### 1. 결정론적 Projection

```ts
SystemState {
  activeProjection: "FILE" | "FUNCTION"
}
```

- Projection은 UI가 아니라 시스템 상태
- 전환 시 노드 재생성 금지

---

### 2. Node Identity 불변성

```ts
Node {
  id: string // 절대 변경 금지
  type: "file" | "function" | "virtual"
  layer: "L1" | "L2" | "L3"
  projections: {
    FILE?: FileView
    FUNCTION?: FunctionView
  }
}
```

---

### 3. Edge 압축

```ts
AggregatedEdge {
  source: NodeID
  target: NodeID
  weight: number
  internalEdges: Edge[]
}
```

| Projection | 표시 |
|-----------|------|
| FILE      | Aggregated |
| FUNCTION  | Internal |

---

### 4. Scope 격리

```ts
CanvasStack = [
  MainCanvas,
  OverlayCanvas
]
```

- MainCanvas freeze
- Overlay 독립 동작

---

### 5. Layer 제약

```ts
RuleEngine {
  validate(edge) {
    if (edge.from.layer !== edge.to.layer) {
      return "VETO"
    }
  }
}
```

---

### 6. Lazy Materialization

- 필요한 노드만 생성
- 전체 생성 금지

---

## 🧱 Rule Externalization 정책

### 원칙

- Rule은 코드가 아니라 **데이터**
- Core는 실행만 담당

---

### 금지

- 조건문 하드코딩
- Projection 로직 코드 고정
- Layer 검증 직접 삽입

---

### 구조

```ts
RuleSet {
  projectionRules
  layerRules
  edgeRules
}

Engine {
  apply(ruleSet, context)
}
```

---

### 효과

- 룰 교체로 동작 변경
- 코어 안정성 유지
- 실험 속도 증가

---

### 선언

코어는 똑똑해지지 않는다.  
**규칙이 똑똑해진다.**
