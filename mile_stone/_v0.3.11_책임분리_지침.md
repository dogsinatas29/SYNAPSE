# v0.3.11 책임 분리 및 단순화 지침

## 1. 목표

- 데이터 / 표현 / 규칙 / 상태 완전 분리
- 각 레이어는 단일 책임만 가진다
- 흐름은 단방향으로 유지한다

---

## 2. 레이어 정의

### Core (데이터)
- Graph 생성
- Node / Edge 구조
- immutable

금지:
- UI 접근
- 상태 변경
- 렌더링 로직

---

### Projection (해상도 변환)
- Graph → View 변환
- File / Function 단위 분리

금지:
- 상태 저장
- UI 이벤트 처리

---

### Rule Engine (표현 규칙)
- Edge Compression
- Layer Isolation

금지:
- Graph 수정
- UI 의존

---

### Renderer (표현)
- View 렌더링만 수행

금지:
- Graph 접근
- 비즈니스 로직

---

### StateManager (상태)
- UI 상태 관리 (selection, mode 등)

금지:
- Graph mutation
- rendering 로직

---

## 3. 금지 패턴

### ❌ 혼합 책임

- Renderer에서 데이터 생성
- StateManager에서 Graph 수정
- Projection에서 상태 변경

---

### ❌ 양방향 흐름

- UI → Graph 직접 수정
- Renderer → Core 호출

---

## 4. 권장 흐름

graph = buildGraph()
view = project(graph)
view = applyRules(view)
render(view)

---

## 5. 이벤트 처리 원칙

### BEFORE
onClick → 데이터 변경

### AFTER
onClick → 상태 변경 → projection 재실행

---

## 6. 리팩토링 순서

1. Core Freeze
2. Renderer에서 graph 접근 제거
3. Projection Layer 도입
4. Rule Engine 분리
5. 이벤트 → 상태 구조 변경

---

## 7. 검증 기준

- Graph는 어디에서도 수정되지 않음
- Renderer는 View만 사용
- Rule 제거 시 기능 유지
- Projection 변경 시 UI만 변경

---

## 8. 단순화 기준

좋은 구조:

- 함수 하나 = 역할 하나
- 파일 하나 = 책임 하나

나쁜 구조:

- 한 함수에서 데이터 생성 + 렌더링
- 상태 + 로직 + UI 혼합

---

## 9. 최종 목표

- 해상도 제어 가능
- 구조 변경 없이 표현 변경 가능
- 디버깅 가능한 구조

---

## 결론

책임 분리는 선택이 아니라
v0.3.11 구조에서 필수 조건이다.
