# 🧠 1. 핵심 아키텍처 진단 (Revised Post-Mortem)

## 🔴 Red-out의 실제 원인

### ❌ 잘못된 해석 (기존)
- 데이터가 적은데 과부하 발생
- 그리드 부재로 CPU 폭주

### ✅ 실제 원인 (확정)
- **그래프 밀도 폭발 (Edge Explosion)**
- **엣지 가중치 부재 (Weight 없음)**
- **무차별 Full Rendering**
- **Render Budget 없음**

---

## 📊 핵심 정의

```
Red-out =
  Edge Density
+ Render Overdraw
+ Layout Entropy
```

👉 **문제는 "많이 계산"이 아니라 "전부 그림"**

---

# 🛠️ 2. 핵심 수정 전략 (Critical Fixes)

## 1️⃣ Edge Weight Filter (최우선)

```ts
if (edge.weight < threshold) {
  skip_render();
}
```

### Weight 기준
- Direct include: 1.0
- Project internal: 0.7
- Utility: 0.2
- Transitive: 0.1

---

## 2️⃣ Render Budget 도입

```ts
MAX_NODES = 100;
MAX_EDGES = 200;

if (currentRenderCount > budget) {
  degradeRendering();
}
```

👉 시스템 폭주 차단 핵심 장치

# 📏 3. Grid System (보조 시스템)

## ✔ Snap-to-Grid

```ts
pos.x = Math.round(pos.x / 40) * 40;
pos.y = Math.round(pos.y / 40) * 40;
```

효과:
- 좌표 안정화
- Diff 기반 렌더링 가능

---

- 동일 입력 → 동일 결과
- 캐싱 가능
