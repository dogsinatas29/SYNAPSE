# Warning Rendering Optimization v0.3.1

📅 작성 일시: 2026.03.30  
상태: 🚧 Performance Stabilization

---

# 🧠 1. 문제 정의

## ❗ 현재 구조

> 분석 결과 → 즉시 시각화 → 매 프레임 렌더링

### 문제점
- 경고 아이콘 수 증가 = Draw Call 증가
- 상태 변화 없음에도 지속적인 Redraw
- 저사양 환경에서 프레임 드랍 발생

👉 **경고 시스템이 성능 병목이 되는 구조**

---

# 🎯 2. 핵심 원칙

## ✔ 경고는 상태이지, 항상 렌더링 대상이 아니다

- 항상 계산 ⭕
- 항상 표시 ❌

---

# 🛠️ 3. 해결 전략

## 1️⃣ Lazy Rendering

```ts
if (!isVisible(node)) return;
```

- 화면 밖 노드 렌더 금지
- 저줌 상태에서 경고 숨김

---

## 2️⃣ Pressure 기반 표시 제어

```ts
if (pressure < 0.7) {
  hideAllWarnings();
}

if (pressure >= 0.7 && pressure < 0.9) {
  showMinesLimited();
}

if (pressure >= 0.9) {
  showCriticalOnly();
}
```

---

## 3️⃣ 샘플링 (Top-K 제한)

```ts
const MAX_WARNINGS = 20;
warnings = pickTopKBySeverity(warnings, MAX_WARNINGS);
```

👉 전체 표시 금지, 대표만 표시

---

## 4️⃣ Dirty Flag 기반 렌더링

```ts
if (!node.warningChanged) return;
renderWarning(node);
```

👉 변경된 것만 렌더링

---

## 5️⃣ Sprite Batch Rendering

```ts
batch.draw(warningIcons);
```

### 효과
- 개별 draw call → batch 1회
- 저사양 환경에서 성능 크게 개선

---

## 6️⃣ LOD (Level of Detail)

```ts
if (zoom < 0.5) hideWarnings();

if (zoom >= 0.5 && zoom < 1.0) showOnlySkull();

if (zoom >= 1.0) showFilteredWarnings();
```

---

## 7️⃣ 디바운싱

```ts
if (now - lastUpdate < 200ms) return;
```

👉 이벤트 폭주 방지

---

# 💣 4. 구조 개선 (핵심)

## ❗ Node 기반 → Cluster 기반 경고로 전환

```ts
cluster.warningLevel = max(childWarnings);
```

### 변화

| 기존 | 개선 |
|------|------|
| 노드 100개 = 아이콘 100개 | 클러스터 5개 = 아이콘 5개 |
| GPU 부하 큼 | GPU 부하 감소 |
| 시각적 노이즈 | 의미 집중 |

---

# 📊 5. 최종 렌더링 파이프라인

```ts
if (!isVisible) return;

if (pressure < threshold) return;

warnings = filterBySeverity(warnings);

warnings = sample(warnings, MAX_WARNINGS);

batchRender(warnings);
```

---

# ⚠️ 6. 주의 사항

## 과도한 필터링
- 중요한 경고가 숨겨질 수 있음
→ severity 기반 유지 필요

## 클러스터 정확도
- 잘못된 aggregation 시 의미 왜곡 가능

---

# 🎯 7. 결론

👉 경고 시스템은 정확해야 하지만, 항상 표시될 필요는 없다
