## 🧠 상세 설계 및 로직

### 1. Runtime Phase Enforcement (`PhaseManager`)
- **목적:** 시스템의 초기화 과정을 7개 단계(Phase)로 강제 분리하고, 각 단계의 성공 여부를 검증한 후에만 다음 단계로 진행.
- **Phase 정의:** `DATA(0) -> GRAPH(1) -> SNAPSHOT(2) -> CONTROL(3) -> GRID(4) -> RENDER(5) -> DEBUG(6) -> FINAL(7)`
- **동작 원리:** 
    - `assertPhase(required)`: 현재 Phase가 요구된 Phase 이상인지 확인. 아니면 Exception 발생.
    - `advancePhase(next)`: 다음 단계로 전이. 순서가 맞지 않거나 시스템이 `locked` 상태면 거부.
    - `lockSystem(reason)`: 치명적 오류 발생 시 시스템을 `LOCKED` 상태로 전환하여 모든 후속 작업 차단.

### 2. Iron Grid Refined Performance Strategy
- **Edge Weight Filtering:** 엣지 가중치에 따른 렌더링 필터링 도입 (Direct Include=1.0, Utility=0.2 등).
- **Render Budget:** 최대 노드/엣지 수 제한 (`MAX_NODES=100`, `MAX_EDGES=200`). 초가 시 `degradeRendering()`.
- **Hub Node Collapse:** 연결성이 너무 높은 노드(Hub)는 축소하여 시각적 복잡도 감소.
- **Incremental Rendering:** 변경된 노드만 렌더링하는 Diff 기반 렌더링 구현.
- **Snap-to-Grid:** 좌표를 40px 단위로 정렬하여 레이아웃 안정성 및 결정성 확보.

### 3. System Validation (MANDATORY)
- 각 Phase별 성공/실패 시나리오를 검증하는 테스트 스위트 구축.
- 실패 시 반드시 `SYSTEM LOCK`이 걸리는지 확인.

## ⚠️ 예외 처리 및 주의 사항
- **Phase Violation:** 개발 중 Phase 순서를 어길 경우 즉시 에러가 발생하므로, 초기화 로직의 순서를 엄격히 준수해야 함.
- **Data Loss Illusion:** Edge filtering으로 인해 실제 존재하는 연결이 안 보일 수 있으므로, 필터링 상태를 사용자에게 알리는 Warning UI 필요.
- **Manual Reset:** `SYSTEM LOCK` 상태가 되면 수동 리셋 명령(`synapse.resetEngine`)이 필요함.
