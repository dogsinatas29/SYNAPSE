# 🚀 SYNAPSE v0.3.23 - Runtime Safety Hardening (Level 2)

## 📌 Objective
Address secondary runtime risks after initial safety hardening:

1. I/O Bottleneck from realpathSync
2. Computation spikes during rebuildDerived
3. Case-sensitivity issues in path normalization

---

# 🧠 Core Principle

> Eliminate synchronous I/O in hot paths, distribute computation, respect OS semantics.

---

# 1️⃣ PATH NORMALIZATION (OPTIMIZED)

## Problem
realpathSync inside runtime → UI freeze

## Solution: Pre-normalized Cache

```ts
const blacklist = new Set<string>()

function preloadBlacklist(paths: string[]) {
  for (const p of paths) {
    blacklist.add(normalizePathStatic(p))
  }
}

function normalizePathStatic(p: string): string {
  let resolved = path.resolve(p)

  try {
    resolved = fs.realpathSync(resolved)
  } catch {}

  return normalizeCase(resolved)
}
```

---

## Runtime Check (NO IO)

```ts
function isBlacklisted(p: string) {
  return blacklist.has(normalizeCase(path.resolve(p)))
}
```

---

# 2️⃣ OS-SAFE CASE HANDLING

```ts
const isCaseInsensitive = process.platform === 'win32' || process.platform === 'darwin'

function normalizeCase(p: string): string {
  return isCaseInsensitive ? p.toLowerCase() : p
}
```

# 3️⃣ INCREMENTAL DERIVED REBUILD

## Problem
computeEdges / computeClusters → CPU spike

## Solution: Chunk Processing

```ts
function rebuildDerivedIncremental(nodes, graphModel, chunkSize = 200) {
  let index = 0

  function processChunk() {
    const end = Math.min(index + chunkSize, nodes.length)

    for (; index < end; index++) {
      updateNodeRelations(nodes[index], graphModel)
    }

    if (index < nodes.length) {
      requestAnimationFrame(processChunk)
    } else {
      finalizeGraph(graphModel)
    }
  }

  processChunk()
}
```
