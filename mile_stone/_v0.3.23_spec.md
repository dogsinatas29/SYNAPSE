# 🚀 SYNAPSE v0.3.23 Spec - Hybrid Blacklist System

## 📌 Objective
Prevent graph explosion caused by uncontrolled file/folder growth by introducing a **hybrid blacklist system** that combines:
- Lightweight pre-filtering
- Real-time graph-level discard
- Post-processing cleanup with full rebuild

---

## 🧠 Core Design Philosophy

> Block early when cheap, discard instantly when detected, and rebuild cleanly when needed.

---

## 🏗️ Architecture Overview

```
Filesystem
   ↓
FileScanner (Light Pre-filter)
   ↓
GraphModel (Immediate Discard - Critical)
   ↓
SnapshotSystem (Full Cleanup / Rebuild)
   ↓
Renderer
```

---

## ⚙️ 1. Blacklist Data Structure

```ts
type Blacklist = {
  folders: Set<string>
  files: Set<string>
}
```

- Use normalized absolute paths
- O(1) lookup required

---

## ⚙️ 2. Path Matching Rules

```ts
function isBlacklisted(path: string): boolean {
  const normalized = normalize(path)

  if (blacklist.files.has(normalized)) return true

  for (const folder of blacklist.folders) {
    if (normalized.startsWith(folder)) return true
  }

  return false
}
```

---

## ⚙️ 3. FileScanner (Light Pre-filter)

Purpose: Avoid unnecessary deep traversal

```ts
function scan(path) {
  if (isBlacklisted(path)) return

  if (isDirectory(path)) {
    for (child of path) scan(child)
  } else {
    processFile(path)
  }
}
```

- Only shallow protection
- Not relied on as primary defense

---

## ⚙️ 4. GraphModel (Critical Layer)

### Immediate Discard Strategy

```ts
function onNodeCreated(node) {
  if (isBlacklisted(node.path)) {
    discard(node)
    return
  }

  insertNode(node)
}
```

- Prevents graph explosion in real-time
- Stops edge propagation early

---

## ⚙️ 5. SnapshotSystem (Full Cleanup)

### Full Rebuild Strategy (Required)

```ts
function rebuildSnapshot() {
  clearGraph()

  for (node of scannedNodes) {
    if (!isBlacklisted(node.path)) {
      addNode(node)
    }
  }

  rebuildEdges()
}
```

### Why Full Rebuild?
- Prevent orphan edges
- Ensure graph consistency
- Avoid partial corruption

---

## ⚙️ 6. Blacklist Update Flow

```ts
onBlacklistUpdated() {
  triggerFullRebuild()
}
```

Steps:
1. Update config
2. Emit event
3. Clear graph
4. Rescan + rebuild

---

## 🖥️ 7. GUI Requirements

### Features
- Right-click folder → Add to Blacklist
- Right-click file → Add to Blacklist

### Behavior
- Normalize path
- Update config
- Trigger rebuild

---

## ⚠️ 8. Critical Constraints

### Performance
- No allocations in hot paths
- Set-based lookup only

### Data Integrity
- Node + Edge must be removed together
- No partial deletion allowed

### Path Safety
- Normalize all paths (OS independent)

---

## 🧪 9. Failure Modes (Must Handle)

| Issue | Cause | Solution |
|------|------|---------|
| Graph explosion | No early discard | GraphModel filter |
| Orphan edges | Partial deletion | Full rebuild |
| Missed blacklist | Path mismatch | Normalize paths |
| Performance drop | Late cleanup | Hybrid strategy |

---

## ✅ 10. Final Strategy Summary

| Layer | Role |
|------|-----|
| FileScanner | Light filtering |
| GraphModel | Immediate protection (core) |
| Snapshot | Full consistency rebuild |

---

## 🧾 Conclusion

- Pure pre-filter is insufficient
- Pure post-cleanup is inefficient
- Hybrid approach is mandatory

> The system must reject, discard, and rebuild — not just filter.
