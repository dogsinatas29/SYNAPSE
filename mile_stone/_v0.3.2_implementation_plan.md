# Implementation Plan - v0.3.2 Edge Rendering Parity

## 1. Problem Analysis
- **Missing Arrows**: Edges are drawn center-to-center. The arrow (rendered at the segment end) is buried inside the target node's collision box.
- **Tapering Lines**: The current shader logic for `arrowWidth` in `vsEdge` causes a linear decrease in width towards the end, making the line look like a needle rather than a uniform edge.

## 2. Proposed Changes

### A. Boundary Intersection Logic (`ui/webgl-renderer.js`)
Modify `updateEdgeData` to calculate the intersection points of the edge line with the source and target node rectangles (120x60).
- Input: `p1` (src center), `p2` (tgt center)
- Calculation: Simple AABB-Line intersection or clamping to the box.
- Output: `p1_border`, `p2_border` passed to `instanceEdge` buffer.

### B. Vertex Shader Refinement (`vsEdge`)
Replace the tapering logic with a "Stepped" width logic:
- `x < 0.85`: Body of the line. `width = lineWidth`.
- `x >= 0.85`: Arrow zone. `width = lineWidth * 3.0` (flaring out for the base).
- The transition should be sharp or slightly sloped to form the back of the arrowhead.

### C. Fragment Shader Refinement (`fsEdge`)
Adjust the `discard` logic to form a proper triangle head within the flare:
- `if (x > 0.85)`: Calculate `y` threshold based on `(1.0 - x)` to form a triangle.
- Ensure the arrow is distinct from the thin line.

## 3. Step-by-Step Execution

1. [ ] **Intersection Utility**: Add a small helper function in `WebGLRenderer` to calculate box-line intersection.
2. [ ] **Update `updateEdgeData`**:
    - Apply intersection to `src.position` and `tgt.position` before storing in `data` buffer.
3. [ ] **Shader Update**:
    - Modify `vsEdge` to stop tapering the body.
    - Modify `fsEdge` to sharpen the arrowhead.
4. [ ] **Validation**: Compare 2D and 3D modes to ensure parity.

## 4. Risks & Mitigations
- **Edge cases (Same position)**: Add checks for length close to zero to avoid division by zero.
- **Zoom flickering**: Ensure the arrow base size feels right at different zoom levels by possibly clamping or capping the multiplier.
