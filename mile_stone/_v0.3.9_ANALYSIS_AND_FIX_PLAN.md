### 1.2 로그 기반 원인 분석

#### [Critical-A] 캔버스 높이 0 문제 (Canvas Height Bug)

**증거**:
```
[SYNAPSE] Canvas stabilized (Async). Size: 1270x0
        ↑ 높이가 0이면 모든 노드가 그려질 공간이 없음
```

**코드 위치**: [canvas-engine.js:1468-1477]
```javascript
resizeCanvas(immediate = false) {
    const container = this.canvas.parentElement;
    const width = container.clientWidth;
    const height = container.clientHeight;  // ← 여기서 0을 가져옴
    const targetWidth = Math.floor(width * dpr);
    const targetHeight = Math.floor(height * dpr);  // ← 0이 됨

    if (this.canvas.width !== targetWidth || this.canvas.height !== targetHeight) {
        this.canvas.height = targetHeight;  // ← 캔버스 높이가 0으로 설정! 
    }
}
```

**근본 원인**:
- 부모 컨테이너의 CSS 레이아웃이 2D 모드(WebGL 비활성화) 전환 시 `clientHeight`를 0으로 계산
- 이는 2D 캔버스를 감싸는 컨테이너의 `display`, `flex`, `height` 설정이 WebGL 캔버스 제거 후 붕괴된 것 같음
- 또는 DOM 리플로우 타이밍에서 높이가 미처 계산되지 않은 상태로 `resizeCanvas` 호출

**검증**:
- 캔버스 높이가 0이면 → 렌더링된 모든 노드는 화면 밖(높이가 없음)으로 그려짐
- 혼합 렌더링(Hybrid): 2D에서 엣지 배지를 그리므로 엣지 위의 아이콘만 보임

#### [Critical-B] 렌더링 루프 단절 (Rendering Loop Break)

**코드 위치**: [canvas-engine.js:4425-4430]
```javascript
if (this.webglEnabled && this.webglRenderer) {
    // WebGL 모드 (가속 ON)...
} else {
    // 2D 모드 (가속 OFF)
    this.renderEdges2D();  
    this.renderNodes2D(zoom);  // ← 함수 호출 있음
    this.renderLabels2D(); 
}
```

**발견**:
- `renderNodes2D()` 함수는 **정의되어 있고 호출되고 있음** (false alarm)
- 하지만 `renderNodes2D` 구현을 보면 [canvas-engine.js:4541-4575]:
  ```javascript
  renderNodes2D(zoom) {
      const dpr = window.devicePixelRatio || 1;
      const canvasWidth = this.canvas.width / dpr;
      const canvasHeight = this.canvas.height / dpr;  // ← 여기서 0 / dpr = 0
      const worldLeft = -this.transform.offsetX / zoom;
      const worldTop = -this.transform.offsetY / zoom;
      const worldRight = (canvasWidth - this.transform.offsetX) / zoom;  // ← 계산 오류
      const worldBottom = (canvasHeight - this.transform.offsetY) / zoom;  // ← canvasHeight = 0
      const margin = 200;
      
      for (const node of this.nodes) {
          if (!node.position) continue;
          // 뷰포트 컬링 로직이 있지만, 캔버스가 높이 0이면 모든 노드가 worldBottom 범위를 벗어남
          this.renderNode(node, zoom);  // ← 호출되지만 canvasHeight=0이므로 render도 안됨
      }
  }
  ```

**근본 원인**:
- `canvasHeight`가 0이면 → 뷰포트 계산이 0으로 고정
- → 모든 노드가 렌더링 범위 밖으로 판단되거나, 렌더링되어도 높이가 없으므로 표시 안됨

### 1.3 2D 모드 버그의 최종 원인 체인

```
1. WebGL 비활성화 (2D 모드 진입)
     ↓
2. DOM 리플로우: WebGL 캔버스 제거 → 레이아웃 재계산
     ↓
3. 부모 컨테이너의 clientHeight가 계산되기 전에 resizeCanvas() 호출
     ↓
4. canvasHeight = container.clientHeight = 0 (아직 리플로우 미완료)
     ↓
5. renderNodes2D() 호출 → canvasHeight=0 → 뷰포트 = 0
     ↓
6. 모든 노드가 렌더링 범위 밖 / 또는 높이가 없어 표시 안됨
     ↓
7. 에코모드가 렌더링 중단하면서 캔버스 상태 변경 불가
     ↓
8. 그 결과: 화면에 아무것도 안 보임 (노드), 느려짐 (재시작 오버헤드)
```

### 2.3 문제 원인 분석

#### [Issue-A] iconMap 접근 가능성 검증

**가능성 1**: `iconMap[e.type]`이 `undefined` 반환
- `e.type`이 iconMap에 없는 값이면 → fallback `'D'` 사용됨
- 예: `e.type = 'call'` 인데 실제로는 `'calls'` 또는 다른 케이스일 수도

**가능성 2**: iconMap이 로컬 스코프라서 접근 불가
- 위 코드는 `renderBadges` 메소드 내 로컬 스코프에 iconMap 정의
- 만약 다른 부분에서 iconMap을 사용하려고 하면 undefined

#### [Issue-B] TextAtlas가 이모지를 제대로 그리지 못함

**TextAtlas._drawGlyph 구현** [webgl-renderer.js:42-67]:
```javascript
_drawGlyph(ch) {
    const ctx = this.ctx;
    ctx.font = '12px Inter, sans-serif';  // ← Inter 폰트는 이모지 미지원!
    
    const m = ctx.measureText(ch);
    const w = Math.ceil(m.width) + 2;
    const h = 16;  // ← 이모지는 보통 더 큼
    
    ctx.fillText(ch, this.x + 1, this.y + 2);  // ← 실제 렌더링
    
    // 이모지가 렌더링 안됨 → ASCII fallback 또는 공백 처리됨
}
```

**문제**:
- `Inter` 폰트는 **이모지를 지원하지 않음**
- 이모지 렌더링 시 → 시스템 fallback 폰트가 사용되거나
- 또는 텍스트가 아예 렌더링 안되거나
- 또는 텍스트 아틀라스에 이모지가 흐릿하게/제대로만 저장됨

**결과**:
- TextAtlas.glyphMap에 이모지가 저장되지만 **이모지 비트맵이 텍스처에 제대로 그려지지 않음**
- 또는 이모지의 비트맵이 매우 작거나 검은색으로 렌더링됨
- WebGL에서 UV coordinates를 계산해서 쿼드를 그려도 → 텍스처에서 아무것도 안 보임

#### [Issue-C] Fallback 메커니즘

**논리**:
```javascript
const typeIcon = iconMap[e.type || 'dependency'] || 'D';
```

**경로**:
1. `iconMap[e.type]` 없음 → `undefined`
2. `iconMap['dependency']` (fallback) → 이모지 반환 (`\u{1F517}`)
3. 하지만 TextAtlas가 이 이모지를 제대로 못그으면 → 텍스처에 빈 공간
4. 마지막 fallback: `|| 'D'` → 절대 사용 안됨 (왜냐하면 `\u{1F517}`은 falsy아님)

**그러면 왜 'D'가 보이는가?**
- 가능성: `iconMap['dependency']` 자체가 제대로 정의되지 않았거나
- 또는 `e.type || 'dependency'`에서 `e.type`이 존재하지만 iconMap에 없는 키라서 `undefined` → fallback `'D'`

### 2.4 3D 모드 아이콘 문제의 최종 원인

```
가능성 1 (가능성 낮음):
  e.type이 iconMap에 없는 값
  → typeIcon = undefined
  → fallback = 'D'
  → TextAtlas.addText('D')
  → WebGL에서 'D' 렌더링 ❌

가능성 2 (가능성 높음):
  iconMap['dependency'] = '\u{1F517}' (이모지)로 정의됨
  → typeIcon = '\u{1F517}'
  → TextAtlas.addText('\u{1F517}')
  → _drawGlyph(이모지)에서 Inter 폰트로 렌더링 시도
  → 폰트 미지원 → 빈 비트맵 또는 잘못된 렌더링
  → WebGL에서 텍스처 좌표 계산 후 그려도
  → 텍스처에 이모지가 없거나 너무 작음
  → 결과: 아무것도 표시 안됨

가능성 3 (가능성 높음):
  v0.3.9에서 코드 수정 중 iconMap 정의가 손상됨
  → 폰트 지정을 다시 'Inter'로 돌렸거나
  → Emoji 지원 폰트(Noto Color Emoji, Apple Color Emoji 등) 제거됨
```
