## 🧠 상세 설계 및 로직
### 1. DTR (Deep-Thinking Ratio) 사고 제어 엔진
- **사고의 계량화:** 전체 추론 경로 중 심층 추론이 차지하는 비율을 $DTR = \frac{Deep Reasoning Steps}{Total Inference Path}$로 정의.
- **ComplexityScouter:** 파일의 코드 복잡도를 정적 분석하여 초기 DTR 값을 휴리스틱하게 산정 (0.1 ~ 0.9).
- **Inference Pressure Gauge:** 에디터 상태바에 AI 사고 압력을 실시간 표시 (Sky Blue → Emerald → Violet).

### 2. SYNAPSE 시각화 물리 법칙
- **Glow Rule:** DTR 0.7 이상의 고밀도 노드에 보라색(#8A2BE2) 네온 발광 효과 적용.
- **Dynamic Tension:** DTR 수치에 비례하여 연결선(Edge)의 두께가 실시간으로 변화하여 논리적 긴장감 표현.
- **Semantic Navigation:** 캔버스 좌우/상하에 맞춤형 스크롤바를 배치하여 대규모 아키텍처 탐색 편의성 극대화.

   - **버튼 재배치**: `Edit Logic` 버튼을 `Node`, `Connect` 버튼 앞으로 이동시키고, `Edit Logic`이 활성화되기 전까지는 해당 두 버튼이 화면에 보이지 않고 활성화되지 않는다.

## 📝 Release Notes (v0.2.17)
### [ENG]
**SYNAPSE v0.2.17 is a monumental update that crystallizes system stability, canvas UX, intelligent AI orchestration, and the 'Logic Edit' workflow.**
- **DTR Engine & Gauges:** Visualize AI reasoning depth through purple glow effects on nodes and control Inference Pressure directly from the VS Code status bar.
- **WYSIWYG Logic Editing:** Adding/deleting nodes and connecting edges natively manipulates workspace files. Connection confirmation automatically injects language-specific `import` syntax.
- **Buffer Cluster Automation:** Newly created manual nodes instantly drop directly into the `Buffer Cluster` coordinates (-1100, 1000) with a smooth camera auto-focus. Connecting from the buffer seamlessly promotes nodes to the `Reserved Cluster`.
- **Enhanced UX Clarity:** The destructive `Node` and `Connect` tools are strictly hidden until `Edit Logic` is enabled. Documentation Shelfs now collapse by default, and validation badges (`?`, `!`) are significantly super-sized for fast recognition.
- **Anti-Resurrection Logic:** Automated full-state snapshots and sequential task queues replace destructive deletions with `// [SYNAPSE_DELETED]` wrappers, completely preventing ghost nodes.

## ⚠️ 스냅샷 및 상태 저장 규정 (Auto-Snapshot)
- **모든 상태 변화 백업**: 캔버스 내에서의 노드 삭제, 노드 생성, 엣지 삭제, 엣지 생성 등 **어떤 형태의 변화든 발생 시 무조건 스냅샷을 자동 생성**합니다. (이름: `Auto Backup (Auto-Save)`)
- **삭제 정보 강제 각인**: 노드나 엣지를 지웠을 때, 지워진 그 즉시의 상태 캔버스가 스냅샷의 최상단 기억(Baseline)으로 덮어씌워지며 파일 스캐너가 과거 기록(Ghost/Stale Summary)에 의해 좀비를 부활시키는 것을 원천 차단합니다.
- **히스토리 접근성**: 스냅샷 히스토리 패널은 스냅샷이 누적됨에 따라 **세로 스크롤 바**를 제공하여 안정적인 백업 탐색 경험을 보장합니다.

## ⚠️ 노드 이름 변경 시 코드 동기화 정책 (Refactoring Policy)
> [!IMPORTANT]
> **현상**: 캔버스에서 노드 이름을 변경하더라도 기존 소스 코드의 `import` 문이 자동으로 수정되지 않음.
> **이유**:
> 1. **메타데이터 분리**: 캔버스의 라벨 변경은 시각적 메타데이터(`project_state.json`)에 우선 반영되며, 소스 코드의 직접적인 텍스트 치환(Global Rename)은 의도치 않은 파괴적 수정을 방지하기 위해 제한됨.
> 2. **안전한 리팩토링**: 이름 변경 시 확장자 혼용이나 파일 시스템 불일치 문제를 방지하기 위해, 사용자가 명시적으로 엣지를 재연결(삭제 후 새 이름으로 확정)하는 방식을 권장함.
