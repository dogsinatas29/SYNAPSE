## 🧠 실무형 아키텍처 제약 보완 (Architecture Guardrail)

### 1. 'Sidecar' 및 'Cross-cutting' 레이어 정의 (Layer 0 / Layer 99)
모든 노드가 수직 계층에만 속할 순 없습니다. Logger, Exception Handler 등 공통 모듈을 위한 예외 규칙입니다.
- **효과**: 인덱스를 `Shared(0)` 혹은 `Global(99)`로 지정하면, 중력 법칙의 1차 검역을 프리패스하여 전역적 접근이 허용됩니다.

### 2. 'State'와 'Event'의 방향성 분리 (Command vs Event)
데이터베이스에서 프론트엔드로의 직접 역류(Command)는 금지되지만, 간접적인 상태 전달(Event)은 가능해야 합니다.
- **효과**: 엣지 타입을 `Command`와 `Event`로 분리하고, 상류로의 역행은 오직 `Event Bus` 노드를 경유한 `Event` 엣지로만 허용합니다.

### 3. 'Escape Hatch' (예외 처리 규정)
레거시 병목 등 불가피하게 레이어 규칙을 파괴해야 하는 찰나의 순간을 위한 도피처입니다.
- **작동**: 코드 내 `// @synapse-bypass` 주석 삽입 시, 💀 CRITICAL 처리를 보류하고 ⚠️ Warning(기술 부채) 상태로 유예시킵니다.

### 4. CI/CD 파이프라인 연동 (Headless Mode)
- **효과**: 캔버스를 열지 않아도 터미널(CI/CD)에서 `synapse-check` 스크립트를 통해 아키텍처 위반 엣지를 빌드 실패로 직결시키는 진정한 '목줄' 역할을 수행합니다.

## 📜 Rules.md - JSON Schema Specification (v0.1)
이 규격은 SYNAPSE 엔진이 `LogicAnalyzer.ts`를 통해 참조하는 실질적인 아키텍처의 헌법(JSON)입니다.

### 1. JSON Schema Draft (synapse.config.json)
```json
{
  "project": "SYNAPSE",
  "version": "v0.3.0",
  "architecture_guardrail": {
    "layers": [
      { "id": "shared", "index": 0, "description": "공통 유틸리티, 상수, 모든 레이어에서 접근 가능" },
      { "id": "frontend", "index": 1, "description": "UI 컴포넌트 및 클라이언트 로직" },
      { "id": "api", "index": 2, "description": "외부 통신 및 데이터 매핑" },
      { "id": "service", "index": 3, "description": "핵심 비즈니스 로직 및 도메인 모델" },
      { "id": "database", "index": 4, "description": "데이터 영속성 및 원천 데이터 모델" }
    ],
    "policies": {
      "gravity_rule": { "enabled": true, "mode": "strict" },
      "inter_cluster_rule": { "enabled": true, "enforce_bridge": true },
      "same_layer_communication": { "allow": true }
    },
    "exceptions": {
      "bypass_keyword": "@synapse-bypass",
      "allowed_cross_layer_paths": [
        { "from": "service", "to": "frontend", "type": "event_bus" }
      ]
    }
  }
}
```

### 2. 규격의 핵심 포인트 (Architecture Insight)
- **The Absolute Zero (`index: 0`)**: 중력의 특이점으로 0번 레이어로 들어오고 나가는 모든 엣지는 검역을 통과합니다.
- **The Gatekeeper (`enforce_bridge: true`)**: 타 클러스터 진입 시 반드시 `Bridge` 노드를 거쳐야 합니다. 직접 구현체 침투 시 ⚠️ Warning 스탬프를 찍습니다.
- **The Wormhole (`allowed_cross_layer_paths`)**: 옵저버 패턴 등 물리적 역방향 흐름이 필연적인 경우 명시적으로 뚫어주는 웜홀입니다. 미등록 역행은 💀 Violation 처리됩니다.

## 🏗️ LogicAnalyzer.ts - Edge Validation Engine Design
관심사 분리(SoC) 원칙에 따라, 뷰 로직과 분리되어 `rules.json`을 단일 진실 공급원으로 삼아 작동하는 실시간 검증 엔진입니다.

### 1. 데이터 로드 및 인덱싱 (Initialization)
- **Config Loader**: `rules.json`을 로드하여 레이어 맵(`Map<LayerID, Index>`)과 예외 웜홀 맵을 생성합니다.
- **Node Indexing**: 캔버스의 모든 노드를 스캔해 레이어 인덱스를 O(1) 조회용으로 캐싱합니다.

### 2. 검증 프로세스 (The Validation Loop)
`checkViolation(edge)` 가동 시 통과하는 4단계 검문소:
1. **Shared Pass (Layer 0)**: `source`나 `target`이 0번 레이어면 즉시 **VALID**.
2. **Gravity Check (The Core)**: `target.layerIndex < source.layerIndex`일 때 웜홀 검사. 미등록 시 **CRITICAL (💀)**.
3. **Boundary Check**: 타 클러스터 횡단 시 `Bridge` 노드가 아니면 **WARNING (⚠️)**.
4. **Same Layer Policy**: 정책상 막힌 동일 계층 내 호출에 대해 **WARNING (⚠️)**.

### 3. 데이터 흐름의 시각화 (Gruvbox Mapping)
엔진의 산출값은 즉각 엣지 렌더링 스타일(SVG)로 주입됩니다.
- **Normal (✅)**: `stroke: #b8bb26` (Gruvbox Green), `dasharray: 0`
- **Warning (⚠️)**: `stroke: #fabd2f` (Gruvbox Yellow), `dasharray: 5, 5`
- **Critical (💀)**: `stroke: #fb4934` (Gruvbox Red), `strokeWidth: 3`, `marker-end: url(#skull-icon)`

### 4. 하이브리드 증폭 검증 전략 (Hybrid Verification Strategy)
실시간성을 빙자한 '우주 쓰레기' 스캔 과부하를 막기 위한 다중 방어 메커니즘입니다.
- **Local Visual-Only (UX 우선)**: 캔버스 드래그 등 `onConnect` 시점엔 메모리에 캐싱된 두 노드의 `layerIndex`만 즉시 대조 ($O(1)$).
- **Debounced AST (정확도 우선)**: 코드 타이핑 시엔 침묵하다가 파일 저장 시 델타 스캔(`Delta Scan`)만 작동.
- **Semantic Aggregation (과부하 방어)**: 줌 아웃(Zoom-out) 시 클러스터 내부 노드를 숨기고, 경계 외부로 흐르는 대표 엣지 하나로 렌더링. 내부 위반이 1개라도 있으면 대표 선박이 💀로 붉게 변함 (LOD 기법).

| 트리거 지점 | 대상/범위 | 시각적 피드백 효과 |
| :--- | :--- | :--- |
| **Edge Connect** | UI/UX (1:1 관계) | 캔버스 엣지 색상 즉각 변경 |
| **File Save** | Code (Surgical Delta) | VS Code Problems 탭 에러 등록 |
| **Milestone Promotion** | Master Hub (Full Scan) | **승격(Merge) 거부 및 위반 리포트 생성** |

### 5. 예외 상황 밀봉 (Edge Cases)
- **Layer Index 누락**: 클러스터 미할당 노드는 가장 위험한 Default Layer(1 혹은 Undefined)로 강등하여 보수적(💀)으로 취급.
- **Circular Dependency 차단**: A ➔ B (L2 ➔ L3) 정상 처리 후 B ➔ A 발생 시 중력 법칙 역행으로 즉각 💀 처리, 구조적으로 DAG(유향 비순환 그래프)가 입증됨.
