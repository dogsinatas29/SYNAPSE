## 🧠 상세 설계 및 로직

### 1. 계층형 메뉴 구조 개편 (Hierarchical Menu Architecture)
상단 툴바의 복잡도를 줄이기 위해 클릭 시 하위 메뉴가 전개되는 계층 구조를 도입합니다.
- **Snap Shot (시스템 형상 관리)**:
  - **정체성**: 온전한 아키텍처 뼈대가 있던 시기를 영구히 기억하고, 대규모 노드/엣지 삭제 등 '형상적 결단' 시점에서의 심리적 부담감을 감소시키기 위한 목적입니다.
  - **경계**: 스냅샷은 위 목적만을 위해 존재하며, 파일 단위의 미세 백업이나 단순 코드 타이핑 트래킹 기능은 **절대 제공하지 않음**을 엄격히 명시합니다.
  - **구현**: `Save` (현재 상태 즉시 저장) / `History` (스크롤바가 지원되는 외부 창 격리 관리).
- **Context Vault (Intelligent Context 관리)**:
  - 기존 캔버스 내부에 있던 비대한 Context Vault를 외부 패널로 완전히 격리합니다.
  - **History 체제**: 스냅샷 히스토리와 완전히 동일한 타임라인 로직으로 외부 창에 격리 관리하며, 캔버스 동작 속도를 완벽히 보장합니다.
  - 캔버스에는 `Rec(녹화)` 표출과 간결한 **방패/링크 버튼**만 남겨 아키텍처 본연의 형상에 집중할 수 있는 쾌적한 뷰를 확보합니다.

### 2. 캔버스 가시성 고도화 (Spatial Isolation & UX)
- **세련된 디자인(Premium Look)**: 버튼 높이와 섀도우, 테두리, 그라디언트 디테일을 세팅하여 견고한 톤앤매너를 구축합니다.
- **클릭 시 크기 고정(Visual Anchor)**: 특정 메뉴 호출 시 툴바 레이아웃이 흔들리던 현상을 안정화합니다.
- **스마트 자동 배치**: 복잡한 의존성의 노드 표출 시 겹침을 방지하는 알고리즘을 도입합니다.
- **수동 위치 영구 기억**: 한 번 사용자가 드래그하여 배치한 노드의 `x, y` 좌표는 `project_state.json`에 영구 기록되어 형상(Shape)이 철저히 부활합니다.

### 3. 고스트(Ghost) & 예약(Reserved) 노드 전이 모델
v0.2.18 좀비 차단 로직에 튕겨나가지 않도록 **'상태 기반 필터링(Status-based Filtering)'**을 도입합니다.
- **Ghost Node (사유의 파편)**: LLM이 제안한 잠재 가설. 백엔드에 기록되나 실제 물리 파일은 건드리지 않고 '반투명' 상태로 캔버스에 투영됩니다.
- **Materialize (실체화)**: 관리자의 클릭 승인 즉시 Ghost에서 Active로 상태가 전환되며, 비로소 물리적 파일이 생성됩니다.
- **Reserved Node (지연된 집행)**: 위험 조치 대기열. 최종 Confirm 전까지는 `EdgeCodeRefactorer`의 가동을 강제로 유예시킵니다.

## 🛠️ 기술적 변경 사항
- **Node Data Schema:**
  - `data_scheme.md` 내 `status` 필드 공식 편입: `[ghost | materialized | reserved | active]`.
  - Node Type 확장 명세화: `[source | cluster | documentation | test | config | history | external | event]`.
- **Edge Logic Engine:**
  - **Virtual Edge 구현**: Reserved 혹은 Ghost 노드 간의 엣지는 시각적으로만 렌더링하고, 코드상의 실질적인 import 주입 시도는 철저히 무시/스킵합니다.
  - **Bridge Interface 준비**: Python ➔ TS 등 이종 언어 간 연결 시도 에러 방지를 위해 'Bridge Pending' 알림 상태를 지원합니다.
- **Core Files:**
  - `architecture.md`를 4개 모듈 시스템으로 분할.
  - `CanvasPanel.ts`: `handleSaveState` 호출 시 `status: ghost` 혹은 `reserved` 인 노드가 좀비 청소기에 의해 증발하지 않도록 예외(Whitelist) 체계를 등록.

## ⚠️ 예외 처리 및 주의 사항
- **논리적 좀비 vs 설계된 고스트**: `status` 필드가 아예 없는 무명 노드는 기존 v0.2.18 원칙에 따라 자비 없이 즉각 사살합니다.
- **Z-Index 동적 조절 (클릭 간섭)**: 밀집된 클러스터 구역 내 Ghost 노드 클릭이 방해받지 않도록, 노드 상태값에 기반한 동적인 레이어 최상단 우선순위(Z-Index) 산출 로직을 강제합니다.
