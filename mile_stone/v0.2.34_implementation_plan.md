# Implementation Plan - v0.2.34 (Dialogue Integrity Fix)

## 🎯 Goal
바이너리 Protobuf 데이터 직접 읽기 기반의 불안정한 텍스트 추출을 폐기하고, UI 렌더링 기반의 클립보드 스크레이퍼를 사용하여 무결성 높은 대화 기록 모델을 구축한다. 화자 식별(Attribution)은 기계적인 순서가 아닌 텍스트 내의 라벨(Label) 파싱에 의존한다.

## 🛠️ 작업 목록 (TODO List)

### 1. PbSessionWatcher.ts: 로직 미니멀리즘
- [ ] `extractReadableStrings()` 함수 및 호출부 삭제.
- [ ] `modCount % 2` 기반의 역할 추측 로직 제거.
- [ ] 단순 "세션 파일 변경" 트리거만 발생시키도록 간소화.

### 2. ClipboardScraperAdapter.ts: 지능형 스크레이핑
- [ ] `parseConversation(rawContent: string)` 로직 전면 재구축.
- [ ] "User:", "Assistant:", "Antigravity:", "Gemini:", "Secretary:" 등의 화자 라벨을 인식하는 고품질 정규식 적용.
- [ ] 메시지 중복 기록 방지를 위한 해시(Hash) 기반 델타 기록 메커니즘 구현.
- [ ] 클립보드 복사(command `workbench.action.chat.copyAll`) 지연 및 포커스 유무에 대응하는 재시도 로직 도입.

### 3. extension.ts: 통합 트리거
- [ ] `Watcher.on('change', ...)` 이벤트 발생 시 즉시 `Scraper.scrape()`를 수행하도록 연결.
- [ ] 수집된 데이터를 통합 세션 로그에 덮어쓰거나 델타를 업데이트하는 로직 정비.

### 4. 검증 (Validation)
- [ ] `.synapse_contexts/` 폴더 내의 로그 파일이 깨끗한 텍스트로 저장되는지 확인.
- [ ] 다중 질문이나 시스템 메시지가 발생해도 화자 구분이 꼬이지 않는지 확인.

## 📅 타임라인
1. 분석 및 설계: 현재
2. 구현 시작: `PbSessionWatcher.ts` -> `ClipboardScraperAdapter.ts` -> `extension.ts` 순서로 진행.
3. 통합 테스트: 완료 후 즉시.

## ⚠️ 위험 요소 (Risks)
- **Clipboard Conflict:** 백그라운드 스크레이핑 시 사용자의 클립보드와 충돌 가능성 (이미 백업/복원 로직이 존재하므로 안정성 체크).
- **UI Parsing:** VS Code UI 테마나 언어 설정에 따라 "User:" 라벨 등이 다르게 보일 가능성 고려.
