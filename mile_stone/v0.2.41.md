## 📅 작업 정보 - **상태:** ✅ Completed
- **관련 마일스톤:** v0.2.40
- **목표:** Webview 격리와 포커스 탈취 불가(Hooking)로 인한 UI 스크래핑 한계를 극복하고, 로컬 디스크의 바이너리 파일(.pb 및 .vscdb-wal)을 직접 파싱하여 대화 이력을 100% 무결성으로 추출.

## 🧠 상세 설계 및 로직
- **[핵심 설계 내용 1] The PB Miner 활성화 (DirectPbExtractor)**: 더 이상 실패가 예견된 UI 렌더링/Clipboard 클론 방식에 매달리지 않습니다. 안티그래비티 확장이 실시간으로 내려받는 `.pb` 파일(Protobuf)을 감지하는 즉시 해당 파일의 버퍼를 읽고, 명시적으로 바이너리 데이터를 UTF-8 포맷 스트링으로 컨버전(`buffer.toString('utf-8')`)하여 순수 텍스트(User와 Assistant)만 수집합니다.
- **[핵심 설계 내용 2] WAL Scanner 스니핑 (VscdbAdapter)**: Copilot이나 IDE 로컬 Storage의 갱신 지연(`wal_checkpoint`)으로 인해 `.vscdb` 메인 파일에 데이터가 병합되지 않는 문제를 해결하기 위해, 임시 디렉토리에 복사된 `.vscdb-wal` 파일을 직접 바이너리 모드로 읽어 휴리스틱 추출기를 통해 대화 조각을 살려냅니다.

## 🛠️ 기술적 변경 사항
- **Node Update:** `DirectPbExtractor` 신규 생성. `fs.readFileSync`로 PB 파일을 버퍼 타입으로 읽고 `toString('utf-8')`을 통해 텍스트로 전환 후 화자(Role)를 분리하는 로직 완비.
- **Edge Update:** `VscdbAdapter` 수정. `.vscdb-wal` 바이너리 단독 파싱 및 파일 복사를 통한 락 회피 스니핑 적용.
- **File Changes:** UI 복사를 시도하던 기존 `DirectChatScraper` 호출을 폐기하고 `DirectPbExtractor`로 완전 컴포넌트 교체 (`src/extension.ts` 등).

## ⚠️ 예외 처리 및 주의 사항
- PB 파일이나 WAL 파일은 순수 텍스트가 아닌 바이너리 청크가 섞여 있으므로, 정규식 기반 Miner의 정확도를 유지하고 노이즈 필터를 보수적으로 운용해야 함.
- 버퍼 데이터 변환 시 항상 `buffer.toString('utf-8')`을 통해 명시적으로 인코딩이 깨지지 않게 보장.
- WAL 파일 강제 병합 지연이나 DB Lock이 발생하면 즉각 바이너리 스니핑 우회(Fallback)로 전환해야 데이터 손실(유실)이 발생하지 않음.
