# Implementation Plan - v0.2.47 "The Ghost in the Shell"

## 🎯 Goal
Implement a robust DOM-level interception mechanism ("Ghost Spy") that captures text directly from the Webview's rendered output. This is a "Nuclear Option" to bypass communication-level isolation (Service Workers, Custom RPCs, etc.) by observing the final state visible to the user.

## 🛠 Proposed Changes

### 1. `src/core/WebviewInterceptor.ts`
- **Refine HTML Interception**:
    - Instead of instance-level `Object.defineProperty`, hook the prototype or intercept the setter properly.
    - Ensure `originalSetter` is called with the modified HTML.
- **Script Injection Improvements**:
    - Inject the spy script at the top of the `<body>` to ensure it runs before the main application script.
    - Implement a `VSCode API Bridge`: Handle the case where `acquireVsCodeApi()` has already been called.
    - Add **Shadow DOM support**: Observe `shadowRoot` recursive changes and hook `attachShadow`.
    - **CSP Modification**: Dynamically relax Content Security Policy if it blocks our injected script.

### 2. `src/core/PromptLogger.ts` (or relevant logging service)
- Ensure it can handle the `[GHOST]` prefix correctly to differentiate from communication-level hits.

### 3. Build & Package
- Update `package.json` to `0.2.47`.
- Create `synapse-visual-architecture-0.2.47.vsix`.

## 📂 Implementation Details: The Ghost Spy Script
The injected script will:
1.  Attempt to `acquireVsCodeApi()`. If it fails, it will attempt to find the existing `vscode` object.
2.  Start a `MutationObserver` on `document.body`.
3.  Recursively find and observe all `shadowRoot`s.
4.  Intercept `Element.prototype.attachShadow` to automatically observe new shadow-based components.
5.  Filter for Korean text (`/[가-힣]/`) and send hits via `synapse-spy-hit`.
