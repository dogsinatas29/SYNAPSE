## 🧠 상세 설계 및 로직

### 🛡️ Architecture Guardrail: The Iron Guard Protocol
**개요 (Concept)**
SYNAPSE는 단순한 코드 시각화 도구를 넘어, 시각적 규칙(Graph Topology)으로 실제 소스 코드를 통제하는 **'아키텍처 관제탑'**으로 진화한다. 이는 AI가 대량의 코드를 생산하는 '바이브 코딩' 시대에 아키텍처의 무결성을 지키는 최종 방어선이다.

#### 1. 지능형 제약 조건 (Contextual Constraints)
이미 존재하는 `Rules.md`와 `architecture.md`를 정적 문서가 아닌, 실시간 검증 엔진의 입력값으로 활용한다.
- **예시 제약 (Architecture Constraints)**:
    - `ui/` 컴포넌트는 오직 `service/` 계층만 호출 가능.
    - `ui/`에서 `repository/`로의 직접 연결(Edge)은 **CRITICAL VIOLATION**.
    - 모든 `Event` 노드는 반드시 `Logic` 노드를 거쳐야 함.

#### 1-5. 클러스터 간 시맨틱 연결 (Cluster-to-Cluster Semantic Connections)
클러스터는 단순한 시각적 그룹핑을 넘어, 시스템 간의 통신 규약과 의존성 제약을 선언하는 강력한 아키텍처 단위로 승격됩니다.
- **상향적 응집 (Bottom-up Aggregation - Semantic Zooming)**: 캔버스를 축소(Zoom-out)하여 클러스터가 접힐 때, 내부 노드들이 외부와 맺고 있던 수십 개의 복잡한 선들이 계산되어 **'단 하나의 굵고 진한 방향성 엣지(대표 선)'**로 자동 병합표시됩니다.
- **하향적 설계 (Top-down Architecture Definition - Constraint Edges)**: 초기 설계 단계에서 빈 클러스터 박스 사이에 직접 **제약선(Constraint Edge)**을 긋습니다. 이 선은 해당 클러스터 내의 모든 하위 노드들이 따라야 할 '방향성 룰(Rule)'로 영구히 작동하며, 이를 어기는 코드가 작성되면 즉각 빨간 선(Violation)으로 시각화됩니다.
- **인터페이스 강제 (Facade Contract - 안티 메인터넌스 헬)**: 
  - 외부 클러스터의 내부 구현(Impl) 노드를 직접 호출하는 선(Edge)은 설계의 결합도를 폭발시키는 주범이므로 **CRITICAL VIOLATION** 처리됩니다.
  - A 클러스터에서 B 클러스터로 향하는 모든 통신은 오직 B 클러스터 내에 명시적으로 선언된 **[Interface / Facade] 속성의 단일 브릿지 노드**만을 거쳐야 합니다. 이를 통해 SYNAPSE(관제탑)는 메서드 단위의 디테일(API 명세 등) 제어에 따른 아키텍처 유지 보수 지옥을 피하고, 숲(의존성의 흐름)을 통제하는 본래의 역할에만 완벽히 집중할 수 있습니다.

#### 2. 실시간 감시자 (Real-time Linter)
`LogicAnalyzer.ts`와 `FileScanner.ts`를 확장하여, 코드 저장 즉시 엣지를 추출하고 아키텍처 규칙 위배 여부를 스캔한다.
- **엣지 추출 (Extraction)**: 소스 코드 내의 `import`, `include`, `use` 구문을 분석하여 실시간 그래프 생성.
- **규칙 검증 (Validation)**: 생성된 엣지가 `Rules.md`에 정의된 계층 구조나 호출 규약을 어겼는지 판별.
- **시각적 제재 (Violation Display)**: 위배된 엣지는 캔버스 상에서 새빨간 점선과 💀 아이콘으로 렌더링되며, VS Code의 `Problems` 탭에 Linter Error로 즉시 등록됨.

#### 3. LLM 시대의 '강력한 목줄' (The Iron Guard)
AI 어시스턴트(Gemini, Copilot 등)가 코드를 생성할 때, 발생할 수 있는 '아키텍처 오염'을 원천 봉쇄한다.
- **통제 원칙**: "기능 구현은 AI의 몫이나, 시스템의 형상(Graph Shape)은 설계자의 캔버스를 절대 벗어날 수 없다."
- **효율적 리뷰**: 수만 줄의 코드를 읽는 대신, 캔버스에 **빨간 선(Violation Edge)**이 발생했는지만 확인하여 아키텍처 무결성 증명.

## 🛠️ 기술적 변경 사항
- **Node Update:** Validation 표시기 추가
- **Edge Update:** 💀 VIOLATION 타입 및 스타일 추가 (새빨간 점선 등)
- **File Changes:** `LogicAnalyzer.ts` 제약 조건 검증 로직 확장, Linter Error 연동 로직 추가

## ⚠️ 예외 처리 및 주의 사항
- 실시간 린팅에 의한 성능 병목 예방 (Debounce 처리 등)
- 잘못 작성된 `Rules.md`에 의한 무한 재검증루프 방지
