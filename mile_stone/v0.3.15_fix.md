🚀 Milestone v0.3.15_fix - Documentation Node Recognition Fix

## 📅 작업 정보
- **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.15
- **목표:** `synapse-visual-architecture`와 같은 문서 관련 노드들이 Documentation Shelf가 아닌 External Ghosts로 잘못 분류되는 버그 수정

## 🧠 상세 설계 및 로직
- **문제 원인 파악:** 
  - `README.md`나 릴리즈 노트 등에서 파싱된 참조 링크 이름(`synapse-visual-architecture-v0.2.20` 등)에 `.md` 같은 명시적인 확장자가 없어서 `DataPipeline`이 일반 노드(Symbol)로 처리함.
  - 마크다운 문서 파생 노드(`NodeType.DOCUMENTATION`)인지 검증하는 로직이 `targetNodeId.toLowerCase().startsWith('v0.')`로 되어 있어, 버전명이 중간에 위치한 참조명들은 해당 관문을 통과하지 못함.
  - 그 결과, 파일 시스템에 존재하지 않는 일반 노드로 잘못 분류되어 최종적으로 `StateManager.ts`에서 유령(Ghost) 판정을 받고 `cluster_ghosts` (External Ghosts)로 강제 락인됨.
- **해결 방안:**
  - `DataPipeline.ts` 및 `StateManager.ts`의 문서 분류(Semantic Routing) 로직에서 버전명을 검사하는 부분을 `startsWith('v0.')`에서 `includes('v0.')`로 변경.
  - 이를 통해 파일명이나 참조명 중간에 버전 정보(`v0.`)가 포함된 마일스톤/릴리즈 관련 아티팩트(예: vsix 파일 패키지명, 버전 트리 이미지 참조 등)가 모두 정확하게 문서 쉘프 도메인으로 판정받게 함.

## 🛠️ 기술적 변경 사항
- **File Changes:** 
  - `src/core/DataPipeline.ts` 수정: `isDocRef` 검증 로직 중 `startsWith('v0.')` -> `includes('v0.')` 로 교체 완료.
  - `src/core/canvas-engine/StateManager.ts` 수정: `isDoc` 검증 조건에 `.includes('v0.')` 케이스를 추가하여 파이프라인의 분류 체계와 통일성 확보.

## ⚠️ 예외 처리 및 주의 사항
- 캔버스 상태(JSON) 상에서 한 번 다른 클러스터나 유저 권한(Sovereignty)을 획득했던 노드들은 StateManager의 강력한 보호 정책(기득권 락인)에 의해 즉각적인 동기화가 차단될 수 있으므로, 해당 버그 패치 후 캔버스 리로드/데이터 클리어를 진행해야 최신화된 파이프라인 정렬이 적용됨.
