# 🛠️ Implementation Plan: v0.3.20 Semantic Hotspot Mapping

## 🎯 Goal
Top-N 핵심 노드를 중심으로 유의미한 기능적 덩어리를 시각화하여, 노드 간의 관계를 '영역(Area)' 단위로 해석할 수 있게 함.

---

## 📅 Step-by-Step Plan

### Step 1: Data Model & Field Setup
- `CanvasEngine` 생성자에 `this.hotspots = []` 초기화.
- `Hotspot` 객체 구조 정의: `{ id, label, x, y, width, height, color, priority }`.

### Step 2: Cluster Extraction Logic (`updateHotspots`)
- `updateNodeStats`가 완료된 시점에 호출.
- `this.focusCoreSet`을 순회하며 각 Anchor에 대한 인접 노드 리스트 구축.
- `Leaf node`는 클러스터 멤버에서 제외 (노이즈 방지).

### Step 3: Bounding Box Calculation
- 추출된 노드 그룹의 `minX, maxX, minY, maxY` 계산.
- `PADDING = 40` 적용하여 영역 확장.

### Step 4: Overlap Merge Algorithm
- 독립된 두 핫스팟 영역이 60% 이상 겹치면 병합하거나 더 큰 박스가 작은 박스를 흡수.
- 박스가 너무 많아지는 것을 방지하기 위해 최대 핫스팟 개수 제한 (예: 5~7개).

### Step 5: Background Rendering Pipeline
- `render` 루프의 가장 이른 시점(배경 그리드 다음)에 `renderHotspots()` 호출.
- `ctx.setLineDash([10, 5])`를 사용하여 점선 테두리 구현.
- `hsla`를 활용해 아주 연한 배경색(`alpha: 0.05`) 적용.

---

## ⚠️ Risks & Constraints
- **Performance**: 매 프레임 박스 좌표를 재계산하면 성능 하락 위험. 반드시 노드 위치가 확정되는 시점(`onUpdate` 등)에만 캐시 갱신.
- **Visual Clarity**: 박스가 서로 뒤엉키면 오히려 더 복잡해 보임. `isTopEdge`처럼 '의미 있는 핫스팟'만 남기는 필터링 필수.
