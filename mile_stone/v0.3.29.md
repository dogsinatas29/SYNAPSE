## 🧠 상세 설계 및 로직

### Core Problem
- `DataPipeline.ts`에서 모든 신규 노드의 기본 위치가 `{x:0, y:0}`, 모든 폴더 클러스터 위치가 `{x:0, y:0}`
- `resolveOverlaps()`는 노드 단위 겹침만 해소하며 **클러스터 바운딩 박스 간 충돌을 전혀 감지하지 않음**
- `applyRoleAlignment()`가 모든 클러스터의 center를 동일한 (0,0)으로 계산 → role 기반 정렬이 모두 같은 지점으로 수렴
- 재스캔 시 `loadProjectState(preserveView=false)` → node-level overlap 해소만 수행 → cluster는 겹친 채로 렌더링

### Solution: Initial Spread + Cluster Push-Apart (3.C)

#### Phase 1 — Initial Spread (DataPipeline.ts)
- 클러스터별 FNV-1a 결정적 해시로 시작 각도 산출 → 동일 cluster_id는 항상 같은 각도
- 모든 클러스터를 원형(circular)으로 배치: `반경 = Math.max(800, clusterCount * 150)`
- 각 클러스터 내 노드들은 cluster 중심 기준 grid offset (col/row)으로 배치
- 재스캔 시에도 동일한 cluster_id → 동일한 위치 배치 (위치 안정성 보장)

#### Phase 2 — Cluster Push-Apart (canvas-engine.js 신규 메서드)
- `loadProjectState()` 내 `resolveOverlaps()` 호출 직후 실행
- 모든 클러스터의 AABB bounds 계산 (node position 기반 + Virtual Padding 40px)
- 겹치는 클러스터 쌍을 Mass(노드 개수) 기반 비율로 push-apart
- 무거운 클러스터(노드多)는 제자리에 가깝게, 가벼운 클러스터(노드少)는 더 멀리 밀려남
- ITERATIONS = 3, 연쇄 충돌 해소

## ⚠️ 예외 처리 및 주의 사항

### 1. Overlap 방향 부호 판정 (Sign Guard)
- overlapX/Y는 항상 양수(크기)로 계산됨 → 두 클러스터 중심점 차이(`centerB - centerA`)의 부호로 push 방향 결정
- A가 B보다 왼쪽에 있으면 A는 -x, B는 +x 방향으로 밀어냄

### 2. 중심점 일치 시 제로 디바이드 방지 (Zero-Divide Guard)
- 두 클러스터 중심점 거리 < 0.001이면 `overlapX = 1` 고정 후 X축 방향으로만 밀어내도록 fallback
- NaN 발생 시 노드 증발(화면 이탈)을 방지하는 안전장치

### 3. Iteration 내 Bounds 동적 업데이트 (Shift Guard)
- 1회차 push 후 push delta만큼 해당 cluster의 min/max bounds를 즉시 shift
- 2회차부터 변경된 bounds 기준으로 다른 클러스터와의 충돌을 정확히 재검사
- bounds를 업데이트하지 않으면 연쇄 충돌이 누락되는 버그 방지

### 성능 병목 예상 지점
- `resolveClusterOverlaps()`는 `loadProjectState()` 내 1회 실행 (프레임 루프 영향 없음)
- Cluster 쌍 검사 O(n²)이지만 cluster 수는 일반적으로 수십 개 이하 → 무시 가능
- WebGL 렌더러는 공유 `this.nodes[*].position`만 읽으므로 수정 불필요

## 📋 Release Notes (v0.3.29)

### 📝 Summary / 요약

This release resolves three interrelated visualization issues: (1) cluster/node overlapping after project re-scan caused by all nodes defaulting to `{x:0, y:0}`, (2) the External Ghosts cluster box disappearing when only the External layer is visible, and (3) excessive cluster expansion after "Align Architecture" that caused clusters to overlap. Fixes span the DataPipeline (initial circular spread), the shared cluster overlap resolution engine, and layer visibility filtering.

이번 릴리즈는 3가지 시각화 문제를 해결합니다: (1) 모든 노드가 `{x:0, y:0}`으로 초기화되어 발생하는 재스캔 후 클러스터/노드 겹침, (2) External 레이어만 켰을 때 External Ghosts 클러스터 박스가 사라지는 문제, (3) "Align Architecture" 후 클러스터가 과도하게 팽창하여 겹치는 문제. DataPipeline(초기 원형 분산), 공유 클러스터 중첩 해소 엔진, 레이어 가시성 필터 전반에 걸쳐 수정이 이루어졌습니다.

### 🚀 Changes / 상세 수정 내역

**1. Initial Spread — Circular Layout in DataPipeline**
- Folder clusters placed in deterministic circular layout (FNV-1a hash)
- Nodes arranged in compact 3-column grid (80x50px spacing)

**2. Cluster Push-Apart Engine (신규)**
- `resolveClusterOverlaps()` — AABB overlap + Mass-weighted push-apart
- Virtual Padding 40px + 3 Iterations + 3 exception guards

**3. External Ghosts Cluster Layer Visibility**
- `getClusterBounds()`에 `isExternalNode` 체크 추가
- 3개 지점 layer fallback에 `cluster_ghosts → external` 강화

**4. Align Architecture — Cluster Expansion Reduction**
- roleOffsets 절반 축소 (Leaf:-300, Hub:-100, Orch:100, Ctrl:300)
- 정렬 완료 시 `resolveClusterOverlaps()` 자동 실행

**5. DataPipeline Spacing Tuning**
- Node grid: 120×60 → 80×50px
- Circular radius: ×150 → ×200
