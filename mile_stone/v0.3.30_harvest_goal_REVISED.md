# SYNAPSE v0.3.30 Harvest Goal

# Purpose

Harvest는 Copy Operation Only 이다.

---

# Core Philosophy (Harvest ≠ Sync)

**Harvest = 데이터 수집 (Data Collection)**
- Client → Snapshot → Server → Archive 단방향 파이프라인.
- 수확물은 병합(Merge)되지 않고 `.synapse/clients/{user}/harvest` 위치에 클라이언트별로 **완전 격리 보관**된다.

**Sync = 데이터 통합 (Data Integration)**
- Client ↔ Server ↔ Client 양방향 파이프라인.
- 덮어쓰기, 충돌 해결, 롤백, Lock 정책 등 복잡성을 동반하므로 **v0.3.30 범위 밖의(v0.4+) 백로그 과제**로 분리한다.

---

# Core Principle

Architect(Server)는 유일한 Source Of Truth이다.
Client는 Source Of Truth가 아니다.
Ownership(소유권)은 **Client 기준**으로 관리된다.

# Harvest Session Model

## Definition

Submission 모델을 사용하지 않는다.

Harvest는 Client Workspace를 직접 검토하여 수행한다.

## Harvest Session

Workflow:

Client Connected
↓
Harvest Session Start
↓
Workspace Lock
↓
Compare
↓
Approval
↓
Harvest
↓
Workspace Refresh
↓
Unlock

## Workspace Lock

Harvest Session 동안 Client Workspace는 Frozen 상태이다.

허용:

- Read
- Compare

금지:

- Edit
- Synapse 작업
- 상태 변경

## Session Consistency

Compare 시점 상태와 Harvest 시점 상태는 동일해야 한다.

Harvest 중 Client 변경은 허용하지 않는다.

필터 조건 (Visibility Filter):

- 가시성이 OFF 상태인 계정은 접속 중이더라도 추수 대상에서 완전 제외

허용 상태:

- UNCHANGED
- MODIFIED
- ADDED

# Final Definition

Architect(Server)는 유일한 Source Of Truth이다.

Harvest는 Submission 기반 시스템이 아니다.

Harvest는 Session 기반 시스템이다.

Client Workspace는 Harvest Session 동안 Lock 된다.

Compare는 Master Layer와 Locked Client Layer를 비교한다. (단, 가시성이 ON인 계정만 대상)

Harvest는 승인된 파일만 복사한다.

Harvest는 Copy Operation Only 이다.
