# v0.3.30 Phase4 — Remote Layer

## Purpose

Phase4 transforms a submitted artifact into a remote visibility model.

```text
Submission Snapshot
        ↓
Import
        ↓
Runtime Projection
        ↓
Layer Classification
        ↓
Visibility Model
```

Phase4 is responsible for visual projection.

Phase4 is not responsible for architecture analysis.

---

## Phase4 Input

Phase4 receives:

```text
Submission Snapshot
```

Phase4 converts the submitted artifact into internal runtime structures.

Internal Runtime Structures:

```text
GraphSnapshot

ViewSnapshot

CanvasState

ProjectState
```

---

## Runtime Snapshot Separation

```text
Submission Snapshot
≠ GraphSnapshot
≠ ViewSnapshot
≠ CanvasState
≠ ProjectState
```

Submission Snapshot is a collaboration artifact.

The remaining snapshots are internal runtime structures.

---

## Stateless Runtime Principle

Phase4 is stateless.

Phase4 does not maintain a persistent runtime store.

All runtime structures may be regenerated from the Submission Snapshot.

---

## No Database

Phase4 does not use a database.

No layer database exists.

No visibility database exists.

No projection database exists.

Reasons:

* Submission Snapshot is authoritative
* Layer information is fully rebuildable
* Layer classification is recomputed every load
* Database synchronization introduces unnecessary complexity
* Runtime projection must remain lightweight

Database persistence is prohibited.

---

## Submission Snapshot Ownership

Submission Snapshot is owned by the server.

Client no longer modifies the submitted artifact.

Server may review, annotate, and prepare modification proposals.

Server never directly modifies the client workspace.

---

## Layer Philosophy

Layer is a visibility classification group.

Layer is NOT:

* Canvas
* Composition Stack
* Independent Render Surface

Layer contains:

```text
Nodes

Clusters
```

Edges do not belong to layers.

---

## Layer Persistence

Layer values may be stored inside runtime snapshots.

Stored layer values are not authoritative.

Layer assignment is always recomputed by:

```text
StateManager.generateMergedState()
```

Stored layer metadata is cache only.

Layer is a derived runtime classification.

Layer is never treated as authoritative project data.

---

## Layer Assignment Authority

Only:

```text
StateManager.generateMergedState()
```

may assign node layers.

DataPipeline is layer-agnostic.

canvas-engine consumes layer information and never reassigns it.

---

## Node Classification Rules

Priority:

```text
hasAtomicSignature  → user

node_manual_*       → user

documentation       → user

user cluster member → user

external://         → external

ghost://            → external

otherwise           → ai
```

---

## Cluster Classification Rules

Cluster classification is ID-driven.

```text
cluster_ghosts → external

folder_*       → ai

sys_*          → ai

other          → user
```

---

## Edge Rules

Edges have no layer.

Visibility:

```text
Visible Edge
=
Visible(From Node)
AND
Visible(To Node)
```

If either endpoint is hidden, the edge disappears.

---

## Visibility Controls

```text
showBaseLayer

showUserLayer

showExternalLayer
```

No layer Z-order exists.

All layers operate on the same graph plane.

---

## Explicitly Excluded

* Layer Database
* Visibility Database
* Projection Database
* Architecture Index Generation
* Function Catalog Generation
* Symbol Registry Generation
* Dependency Registry Generation
* Verify Engine
* Harvest Engine
* Architectural Interpretation
* Client Workspace Modification

---

## Exit Criteria

```text
Submission Snapshot Imported

Runtime Projection Complete

Nodes Classified

Clusters Classified

Visibility Operational

Remote Layer Visible
```
