# v0.3.30 Phase5 — Verify Integration Layer

## Purpose

Phase5 transforms a Submission Snapshot into a verification-ready structural model.

```text
Submission Snapshot
        ↓
Architecture Projection
        ↓
Architecture Index
```

Phase5 does not perform verification.

Phase5 prepares the structural model required by Phase6.

---

## Core Principle

Submission Snapshot is the only authoritative source.

All Phase5 outputs are derived artifacts.

```text
Submission Snapshot
        ↓
Architecture Index
```

Architecture Index may be regenerated at any time.

If inconsistency occurs:

```text
Submission Snapshot wins
```

---

## No Database Principle

Phase5 does not use a database.

Architecture Index is a transient derived structure.

```text
Load Snapshot
        ↓
Generate Architecture Index
        ↓
Use
        ↓
Discard
```

Persistent storage is unnecessary because:

* Submission Snapshot is authoritative
* Architecture Index is rebuildable
* No synchronization is required
* No schema migration is required
* Startup overhead remains minimal

Phase5 intentionally avoids database-backed indexing.

The cost of maintaining persistent architectural state exceeds the cost of rebuilding it from the Submission Snapshot.

Reconstruction is preferred over synchronization.

Synapse is designed for lightweight collaborative architecture workflows.

It is not intended to operate as an enterprise-scale repository management platform.

---

## Input

Phase5 receives:

```text
Submission Snapshot
```

---

## Output

Phase5 produces:

```text
Architecture Index
```

Architecture Index becomes the primary input of Phase6.

---

## Architecture Projection

Phase5 extracts structural information from a Submission Snapshot.

```text
Submission Snapshot
        ↓
Project Structure
        ↓
Architecture Index
```

Phase5 is structure-oriented.

Phase5 is not visualization-oriented.

---

## Derived Artifact Principle

Architecture Index is not authoritative.

Architecture Index may be regenerated at any time from the Submission Snapshot.

If any inconsistency occurs:

```text
Submission Snapshot wins
```

---

# Architecture Index

Architecture Index contains only structures that can be reconstructed directly from the submitted project.

---

## Architecture Scope

Phase5 models only reconstructable source-code structure.

### Included

```text
Project Tree

Folder Tree

Source File Registry

Function Catalog
```

### Excluded

```text
Documentation

Reports

Logs

Context Archives

Review Artifacts

Generated Synapse Documents

User Clusters

Layer Information

External Ghosts

Visualization Metadata

Runtime Snapshots
```

Anything that cannot be reconstructed directly from the submitted source structure is outside the scope of Phase5.

---

## Project Tree

Purpose:

Represent project-level structure.

```text
Project
```

---

## Folder Tree

Purpose:

Represent physical directory hierarchy.

```text
Project
 ├─ src
 ├─ docs
 └─ tests
```

Folder Tree reflects the submitted filesystem structure.

---

## Source File Registry

Purpose:

Represent source files contained in the submission.

Current Synapse model:

```text
Node
=
File
```

Source File Registry therefore becomes the primary structural registry.

---

### Included

```text
.py
.rs
.ts
.js
.cpp
.c
.go
.java
```

and other source code files.

---

### Excluded

```text
.md
.txt
.log
.report
```

Generated reports.

Context archives.

Review artifacts.

Documentation artifacts.

Synapse-generated documents.

Reason:

Documentation is not part of the verification structure.

Documentation volume may grow independently from source architecture.

Verification must operate on executable project structure.

---

## Function Catalog

Purpose:

Represent executable units discovered from source files.

Function Catalog contains:

```text
Function ID

Function Name

File Path
```

No semantic interpretation is performed.

No ownership information is required.

No architectural classification is required.

---

### Included Functions

```text
Top-Level Functions

Class Methods
```

Examples:

```python
def login():
```

```python
class User:
    def save():
```

Both are included in the Function Catalog.

---

### Excluded Functions

```text
Lambda Functions

Anonymous Functions

Closures

Runtime Generated Functions
```

Reason:

Phase5 extracts stable structural elements only.

Transient runtime constructs are outside the scope of architectural verification.

---

### Function ID

Function ID must uniquely identify a function within a submission.

Exact generation rules will be defined in a later phase.

Function ID exists solely for structural tracking.

Function Name is informational only.

Function ID is authoritative.

---

## Explicitly Excluded

### Layer Information

Excluded.

Reason:

```text
Layer
=
Derived Projection
```

Layer is recalculated by runtime systems and is not authoritative.

---

### User Clusters

Excluded.

Reason:

```text
User Cluster
=
UI State
```

User clusters are not guaranteed to survive re-bootstrap operations and are not reconstructable from the Submission Snapshot.

---

### External Ghosts

Excluded.

Reason:

```text
External Ghost
=
Visualization Artifact
```

Ghost nodes represent unresolved references, external APIs, and runtime visualization constructs.

They are not part of the submitted project structure.

---

### Visualization Metadata

Excluded.

Examples:

```text
Node Positions

Canvas Layout

View State

Rendering Metadata

Visual Opacity

Visibility State
```

These belong to visualization systems and are unrelated to verification.

---

### Runtime Snapshots

Excluded.

```text
GraphSnapshot

ViewSnapshot

CanvasState

ProjectState
```

These are internal runtime structures.

They are not architectural structures.

---

## Relationship To Phase4

Phase4:

```text
Submission Snapshot
        ↓
Remote Layer Projection
        ↓
Visibility Layer
```

Phase5:

```text
Submission Snapshot
        ↓
Architecture Projection
        ↓
Architecture Index
```

Both phases operate on the same Submission Snapshot.

Phase4 produces visualization structures.

Phase5 produces verification structures.

---

## Explicitly Excluded From Phase5

Phase5 must NOT perform:

* Verification
* Pass / Fail Decisions
* Harvest
* Workspace Merge
* Remote Editing
* Layer Assignment
* Visualization
* Architectural Review

---

```text
Submission Snapshot Parsed

Project Tree Generated

Folder Tree Generated

Source File Registry Generated

Phase6 Ready
```
