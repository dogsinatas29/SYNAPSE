# v0.3.30 Phase6 — Reference Verification Layer

## Purpose

Phase6 transforms an Architecture Index into a verification-ready reference graph.

Phase6 discovers relationships between source files, constructs the Synapse graph, and performs architectural verification.

Phase6 does not perform Harvest.

```text
Architecture Index
        ↓
Reference Analysis
        ↓
Graph Construction
        ↓
Verification
        ↓
Review Findings
        ↓
Architect Decision
        ↓
Harvest Candidate Set
```

---

## Core Principle

Phase5 describes structure.

Phase6 describes relationships.

```text
Phase5
=
What Exists

Phase6
=
How Files Relate
```

Phase6 operates exclusively on file-level references.

Phase6 does not analyze function call relationships.

---

## Input

Phase6 receives:

```text
Project Tree

Folder Tree

Source File Registry

Function Catalog
```

All inputs originate from Phase5.

---

# Synapse Graph Model

## Node

```text
Node
=
Source File
```

Every source file becomes a graph node.

Examples:

```text
auth.py
user.py
database.rs
index.ts
```

---

## Cluster

```text
Cluster
=
Folder
```

Clusters represent filesystem organization only.

Clusters do not participate in verification decisions.

Clusters are organizational structures.

---

## Edge

```text
Edge
=
File-Level Reference
```

Edges represent discovered references between files.

Examples:

```python
from auth import login
```

```javascript
import axios from 'axios'
```

```rust
use crate::database;
```

```cpp
#include "network.h"
```

All such references may produce graph edges.

Edges represent file-level relationships only.

Edges do not represent function-call relationships.

---

# Function Catalog

Function Catalog is not a graph structure.

Function Catalog is architectural metadata.

Purpose:

```text
Identify executable units
contained within source files.
```

Function Catalog does not generate edges.

Function Catalog does not produce call graphs.

Function Catalog does not participate in reference discovery.

Included:

```text
Top-Level Functions

Class Methods
```

Excluded:

```text
Lambda Functions

Anonymous Functions

Closures

Runtime Generated Functions
```

---

# Reference Discovery

Phase6 scans reference information extracted during Phase5.

Examples:

```text
import

include

use

require

command references

configuration references

document references
```

Phase6 operates on discovered references only.

No function-call analysis is performed.

---

# Reference Resolution

Each discovered reference is resolved against the Source File Registry.

```text
Reference Found?
        ├─ YES
        │     ↓
        │   Edge Generation
        │
        └─ NO
              ↓
         Ghost Projection
```

---

# Edge Generation

Resolved references become graph edges.

Supported edge categories include:

```text
INCLUDE

REFERENCE

CALL

DB_QUERY

DATA_FLOW

EVENT

CONDITIONAL

LOOP_BACK
```

These categories represent file-level relationships.

They do not represent function-call relationships.

---

## Edge Source Principle

Edges originate from discovered references.

Examples:

```text
Python imports

JavaScript imports

C/C++ includes

Rust use/mod statements

Shell command references

Markdown links

Configuration references
```

Edges are never generated from:

```text
Function Calls

Method Calls

Runtime Execution Paths

Control Flow Analysis
```

---

# Ghost Projection

When a reference cannot be resolved, a Ghost Node is created.

---

## External Ghost

External Ghosts represent external dependencies.

Examples:

```text
axios

requests

fetch

connect
```

Generated as:

```text
external://axios

external://requests

external://fetch
```

Assigned to:

```text
cluster_ghosts
```

---

## Internal Ghost

Internal Ghosts represent unresolved internal references.

Examples:

```text
ghost://missing_module

ghost://unknown_reference
```

---

## Ghost Principle

Ghost generation is not a verification failure.

```text
Ghost
≠
Failure
```

Ghosts preserve unresolved relationships discovered during analysis.

Ghosts are architectural findings.

Architects decide whether action is required.

---

# Graph Construction

Phase6 constructs the Synapse graph.

Components:

```text
File Nodes

Folder Clusters

Reference Edges

Ghost Nodes
```

Output:

```text
Reference Graph
```

---

# Verification

Phase6 verifies graph integrity.

Verification may include:

```text
Node Integrity

Cluster Integrity

Reference Integrity

Edge Integrity

Ghost Consistency

UUID Consistency
```

Phase6 validates structural correctness of the graph.

Phase6 does not validate program behavior.

Phase6 identifies findings.

Phase6 does not automatically accept or reject submissions.

---

# Review Findings

Phase6 produces architectural findings for review.

Examples:

```text
Unresolved References

Ghost Projections

Folder Structure Mismatches

Reference Anomalies

Disconnected Components

Unexpected External Dependencies

UUID Conflicts
```

Findings are informational.

Findings do not automatically block Harvest.

---

# Architect Authority

Submission Snapshots are immutable by default.

Architects may temporarily unlock a submitted snapshot for corrective actions.

Examples:

```text
File Content Fix

Import Path Correction

Reference Repair

File Relocation

Folder Relocation
```

After modification:

```text
Snapshot Rebuild
        ↓
Verification Re-run
```

Architect modifications occur before Harvest.

---

# Architect Decision

Phase6 provides information.

Architects make decisions.

Possible outcomes:

```text
Accept

Modify

Request Resubmission

Prepare Harvest Candidate
```

Phase6 assists decision-making.

Phase6 does not perform Harvest.

---

# Verification Output

Phase6 produces:

```text
Verification Report
```

Containing:

```text
Review Findings

Graph Statistics

Ghost Statistics

Integrity Findings

Risk Markers
```

---

# Harvest Candidate Generation

Review-completed graph structures become Harvest Candidates.

Output:

```text
Harvest Candidate Set
```

This becomes the input of Phase7.

Phase6 does not perform Harvest.

---

# Explicitly Excluded

Phase6 must NOT perform:

```text
Function Call Analysis

Call Graph Construction

Control Flow Analysis

Type Analysis

Runtime Analysis

Code Execution

Behavior Verification

Harvest
```

Phase6 is reference-oriented.

It is not a semantic execution engine.
