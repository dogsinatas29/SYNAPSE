# SYNAPSE v0.3.30

# Phase7 — Harvest Engine

---

# Purpose

Phase7 materializes approved work into the project.

Harvest is not analysis.

Harvest is not verification.

Harvest is not merge resolution.

Harvest is collection.

```text
Verified Review Workspace
        ↓
Harvest
        ↓
Master Layer
```

Phase7 applies the Architect-approved workspace to the project.

---

# Core Principles

```text
Harvest
=
Collection
```

```text
Harvest
=
Physical Materialization
```

```text
Harvest
≠ Verification
```

```text
Harvest
≠ Conflict Resolution
```

```text
Harvest
≠ Merge Engine
```

```text
Architect
=
Final Decision Authority
```

---

# Harvest Philosophy

All review decisions must occur before Harvest.

Harvest itself performs no architectural judgment.

When Harvest begins:

```text
Decision Complete
```

must already be true.

Harvest only materializes the approved result.

---

# Input

Phase7 receives:

* Original Submission Snapshot
* Review Workspace
* Verification Report

Produced by previous phases.

---

# Input Principle

The original snapshot remains preserved.

The Review Workspace represents the current approved state.

```text
Original Snapshot
        ↓
Review
        ↓
Remote Edit
        ↓
Review Workspace
```

Harvest consumes the Review Workspace.

Harvest never modifies the original snapshot.

---

# Harvest Target

Harvest targets the project's Master Layer.

```text
Review Workspace
        ↓
Master Layer
```

The Master Layer becomes the authoritative project state.

---

# Harvest Scope

Harvest copies:

* Source Files
* Configuration Files
* Documentation Files
* Folder Structures

---

# Folder Principle

Folders are harvested exactly as approved.

Example:

```text
src/
```

Harvest creates:

```text
src/
```

If the approved workspace contains:

```text
Src/
```

Harvest creates:

```text
Src/
```

Harvest does not rename folders.

Harvest does not normalize folder names.

Harvest copies exactly what was approved.

---

# File Principle

Files are harvested exactly as approved.

Example:

```text
auth.ts
```

Harvest creates:

```text
auth.ts
```

Harvest does not rename files.

Harvest does not reinterpret file contents.

Harvest copies exactly what was approved.

---

# Conflict Principle

Harvest does not resolve conflicts.

Conflict handling belongs to review.

Architect review must occur before Harvest.

Example:

```text
Master:
login.ts

Client:
login.ts
```

Different contents.

Architect decides during review.

Harvest copies the approved version.

---

# Graph Relationship

Harvest does not operate on graphs.

Harvest operates on files and folders.

However:

```text
Review Workspace
        ↓
Phase6 Graph
        ↓
Architect Review
```

may be used to support decision making.

The graph is advisory.

Harvest is physical.

---

# Remote Edit Relationship

Remote Edit may occur before Harvest.

```text
Submission Snapshot
        ↓
Review
        ↓
Remote Edit
        ↓
Approved Workspace
        ↓
Harvest
```

Harvest always uses the latest approved workspace.

---

# Layer Relationship

Before Harvest:

```text
Master Layer
```

and

```text
Client Layer
```

may coexist.

After Harvest:

```text
Approved Workspace
```

is materialized into the Master Layer.

---

# Session Completion Principle

Harvest represents completion of review.

After successful Harvest:

```text
Harvest Complete
        ↓
Client Session Closed
```

The server may disconnect the client.

The review lifecycle is complete.

---

# Snapshot Preservation

Harvest never destroys:

```text
Original Submission Snapshot
```

The original snapshot remains available for:

* Audit
* Comparison
* Verification History
* Review History

---

# Storage Principle

The original submission remains preserved.

The harvested result becomes the current project state.

```text
Original Snapshot
        ↓
Preserved

Approved Workspace
        ↓
Harvest
        ↓
Master Layer
```

---

# Relationship To Phase6

Phase6 prepares.

Phase7 applies.

```text
Reference Graph
        ↓
Verification
        ↓
Review Complete
        ↓
Harvest
```

Phase7 assumes review has already finished.

---

# Explicitly Excluded

Phase7 must NOT perform:

* Reference Discovery
* Graph Construction
* Visualization
* Function Analysis
* Call Graph Analysis
* Verification Execution
* Conflict Resolution
* Automatic Merge
* Semantic Interpretation
* Runtime Analysis
* Code Execution
