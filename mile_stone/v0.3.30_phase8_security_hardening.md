# Phase 8 - Boundary Enforcement

## Purpose

Phase8 enforces the ownership and authority boundaries established by previous phases.

Phase8 does not introduce new collaboration features.

Phase8 protects:

* Project Boundary
* Session Boundary
* Submission Boundary
* Harvest Authority

---

# Goal

Prevent unauthorized access across collaboration boundaries.

Ensure:

* Projects remain isolated
* Sessions remain isolated
* Submission ownership is respected
* Harvest authority is enforced

---

# Core Principle

Ownership determines authority.

Authority determines access.

```text
Ownership
        ↓
Authority
        ↓
Access
```

Access outside an object's ownership boundary is denied.

---

# Project Isolation

Projects are independent collaboration domains.

A project may only access:

* Its own runtime
* Its own sessions
* Its own submissions
* Its own harvested layer

Cross-project access is prohibited.

---

# Session Isolation

Sessions are independent collaboration environments.

A participant may only access:

* Sessions they have joined
* Sessions approved by the Lead

Access to unrelated sessions is denied.

---

# Workspace Boundary

All file operations must remain inside the active project workspace.

All user-specified paths are interpreted as:

```text
Workspace Relative Paths
```

Example:

```text
src/auth/login.rs
docs/api/auth.md
tests/unit/login_test.rs
```

Operations attempting to escape the workspace root are rejected.

Examples:

```text
../../../etc/passwd
../../other_project
```

---

# Submission Ownership

Submission Snapshots are review artifacts.

Only authorized participants may access the active submission.

Submission ownership remains bound to the active review process.

Unauthorized access is denied.

---

# Remote Edit Authorization

Remote Edit is restricted to the active submission under review.

Remote Edit does not grant unrestricted filesystem access.

Remote Edit may only operate within the reviewed submission workspace.

---

# Harvest Authorization

Harvest is a privileged operation.

Only Lead may execute Harvest.

Harvest may only operate on approved review targets.

Unauthorized Harvest requests are denied.

---

# Authentication Requirements

Every collaboration operation must validate:

* Identity
* Role
* Project
* Session

Failed validation results in access denial.

---

# Cache Cleanup

Temporary collaboration artifacts must not persist after session termination.

Examples:

* Submission Cache
* Review Cache
* Remote Layer Cache
* Temporary Projection Data

Caches must be released when no longer required.
