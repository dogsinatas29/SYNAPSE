# SYNAPSE v0.3.30 Secure Architecture

## Purpose

SYNAPSE는 일반 웹 애플리케이션이 아니다.

SYNAPSE는 프로젝트 경계 내부에서만 동작하는 제한된 협업 전송 시스템(Restricted Collaboration Transport)이다.

목표:

* 프로젝트 경계 보호
* 인증된 SYNAPSE Client만 허용
* 브라우저 접근 차단
* 위장 클라이언트 차단
* Server Authority 보장
* 안전한 파일 접근
* Harvest 기능의 보안 기반 제공

---

# Core Principles

## Principle 1 — Server Authority

Architect(Server)는 유일한 Source Of Truth이다.

Client는 Source Of Truth가 아니다.

모든 공식 상태는 Server가 결정한다.

Client는 상태를 제안할 수 있다.

Client는 상태를 결정할 수 없다.

---

## Principle 2 — Project Boundary First

SYNAPSE의 최상위 보안 경계는 네트워크가 아니라 프로젝트 루트이다.

예:

PROJECT_ROOT=/workspace/projectA

모든 파일 접근은 반드시 PROJECT_ROOT 내부로 제한된다.

허용:

* src/*
* docs/*
* data/*
* .synapse/*

거부:

* ../
* ../../
* /etc/*
* /home/*
* 다른 프로젝트 루트

결과:

* 프로젝트 외부 파일 읽기 금지
* 프로젝트 외부 파일 쓰기 금지
* Harvest 경로 탈출 금지

---

## Principle 3 — Restricted SSH Model

SYNAPSE는 SSH Shell이 아니다.

허용:

* 로그인
* 프로젝트 구조 조회
* 파일 조회
* 파일 저장
* 파일 제출
* Layer 비교
* Harvest

금지:

* Shell 실행
* 명령 실행
* 프로세스 실행
* 임의 파일 접근
* 임의 경로 탐색

SYNAPSE는 제한된 SSH와 유사한 협업 프로토콜이다.

---

## Principle 4 — Browser Deny

일반 브라우저는 지원 대상이 아니다.

거부:

* Chrome
* Firefox
* Edge
* curl
* Postman

허용:

* SYNAPSE VSCode Extension
* SYNAPSE Desktop Client (Future)

모든 요청은 SYNAPSE Handshake 이후에만 허용된다.

---

## Principle 5 — SYNAPSE Identity Verification

클라이언트는 반드시 자신이 SYNAPSE Client임을 증명해야 한다.

예시:

Client

```json
{
  "protocol": "synapse",
  "version": "0.3.30"
}
```

Server

```json
{
  "protocol": "synapse",
  "version": "0.3.30",
  "nonce": "..."
}
```

검증 실패:

* 연결 거부
* 로그인 거부
* API 접근 거부

목적:

* 브라우저 차단
* 가짜 클라이언트 차단
* 프로토콜 위조 차단

---

## Principle 6 — Internal Collaboration Network

SYNAPSE는 인터넷 공개 서비스를 목표로 하지 않는다.

기본 사용 시나리오는 내부망 협업이다.

외부 공개 서비스는 기본 전제가 아니다.

---

# Runtime Lifecycle

## Neutral State

상태:

NEUTRAL

---

## Client Mode

사용자가

Connect

를 수행하면

Client Mode가 된다.

Client는 Authority가 아니다.

---

# Authentication

## Server Controlled Accounts

계정 생성은 Server만 수행할 수 있다.

순서:

Server Start

↓

Account Creation

↓

Client Login

Client는 계정을 생성할 수 없다.

---

## Account Storage

기본 저장 위치:

data/accounts.json

향후 DB로 교체 가능하다.

그러나 계정 생성 권한은 항상 Server에 있다.

---

## Login Requirement

모든 연결은 인증을 요구한다.

인증 실패 시 모든 요청을 거부한다.

---

## Session Rule

인증 성공 후 Session을 생성한다.

Session 없이는 프로젝트 접근을 허용하지 않는다.

---

# Project Boundary

## Server Project Boundary

Server는 PROJECT_ROOT를 절대 벗어날 수 없다.

허용:

src/main.ts

docs/spec.md

Cargo.toml

거부:

../../../etc/passwd

../../../home/user/.ssh/id_rsa

/etc/shadow

---

## Path Traversal Protection

다음을 모두 차단해야 한다.

* ../
* ../../
* 절대 경로 우회
* 심볼릭 링크 우회

---

## Boundary Validation Rule

모든 파일 접근 API는 실제 파일 접근 전에 경계 검증을 수행해야 한다.

검증 실패 시 즉시 거부한다.

---

# Client Project Boundary

## Client Workspace Access

Server는 Client Workspace에 접근할 수 있다.

Server는 Client 파일을:

* Read
* Write
* Save

할 수 있다.

---

## Client Project Boundary Rule

그러나 접근 범위는 Client Project Root 내부로 제한된다.

허용:

client_project/src/main.ts

client_project/docs/spec.md

거부:

../../../home/user/.ssh/id_rsa

../../../etc/passwd

C:\Users\User\Documents\secret.txt

---

## Boundary Symmetry

Server와 Client 모두 동일한 프로젝트 경계 규칙을 따른다.

프로젝트 외부 접근은 허용하지 않는다.

---

# Authority Model

## Server Authority Rule

Server만 Authority가 될 수 있다.

Client는 Authority가 될 수 없다.

---

## State Ownership

프로젝트 상태의 최종 소유자는 Server이다.

Client는 상태를 제안할 수 있다.

Client는 상태를 결정할 수 없다.

---

## Modification Rule

Client 변경은 Server 승인 전까지 공식 상태가 아니다.

---

# Layer Architecture

## Functional Layer

현재:

* AI Layer
* User Layer
* External Layer

---

## Client Layer

각 Submission은 Client Layer를 가진다.

예:

Client A

src/main.ts

Client B

src/main.ts

동일 경로 파일이 여러 Layer에 존재하는 것은 정상 상태이다.

---

## Layer Identity Rule

파일의 고유 식별자는 다음과 같다.

(Layer, File Path)

예:

(Master, src/main.ts)

(ClientA, src/main.ts)

(ClientB, src/main.ts)

동일 경로 파일은 Layer가 다르면 서로 다른 객체이다.

---

# Compare Security Model

Harvest 이전 단계로 Compare를 수행할 수 있다.

목적:

무엇이 다른지 확인

---

## Compare Trigger

Harvest 버튼을 누를 때 수행한다.

자동 Compare는 수행하지 않는다.

이유:

* 서버 부하 감소
* 불필요한 계산 방지
* 대규모 프로젝트 대응

---

## Compare Scope

비교 대상:

Master Layer

VS

Submission Snapshot

Master는 항상 Source Of Truth이다.

---

## Compare Result

허용 상태:

* UNCHANGED
* MODIFIED
* ADDED

REMOVED 상태는 사용하지 않는다.

삭제는 Harvest의 범위가 아니다.

---

## Diff Integration

SYNAPSE는 Diff Viewer가 아니다.

SYNAPSE는 Diff Detector이다.

상세 Diff는 VSCode Diff 기능을 사용한다.

---

# Security Goals

# Final Definition

SYNAPSE는 Git이 아니다.

SYNAPSE는 Merge Tool이 아니다.

SYNAPSE는 SSH Shell도 아니다.

SYNAPSE는 프로젝트 경계 내부에서만 동작하는 제한된 협업 전송 시스템이다.

Architect(Server)는 유일한 Source Of Truth이다.

Server만 Authority가 될 수 있다.

Client는 Authority가 될 수 없다.

브라우저 직접 접속은 허용하지 않는다.

위장 SYNAPSE Client는 허용하지 않는다.

모든 연결은 인증을 요구한다.

Server와 Client 모두 프로젝트 경계를 벗어날 수 없다.

Compare는 Master Layer를 기준으로 수행된다.

Harvest는 승인된 파일만 복사할 수 있다.
