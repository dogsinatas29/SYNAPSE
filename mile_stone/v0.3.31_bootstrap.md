# Mission

v0.3.31의 목표는 새로운 협업 기능을 추가하는 것이 아니다.

이미 구축된 SYNAPSE 협업 구조 위에서
Virtual Debugger를 네트워크 클라이언트까지 확장하여

Harvest 이전에

* 코드 품질
* 컴파일 오류
* 경고 상태

를 확인할 수 있도록 만드는 것이다.

Harvest는 최종 수집 단계이며,

Virtual Debugger → Validation → Harvest

순서를 완성하는 것이 이번 마일스톤의 목표이다.

# Principles

🚀 [LLM 코딩 원칙]

LLM Coding Principles:

1. [Think Before Coding]
   코딩 전 사고.
   추측하지 마라.
   요구사항이 모호하면 즉시 질문한다.
   접근 방식과 트레이드오프를 먼저 제시한다.
   항상 가장 단순한 해결책부터 제안한다.

2. [Simplicity First]
   단순성 우선.
   최소한의 코드만 작성한다.
   요청되지 않은 기능을 추가하지 않는다.

3. [Minimal Changes]
   정밀 타격.
   전체를 갈아엎지 않는다.
   필요한 부분만 수정한다.

4. [Goal-Oriented Execution]
   목표 → 계획 → 구현 → 검증
   순서를 반드시 지킨다.

5. [No Hallucinated APIs]
   존재하지 않는 API를 만들지 않는다.

6. [Stable Code Protection]
   검증된 코드는 건드리지 않는다.

7. [Context Confirmation]
   코드 수정 전 맥락을 확인한다.

8. [Rendering Isolation]
   렌더링 상태를 강제 초기화하여 뷰 간 간섭을 차단한다.

9. 작업 시작 전 반드시 계획서를 제출하고 승인을 받는다.

# Gemini Performance Constraints

## Rule 1

Frame Loop는 반드시 O(1)

금지:

* for
* while
* map
* filter
* reduce

허용:

* 직접 접근
* 상수 시간 연산

---

## Rule 2

상태 변경이 없으면 재계산 금지

필수:

* cache
* dirty flag

---

## Rule 3

State Driven

Polling 기반 로직 추가 금지

---

## Rule 4

CPU Budget Protection

반복 시각 연산은 GPU로 이동

---

## Rule 5

Hot Path Allocation 금지

new
push
array resize

금지

---

## Rule 6

Forbidden Patterns

* loop inside render
* repeated calculation
* allocation inside frame
* hidden O(n)

---

## Rule 7

Review Checklist

* [ ] Frame Path O(1)
* [ ] Recalculation 제거
* [ ] Allocation 제거
* [ ] State Driven
* [ ] CPU 최소화
