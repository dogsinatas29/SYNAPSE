# v0.3.31 — Distributed Virtual Debugger

## Goal

Harvest 이전 단계에서 원격 클라이언트의 코드 품질을 검증할 수 있는 분산 가상 디버깅(Distributed Virtual Debugging) 시스템을 구축한다.

v0.3.30이 협업 데이터 수집(Harvest)을 완성했다면, v0.3.31은 "수집할 가치가 있는 결과물인가?"를 판단하는 검증 레이어를 완성한다.

Harvest는 검증 이후에만 수행된다.

Pipeline:

Client Source
→ Virtual Debugger
→ Quality Verification
→ Harvest
→ Archive

---

# Core Philosophy

## Harvest ≠ Validation

Harvest는 데이터 수집이다.

Validation은 코드 품질 검증이다.

둘은 분리된다.

Harvest 엔진은 파일을 복사한다.

Virtual Debugger는 파일을 평가한다.

서로의 책임 영역을 침범하지 않는다.

---

## No Synchronization

동기화는 구현하지 않는다.

Client는 자신의 코드를 소유한다.

Server는 검증하고 관찰한다.

소유권 충돌 문제를 만들지 않는다.

---

## Existing Technology Only

새로운 프로토콜을 발명하지 않는다.

새로운 언어 서버를 만들지 않는다.

새로운 AST 엔진을 만들지 않는다.

VSCode Diagnostic System을 활용한다.

Rust Analyzer, TypeScript Server, Pyright 등
기존 언어 서버가 생성한 진단 정보를 사용한다.

---

# Problem Statement

현재 Virtual Debugger는 Server Workspace에 존재하는 파일만 분석할 수 있다.

Harvest 이전의 Client 파일은 다음 문제를 가진다.

* Server Workspace에 존재하지 않음
* Diagnostic Mapping 불가
* Necrosis 표시 불가
* Fracture 표시 불가

결과적으로 Harvest 전 품질 평가가 불가능하다.

---

# Target

Harvest 이전 단계에서 다음 정보를 확인 가능해야 한다.

* Error Count
* Warning Count
* Diagnostic Severity
* Necrosis State
* Fracture State
* Last Analysis Timestamp

Client가 서버에 접속해 있는 동안
Server Canvas에서 실시간으로 확인 가능해야 한다.

---

# Architecture

## Client-side Analysis

분석은 Client에서 수행한다.

Server가 Client 파일을 직접 분석하지 않는다.

Client의 VSCode Language Server가
자신의 Workspace를 분석한다.

Client는 Diagnostic 결과만 전송한다.

---

## Diagnostic Snapshot

Client는 주기적으로 Diagnostic Snapshot을 생성한다.

Example:

{
"file": "src/main.ts",
"errors": 2,
"warnings": 4,
"severity": "error",
"timestamp": 123456789
}

Server는 Snapshot만 수신한다.

원본 Diagnostic 객체는 전송하지 않는다.

---

## Ownership Preservation

Client Diagnostic은 Client 소유다.

Server는 표시만 한다.

수정하지 않는다.

병합하지 않는다.

재해석하지 않는다.

# Non Goals

이번 버전에서 구현하지 않는다.

* File Synchronization
* Auto Merge
* Conflict Resolution
* Remote Editing
* Shared Workspace
* Live Collaborative Editing
* Git Replacement
* WebSocket State Ownership System
