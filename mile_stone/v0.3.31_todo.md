# v0.3.31 TODO

## Network Virtual Debugger

### Goal

Harvest 이전 단계에서 클라이언트의 실제 진단 정보(Diagnostics)를 서버(Architect)가 수집하여 Virtual Debugger에 통합한다.

본 버전은 Harvest, Sync, AST 복제, 원격 분석 엔진을 구현하지 않는다.

클라이언트가 이미 보유하고 있는 VS Code Diagnostics를 서버로 전달하고, Architect Canvas에서 Necrosis를 생성하는 것만을 목표로 한다.

---

# Architecture Principle

## KISS

새로운 분석 엔진을 만들지 않는다.

VS Code가 이미 생성한 Diagnostics를 사용한다.

---

## Don't Reinvent The Wheel

LSP를 재구현하지 않는다.

AST Parser를 만들지 않는다.

TypeScript Server, Rust Analyzer, Pyright 등 기존 생태계를 그대로 사용한다.

---

## Solve Real Problems Only

Harvest 이후 디버깅이 아니라 Harvest 이전 품질 검증이 목적이다.

Virtual Debugger는 Harvest 승인 판단 도구이다.

---

# Scope

## Included

* Client Diagnostics Export
* Network Diagnostics Transfer
* Server Diagnostics Cache
* Virtual Debugger Integration
* Necrosis Visualization

## Excluded

* Harvest 기반 Debug
* Sync Engine
* Conflict Resolution
* WebSocket
* Remote AST
* Remote Compile
* Remote Execution
* LSP Reimplementation

# Phase 1

## Diagnostic Provider 분리

### Goal

### Tasks

* DiagnosticProvider 인터페이스 생성
* LocalDiagnosticProvider 생성
* RemoteDiagnosticProvider 생성

### Validation

---

# Phase 2

## Client Diagnostics Export

### Goal

클라이언트가 현재 Workspace Diagnostics를 추출

### Tasks

사용 API

```ts
vscode.languages.getDiagnostics()
```

추출 정보

```ts
{
    file,
    severity,
    message,
    line,
    source
}
```

### Validation

Client Console에서 Diagnostics 출력 확인

---

# Phase 3

## Network Transport

### Goal

Client Diagnostics를 Architect로 전달

### Tasks

새 메시지 타입 추가

```text
CLIENT_DIAGNOSTICS_UPDATE
```

Payload

```ts
{
    clientId,
    timestamp,
    diagnostics:[]
}
```

### Validation

Server 로그에서 수신 확인

---

# Phase 4

## Server Diagnostics Cache

### Goal

클라이언트별 Diagnostics 저장

### Tasks

```ts
Map<string, DiagnosticRecord[]>
```

생성

예시

```ts
clientDiagnostics
```

저장

```ts
clientDiagnostics.set(
    clientId,
    diagnostics
);
```

### Validation

접속 클라이언트별 Diagnostics 조회 가능

---

# Phase 5

## Virtual Debugger Integration

### Goal

Local + Remote Diagnostics 통합

### Tasks

현재

```text
VirtualDebugger
    ↓
getDiagnostics()
```

변경

```text
Local Provider
Remote Provider
        ↓
VirtualDebugger
```

### Validation

로컬 Diagnostics 정상 동작 유지

---

# Phase 6

## Necrosis Generation

### Goal

클라이언트 오류를 Architect Canvas에서 시각화

### Tasks

Remote Diagnostics → Node Mapping

Node → Necrosis 생성

### Validation

클라이언트 파일에 의도적 오류 삽입

예시

```ts
const x: string = 123;
```

Architect Canvas에 Necrosis 생성 확인

# Success Criteria

모든 조건 충족 시 완료

* Client Diagnostics Export 성공
* Diagnostics Network Transfer 성공
* Server Cache 저장 성공
* Virtual Debugger 통합 성공
* Necrosis 생성 성공

* Sync 없이 동작
* WebSocket 없이 동작

# Completion Definition

Architect는 Harvest 이전 단계에서

* Client A 오류
* Client B 오류
* Client C 오류

를 실시간으로 확인할 수 있다.

Harvest는 Debug 완료 후 실행된다.

즉

```text
Client Work
    ↓
Virtual Debug
    ↓
Architect Review
    ↓
Harvest
```

순서가 성립해야 한다.
