# v0.3.31 — Network Virtual Debugger

## Goal

Harvest 이전 단계에서 연결된 클라이언트의 소스코드를 실시간으로 분석하고,
Architect 캔버스에 Virtual Debug 결과를 시각화한다.

Harvest는 검증 완료된 결과물만 수집하는 단계로 유지한다.

---

# Problem Statement

현재 VirtualDebugger는 VS Code Diagnostics 기반으로 동작한다.

```text
vscode.languages.getDiagnostics()
```

Diagnostics는 Architect 머신에 존재하는 파일에 대해서만 생성된다.

따라서 다음과 같은 문제가 발생한다.

```text
Client Node
 └─ src/main.ts

Harvest File
 └─ .synapse/clients/test1/harvest/src/main.ts
```

노드 경로와 실제 Diagnostic 경로가 다르므로
VirtualDebugger가 노드를 찾지 못한다.

결과적으로 클라이언트 노드는 Necrosis 및 Fracture 분석 대상에서 제외된다.

---

# Architectural Decision

Harvest 기반 진단을 하지 않는다.

Harvest는 결과물 수집 단계다.

가상 디버깅은 반드시 Harvest 이전에 수행되어야 한다.

따라서 Diagnostics 자체를 클라이언트에서 생성하고
Architect에게 전송한다.

```text
Client Workspace
      ↓
Local Diagnostics
      ↓
Network Transport
      ↓
Architect
      ↓
Virtual Debug Overlay
      ↓
Harvest
```

---

# Design Principles

## 1. Ownership Preservation

파일 소유권은 항상 Client에 있다.

Architect는 Diagnostics만 수신한다.

Architect는 원격 파일을 수정하지 않는다.

---

## 2. No Remote Parsing

서버가 클라이언트 코드를 다시 파싱하지 않는다.

클라이언트가 이미 생성한 Diagnostics를 재사용한다.

바퀴를 다시 만들지 않는다.

---

## 3. KISS

새 AST 엔진을 만들지 않는다.

새 분석기를 만들지 않는다.

기존 VS Code Language Server 결과를 활용한다.

---

# Solution

## Phase A

Client Diagnostics Export

클라이언트 확장에서:

```typescript
vscode.languages.getDiagnostics()
```

결과를 수집한다.

전송 형식:

```typescript
{
  file: "src/main.ts",
  severity: "error",
  message: "...",
  line: 42
}
```

---

## Phase B

Diagnostics Transport

기존 Session 채널을 사용한다.

새 프로토콜:

```text
CLIENT_DIAGNOSTICS_UPDATE
```

새 네트워크 스택을 만들지 않는다.

---

## Phase C

Server Cache

Architect 서버는

```typescript
Map<ClientId, Diagnostic[]>
```

형태로 캐싱한다.

---

## Phase D

Virtual Debug Mapping

노드:

```text
src/main.ts
```

Diagnostic:

```text
src/main.ts
```

직접 매핑한다.

Harvest 경로를 사용하지 않는다.

---

## Phase E

Canvas Visualization

기존 Necrosis 시스템 재사용.

Severity:

```text
Error   → Necrosis
Warning → Fracture
Info    → Hint
```

# Non Goals

* Conflict Resolution
* Remote Editing
* Distributed AST
* Multi-Master State Merge
