# Motivation

v0.3.32 협업(Client Layer) 통합 과정에서 클라이언트 노드의 Flow View 가시화 문제를 대부분 해결했다.

그러나 한 가지 구조적 문제가 남았다:

클라이언트 노드가 Flow View에 렌더링되지만, 메인 플로우와 연결되지 않고 화면 중앙에 독립적으로 배치된다.

## 조사에서 확인된 사실

### Flow Engine은 이미 Topological Layering을 보유하고 있다

`layoutFlow()`는 다음을 수행한다:

```text
1. In-degree 계산
2. BFS level 배정 (in-degree=0 노드에서 시작)
3. y = startY + (level * stepHeight)
4. X축 parent alignment
```

따라서 "Topology Layer가 없다"는 최초 가설은 사실이 아니다.

### Flow Engine은 Entry Point를 식별하지 못한다

현재 Root 선택 로직:

```javascript
const roots = nodes.filter(n => !inDegrees[n.id] && n.type !== 'external');
```

→ **순수 topology 기반.** in-degree=0인 노드 전부가 root.

START 연결:

```javascript
steps.push({
    id: 'step_start',
    allNexts: rootStepIds  // 모든 root 노드에 연결
});
```

→ START → **모든 root** (mod, rules, spec, campaign, constraint_meta... 전부)

### START는 장식에 가깝다

| 주장 | 사실 |
|------|------|
| "START는 진짜 시작점이다" | ❌ 장식에 가까움 |
| "START에서 의미적 흐름이 시작된다" | ❌ in-degree=0 노드 전부에 연결 |
| "Entry Point를 알고 있다" | ❌ topology만 보고 semantics 모름 |

### Connected Component 검증 결과

```
서버 단독:  Component #0 size=265 hasStart=true
클라이언트 접속: Component #0 size=269 hasStart=true
```

client 노드 4개가 메인 그래프와 **같은 Connected Component**에 편입됨.

따라서 "Client Node는 Detached Component"라는 가설은 기각. Client Node는 Main Component 내부에 존재.

### client 노드의 실제 상태

client 노드는 메인 그래프와 약한 edge로 연결되어 있어 같은 Component에 포함되지만, **의미적으로는 메인 실행 흐름과 무관**한 include-only 파일이다.

# Problem Statement

```text
Flow Engine은 이미 Topological Layering을 보유하고 있다.

그러나 실제 프로그램의 시작점(Entry Point)을 식별하지 못하며,
in-degree=0인 모든 노드가 같은 급의 root로 취급된다.

START는 장식에 가깝다.

현재 확인된 가장 큰 구조적 결함은 Entry Point 부재이다.
```

---

# Goal

Flow View를 **Graph Layout**에서 **Execution Flow**로 전환한다.

```text
Before: 연결된 노드들의 DAG (의미 없는 root 다수)
After:  Entry Point에서 시작되는 실행 흐름 (단일 시작점)
```

---

# Core Principles

## Principle 1 — Single Entry Point

Flow Engine은 반드시 하나의 Entry Point를 가진다.

### Entry Point 탐색 우선순위

1. User Selected Entry (사용자 지정)
2. Workspace Metadata (`flowEntry` 또는 `main` 필드)
3. `extension.ts` / `extension.js`
4. `main.ts` / `main.js`
5. `index.ts` / `index.js`

### Entry Point가 없을 때

Fallback: in-degree=0 노드 중 파일명 기반 우선순위 정렬 (현재 로직 유지)

### Entry Point 노드의 layer

```ts
entryNode.layer = 0
```

---

## Principle 2 — Graph Distance Layer

BFS level은 Entry Point로부터의 **그래프 거리**를 나타낸다.

```text
Layer 0: Entry Point (extension.ts)
Layer 1: Entry Point에서 직접 연결된 노드
Layer 2: Layer 1에서 직접 연결된 노드
```

이것은 "의미적 계층"이 아니라 "그래프 거리 기반 계층"이다.

Checkpoint A에서 edge 방향이 실제 실행 흐름과 일치하는지 검증된 후에만 "Execution Distance"라고 부를 수 있다.

---

## Principle 3 — Zone Separation (Node Attribute 기반)

Zone 판정은 Connected Component가 아니라 **Node Attribute** 기반으로 한다.

### Zone 판정 기준

| Zone | 판정 기준 |
|------|----------|
| Main Flow | `reachableIds.has(node.id)` && `!isClientNode` |
| Client Zone | `node.clientLayer` 존재 \|\| `node.data?.clientLayer` 존재 |
| Orphan Zone | Main Flow에도 Client Zone에도 속하지 않는 노드 |

### Zone 배치 규칙

```
Main Flow (START → ... → END)
────────────────────────────
Client Zone
────────────────────────────
Orphan Zone
```

각 Zone 내부에서 기존 BFS Layering을 유지한다.

---

## Principle 4 — Orphan Isolation

BFS 종료 후에도 도달 불가인 노드는 Orphan Zone으로 배치한다.

다음 노드가 여기에 배치된다:

* include-only 파일
* export-only 파일
* 단독 유틸리티
* 연결되지 않은 협업 노드
* 미분석 노드

# Phase Plan

## Phase 1 — Entry Point Resolver (최우선)

`buildFlow()` 내부의 Root 선택 로직 수정.

**현재:**
```javascript
const roots = nodes.filter(n => !inDegrees[n.id] && n.type !== 'external');
```

**수정:**
```javascript
const entryPoint = resolveEntryPoint(nodes);
const roots = entryPoint ? [entryPoint] : nodes.filter(n => !inDegrees[n.id] && n.type !== 'external');
```

`resolveEntryPoint()`:
```javascript
function resolveEntryPoint(nodes) {
    // 1. User Selected Entry (TODO: settings 연동)
    // 2. Workspace Metadata
    // 3~5. 파일명 기반 탐색
    const candidates = [
        nodes.find(n => n.data?.file?.match(/extension\.[tj]s$/)),
        nodes.find(n => n.data?.file?.match(/main\.[tj]s$/)),
        nodes.find(n => n.data?.file?.match(/index\.[tj]s$/)),
    ].filter(Boolean);
    return candidates[0] || null;
}
```

## Phase 2 — START 재구성

START → Entry Point 단일 연결.

**현재:**
```javascript
allNexts: rootStepIds  // 모든 root 노드에 연결
```

**수정:**
```javascript
allNexts: [entryStepId]  // Entry Point에만 연결
```

기존처럼 모든 in-degree=0 노드에 연결하지 않는다.

---

### Checkpoint A — Entry Point 검증

Phase 1 + Phase 2 적용 후 Flow View에서 확인:

```text
START
 ↓
extension.ts (Entry Point)
 ↓
session.ts
 ↓
protocol.ts
 ↓
...
 ↓
END
```

**검증 기준:**
- START → extension.ts 단일 연결 확인
- mod, rules, spec 등이 root에서 제거됨 확인
- Main Flow가 형성되는지 확인
- **Edge 방향이 실제 실행 흐름과 일치하는지 확인** (session → extension 방향이면 그래프가 비어버림)

**만약 여기서 기대한 흐름이 형성되지 않으면 Phase 3(Zone Layout)로 진행하지 않고 원인을 재조사한다.**

---

## Phase 3 — Zone Layout

`layoutFlow()`에 Zone 분리 로직 추가.

### reachableFromStart 계산

Phase 1의 Entry Point에서 BFS를 수행하여 START에서 도달 가능한 노드 집합을 생성한다:

```javascript
const reachableFromStart = new Set();
const bfsQueue = ['step_start'];
while (bfsQueue.length > 0) {
    const current = bfsQueue.shift();
    if (reachableFromStart.has(current)) continue;
    reachableFromStart.add(current);
    (adj[current] || []).forEach(n => bfsQueue.push(n));
}
```

### Zone 판정 (Node Attribute 기반)

```javascript
const isClientNode = step.node && (
    step.node.clientLayer ||
    step.node.data?.clientLayer ||
    step.node.layer === 'client'
);

if (isClientNode) {
    zones.client.push(step.id);
} else if (!reachableFromStart.has(step.id)) {
    zones.orphan.push(step.id);
} else {
    zones.main.push(step.id);
}
```

Zone별 Y 오프셋 적용:

```javascript
mainZoneY = startY + (level * stepHeight)
clientZoneY = mainMaxY + ZONE_GAP + (level * stepHeight)
orphanZoneY = clientMaxY + ZONE_GAP + (level * stepHeight)
```

---

### Checkpoint B — Zone Layout 검증

Phase 3 적용 후 Flow View에서 확인:

**검증 기준:**
- Client Node가 Main Flow와 섞이지 않고 별도 영역에 배치됨 확인
- client 노드의 BFS level과 Y 좌표 확인
- Orphan Node가 별도 영역에 배치됨 확인

## Phase 4 — Flow Rendering

`renderFlow()`에 Zone 구분선 렌더링.

```javascript
// Main Flow: 기본 렌더링
// Client Zone: 마젠타 구분선 + CLIENT ZONE 라벨
// Orphan Zone: 회색 구분선 + ORPHAN ZONE 라벨
```

시각적 구조:

```
START
 ↓
Entry Point (extension.ts)
 ↓
Main Flow (session, protocol, ...)
────────────────────────────
CLIENT ZONE
test_network.ts → TEST_network.ts
────────────────────────────
ORPHAN ZONE
isolated_file.ts
```

# Projection Rules

Y축은 Layer에 의해 결정된다.

```ts
y = layer * ROW_HEIGHT
```

X축은 기존 Cluster 정렬 로직을 유지한다.

Zone 간에는 수직 분리를 강제한다.

# Success Criteria

## Test A

Entry Point가 `extension.ts`로 식별된다.

## Test B

START → Entry Point 단일 연결이 생성된다.

## Test C

`mod`, `rules`, `spec` 등이 root에서 제거된다.

## Test D

Client Node가 `clientLayer` attribute로 판정되어 Client Zone에 배치된다.

## Test E

Orphan Node가 Orphan Zone에 배치된다.

## Test F

각 Zone 내부에서 기존 BFS Layering이 유지된다.

## Test G

기존 main flow 그래프가 깨지지 않는다.
