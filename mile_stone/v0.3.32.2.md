## 🛠️ [v0.3.32.2] 가설 1 증명 및 진단 로직(Diagnostic Logging) 강화
- **문제 인식**: 안드로이드 환경(NowInAndroid, AntennaPod 등)에서 External Ghost Box가 거대하게 생성되고, 트래픽 히트맵의 모든 붉은 선(Heat)이 특정 고스트 노드(예: `Flow`, `@Inject` 등) 한 곳으로 쏠리는 블랙홀 현상(Star Topology) 발견.
- **원인 (가설 1 증명)**: 
  - 현재 `GhostRule` 블랙리스트(`android.*`, `java.*`)를 통과한 특정 외부 라이브러리 심볼(`kotlinx.coroutines.flow.Flow` 등)이 백여 개의 내부 파일에서 호출됨.
  - 이로 인해 해당 고스트 노드의 Degree(연결 수)가 100~500 수준으로 폭증.
  - 트래픽 히트맵은 가장 높은 Degree를 기준으로 그라데이션(Heat)을 렌더링하므로, 실제 내부 아키텍처의 의미 있는 흐름(Degree 10~20)이 거대 고스트에 묻혀 완전히 시각적으로 소거됨.
- **조치 사항 (DataPipeline.ts)**: 
  - 그래프 생성 완료 직후, 파이프라인의 진단 가능성을 극대화하기 위해 유저 요청 포맷에 맞춘 정밀 계측 로그를 강제 출력하도록 변경:
    - `=== CLUSTER SUMMARY ===`: 각 클러스터명과 소속 노드 수 출력 (클러스터 정상 생성 여부 검증용).
    - `=== TRAFFIC TOP 20 ===`: 트래픽을 독식하는 상위 20개 노드와 Degree(in/out) 출력 (블랙홀 색출용).
    - `=== EDGE SUMMARY ===`: `Internal Edges`와 `External/Ghost Edges` 비율을 명확히 분리하여 덤프.
- **다음 단계 (Next Step)**: 출력된 계측 로그를 기반으로, 방사형 블랙홀을 유발하는 노드들을 `GhostRule`에 추가 등록하여 트래픽 쏠림을 캔슬링하거나 히트맵 렌더링 시 External/Ghost 엣지에 가중치 페널티를 부여하는 방향으로 수술 예정.

## 🛠️ [v0.3.32.2] 2차 계측: 클러스터 파편화 및 고스트 트래픽 실측 완료

## 🛠️ [v0.3.32.2] Phase 2A: Semantic Continent Extraction 및 진단
- **문제 인식**: 단순한 폴더 압축만으로는 거시적인 아키텍처(대륙) 형태를 파악하기 어려웠으며, 레이아웃 엔진에 무작정 Force를 추가하면 구조적 진실을 가릴 위험성이 있었음.
- **조치 사항 (DataPipeline.ts)**:
  - **Semantic Continent 추출**: 압축된 `semanticPath`의 첫 번째 세그먼트를 `continent`로, 두 번째 뎁스까지를 `subcontinent`로 추출하여 노드 메타데이터에 주입.
  - **Continent-aware Bin Packing**: 물리 엔진(Force)을 조작하기 이전에, 클러스터의 초기 배치(Grid)를 `continent` 기준 알파벳순으로 1차 정렬하도록 `Flow Bin Packing` 로직 수정. 이로 인해 같은 대륙(예: `storage`, `ui`)을 가진 클러스터들이 화면상에 자연스럽게 인접하게 배치됨.

    - `=== SUBCONTINENTS ===`: 서브 대륙별 분포

- **진단 로그 (Layout Diagnostics)**:
  - `=== CONTINENT LAYOUT ===`: 각 대륙의 소속 클러스터 수, BBox 크기, Center 절대 좌표, Weight 수치 출력.

- **해결 방안 (Resolution):**
  - `handleCreateManualNode` 함수가 `finalState.nodes` 배열에 요소를 추가할 때, `.push()` 메서드를 사용해 정상적으로 배열의 인덱스 요소로 삽입하도록 수정했습니다.
  - `handleSaveState` 내부의 `UPDATE_NODE` 디스패치 과정에서, 값이 존재하는 필드(`position`, `cluster_id`, `layer`)만을 선택적으로 객체에 담아 전송하도록 수정하여 의도치 않은 `undefined` 속성 덮어쓰기(Overwrite)를 원천 차단했습니다.

- **증상:**
  1. 사용자가 다수의 노드를 삭제한 직후 UI가 리로드되면서 방금 삭제한 노드가 화면에 다시 부활함(Zombie Nodes).

  - **Single Thread Command Pipeline (Task Queue) 통일:** 상태를 읽는(`getProjectState`, `sendProjectState`) 모든 명령 및 엔진을 초기화하는(`reBootstrap`) 명령도 상태 변이 명령(`saveState`, `deleteNodes`)과 동일한 `_taskQueue` 파이프라인(FIFO)에 무조건 편입시켜 순차성을 보장(Serialization). 이를 통해 삭제 → 디스크 기록 → UI 업데이트의 동시성 결함을 원천 차단하고 좀비 노드 부활을 완전 근절함.

  1. 클라이언트 스캔 시 새롭게 생성된 노드들은 레이아웃(좌표) 정보가 없으므로 백엔드에서 모두 `x:0, y:0`을 기본값으로 할당받습니다.
  2. 백엔드(`DataPipeline.ts`)의 위치 할당(레이아웃) 로직은 노드가 속한 `cluster`를 순회하며 노드 위치를 계산하는데, 루트에 위치한 파일들은 `cluster_id`가 할당되지 않아(`__unclustered__`) **클러스터 목록(`clusters` 배열)에서 누락되어 레이아웃 계산 단계 자체를 완전히 건너뛰고 있었습니다.** 이로 인해 루트 파일과 빈 폴더 하위 파일들은 영구적으로 `(0,0)`에 고정되었습니다.
  3. 프론트엔드의 `normalizeProjectState` 처리 후 `canvas-engine.js`에서 겹침 해소(`resolveOverlaps`)를 수행할 때, 기존에는 `n.position.x`가 유효한 숫자(`Number.isFinite`)이면 위치가 유효하다고 판단하여 위치 재계산(overlap resolution)을 스킵했습니다.
  4. `0` 역시 유효한 숫자로 취급되어, `preserveView`가 `true`일 때 노드들이 퍼지지 않고 `(0,0)` 좌표에 수십 장이 정확히 포개져서(Stacked) 렌더링되었습니다.
  5. **State Serialization False Positive Fix**: `project_state.json` 작성 전 노드 데이터가 배열인지 검사하는 `validateProjectState` 로직이, UI 뷰어 상태인 `synapse_workspace.json`를 검사할 때 노드 필드가 없어 `[ERROR] Schema Validation Failed`를 내뿜는 허위 경고(False Positive) 버그를 추가로 발견하여 수정했습니다. (워크스페이스 상태 객체일 경우 그래프 배열 검증을 건너뛰도록 예외 처리)
  5. 추가적으로 `extension.ts`에서 부트스트랩 완료 직후 강제로 뷰를 리셋하라는 신호(`forceReset=true`)를 보냈으나, `CanvasPanel`이 기존 동기화(`_isSyncing`) 중일 경우 해당 신호가 씹히는(dropped) 타이밍 이슈가 겹쳐 현상이 악화되었습니다.
- **해결 방안 (Resolution):**
  - **DataPipeline 레이아웃 누락 수정**: `DataPipeline.ts`에서 클러스터가 없는 노드들(`__unclustered__`)을 위해 가상의 `📁 Root` 클러스터를 동적으로 생성하여 `activeClusters` 및 `clusters` 배열에 강제 추가함으로써 루트 파일들도 정상적으로 레이아웃 계산(World Packing) 단계에 진입하도록 아키텍처 로직을 보완했습니다.
  - **Canvas Engine 수정**: `canvas-engine.js`의 `resolveOverlaps` 진입 조건에 `allAtOrigin` 조건을 추가하여, 다수의 노드가 정확히 `(0,0)`에 겹쳐 있다면 강제로 겹침 해소를 수행하도록 물리 엔진 예외처리를 추가했습니다.
  - **Task Queue 반영**: `extension.ts`의 강제 리프레시 명령을 `CanvasPanel.currentPanel.pushTask`를 통해 이벤트 큐(Task Queue)에 넣도록 변경하여, 동기화 타이밍이 꼬이더라도 `forceReset` 신호가 안전하게 프론트엔드까지 전달되도록 구조적 결함을 치유했습니다.
