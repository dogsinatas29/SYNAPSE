# 🚀 [v0.3.32.2] Graph Architecture Audit (그래프 파이프라인 해부도)

현재 SYNAPSE 시각화 계층의 데이터 파이프라인은 최소 4개 이상의 레이어로 분리되어 동작합니다. 현재 발생하는 시각적 병목(Star Topology, 밀도 폭증)을 디버깅하기 위한 **전체 파이프라인의 데이터 흐름과 역할 정의**입니다.

---

## 🏗️ 1. Pipeline Architecture (그래프 생성 체인)

전체 시스템은 다음과 같은 단방향 데이터 흐름(Unidirectional Data Flow)을 가집니다.

```text
[1. FileScanner]
  │ (Raw Files)
  ↓
[2. DataPipeline]
  │ (Resolved Nodes, Edges, Clusters)
  ↓
[3. Layout Engine / Webview] 
  │ (Positioning, Filtering)
  ↓
[4. Canvas Renderer]
  │ (Final Pixels)
```

### 단계별 상세 역할 및 입출력

#### 1. FileScanner (`src/core/FileScanner.ts`)
- **역할**: 프로젝트 디렉토리를 순회하며 언어별 파서를 통해 심볼(`class`, `import` 등)을 추출합니다.
- **Node 생성**: 파일 단위의 노드를 1차적으로 생성합니다.
- **Edge 생성 (Raw)**: 파일 내부에 선언된 참조 정보(문자열 형태)를 배열로 모아둡니다.
- **출력**: `nodes` (미완성), `rawEdges` (문자열 참조)

#### 2. DataPipeline (`src/core/DataPipeline.ts`)
- **역할**: `FileScanner`가 수집한 단서를 바탕으로 실제 **그래프 노드와 엣지, 클러스터를 확정**합니다.
- **Node 확정**: 시스템 노드, 고스트 노드(External 참조)를 포함하여 노드를 최종 확정합니다.
- **Edge 확정**: `SymbolIndex` 및 `PackageResolver`를 활용해 "문자열 참조"를 "실제 노드 ID 간의 연결(Edge)"로 Resolve합니다.
- **Cluster 확정**: 최하단에서 Label Propagation(LPA)을 돌려 기능적 커뮤니티(Cluster)를 묶어냅니다.
- **출력**: 확정된 `Nodes`, `Edges`, `Clusters`

#### 3. FlowGenerator (`src/core/FlowchartGenerator.ts`)
- **역할**: 사용자가 AI(Gemini) 분석을 요청했을 때만 활성화되어 프롬프트용 텍스트 다이어그램(Mermaid 등)을 생성합니다.
- **참고사항**: **현재 Architecture Mode 화면 렌더링 파이프라인에는 직접적으로 개입하지 않습니다.** (UI 렌더링에 영향을 미치지 않음이 확인됨)

#### 4. Layout Engine (`ui/canvas-engine.js` 내장)
- **역할**: 확정된 노드들의 화면상 X, Y 좌표를 계산합니다.
- **Force-directed**: 물리 엔진을 통한 자연스러운 노드 배치.
- **Satellite 변환**: SATELLITE 모드 진입 시 Cluster(커뮤니티) 단위의 거시적 배치로 변환.

#### 5. Canvas Renderer (`ui/canvas-engine.js` 내장)
- **역할**: Layout Engine이 정해준 좌표를 바탕으로 실제 픽셀을 그립니다.
- **Visibility Filtering**: `showExternalLayer`, `focusTopNodes`, `hideLeafNodes` 등의 토글 상태를 읽어 그릴 노드/엣지를 결정합니다.
- **Edge 연결 로직**: 가시성이 통과된 노드들 사이의 선형 엣지를 그립니다.

## 📊 2. 각 단계 출력값 로그 스펙 (Data Flow Metrics)

현재 시스템 상태를 진단하기 위해 파이프라인 각 구간에서 측정된 데이터량입니다.


## 🔍 3. 향후 수술 우선순위 (Action Items)

해부도를 바탕으로 도출된 수술/리팩토링 방향성입니다.

### 1순위: 레이아웃 엔진 분리 (Separation of Concerns)
- **현재 상황**: `ui/canvas-engine.js` 내부에 "물리 엔진 배치(Layout)"와 "렌더링(Renderer)", "필터링 로직"이 전부 섞여 있습니다.
- **조치**: 필터링 엔진과 좌표 계산 엔진을 독립된 클래스(`VisibilityEngine`, `PhysicsEngine`)로 분리하여 거대한 10,000줄짜리 캔버스 엔진을 리팩토링해야 합니다.

### 2순위: 노드 배치 로직 (Positioning)
- **현재 상황**: Force-directed와 Satellite가 상태를 공유하며 섞여서 동작하고 있어, 화면 전환 시 노드 위치가 불안정하게 튀는 현상이 있습니다.
- **조치**: 각 뷰 모드(Mode)별 독립된 State를 가지도록 구조 개선이 필요합니다.

### 3순위: 클러스터 배치 및 엣지 연결
- **조치**: 1, 2순위가 정리된 후, 그래프 품질 자체가 안정화되면 최종적으로 커뮤니티(Cluster) 렌더링 스타일과 엣지 번들링(Edge Bundling)을 고도화합니다.
