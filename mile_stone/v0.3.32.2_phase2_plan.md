# [Goal Description]
현재 발생하는 "클러스터 경계 교차 및 중첩 현상"의 근본 원인을 제거하고, **Directory Zone 기반의 Packed Grid 배치**를 구현하여 그래프 렌더링을 완전히 정상화합니다.

주요 원인은 이전 단계에서 추가된 **LPA(Label Propagation Algorithm)**가 물리적 디렉토리(`folder_`) 구조를 파괴하고 의존성 기반의 `community_`로 `cluster_id`를 덮어씌웠기 때문입니다. 이로 인해 물리적으로 멀리 떨어진 노드들이 하나의 클러스터 박스로 묶이면서 거대한 중첩 바운딩 박스가 생성되었습니다.

이를 해결하기 위해 LPA 개입을 차단하고, 클러스터의 실제 노드 수에 비례하여 공간을 할당하는 Packing 알고리즘을 도입합니다.

## User Review Required
> [!IMPORTANT]
> - LPA(Community Detection) 기능은 `cluster_id`를 덮어씌우지 않고, 노드의 보조 데이터(`n.data.community`)로만 남겨두도록 강등시킵니다.
> - 클러스터 배치 순서를 역전시킵니다: **노드 수 기반 예상 면적 계산 -> 클러스터 간 패킹(Packing) -> 내부 노드 Grid 배치**

## Open Questions
- 클러스터 간 패킹을 할 때 단순 2D Grid(가장 큰 클러스터 기준 정렬)를 사용할지, 아니면 간단한 Bin Packing(가로로 채우다 넘어가기) 방식을 선호하시는지 피드백 부탁드립니다. (본 계획안에서는 구현이 직관적이고 안정적인 **Flow Layout 스타일의 Bin Packing**을 기본으로 제안합니다.)

## Proposed Changes

### DataPipeline.ts

#### [MODIFY] `src/core/DataPipeline.ts`
- **LPA 강등**: Phase 4의 LPA 로직이 `clusters` 배열을 갈아엎고 노드의 `cluster_id`를 변경하는 부분을 삭제합니다. 대신 `n.data.community_label`에 결과만 주입합니다.
- **클러스터 면적 추정**: `folderClusters` (Active 상태인 것만) 각각이 보유한 노드 수(`nodeCount`)를 바탕으로 `cols = Math.ceil(Math.sqrt(nodeCount))`를 구해 클러스터의 논리적 `width`, `height`를 계산합니다.
- **Packed Layout 알고리즘**:
  - 클러스터들을 면적(또는 노드 수) 내림차순으로 정렬합니다.
  - X축 방향으로 배치해 나가며, 설정된 최대 폭(Max Width)을 초과하면 다음 줄(Y축)로 줄바꿈하여 클러스터의 `centerX, centerY`를 할당합니다.
- **노드 Grid 배치**: 할당된 클러스터 중심점 내부에서 노드들을 정사각형 형태의 Grid로 배치하고 약간의 Jitter를 주입합니다.
- **진단 로그 (Phase 1)**: 파이프라인 마지막에 보스가 요청하신 `[CLUSTER] id, nodes, center, bbox, overlap` 로그를 계산하여 출력하는 로직을 삽입합니다.
