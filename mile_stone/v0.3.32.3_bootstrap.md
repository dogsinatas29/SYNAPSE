# 🚀 LLM Coding Principles

## 1. Think Before Coding

* 추측하지 않는다.
* 요구사항이 모호하면 즉시 질문한다.
* 접근 방식과 트레이드오프를 먼저 제시한다.
* 항상 가장 단순한 해결책부터 제안한다.

---

## 2. Simplicity First

* 최소한의 코드만 작성한다.
* 요청되지 않은 기능을 추가하지 않는다.
* 요청되지 않은 추상화를 추가하지 않는다.
* 가독성과 유지보수성을 우선한다.

---

## 3. Minimal Changes

* 전체 재작성을 금지한다.
* 필요한 부분만 수정한다.
* 기존 스타일을 유지한다.
* 이미 검증된 코드는 보호한다.

---

## 4. Goal-Oriented Execution

반드시 아래 순서를 따른다.

```text
목표
 ↓
계획
 ↓
구현
 ↓
검증
```

---

## 5. No Hallucinated APIs

* 존재하지 않는 API 생성 금지
* 존재 여부가 불명확하면 확인 후 진행
* 추측 구현 금지

---

## 6. Stable Code Protection

* 검증된 코드 수정 최소화
* 요청 범위 외 수정 금지
* 가능하면 Diff 기준 작업

---

## 7. Context Confirmation

* 수정 전 관련 파일 확인
* 구조를 추측하지 않는다
* 필요한 파일이 없으면 요청한다

---

## 8. Rendering Isolation

뷰 전환 시 렌더링 상태를 초기화한다.

대상:

```text
Graph View
File View
Flow View
```

WebGL 상태 오염 금지.

---

## 9. Approval First

* 작업 시작 전 계획 제출
* 승인 후 구현
* 문서에 없는 작업 금지
* 임의 문서 생성 금지

---

## 10. Regression First

수정 전 현재 상태를 기록한다.

```text
Node Count
Edge Count
Ghost Count
Cluster Count
```

기준값 확보 전 구현 금지.

---

## 11. One Responsibility Per Task

허용

```text
Resolver 분리
↓
검증
↓
완료
```

금지

```text
Resolver 분리
+
Mutation 분리
+
UI 수정
```

---

## 12. No Opportunistic Refactoring

금지

```text
김에 이것도 수정
김에 이것도 정리
```

범위 외 발견 사항은 보고만 한다.

---

## 13. Existing Behavior Wins

문서보다 실제 동작을 우선한다.

문서와 구현이 다르면 즉시 중단 후 보고한다.

---

## 14. Interface Before Migration

순서

```text
Interface 작성
 ↓
컴파일 확인
 ↓
구현 이동
 ↓
검증
```

반대 순서 금지.

---

## 15. Two-Step Verification

### 1차 검증

```text

Unit Test
```

### 2차 검증

```text

```

## 16. Scope Lock

승인된 범위 외 수정 금지.

새 의존성 발견 시 즉시 보고.

# Regression Stop Condition

다음 조건 중 하나라도 발생하면 즉시 작업을 중단한다.

## Critical Stop (즉시 중단)

```text
Node Count 변화 발생
Edge Count 변화 발생
Ghost Count 변화 발생
Cluster Count 변화 발생

Root Cluster (__unclustered__) 소실
cluster_ghost_network_remote 소실

Buffer → Reserved 승격 실패
Snapshot Save 실패
Snapshot Restore 실패

Compile Error 발생 (tsc --noEmit 실패)
Webpack Build 실패
```

## Warning Stop (보고 후 계속 여부 결정)

```text
UNKNOWN Ownership 항목 발견
기존 함수 시그니처 변경 필요
새 의존성 추가 필요
인터페이스 불일치 발견
```

발생 시:

```text
1. 작업 즉시 중단
2. 원인 보고 (Architecture Report)
3. 수정안 제출
4. 승인 후 재개
```
