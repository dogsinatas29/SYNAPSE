# Language Layer Ownership Matrix

## Frontend — Language Scanners

Frontend는 언어별 파서(Scanner)를 플러그인 형태로 보유한다.

```text
Frontend
 ├─ PythonScanner       (.py)
 ├─ JsTsScanner         (.ts, .js, .tsx, .jsx)
 ├─ CppScanner          (.cpp, .c, .h, .hpp, .cc)
 ├─ RustScanner         (.rs)
 ├─ ShellScanner        (.sh)
 ├─ SqlScanner          (.sql)
 ├─ ConfigScanner       (.json, .yaml, .yml, .toml)
 ├─ MarkdownScanner     (.md)
 ├─ JavaScanner         (.java)
 └─ KotlinScanner       (.kt, .kts)
```

각 Scanner의 책임:

```text
- 클래스/함수/심볼 추출
- 의존성(imports/includes/uses) 추출
- 패키지명 추출 (해당 언어만)
- Sovereignty Signature 탐지
```

공통 출력 형식:

```text
CodeSummary {
    classes: string[]
    functions: string[]
    references: { target, type, fullPath? }[]
    package?: string
    hasAtomicSignature: boolean
    hasImportSignature: boolean
}
```

새 언어 추가 시 기존 Scanner 수정 금지. 새 Scanner 추가만 허용.

---

## Resolver — Language Classifiers

Resolver는 Frontend가 추출한 DependencyFact를 해석한다.

```text
Resolver
 ├─ GhostRule Engine        (packagePrefix, exact blacklist)
 ├─ External Package DB     (EXTERNAL_PACKAGES Set)
 ├─ Reference Resolver      (resolveReference)
 └─ Network Link Resolver   ([SYNAPSE_NETWORK_LINK])
```

Resolver의 책임:

```text
- Ghost 판별 (external vs internal)
- External Package 판별
- Workspace Link 판별
- Reference → 실제 파일 경로 해석
```

Resolver는 언어를 알지 못한다. 오직 DependencyFact와 CodeSummary만 소비한다.

---

## Resolver — Language Reference Patterns

Resolver는 언어별 참조 패턴을 해석하여 DependencyFact를 Classification한다.

### TypeScript / JavaScript (.ts, .js, .tsx, .jsx)

```text
Frontend 추출:
  import X from 'Y'
  require('Y')
  import('Y')  (dynamic)

Resolver 판별:
  target이 node_modules → THIRD_PARTY (EXTERNAL_PACKAGES 확인)
  target이 상대 경로   → LOCAL (파일 존재 확인)
  target이 절대 경로   → LOCAL 또는 GHOST
  target이 builtin     → STDLIB (fs, path, os 등)
```

### Python (.py)

```text
Frontend 추출:
  import X
  from Y import Z

Resolver 판별:
  target이 stdlib 모듈   → STDLIB (os, sys, json 등)
  target이 pip 패키지    → THIRD_PARTY (requests, flask 등)
  target이 로컬 모듈     → LOCAL (파일 존재 확인)
  target이 상대 import   → LOCAL (경로 해석)
```

### Rust (.rs)

```text
Frontend 추출:
  use crate::X
  use X::Y
  mod Z
  extern crate W

Resolver 판별:
  target이 std/core/alloc → STDLIB
  target이 crate::        → LOCAL (모듈 경로 해석)
  target이 외부 crate     → THIRD_PARTY (Cargo.toml 기준)
  target이 mod            → LOCAL (파일 존재 확인)
```

### Java (.java)

```text
Frontend 추출:
  package X
  import Y.Z

Resolver 판별:
  target이 java./javax.   → STDLIB
  target이 org./com.      → THIRD_PARTY (EXTERNAL_PACKAGES 확인)
  target이 로컬 패키지     → LOCAL (파일 존재 확인)
```

### Kotlin (.kt, .kts)

```text
Frontend 추출:
  package X
  import Y.Z

Resolver 판별:
  target이 kotlin.        → STDLIB
  target이 java./javax.   → STDLIB
  target이 org./com.      → THIRD_PARTY (EXTERNAL_PACKAGES 확인)
  target이 로컬 패키지     → LOCAL (파일 존재 확인)
```

### C/C++ (.cpp, .c, .h, .hpp, .cc)

```text
Frontend 추출:
  #include "X"
  #include <Y>

Resolver 판별:
  target이 <> (시스템)    → STDLIB (iostream, vector 등)
  target이 "" (로컬)      → LOCAL (파일 존재 확인)
  target이 외부 라이브러리 → THIRD_PARTY
```

### Shell (.sh)

```text
Frontend 추출:
  source X
  . X
  bash X

Resolver 판별:
  target이 상대 경로      → LOCAL
  target이 절대 경로      → LOCAL
  external reference 없음
```

### SQL (.sql)

```text
Frontend 추출:
  CREATE TABLE
  참조 패턴 없음

Resolver 판별:
  external reference 없음
  Ghost 생성 안 함
```

### Markdown (.md)

```text
Frontend 추출:
  [text](path)
  file:// links

Resolver 판별:
  target이 외부 URL       → 무시 (http://, https://)
  target이 상대 경로      → LOCAL (파일 존재 확인)
  target이 존재 안 함     → GHOST
```

# Migration Boundary Rules

## Rule 1

---

## Rule 4
