# Final Mission

v0.3.32.4의 목표는 성능 최적화가 아니다.

사용자가 대규모 그래프에서 원하는 영역을 빠르게 발견하고 탐색할 수 있도록 하는 것이다.

이 마일스톤은 Visibility State를 제공한다.

v0.3.33은 그 Visibility State를 이용해 Materialization과 Virtualization을 수행한다.

따라서 v0.3.32.4는 탐색 UX를 완성하고, v0.3.33은 성능 아키텍처를 완성한다.

## 📝 Post-Work Log (작업 후 기록)

### 1. Logic Edit Mode 설정 동기화 패치 (Hotfix)
- **발생 원인**: 확장 프로그램 업데이트 후 VS Code 윈도우가 리로드되지 않아 `synapse.editLogicMode` 구성이 등록되지 않은 상태일 때, UI에서 **Edit Logic: ON**을 켜도 백엔드 설정(`settings.json`) 쓰기에 실패하는 치명적 에러(`Unable to write to User Settings`) 발생. 이로 인해 백엔드(`CanvasPanel.ts`)에서는 해당 모드를 계속 `false`로 인식하여, 엣지를 연결해도 실제 물리적 파일(`EdgeCodeRefactorer` 로직)에 `import` 문이 생성되지 않는 현상이 있었습니다.
- **해결 로직**: 
  - `CanvasPanel.ts`의 `setEditLogicMode` IPC 수신부에서 전역 설정 쓰기가 실패(Exception)하더라도, 현재 세션 동안 사용할 수 있는 **메모리 기반 Fallback 변수**(`(this as any)._isEditLogicMode`)를 설정하도록 긴급 패치했습니다.
  - `handleCreateManualEdge`, `handleDeleteEdge` 시 설정값을 조회할 때 해당 Fallback 변수도 함께 체크하도록 개선하여 에러가 발생한 세션에서도 파일 주입 로직이 정상 동작하도록 조치했습니다.
- **아키텍처 부채 기록**: 현재 엣지 연결에 따른 물리적 파일 변경(`EdgeCodeRefactorer` 호출)과 초기 UI 렌더링이 `CanvasPanel.ts`와 `canvas-engine.js`에 파편화되어 있습니다. 이는 차기 마일스톤에서 `ExecutionLayer` 및 `StateManager`의 Intent(`CONNECT_EDGE`) 파이프라인 내부로 통합(SSOT)되어야 합니다.

### 2. Edge Connection/Disconnection SSoT 및 트랜잭션 파이프라인 리팩터링
- **문제 인식**: 기존 엣지 생성 및 삭제 로직이 UI 레이어(`canvas-engine.js`)에서 낙관적 업데이트(`edges.push`, `edges.splice`)로 먼저 그려지고, `CanvasPanel.ts`가 물리적 파일 조작 및 저장, 그래프 반영 등 지나치게 많은 책임(Fat Controller)을 지고 있어 트랜잭션 실패 시 상태 불일치(SSoT 위반)가 발생할 위험이 있었습니다.
- **아키텍처 분리 및 3원칙 적용**:
  1. **ExecutionLayer 오케스트레이션 제한**: `ExecutionLayer`가 `StateManager`를 직접 호출하지 못하게 하고, `CanvasEngine` 내부에서 트랜잭션(오류 감지 및 조기 중단)을 오케스트레이션하도록 설계했습니다.
  2. **Persistence 분리**: `StateManager`에서 파일 입출력 로직을 떼어내고 `CanvasPanel.ts`의 `handleSaveState` 호출(또는 SnapshotSystem 등 영속화 전담 모듈)을 이용해 처리하도록 명시했습니다.
  3. **트랜잭션(Transaction) 처리**: 의도(`CONNECT_EDGE`, `DELETE_EDGE`) 발생 시 파일 시스템(Import 추가/삭제)을 우선 조작하고 성공 시에만 메모리 그래프를 변이하도록 트랜잭션 순서를 엄격하게 지정했습니다.
- **수정 범위**:
  - `ExecutionLayer.ts`: 물리 변경을 전담하는 `connectEdge`와 `disconnectEdge` 메서드 신설.
  - `CanvasEngine.ts`: 의도(`CONNECT_EDGE`, `DELETE_EDGE`) 실행 파이프라인 내에 `ExecutionLayer` 호출 및 실패 시 예외 처리 적용.
  - `CanvasPanel.ts`: `handleCreateManualEdge`, `handleDeleteEdge`에 있던 Fat Controller 로직을 삭제하고 단순 Intent Dispatcher로 축소.
  - `ui/canvas-engine.js`: `createManualEdge`의 로컬 `this.edges.push()`를 삭제하고 의도 발생 메시지만 백엔드로 전송한 후, 백엔드의 정상 처리(Broadcast) 이후 UI가 갱신되도록 철저한 비동기 SSoT 흐름 적용.
