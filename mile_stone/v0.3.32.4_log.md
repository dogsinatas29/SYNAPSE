# v0.3.32.4 작업 로그 — Cluster Visibility & Navigation

## 목표

대규모 그래프에서 사용자가 원하는 클러스터 영역을 **빠르게 탐색·검색·제어**할 수 있도록 Cluster Visibility Panel을 제공한다.

```
탐색 → 검색 → 표시 제어 → 집중(Focus)
```

### 3. JS — `renderClusterVisibilityPanel(filterText)`

**파일:** `ui/canvas-engine.js`

- 기존 `this.clusters[]`의 `parent_id` 계층 구조를 파싱하여 Tree 렌더링
- 노드 수: `this.nodes[]` 순회 → `nodeCountMap` (O(N))
- 계층 구성: `childMap` (parent_id → children[])
- Search: `filterText`로 label/id 필터링. 서브트리에 매칭 항목 있으면 부모도 표시
- 각 행: 체크박스 + label + `(count)` + `→` Reveal 버튼

### 4. JS — `_clusterVisToggle(clusterId, visible)`

**재사용:** `cluster.collapsed` 필드 → 기존 Fold 렌더링 파이프라인 연동

```
체크박스 OFF
  → cluster.collapsed = true
  → Parent Propagation: 자식 클러스터 재귀적으로 collapsed = true
  → this.isGraphDataDirty = true
  → this.render()
  → this.saveState()
  → renderClusterVisibilityPanel() 재실행 (체크박스 동기화)
```

**Parent Propagation 규칙:**
- Parent OFF → Child 자동 OFF (cascade)
- Parent ON → Child는 개별 상태 유지 (전파 없음)

### 5. JS — `_clusterVisReveal(clusterId)`

```
해당 클러스터의 노드들 평균 위치 계산
  → offsetX = canvas.width/2 - avgX * scale
  → offsetY = canvas.height/2 - avgY * scale
  → render()
```

트리거:
- `→` 버튼 클릭
- 트리 행 더블클릭

### 6. 자동 갱신

`loadProjectState` 완료 후 패널이 열려있으면 `renderClusterVisibilityPanel('')` 자동 호출 → 노드 수, 상태 항상 최신 유지

## v0.3.32.4 → v0.3.33 연결 포인트

v0.3.32.4에서 생성한 `cluster.collapsed` Visibility State는
v0.3.33의 `MaterializationPolicy`에서 다음과 같이 활용된다:

```
cluster.collapsed === true
  → Density Mode: 해당 클러스터 Edge 전송 생략
  → Focus Mode: 해당 클러스터 노드 로드 생략
```

즉 이 패널의 체크박스가 v0.3.33 성능 최적화의 입력값이 된다.

### 실패 및 버그 수정

#### Parent Propagation 실패 (수정 완료)

**증상:** build-logic OFF 시 내부 convention 클러스터가 캔버스에서 사라지지 않음

**원인 분석:**
- `_clusterVisToggle`의 체크박스 cascade 자체는 정상 작동 (convention 체크박스 자동 해제 확인)
- 하지만 `renderClusters()` 루프에서 **부모 클러스터의 collapsed 여부를 확인하지 않음**
- 자식 클러스터는 독립적으로 그려지기 때문에, 부모가 collapsed여도 자식 클러스터 헤더가 렌더링됨
- 마찬가지로 노드 렌더링에서도 직접 소속 클러스터만 체크 (할아버지 클러스터는 미확인)

**수정 내용 (`ui/canvas-engine.js`):**

1. `renderClusters()` 루프 진입부에 조상 collapsed 체크 추가:
```js
// [v0.3.32.4] Build parent-collapsed lookup
const _collapsedParents = new Set();
const _isAncestorCollapsed = (c) => { /* 조상 traverse */ };
// 루프 내
if (_isAncestorCollapsed(cluster)) continue;
```

2. 노드 hit-test 및 노드 렌더링에서 조상 collapsed 체크 추가:
```js
if (cluster && cluster.parent_id) {
    // 조상 traverse → 하나라도 collapsed면 skip
}
```

#### Reveal 기능 설명 추가

**질문:** "어떤 항목 우측을 말하는건가?"

**답:** 트리 항목에 **마우스를 올리면** (hover) 우측에 `→` 버튼이 나타남. 클릭 시 해당 클러스터 평균 위치로 캔버스 이동. 더블클릭도 동일.

## 2차 개선 (2026-07-04 오후)

### 버그 수정: Reveal 무반응

**원인:** `_clusterVisReveal()`에서 잘못된 필드 참조
```js
// 수정 전 (버그)
this.offsetX = this.canvas.width / 2 - avgX * this.scale;   // ← 필드 없음
this.offsetY = ...

// 수정 후 (정상)
this.transform.offsetX = cw / 2 - avgX * this.transform.zoom;
this.transform.offsetY = ch / 2 - avgY * this.transform.zoom;
```

추가로 노드 좌표도 `n.x` → `n.position.x` 우선 사용으로 수정.

### 개선 1: 계층 구조 표시 (depth 기반 들여쓰기)

**변경:** 고정 CSS class(`.cv-child`, `.cv-grandchild`) → 동적 `padding-left: (8 + depth * 16)px`

```
Root (0)
└ build-logic (1)          ← 16px indent
  └ convention (2)         ← 32px indent
    └ .gradle (3)          ← 48px indent
```

`depth` 인자를 재귀 함수에 전달하여 무한 계층 지원.
`└ ` prefix는 depth > 0 인 경우에만 표시.

### 개선 2: 검색 결과 계층 표시

부모가 검색어에 매칭되지 않아도 자식에 매칭 항목이 있으면 부모를 표시 (기존 동작 유지).
매칭되지 않은 부모는 `opacity: 0.45`로 구분.
계층 들여쓰기는 검색 결과에서도 그대로 유지 → 어느 클러스터 하위인지 즉시 파악 가능.

### 개선 3: 검색 시 자동 카메라 이동

검색어 입력 시 **첫 번째 매칭 클러스터**로 자동 `_clusterVisReveal()` 호출.

```
"build" 입력 → build-logic 클러스터 위치로 즉시 이동
"conv"  입력 → convention 클러스터 위치로 즉시 이동
```

## Reveal 버그 3차 수정 (2026-07-04 저녁)

**근본 원인 재분석:**
`fitView()` 공식과 비교하여 두 가지 오류 발견:

| 항목 | 오류 코드 | 수정 코드 |
|---|---|---|
| 캔버스 크기 기준 | `canvas.width` (물리 픽셀) | `canvas.clientWidth` (CSS 픽셀) |
| 렌더 호출 | `this.render()` | `this.isDirty = true; this.requestRender()` |
| 중앙 공식 | `cw/2 - avgX * zoom` (단순 중점) | `(clientWidth - w*zoom)/2 - minX*zoom` (fitView 동일) |

**수정된 코드:**
```js
// 클러스터 노드 bbox 계산 후 fitView 공식으로 중앙 이동
this.transform.offsetX = (this.canvas.clientWidth  - w * zoom) / 2 - minX * zoom;
this.transform.offsetY = (this.canvas.clientHeight - h * zoom) / 2 - minY * zoom;
this.isDirty = true;
this.requestRender();
```

## 4차 수정 — 프론트엔드 계층 추론 (2026-07-04 심야)

### 버그 분석: 백엔드 `parent_id` 누락

Java/Android 프로젝트 분석 시 백엔드가 `cluster.parent_id`를 보내지 않음.
클러스터 ID는 패키지 경로나 폴더 경로의 변형(`de.danoeh...` 또는 `cluster_app_src_...`)으로 생성됨.

### 해결: Frontend Hierarchy Inference

`canvas-engine.js`의 `loadProjectState` 단계에 **계층 자동 추론 로직**을 주입.

**알고리즘:**
1. `this.clusters`를 순회하며 `parent_id`가 없는 클러스터 탐색
2. 다른 모든 클러스터(`pid`)와 비교
3. `c.id`가 `pid` + 구분자 (`_`, `/`, `.`, `\`) 로 시작하는지 검사
   - 예: `ui.chapters` 는 `ui` + `.` 으로 시작하므로 부모.
   - 예: `cluster_ui_chapters` 는 `cluster_ui` + `_` 로 시작하므로 부모.
4. 매칭되는 부모 중 **가장 길이가 긴 것**을 직계 부모(`bestParentId`)로 확정
5. `c.parent_id = bestParentId` 강제 할당

**기대 효과:**
- 백엔드 수정 없이 **모든 프로젝트(Rust, Java, Python 등)**의 클러스터 계층 구조 즉시 복구.
- `ui` 폴더 하위의 `chapters`, `common` 등이 패널에서 들여쓰기 됨.
- `ui` 체크박스 OFF 시 하위 폴더 캔버스에서 모두 사라짐 (Cascade 복구).

## 5차 수정 — 가상 클러스터 생성 및 검색 기호 무시 (2026-07-04 심야)

### 버그 현상 및 원인 분석
1. **`ui`가 검색에 안 나오는 현상:**
   - 백엔드는 폴더 내에 "직접적으로 포함된 파일"이 있을 때만 클러스터를 생성함.
   - `ui` 폴더 자체에는 파일이 없고 서브 폴더(`app-start-intent`, `chapters` 등)만 있는 경우, 백엔드는 `ui` 클러스터를 생성하지 않음.
   - 따라서 프론트엔드에서 `parent_id`를 `ui`로 추론해도, 부모 역할을 할 실제 `ui` 클러스터 객체가 없어서 자식들이 모두 최상단 Root로 튀어나옴.

2. **`app-start-intent`가 검색 안 되는 현상:**
   - Java 프로젝트의 패키지명(예: `appstartintent`)으로 클러스터 ID가 생성되어 기호(`-`, `_`)가 유실됨.
   - 검색어에 `-`가 포함되어 있으면 완전히 다른 문자열로 인식해 매칭 실패.

### 해결 적용 내용
1. **가상 부모 클러스터(Virtual Clusters) 동적 생성 로직 추가:**
   - 프론트엔드가 ID 패턴을 분석하다가 "부모 ID"는 찾았는데 해당 ID를 가진 클러스터가 존재하지 않으면, **프론트엔드 단독으로 빈 가상 클러스터를 생성**함. (예: `cluster_ui` 강제 생성)
   - 이제 `ui` 클러스터가 검색 결과와 캔버스 트리에 정상적으로 나타나며, 하위 폴더들을 감싸는 부모 역할을 수행함.

2. **검색 시 기호 무시 (Fuzzy Match):**
   - 검색어(`q`)와 대상 문자열(`label`, `id`)에서 `-`와 `_`를 모두 제거하고 비교하도록 검색 로직 수정.
   - 이제 `app-start-intent` 로 검색해도 `appstartintent` 를 정상적으로 찾아냄.

## 6차 수정 — 결정론적 아키텍처 복구 및 UI 고도화 (Phase 1 & Phase 2)

### 버그 분석: 프론트엔드 환각(Hallucination) 렌더링
앞서 도입된 `Frontend Hierarchy Inference`가 `folder_src`나 `__unclustered__` 같은 백엔드 ID를 `_` 기준으로 무조건 분리하여 가상의 부모(`folder`, `cluster___unclustered_`)를 만들어내는 치명적인 문제를 야기함. 이는 SYNAPSE의 **결정론적 아키텍처(백엔드 데이터 = 프론트엔드 렌더링)** 철학을 정면으로 위반함.

### 해결 적용 내용 (Phase 1 & Phase 2)

1. **프론트엔드 추론 로직 완전 제거 (Phase 1)**
   - `canvas-engine.js`에서 ID를 `split`하여 부모를 추측하던 로직(`Frontend Hierarchy Inference`)을 완전히 삭제함.
   - 더 이상 유령 클러스터(`folder`, `cluster___unclustered_`)가 렌더링되지 않음.

2. **백엔드 `parent_id` 명시적 지원 (Phase 2)**
   - `RemoteLayerProjector.ts`에서 폴더 경로를 분석하여 `parent_id`를 스스로 계산하고 할당하도록 수정.
   - `ClassifiedCluster`에 `parent_id`와 `type`(`folder`, `system`, `external`) 정보를 정확히 담아 프론트엔드로 전송함.

3. **상태 복원형 가시성 제어 (State-Preserving Visibility)**
   - 기존의 `cascade` 방식(부모를 끄면 자식의 체크박스 상태 자체를 강제 초기화)을 제거함.
   - 자식의 체크박스 상태는 그대로 유지한 채, 렌더링 로직(`_collapsedParents` 활용)에서 부모가 OFF일 때 자식을 물리적으로만 숨기도록 변경.
   - 부모를 다시 ON으로 켜면, 자식들의 세밀한 필터링 세팅이 완벽히 복원됨.

4. **Expand/Collapse 및 Click-to-Reveal 텍스트 네비게이션**
   - 자식이 있는 클러스터의 좌측에 `▼`/`▶` 토글(접기/펼치기) UI를 추가함.
   - 패널의 **클러스터 텍스트 라벨 영역을 클릭**하면 해당 클러스터 뷰로 즉시 카메라가 이동(`_clusterVisReveal`)하도록 이벤트를 개선하여, 수백 개의 클러스터 환경에서도 강력한 탐색 도구로 활용할 수 있도록 함.
   - `__unclustered__` 시스템 클러스터의 라벨을 직관적인 `📁 Project Root`로 변경함.
