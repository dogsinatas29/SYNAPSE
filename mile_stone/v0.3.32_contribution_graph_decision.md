# SYNAPSE v0.3.32

## Contribution Entity Graph Decision

ADR (Architecture Decision Record)

---

# Problem

CompareResult와 HarvestCandidate 사이의 관계를 어떻게 표현할 것인가?

현재 확인된 런타임 구조:

```
POST /api/harvest/compare
    ↓
CompareResult[] (서버 → 클라이언트)

Architect UI 선택 (클라이언트)

    ↓
HarvestCandidate[] (클라이언트 → 서버)
POST /api/harvest/execute
```

서버 코드에는 CompareResult → HarvestCandidate 변환이 없다.
변환은 클라이언트(UI)에서 발생한다.

---

# Decision Criteria

| # | Criteria | Definition |
|---|----------|------------|
| 1 | **Audit Consistency** | 감사(Audit) 결과와 일치하는가 |
| 2 | **Runtime Fidelity** | 실제 런타임 객체를 사용하는가 |
| 3 | **Flow Completeness** | Flow View로 표현 가능한가 |
| 4 | **Projection Simplicity** | 기존 구조 변경 없이 투영 가능한가 |

---

# Options

## Option A — Runtime Object Projection

```
CompareResult
HarvestCandidate
```

Entity만 표시하고 관계는 표현하지 않는다.

- Audit Consistency: 100%
- Runtime Fidelity: 100%
- Flow Completeness: 낮음 (Entity Listing)
- Projection Simplicity: 높음

## Option B — Runtime Entity Relationship Projection

```
CompareResult
    ↓ (derived_from)
HarvestCandidate
```

두 객체 사이의 계보(Lineage) 관계를 표현한다.

Edge는 "Architect Selection"이 아니라 "derived_from" 의미.

- Audit Consistency: 높음
- Runtime Fidelity: 높음 (두 객체 모두 실존)
- Flow Completeness: 중간 (최소한의 Flow)
- Projection Simplicity: 높음

## Option C — Conceptual Workflow Projection

```
CompareResult
    ↓
Architect Selection
    ↓
HarvestCandidate
```

사용자 의사결정을 노드/엣지로 모델링한다.

- Audit Consistency: 낮음 (추론 객체)
- Runtime Fidelity: 낮음 (Architect Selection은 런타임 객체 아님)
- Flow Completeness: 높음
- Projection Simplicity: 중간

---

# Evaluation

| Criteria | Option A | Option B | Option C |
|----------|----------|----------|----------|
| Audit Consistency | 높음 | 높음 | 낮음 |
| Runtime Fidelity | 높음 | 높음 | 낮음 |
| Flow Completeness | 낮음 | 중간 | 높음 |
| Projection Simplicity | 높음 | 높음 | 중간 |

---

# Decision

**Option B를 선택한다.**

Flow View projects runtime entity lineage, not workflow semantics.

The graph represents relationships between runtime entities that can be observed in code.

User actions and workflow concepts are not modeled unless they exist as runtime objects.

## Reasoning

1. 두 객체 모두 런타임에서 실존
2. 동일 `(filePath, userId)`를 공유하며 하나의 Contribution을 나타냄
3. 서버 내부 변환이 아니지만, 두 API 응답/요청 사이의 관계는 실재
4. "Architect Selection"은 객체도 아니고 상태도 아니며 이벤트 기록도 없음
5. "Observe, Not Invent" 원칙 유지

# Consequences

## Entity Structure

```typescript
interface ContributionNode {
    kind: 'compared' | 'harvested';
    filePath: string;
    userId: string;
}
```

## Edge Structure

```typescript
interface ContributionEdge {
    from: ContributionNodeId;
    to: ContributionNodeId;
    relation: 'derived_from';
}
```

## Edge 의미

`derived_from`는 다음을 의미한다:

- HarvestCandidate was derived from CompareResult
- 동일 `(filePath, userId)`를 공유한다
- 객체 간 계보(Lineage)를 표현한다

`derived_from`는 다음을 의미하지 않는다:

- Architect selected this (행위)
- 서버 내부 상태 전이 (워크플로우)
- 자동 변환 (프로세스)
- 런타임 이벤트 (이벤트)

## Excluded from Graph

| Concept | Reason |
|---------|--------|
| ArchitectSelectionNode | 런타임 객체 아님 |
| ApprovalState | 런타임 상태 아님 |
| WorkflowStep | 추론된 개념 |
| Contribution Lifecycle State | 증명되지 않음 |
