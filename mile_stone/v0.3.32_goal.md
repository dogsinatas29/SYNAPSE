# SYNAPSE v0.3.32

## Contribution Entity Relationship Visualization

---

# Objective

v0.3.31에서 클라이언트 노드에 대한 Virtual Debugger 적용을 완성함으로써,
서버는 더 이상 단순한 그래프 집계기(Aggregator)가 아니라
분산 그래프를 이해할 수 있는 분석 엔진으로 진화한다.

v0.3.32의 목표는 **Compare Domain과 Harvest Domain 사이의 Contribution Entity Relationship을 시각화**하는 것이다.

본 버전은 동기화(Synchronization)를 구현하지 않는다.

본 버전은 새 그래프 엔진을 구축하지 않는다.

본 버전은 **기존 런타임 메타데이터를 Flow View로 투영(Projection)** 한다.

---

# Philosophy

## Observe, Not Invent

v0.3.32는 추론된 구조를 만드는 것이 아니라,
런타임에서 관측 가능한 객체와 관계를 시각화한다.

## Entity Relationship, Not Lifecycle

Flow View는 Lifecycle 상태 전이를 보여주는 것이 아니다.

Flow View는 런타임 엔티티 간의 계보(Lineage) 관계를 보여주는 것이다.

# Code Audit Findings

## Dead Code (v0.3.32에서 제외)

| Component | Status | Reason |
|-----------|--------|--------|
| `SubmissionSnapshot` | Dead Code | 인터페이스만 존재, 생성자 없음 |
| `RemoteLayerProjector` | Dead Code | `project()` 호출자 없음 |
| `SubmissionManager` | Dead Code | 파일 자체 미존재 |

## Active Code (v0.3.32 투영 대상)

| Component | Status | Runtime Evidence |
|-----------|--------|------------------|
| `CompareEngine` | Active | SSE 해시 요청 → 마스터↔클라이언트 비교 → CompareResult[] |
| `HarvestEngine` | Active | SSE 파일 요청 → `.synapse/clients/` 복사 → HarvestResult |

## Actual Pipeline (코드 역추적 결과)

```
POST /api/client/push
    ↓ (clientPushData Map 저장 + 영속화)
    ↓ (Canvas 렌더링용, Contribution Graph 미참여)

POST /api/harvest/start
    ↓ hsm.startSession()
    ↓ state → Locked
    ↓ SSE broadcast: session_locked

POST /api/harvest/compare
    ↓ hsm.transitionState(Locked, Comparing)
    ↓ SSE: request_hashes → 클라이언트 해시 요청
    ↓ CompareEngine.compare() → CompareResult[] 생성
    ↓ hsm.transitionState(Comparing, Approving)

POST /api/harvest/execute
    ↓ hsm.transitionState(Approving, Executing)
    ↓ hsm.transitionState(Executing, Harvesting)
    ↓ SSE: send_file_content → 클라이언트 파일 요청
    ↓ HarvestEngine.harvest(candidates, requestClientFile)
    ↓ synapse_history.json → 스냅샷 기록
    ↓ SSE broadcast: session_unlocked
    ↓ hsm.unlockSession()
```

# Flow Subject

## Subject = Contribution Entity Relationship

Flow View가 보여주는 것은 Harvest Session도 아니고 Workspace도 아니다.

**Compare Domain과 Harvest Domain 사이의 Contribution Entity Relationship**을 시각화한다.

| Evidence | Support |
|----------|---------|
| CompareEngine 출력 | CompareResult[] (filePath, userId) ✅ |
| HarvestEngine 입력 | HarvestCandidate[] (filePath, userId) ✅ |
| 동일 Identity 공유 | (filePath, userId) ✅ |
| Goal 문서 | "클라이언트↔서버 경계를 넘는 실행 트리" ✅ |

## Why Not Others

| Candidate | Rejection Reason |
|-----------|------------------|
| Harvest Session | 상태 머신, Entity가 아님 |
| Action | 렌더링 결과물, 객체가 아님 |
| Workspace | 컨테이너, 실제 이동 객체가 아님 |
| Contribution Lifecycle | Lifecycle State 미증명 |

# Contribution Entity Graph

```
Compared (filePath, userId)
    ↓ (derived_from)
Harvested (filePath, userId)
```

## Entities

| Entity | Identity | Source |
|--------|----------|--------|
| **Compared** | `(filePath, userId)` | `CompareEngine.compare()` 출력 |
| **Harvested** | `(filePath, userId)` | `HarvestEngine.harvest()` 입력 |

## Relationship

| Relationship | Meaning |
|--------------|---------|
| **derived_from** | HarvestCandidate was derived from CompareResult |

### derived_from 의미

`derived_from`는 다음을 의미한다:

- HarvestCandidate was derived from CompareResult
- 동일 `(filePath, userId)`를 공유한다
- 객체 간 계보(Lineage)를 표현한다

`derived_from`는 다음을 의미하지 않는다:

- Architect selected this (행위)
- 서버 내부 상태 전이 (워크플로우)
- 자동 변환 (프로세스)

## Excluded from Graph

| Concept | Reason |
|---------|--------|
| Architect Selection | 런타임 객체 아님 |
| Discovered | Canvas Projection Event |
| Approved | 런타임 상태 아님 |
| Archived | Persistence Event |

# Projection Design

## Projection Source

```
CompareResult[] → Compared Node
HarvestCandidate[] → Harvested Node
동일 (filePath, userId) → derived_from Edge
```

## Projection Target

```
FlowRenderer.buildFlow() 입력:
- ContributionNode { kind: 'compared' | 'harvested', filePath, userId }
- ContributionEdge { from, to, relation: 'derived_from' }
```

## Excluded Projection

| Source | Reason |
|--------|--------|
| `clientPushData` | Canvas Rendering용, Flow Source 아님 |
| `History Snapshot` | Persistence Event |

# Phase Architecture

## Phase 1 — Contribution Entity Catalog

목표: Contribution Entity를 Flow View가 이해할 수 있는 정식 Entity 집합으로 고정

산출물:
```ts
interface ContributionNode {
    kind: 'compared' | 'harvested';
    filePath: string;
    userId: string;
}

interface ContributionEdge {
    from: ContributionNodeId;
    to: ContributionNodeId;
    relation: 'derived_from';
}
```

검증:
- 모든 Entity가 실제 런타임 근거를 가짐
- 추론 Entity 없음
- dead code 의존 없음

---

## Phase 2 — Compare Domain Projection

목표: CompareResult를 Compared Node로 변환

```
CompareResult[]
    ↓
ContributionNode[] { kind: 'compared', filePath, userId }
```

검증:
- CompareEngine.compare() 출력과 1:1 대응
- (filePath, userId) Identity 보존

---

## Phase 3 — Harvest Domain Projection

목표: HarvestCandidate를 Harvested Node로 변환

```
HarvestCandidate[]
    ↓
ContributionNode[] { kind: 'harvested', filePath, userId }
```

검증:
- HarvestEngine.harvest() 입력과 1:1 대응
- (filePath, userId) Identity 보존

---

## Phase 4 — Contribution Edge Generation

목표: 동일 (filePath, userId)를 공유하는 Compared Node와 Harvested Node를 derived_from Edge로 연결

```
동일 (filePath, userId)를 공유하는 CompareResult와 HarvestCandidate
    ↓
ContributionEdge { from: comparedId, to: harvestedId, relation: 'derived_from' }
```

검증:
- 같은 (filePath, userId)를 가진 Compared Node와 Harvested Node를 연결
- Edge는 계보(Lineage) 관계를 표현

---

## Phase 5 — FlowRenderer Integration

목표: 기존 buildFlow() 확장

현재: File Dependency Flow
추가: Contribution Entity Relationship Flow

검증:
- 기존 Flow View 깨지지 않음
- Contribution View 생성 가능
- 기존 Dependency Flow 성능 저하 없음

---

# Non Goals

본 버전에서 구현하지 않는다.

* File Synchronization
* Auto Merge
* Conflict Resolution
* Git Replacement
* Shared Editing
* New Graph Engine
* Protocol Visualization (SSE/REST 내부 표현)
* Lifecycle Visualization (상태 전이 시각화)
* Workflow Visualization (워크플로우 시각화)

---

# Success Criteria

다음이 모두 가능해야 한다.

1. CompareResult를 수집할 수 있다
2. Compared Node를 생성할 수 있다
3. HarvestCandidate를 Harvested Node로 변환할 수 있다
4. 동일 (filePath, userId)를 공유하는 Node를 derived_from Edge로 연결할 수 있다
5. Contribution Entity Relationship을 Flow View로 렌더링할 수 있다
6. 기존 Dependency Flow를 깨지 않는다
