# v0.3.33.1 — Architecture Focus LOD

---

# Goal

v0.3.33.1의 목표는 단순한 렌더링 최적화가 아니다.

본 버전의 목표는 Synapse에 계층적 LOD(Hierarchical Level of Detail)를 도입하여 대규모 소프트웨어 아키텍처를 효과적으로 탐색할 수 있도록 만드는 것이다.

이를 통해 사용자는 프로젝트의 전체 구조를 잃지 않으면서 특정 영역을 점진적으로 확대하여 관찰할 수 있다.

---

# Synapse의 정체성

본 기능을 설계하기 전에 Synapse가 어떤 도구인지 먼저 정의해야 한다.

---

Synapse는

```text
파일 탐색기(File Explorer)
```

가 아니다.

---

Synapse는

```text
Dependency Graph Viewer
```

도 아니다.

---

Synapse는

```text
소프트웨어 아키텍처를 이해하기 위한 도구
```

이다.

---

아키텍트가 궁금한 것은

```text
어떤 파일이 어떤 파일을 참조하는가
```

가 아니다.

---

아키텍트가 궁금한 것은

```text
시스템은 어떤 구조로 이루어져 있는가

어떤 모듈이 핵심인가

어떤 영역이 강하게 결합되어 있는가

어떤 경계가 존재하는가

어떤 의존성 흐름이 형성되어 있는가
```

이다.

---

따라서 Synapse의 목적은

```text
Dependency Visualization
```

이 아니라

```text
Architectural Comprehension
```

이다.

---

# Architecture Telescope

Synapse는 현미경(Microscope)이 아니다.

---

현미경 모델

```text
Project
 ↓
Folder
 ↓
File
 ↓
Function
```

끝없이 내려간다.

---

이 방식은 전체 구조를 잃어버린다.

---

Synapse는 단순한 망원경(Telescope)도 아니다.

---

망원경 모델

```text
Project
 ├ Core
 ├ Protocol
 ├ UI
```

전체 구조만 보여준다.

---

이 방식은 세부 원인을 파악할 수 없다.

---

Synapse는

```text
Architecture Telescope
```

를 지향한다.

---

즉

```text
전체 구조를 유지하면서

특정 영역을 확대할 수 있어야 한다.
```

---

# Focus + Context

v0.3.33.1의 최상위 설계 원칙이다.

---

사용자는 항상

```text
현재 시스템이 전체 구조에서 어디에 위치하는가
```

를 알 수 있어야 한다.

---

동시에

```text
특정 영역을 상세하게 분석할 수 있어야 한다.
```

---

즉

```text
Context
+
Focus
```

를 동시에 유지한다.

---

예시

초기 상태

```text
Project

 ├ Core
 ├ Protocol
 ├ UI
 └ Test
```

---

Core 확대

```text
Project

 ├ Protocol
 ├ UI
 └ Test

 Core
   ├ Runtime
   ├ Graph
   └ Verify
```

---

사용자는

```text
Core의 내부 구조
```

와

```text
전체 프로젝트 구조
```

를 동시에 이해할 수 있어야 한다.

---

# 왜 Hierarchical LOD가 필요한가

대규모 프로젝트에서는 다음 문제가 발생한다.

---

예시

```text
10,000 Nodes

50,000 Edges
```

---

문제

```text
렌더링 부하

카메라 이동 비용

줌 비용

레이아웃 비용

구조 이해 난이도
```

---

현재는 모든 정보를 동시에 표시한다.

---

그러나 아키텍트는 특정 시점에

```text
현재 관심 있는 수준
```

만 이해하면 된다.

---

따라서 Synapse는

```text
현재 필요한 수준의 정보만 표시
```

하는 계층적 LOD를 도입한다.

---

# 계층 탐색의 목적

계층 탐색의 목적은

```text
파일까지 내려가는 것
```

이 아니다.

---

계층 탐색의 목적은

```text
현재 분석 중인 구조를

더 적절한 수준의 추상화로 표현하는 것
```

이다.

---

즉

```text
줌인
=
더 많은 정보
```

가 아니라

```text
줌인
=
더 구체적인 추상화
```

이다.

# Visibility 와 Hierarchy 분리

본 버전의 가장 중요한 기술적 원칙이다.

---

Visibility

```text
무엇을 렌더링할 것인가
```

---

Hierarchy

```text
무엇이 존재하는가
```

---

예

```text
Project
 ├ Core
 ├ UI
 ├ Protocol
 └ Test
```

---

사용자 설정

```text
Test = OFF
```

---

결과

Hierarchy

```text
Project
 ├ Core
 ├ UI
 ├ Protocol
 └ Test
```

---

Rendering

```text
Core
UI
Protocol
```

---

숨겨진 클러스터는 렌더링되지 않을 뿐 계층 구조에서는 제거되지 않는다.

---

# LOD와 Collapse

기존 Collapse

```text
내부 노드 숨김

내부 엣지 숨김

외부 엣지 숨김
```

---

기존 목적

```text
화면 정리
```

---

Hierarchical LOD에서는 의미가 달라진다.

---

LOD Collapse

```text
내부 노드 숨김

내부 엣지 숨김

집계 엣지(Aggregate Edge) 유지
```

---

즉

```text
클러스터는 닫혀 있어도

아키텍처 관계는 유지
```

되어야 한다.

---

# Aggregate Edge

Hierarchical LOD에서 필수 기능이다.

---

예

```text
a ∈ Core

z ∈ Protocol

a → z
```

존재

---

Core Collapse

Protocol Collapse

---

표시

```text
Core ─────► Protocol
```

---

개별 파일은 보이지 않는다.

---

그러나

```text
Core와 Protocol이 연결되어 있다
```

는 사실은 유지된다.

---

이것이 아키텍처 탐색에 필요한 정보이다.

---

# 동일 계층 연결

LOD는

```text
동일 계층의 모든 연결
```

을 표시하는 기능이 아니다.

---

LOD는

```text
현재 화면에 보이는 객체들 간의 관계
```

를 표시한다.

---

예

```text
core → protocol
```

이 존재

---

현재 화면

```text
src
test
```

---

결과

```text
src 내부 관계
```

는 상위 계층으로 승격하지 않는다.

---

반면

```text
core → test
```

가 존재하면

```text
src → test
```

를 표시한다.

---

이를 통해 Edge Explosion을 방지한다.

```

```
