# v0.3.33.1_add2 — Architecture Telescope 기술 리스크 및 검증 문서

---

# 목적

본 문서는 v0.3.33.1 Architecture Telescope 구현 과정에서 예상되는 기술적 리스크를 식별하고, 구현 이전에 반드시 검증해야 할 사항들을 정의한다.

본 문서는 구현 문서가 아니다.

또한 기능 명세 문서도 아니다.

본 문서는 다음을 판단하기 위해 존재한다.

```text
현재 Synapse 구조에서

Architecture Telescope가

실제로 구현 가능한가?
```

---

# 배경

초기 설계에서는 다음과 같이 판단하였다.

```text
Hierarchy Tree

LOD Resolver

Aggregate Edge
```

를 추가하면 계층적 LOD가 구현될 것으로 예상하였다.

---

그러나 설계 검토 과정에서 보다 근본적인 문제가 발견되었다.

```text
Focus + Context
```

구현은 단순한 계층 탐색 문제가 아니라

```text
Layout

Camera

Selection

Viewport

Cluster Expansion
```

전반에 영향을 주는 시스템 수준 변경이다.

---

# 핵심 발견

계층 구조 자체는 어렵지 않다.

---

예

```text
Project
 └ src
     └ core
         └ runtime
```

---

이 구조 생성은 기존 Cluster Builder 확장으로 해결 가능하다.

---

실제 난관은 다음이다.

```text
사용자가 Core를 확대했을 때

나머지 구조를 유지하면서

Core만 세분화할 수 있는가?
```

---

즉

```text
Hierarchy
```

보다

```text
Layout Stability
```

가 더 어려운 문제일 수 있다.

---

# 기술 리스크 분석

---

## Risk 1

Hierarchy Tree

위험도

```text
낮음
```

---

이유

기존 Cluster Builder 데이터 활용 가능

---

예상 작업

```text
부모

자식

깊이 정보 저장
```

---

## Risk 2

LOD Resolver

위험도

```text
중간
```

---

이유

현재 렌더링 그래프와

표시 그래프를 분리해야 함

---

예상 작업

```text
Graph

↓

Visible Graph
```

변환 계층 추가

---

## Risk 3

Aggregate Edge

위험도

```text
중간
```

---

이유

현재 파일 수준 Edge를

Cluster 수준 Edge로 집계해야 함

---

예상 작업

```text
File → File

↓

Cluster → Cluster
```

---

## Risk 4

Focus + Context Layout

위험도

```text
매우 높음
```

---

이유

Layout 엔진 자체에 영향을 줄 가능성이 있음

---

예

```text
Core
```

확장

↓

```text
Runtime
Graph
Verify
```

표시

---

동시에

```text
Protocol
UI
Test
```

위치는 유지

---

현재 레이아웃 엔진이

이를 지원하는지 불명

---

## Risk 5

Camera Stability

위험도

```text
높음
```

---

사용자가 확대 시

현재 위치를 잃으면 안 됨

---

검증 필요

```text
Expand

Collapse

LOD 전환
```

시 카메라 정책

# 현재 판단

현재 시점에서 가장 큰 기술적 리스크는

```text
Hierarchy
```

가 아니다.

---

가장 큰 리스크는

```text
Focus + Context Layout
```

이다.

---

따라서 v0.3.33.1 구현 이전에

현재 Synapse Layout 엔진의 동작 방식을 분석하고

부분 재배치(Local Layout Update)가 가능한지 검증해야 한다.

---

# 결론

Architecture Telescope 구현의 핵심은

```text
Hierarchy Tree
```

가 아니다.

---

또한

```text
Aggregate Edge
```

도 아니다.

---

실제 핵심은

```text
사용자가 전체 구조를 잃지 않으면서

특정 영역만 확대할 수 있는가
```

이다.

---

이를 위해서는

```text
Focus + Context

Layout Stability

Camera Stability
```

에 대한 별도 검증이 반드시 선행되어야 한다.

본 문서는 해당 검증을 위한 기술 리스크 관리 문서로 사용한다.
