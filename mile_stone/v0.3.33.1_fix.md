# Milestone v0.3.33.1_fix - Layout Bounds Calibration

## 목표
VSCode-main 등 거대 모노레포에서 노드 패킹(Grid)은 정상적으로 동작하나, 부모 클러스터(예: `agentHost/node`)의 면적이 실제 콘텐츠 대비 3~5배 이상 비정상적으로 비대해지는 **Cluster Bloating 현상**을 정밀 계측하고 원인을 제거한다.

## 핵심 가설 및 계측 항목
사용자의 정확한 지적에 따라 노드 간격(`120x80`)은 건드리지 않으며, 다음 두 가지 가설을 검증한다.

1. **Recursive Padding 누적 버그:** 
   - `childGridWidth` 등에 150px 패딩이 재귀적으로 합산되어 자식 폴더가 많을수록 부모 면적이 기하급수적으로 폭발하는지 여부 확인.
2. **Collapsed/Expanded 상태 비동기성:** 
   - UI에서는 `cluster.collapsed = true` 인 폴더를 작은 띠(`height: 30`)로 렌더링하는데, `layoutBottomUp` 알고리즘은 접힘 상태를 무시하고 **완전 전개된 면적(Full Expanded Area)**을 그대로 할당하여 거대한 빈 공간(Void)이 발생하는지 여부 확인.

## 계측 프로브(Probe) 삽입 내역
`canvas-engine.js`의 `layoutBottomUp` 알고리즘에 다음 계측 코드를 주입하여 VSCode Output에서 직접 데이터를 확인한다.
```js
console.log("[CLUSTER_BOUNDS_PROBE]", cluster.id, 
    "directNodes=", directNodes.length, 
    "childClusters=", children.length, 
    "wNodes=", wNodes, "hNodes=", hNodes,
    "childGridW=", childGridWidth, "childGridH=", childGridHeight,
    "totalWidth=", totalWidth, "totalHeight=", totalHeight,
    "ratio (Total/wNodes)=", ratio.toFixed(2));
```

이 계측 결과(`ratio`가 비정상적으로 튀는 클러스터)를 바탕으로, 클러스터의 실제 Content Box와 Bounding Box 간의 계산 오차를 교정할 예정이다.

## 📝 Post-Work Log (작업 후 기록)
- **v0.3.33.1_fix 계측 프로브 주입 (2026-07-16):**
  - `ui/canvas-engine.js` 내 `layoutBottomUp` 엔진에 `[CLUSTER_BOUNDS_PROBE]` 콘솔 출력 로직 추가.
  - 노드 간격(`120x80`)은 유지한 채로, 부모 클러스터의 면적이 자식 콘텐츠(`wNodes` 등) 대비 몇 배(`ratio`)로 부풀려지는지 추적.
- **거대 클러스터(Cluster Bloat) 원인 2가지 동시 타격 및 수술 완료:**
  - **원인 1 (Empty Cluster Bloat):** 파일이 없는 빈 껍데기 자식 폴더들이 기본 면적(`200x200` + 마진 `150`)을 점유하던 치명적 버그 수정. 빈 클러스터는 면적 `0x0` 반환 후 레이아웃에서 완전 배제.
  - **원인 2 (Collapsed/Expanded 비동기성):** 가장 핵심적인 원인이었던 접힌(Collapsed) 상태 무시 버그 완벽 수정. 
    - 수정 전: `agentHost/node` 안의 자식 폴더가 접혀있든 펴있든 모두 수천 픽셀의 **풀사이즈 확장 면적(Expanded Area)**을 요구하여 빈 공간 유발.
    - 수정 후: `cluster.collapsed` 상태를 `layoutBottomUp`이 직접 인지하고, 접힌 상태면 고정된 작은 크기(`250x60`)만 할당.
  - **Dynamic Layout Trigger 연동:** 유저가 캔버스에서 `[+]` / `[-]` 버튼 클릭 시 `distributeClustersHierarchically` 를 즉시 재호출하도록 하여, 폴더 확장/축소 시 빈 공간 없이 주변 클러스터들이 부드럽게 재배치되도록 구현 (Dynamic Reflow).

- **Edge Visibility Pipeline 복구 (Edge Budget Protection 해제):**
  - **문제 원인:** VSCode-main 로딩 시 전체 엣지 수(약 66,000개)가 하드코딩된 엣지 한계치(50,000개)를 초과하여, 렌더링 파이프라인(`renderEdges2D()`) 진입 즉시 엣지를 모두 버리고 강제 종료하던 방어 로직 발견.
  - **조치 사항:** 파이프라인 최상단의 `> 50000` 무조건 반환 로직을 제거하고, Spatial Hashing 뷰포트 컬링을 통해 가시 영역 내의 엣지만 능동적으로 렌더링하도록 개선. GPU 크래시 없이 거대 모노레포의 엣지망 출력 성공.
  - **진단 기능 추가:** 엣지가 증발하는 원인을 4단계로 추적할 수 있도록 렌더러 심층부에 핵심 프로브 로그 주입 (`[EDGE_STATS]`, `[BUNDLE_STATS]`, `[EDGE_MODE]`, `[ARC_DRAW]`).
- **UI 모드 복구:**
  - 엣지 뱃지 없이 선만 출력하는 `LINES (No Badges)` 옵션을 UI(`index.html`)에 부활시키고 상태 토글 이벤트 핸들러 복구.

## 릴리즈 노트 (Release Notes)
> 본 릴리즈 노트의 전문은 `release_note/v0.3.33.1_fix_release_notes.md`에 보관됩니다.

### 🌟 Highlights (주요 변경 사항)

#### 🚀 Edge Rendering Pipeline Optimization (엣지 렌더링 파이프라인 최적화)
- **[EN]** Removed the hard limit of 50,000 edges that was prematurely aborting the rendering pipeline. The renderer now intelligently culls edges using Spatial Hashing, enabling full architecture exploration even for massive monorepos like VSCode-main (66,000+ edges) without silent rendering failures.
- **[KR]** 렌더링 파이프라인 최상단에서 동작을 강제 중단시키던 50,000개 엣지 방어 로직(Hard Limit)을 제거했습니다. 이제 공간 해싱(Spatial Hashing) 기반의 뷰포트 컬링을 통해 화면에 보이는 엣지만 스마트하게 그려내며, VSCode-main과 같이 엣지가 66,000개 이상인 거대 모노레포에서도 엣지가 증발하는 현상 없이 완벽한 렌더링을 지원합니다.

#### 🔍 Edge Visibility Modes & Diagnostics (엣지 렌더링 모드 및 진단 도구 추가)
- **[EN]** Restored the `LINES (No Badges)` mode in the UI, allowing users to view physical edges without the clutter of edge labels.
- **[KR]** UI 메뉴에 엣지 라벨(뱃지) 없이 선만 깔끔하게 보여주는 `LINES (No Badges)` 가시성 모드를 성공적으로 부활시켰습니다.
- **[EN]** Injected critical telemetry probes (`[EDGE_STATS]`, `[BUNDLE_STATS]`, `[EDGE_MODE]`, `[ARC_DRAW]`) deep inside the rendering pipeline to strictly monitor culling efficiency, LOD behavior, line thickness, and dynamic transparency.
- **[KR]** 파이프라인 심층부에 4대 핵심 계측 프로브(`[EDGE_STATS]`, `[BUNDLE_STATS]`, `[EDGE_MODE]`, `[ARC_DRAW]`)를 주입하여 컬링 효율성, LOD 동작, 두께 산정 및 투명도 렌더링을 실시간으로 추적할 수 있도록 개선했습니다.

### 🛠️ Technical Details (기술적 세부 사항)
- **Edge Budget Protection Removed:** The pipeline no longer instantly skips processing for graphs with > 50,000 edges. It now relies completely on dynamic viewport bounds checking.
- **UI State Synchronization:** Re-wired the edge visibility HTML buttons (`btn-edge-vis-nobadge`) to synchronize perfectly with the WebGL & Canvas2D rendering core.
