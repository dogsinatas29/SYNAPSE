# 🚀 Implementation Plan: LOD Performance & Layout Hierarchy Fix (v2)

## 1. Goal Description
`vscode-main` 로드 시 발생하는 **O(E * D) 병목(프레임 5000ms+ 프리징)**과 **"Architecture Telescope" 계층 파괴(Cluster Rack 현상)**를 해결합니다. 추가 조사 결과, 동일한 패턴의 성능 병목과 계층 파괴 로직이 백엔드(Extension Host)와 렌더러(Webview) 전반에 걸쳐 광범위하게 복제되어 있음을 확인했습니다.

## 2. Root Cause Analysis (추가 조사 결과)

### 1) O(E * D) 병목의 백엔드 복제 발견 (`VisibleGraphResolver.ts`)
`ui/canvas-engine.js`에 존재하는 O(N^2) 엣지 취합 로직이 Extension Host 내부의 `src/core/VisibleGraphResolver.ts`에도 완전히 동일하게 존재합니다.
심지어 백엔드 버전은 `hierarchy.getAncestors()`를 호출해 매 엣지, 매 프레임마다 새 배열(Array) 객체를 할당하는 치명적인 메모리 누수 및 오버헤드 구조를 갖고 있습니다.

### 2) BOILERPLATE 로직의 전역 복제 발견 (`NodeBuilder.ts`, `DirectoryTreeBuilder.ts`)
`src`, `main` 등 최상위 구조를 무의미한 껍데기(BOILERPLATE)로 간주하고 잘라버리는 로직이 `ClusterBuilder.ts`뿐만 아니라 `NodeBuilder.ts`, `DirectoryTreeBuilder.ts` 등 도메인 빌더 전반에 박혀 있습니다.
이로 인해 파일 트리를 읽어 들이는 최초 순간부터 `src` 계층이 평탄화(Flatten)되어, LayoutEngine이 계층을 전혀 알지 못하는 1차원 "Cluster Rack" 구조로 강제 배치되고 있습니다.

---

## 3. Proposed Changes (해결 방안)

### Step 1: `findVisibleRep` 메모이제이션 일괄 적용 (Webview & Extension Host)
- **대상 파일**: `ui/canvas-engine.js`, `src/core/VisibleGraphResolver.ts`
- **수정 내용**: 
  - `Map<string, string | null>` 형태의 룩업 캐시(`memo`)를 루프 바깥에 선언.
  - 한 번 계산된 클러스터의 Visible Representative는 다시 계층을 타고 오르지 않도록 $O(1)$로 리턴.
  - 백엔드의 불필요한 `getAncestors` 배열 할당을 제거하고 while 루프로 최적화.

### Step 2: BOILERPLATE 기반 `continent` 추출 로직 교정 (Cluster Rack 복원)
- **대상 파일**: `src/core/ClusterBuilder.ts`, `src/core/NodeBuilder.ts`, `src/core/DirectoryTreeBuilder.ts`
- **수정 내용**: 
  - `BOILERPLATE`를 무작정 지워서 대륙(continent)을 쪼개는 대신, **첫 번째 유효 경로(예: `src`)**를 대륙 그룹으로 유지시켜 LayoutEngine이 뿔뿔이 흩어진 폴더들을 하나의 거대한 망원경(Telescope) 덩어리로 인식하게 만듦.

### Step 3: 초기 LOD 뷰포트 제한 (Default Collapsed 설정)
- **수정 내용**: 
  - 1만 개 이상의 거대 노드 로드 시, 모든 클러스터를 강제로 열어두는(`expandedClusters`에 전부 삽입) 기본 동작을 제어.
  - 최상위 Depth(0~1) 클러스터만 초기에 Expand 하도록 변경하여, 11924개 노드가 한 번에 화면에 노출되지 않도록(LOD Culling 발동) 제동.
