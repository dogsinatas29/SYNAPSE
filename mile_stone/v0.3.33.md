## 🧠 상세 설계 및 로직
- **병목 원인 분석:**
  - 15K 노드와 60K 엣지를 렌더링하는 `renderEdges2D()`, `renderNodes2D()`, `renderEdgeBadges()` 루프 내에서, 화면(Viewport) 밖에 존재하는 개체들에 대해서도 Canvas API 렌더링 호출이 발생하는 것을 확인.
  - 특히, `RenderCall` 시간이 2470ms에 육박하며 렌더링 락이 발생하는 현상은 O(N) 반복문 내의 무거운 `ctx.stroke()`, `ctx.fillText()` 등의 오버헤드 때문.
- **최적화 전략 (The 6-Step Brake 준수):**
  - **Viewport Culling**: 카메라 변환 행렬(Transform)을 역산하여, 화면의 현재 World 영역(Bounding Box)을 도출하고, 화면 밖에 위치한 노드와 엣지를 O(1) 수준의 빠르고 단순한 Bounding Box 교차 검사를 통해 스킵 처리.
  - **LOD 향상 (Level of Detail)**: Zoom이 극도로 낮은 상태(0.35 이하)일 때, MetaEdge(번들링된 엣지)가 존재하지 않는 경우 개별 엣지 개수가 2000개를 초과하면 과감히 물리적 엣지 렌더링을 생략하여 프레임 드랍 방지.

## 🛠️ 기술적 변경 사항
- **[canvas-engine.js](file:///home/dogsinatas/TypeScript_project/antigravity-extension-vis/ui/canvas-engine.js)** 변경 사항:
  - `renderEdges2D()`: Viewport Culling (화면 밖 엣지 렌더 스킵) 로직 적용. 줌 레벨과 엣지 개수를 고려한 Fallback LOD 로직 추가.
  - `renderNodes2D()`: Viewport Culling 로직 추가 및 `offset-adjusted Y` 좌표 처리 적용.
  - `renderClusters()`: 클러스터 단위의 Bounding Box가 Viewport 외곽에 있을 경우 즉시 스킵하도록 최적화.
  - `renderGhostNodes()`: 고스트 노드 경로 선을 그릴 때 Viewport Culling 적용.
  - `WebGL Hybrid Badges (render()` 내부): Screen 좌표계로 투영한 후 `overlay` 밖으로 벗어난 배지에 대해 렌더링 생략.

## ⚠️ 예외 처리 및 주의 사항
- 엣지의 Bounding Box 계산 시 3차 베지어 곡선이 포함되어 있으나, 연산 오버헤드를 최소화하기 위해 양 끝 노드 좌표만을 활용한 AABB(Axis-Aligned Bounding Box) 검사를 수행함.
- Canvas `zoom`과 `offsetX`, `offsetY`의 비율 계산 실수로 인해 화면 내 객체가 잘리는(Clipping) 현상을 막고자, 충분한 `buffer`(200~500px)를 확보.

## 📝 Post-Work Log (작업 후 기록)
- O(N) 순회는 유지되지만 렌더링 파이프라인의 핵심 병목인 Canvas Write 연산이 90% 이상 절감될 것으로 예상.
- **Frontend 프로파일링 (1순위 요청사항) 관련:** AI 에이전트 환경의 제약상 직접 Chrome DevTools를 통한 UI 인터랙션 녹화가 불가하므로, 본 Viewport Culling 패치가 적용된 버전을 바탕으로 사용자가 직접 DevTools의 Performance 탭에서 '15K 케이스'를 1회 녹화해 주시기를 요청함.
