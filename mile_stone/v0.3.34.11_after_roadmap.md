# v0.3.34.11 Post-MVP Roadmap & Stabilization Plan

현재 v0.3.34.11 MVP 기준의 파이프라인(Provider → Aggregator → Confidence → Bundle → Markdown/HTML)은 코드와 E2E 테스트 레벨에서 성공적으로 완성되었습니다.
따라서 본 문서부터는 신규 기능 추가(Feature)를 동결(Freeze)하고, 실무 환경에서의 **검증과 안정화(Stabilization)**에 집중하는 전략을 정의합니다.

## 1. 실제 프로젝트 검증 (Real-World Project Audit)

현재의 엔진은 테스트 목업 데이터를 통과한 상태입니다. 이제 실제 거대 코드베이스에 투입하여 병목과 엣지 케이스를 파악해야 합니다.

### 검증 대상 (순차적 스케일업)
1. 소형 프로젝트
2. SYNAPSE 자체 코드베이스
3. AXON
4. AntennaPod
5. VSCode-main (최종 부하 테스트)

### 핵심 관측 지표
- **Evidence 수**
- **IntentEdge 수**
- **평균 Confidence**
- **보고서 생성 시간**
- **출력물 크기 (HTML / Markdown)**

**주의:** 만약 `Evidence: 250,000 / IntentEdge: 40,000` 처럼 예상치 못한 데이터 폭증이 발생할 경우, 최우선적으로 `EvidenceAggregator`의 정규화/병합 규칙을 튜닝해야 합니다.

---

## 2. Report Size Audit

초대형 프로젝트(VSCode-main 등)를 분석할 때 출력물의 용량이 허용 범위 내인지 측정해야 합니다.

- **안정 권장선:** `logic_report.md` ~ 12MB / `logic_report.html` ~ 18MB
- **위험 한계선:** 200MB 이상의 거대 HTML 파일이 생성될 경우 렌더링이 불가할 수 있습니다.

**대응 전략:** 파일 크기가 한계선을 돌파할 경우, 생성된 전체 `EvidenceIR[]`를 모두 HTML에 렌더링하는 정책을 폐기하고 "Confidence 상위 N개만 출력" 또는 "IntentEdge 요약만 렌더링"하는 정책으로 변경해야 합니다.

---

## 3. Provider 품질 측정 (Provider Telemetry)

현재 `ConfidenceEngine`의 가중치(Regex 0.30, Definition 0.40, Reference 0.20, Symbol 0.10)는 이론적 설계값입니다. 실제 프로젝트 구동 결과를 바탕으로 이 수치가 현실과 부합하는지 재평가해야 합니다.

### 수집 데이터 예시
- Regex Evidence 수
- Definition Evidence 수
- Reference Evidence 수
- Symbol Evidence 수

**대응 전략:** 언어별 LSP 품질 편차로 인해 `Definition` 추출량이 현저히 낮고 `Regex` 의존도가 기형적으로 높다면, 점수 비중을 조정하거나 Regex 수집기의 노이즈 필터링을 강화해야 합니다.

---

## 4. MVP Feature Freeze & Future Release Plan

이 시점에서 **v0.3.34.11의 기능 추가를 완전히 동결(Feature Freeze)**합니다.
SCC, Hub, Bridge, Health Score, LLM Layer 등의 상위 추론 엔진은 v0.3.35 이후 릴리스로 이관하여 MVP의 경계를 지킵니다.

### 릴리스 로드맵
- **v0.3.34.11**: Stabilization (현재 - 데이터 수집, 파이프라인 안정화 및 부하 테스트)
- **v0.3.35**: Interactive Evidence Explorer
- **v0.3.36**: Conditional Compilation Evidence
- **v0.4.x**: Reasoning Layer (SCC, Hub/Bridge Analysis, Interventions)

> **핵심 원칙:** "무엇을 더 만들까?"보다 실제 대형 프로젝트에서 `Evidence → IntentEdge → Report`가 얼마나 잘 수렴되는지 측정하는 것이 우선입니다. 이 기반이 탄탄해야 향후 v0.4.x의 상위 추론 엔진(Reasoning Layer)이 뱉어내는 결론을 온전히 신뢰할 수 있습니다.
