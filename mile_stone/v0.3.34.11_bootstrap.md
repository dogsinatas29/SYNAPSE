# Architecture Principles

## Architecture Intelligence First

SYNAPSE는

```text
Code Analyzer
```

가 아니다.

SYNAPSE는

```text
Architecture Intelligence System
```

이다.

---

## Evidence First

모든 결론은 증거를 가진다.

허용되지 않는 형태

```text
결론만 존재
```

허용되는 형태

```text
결론

↓

증거

↓

원본 소스

↓

신뢰도
```

---

## Intent First

AST

↓

Intent

이 아니다.

반드시

```text
Intent Candidate

↓

Evidence

↓

Intent Engine

↓

Conclusion
```

순서를 유지한다.

---

## Architecture Before Implementation

코드 구조보다

구조적 의미를 우선한다.

---

## Deterministic Architecture Rule

가장 중요한 원칙.

동일한 소스코드는 반드시 동일한 결과를 생성해야 한다.

```text
Windows

Linux

macOS

VSCode

Cursor

VSCodium

OpenVSX Fork
```

어디서 분석하더라도

최종 Architecture Conclusion은 동일해야 한다.

---

허용되는 차이

```text
Evidence Quantity

Confidence

Evidence Source
```

---

허용되지 않는 차이

```text
Intent Graph

Contract Graph

Root Cause

Surgery Target

Logic Report

Architecture Conclusion
```

---

## Linus Test

모든 결과는 아래 질문에 답할 수 있어야 한다.

```text
어디를 수정해야 하는가?

왜 수정해야 하는가?

무엇이 실제 결합을 만들고 있는가?

수정하면 무엇이 달라지는가?

그 증거는 무엇인가?

그 증거를 신뢰할 수 있는가?
```

답할 수 없으면 구현 실패로 간주한다.

---

## Principle F — Evidence Conflict Transparency

Evidence Provider들이 서로 다른 답을 내면

숨기지 않는다.

반드시 출력에 표시한다.

허용되지 않는 형태

```text
Confidence: 41%
```

허용되는 형태

```text
Evidence Conflict Detected

Regex:      Positive
AST:        Negative
Contract:   Positive
Runtime:    Unknown

Decision:   Weak Dependency
Confidence: 41%
Reason:     AST Negative → Contract 우선, Runtime 미확인
```

Conflict를 숨기고 Confidence만 내보내는 것은

허용되지 않는다.

---

## Principle G — Traceability Required

모든 Evidence는 반드시 아래를 포함한다.

```text
File

Line

Column (가능한 경우)

Symbol
```

최소 요건

```text
File + Line
```

이 없으면 Evidence로 인정하지 않는다.

결론에 사용될 수 없다.

---

## Principle H — Deterministic Rendering

HTML은 Truth가 아니다.

Truth는

```text
JSON Snapshot
```

이다.

HTML은 Snapshot을 렌더링할 뿐이다.

결론, 순서, 우선순위는

JSON Snapshot에서 결정된다.

HTML 렌더링이 결론에 영향을 주어서는 안 된다.

---

## Principle I — Evidence Ranking Transparency

상위 N개 Evidence만 표시하는 경우

반드시 아래를 함께 표시한다.

```text
Top Evidence

+

Hidden Evidence Count

+

Expand (View All)
```

숨겨진 Evidence가 있는데 개수를 표시하지 않는 것은

허용되지 않는다.

# LLM Coding Principles

추측 금지.

요구사항이 모호하면 질문.

접근 방식과 트레이드오프 먼저 제시.

항상 가장 단순한 해결책 우선.

## 2. Simplicity First

최소 코드.

요청하지 않은 기능 추가 금지.

과도한 추상화 금지.

---

## 3. Minimal Changes

필요한 부분만 수정.

전체 재작성 금지.

기존 스타일 유지.

---

## 4. Goal-Oriented Execution

반드시

```text

↓

↓

↓

Validation
```

순서 유지.

---

## 5. No Hallucinated APIs

존재하지 않는 API 생성 금지.

확신 없으면 질문.

---

## 6. Stable Code Protection

검증된 코드 수정 금지.

요청 범위 외 변경 금지.

---

## 7. Context Confirmation

맥락 확인 후 작업.

추측 구현 금지.

## 8. Rendering Isolation

# Gemini Performance Constraints

## Frame Loop Constraints

### Rule

Frame 경로는 반드시 O(1)

### Forbidden

```text
for

while

map

filter

reduce

dynamic allocation
```

### Allowed

```text
direct access

constant-time operation
```

---

## Recalculation Prohibition

상태 변경 없으면 재계산 금지.

반드시

```text
Cache

Dirty Flag
```

사용.

---

## State-Driven Execution

업데이트는

```text
State Change
```

기반.

Polling 금지.

---

## CPU Budget Protection

반복 시각 계산은 GPU 우선.

CPU 반복 처리 최소화.

---

## Allocation Constraints

Hot Path에서

```text
new

push

resize
```

금지.

---

## Forbidden Patterns

```text
Loop in render

Loop in update

Repeated calculation

Allocation in frame

Hidden O(n)

State-independent recomputation
```

---

## Mandatory Review Checklist

구현 전 반드시 검증.

```text
[ ] Frame Loop O(1)

[ ] No repeated calculation

[ ] No allocation in hot path

[ ] State-driven update

[ ] CPU workload minimized

[ ] Rendering isolation preserved
```
