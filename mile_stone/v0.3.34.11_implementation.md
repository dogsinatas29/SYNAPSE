# Phase 1

## Evidence Provider Layer

---

### 목적

Language Intelligence 결과 수집

---

### 입력

VSCode Commands

* executeDefinitionProvider
* executeReferenceProvider
* prepareCallHierarchy
* executeDocumentSymbolProvider
* executeImplementationProvider
* executeTypeDefinitionProvider

---

### 출력

Evidence IR

```json
{
  "id": "...",
  "file": "...",
  "line": 123,
  "source": "...",
  "target": "...",
  "evidenceType": "...",
  "provider": "DefinitionProvider",
  "reason": "...",
  "metadata": {}
}
```

**중요:** `confidence`는 Evidence 자체의 속성이 아니다. Evidence는 Fact(사실)이며, Confidence는 Interpretation(해석)이므로 Engine 단계에서 별도로 계산한다. `metadata` 필드는 향후 Provider별 세부 정보(예: `symbolKind`, `referenceCount` 등) 확장을 위한 예약 슬롯이다.

---

### Evidence Types

초기 MVP에서는 10개 이상의 Enum을 고정하여 파이프라인을 무겁게 만들지 않는다.

```typescript
type EvidenceType = string;
```

기본적으로 `FunctionCall`, `InterfaceContract`, `Implementation` 등을 문자열로 시작하며, 확장이 필요한 시점에 구체화한다.

# Phase 3

## Confidence Engine

---

### 목적

신뢰도 계산

---

예

```text
Regex only = 0.30

DefinitionProvider = +0.40

ReferenceProvider = +0.20

SymbolProvider = +0.10
```

---

계산 결과

```text
Regex + Definition = 0.70

Regex + Definition + Reference = 0.90

All Evidence = 1.00
```

---

### Penalty (Negative Evidence)

단순 합산뿐만 아니라, 예상되는 증거가 누락된 경우 Confidence를 차감한다.

```text
Regex 있음 (+0.30)
Definition 없음 (-0.10)
Reference 없음 (-0.10)

Result: 0.10 (Positive 0.30 - Negative 0.20)
```

Positive Evidence와 Negative Evidence를 분리하여 신뢰도를 정밀하게 제어한다.

**주의:** v0.3.34.11 첫 릴리스에서는 언어 서버 품질 차이(예: Python, JavaScript)를 고려하여 Positive Evidence만 적용하고 Negative Evidence는 Feature Flag로 비활성화하여 보수적으로 시작하는 것을 권장한다.
