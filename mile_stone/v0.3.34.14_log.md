# v0.3.34.14_log.md - 작업 진행 로그

## Phase 27-B: Semantic Contract Layer 도입 (2026-08-04 시작)

### 작업 개요
v0.3.34.14는 **Validation 결과와 Report Generator 사이에 의미 정규화 계층(Semantic Contract Layer)을 추가**하는 단계.

**근본 문제 진단 (v0.3.34.13 결과):**
- 현재 4개로 보이는 버그는 사실 1개의 뿌리에서 나온 증상
- Root Cause: Report Generator가 Raw Metrics와 Calibrated Metrics를 동시에 사용

**구체적 증상:**
```
Infrastructure Mesh:
  Raw (hit=1/3, count=1)     → "Mesh: ✅ Detected"
  Calibrated (count=0)       → "No high-priority residue"
  
  → 모순: "Mesh 없음"과 "Mesh 존재" 동시 출력

유사 증상들:
  ROI:        70% vs 56% (다른 계산식 사용)
  AI Prompt:  4543 vs 7500 (다른 소스 참조)
  Evidence:   0/3 vs 1/3 (오래된 필드 사용)
```

**해결책:**
```
Validation JSON (Raw Metrics)
  ↓ [NEW] Semantic Normalization
  ↓
Semantic Contract (정규화된 최종 진실)
  {
    "Infrastructure_Mesh": {
      "state": "CALIBRATED_OUT",
      "confidence": 0.33,
      "hitRate": "1/3",
      "decision": "EXCLUDE_FROM_SURGERY"
    }
  }
  ↓
Report Generator (Contract만 읽음, Raw는 절대 안 봄)
  ↓
Report Output (일관됨)
```

### 정규화 규칙 요약

**Infrastructure Mesh 사례:**
```
Raw Validation:
  hit: 1/3
  confidence: 0.33
  threshold_sweep: [0, 0, 0, 0] (모두 0)

정규화 판정:
  threshold_sweep이 모두 0 → CALIBRATED_OUT
  confidence는 0.33 (기록용)
  decision: EXCLUDE_FROM_SURGERY

Contract 결과:
  {
    "state": "CALIBRATED_OUT",
    "confidence": 0.33,
    "hitRate": "1/3",
    "decision": "EXCLUDE_FROM_SURGERY",
    "reason": "Species not detected at any threshold level (0.80-0.86)"
  }
```

**Contract Core 사례:**
```
Raw Validation:
  hit: 4/5
  confidence: 0.80
  rel: 0.26 (변동성 낮음)

정규화 판정:
  confidence 0.80 ≥ 0.75 (stable gate) → STABLE
  rel 0.26은 변동성 낮음 (신뢰도 가산)
  decision: INCLUDE_IN_SURGERY

Contract 결과:
  {
    "state": "STABLE",
    "confidence": 0.80,
    "hitRate": "4/5",
    "decision": "INCLUDE_IN_SURGERY",
    "reason": "Stable across runs with low variance (rel=0.26)"
  }
```
