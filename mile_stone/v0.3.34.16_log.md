## ⚠️ 디버깅 및 버그 픽스 (VisibleBounds Engine 미작동 해결)
- **증상**: 프론트엔드 콘솔에서 `visibleClusters=2908, visibleNodes=69226`가 출력되며 Telescope LOD 및 Bounds 필터링이 실패하는 현상 발견. `[DEBUG] fitCameraToBounds applied` 호출이 거대한 Reality 좌표를 추적하여 여전히 우주 공간으로 카메라가 튕겨져 나감.
- **원인 1 (Collapse 상태 초기화 실패)**: 백엔드 `ClusterBuilder.ts`와 `GraphModel.ts`에 하드코딩된 최상위 `cluster_ghosts` 초기 선언부에 `collapsed: true` 속성이 누락되어 있었음. 이로 인해 프론트엔드가 초기화될 때 `!c.collapsed` 조건에 걸려 `cluster_ghosts`를 무조건 `expandedClusters`에 추가해버림.
- **원인 2 (Bounds 계산 시 부모 상태 무시)**: `computeVisibleBounds`가 배열 내의 모든 클러스터(예: 숨겨져야 할 `cluster_ghost_linux`)를 순회하면서, 250x80 크기일지언정 그 실제 위치인 `(-38140, -35860)`를 bounds에 포함시켜버림.
- **해결 방안**:
  1. `ClusterBuilder.ts`, `GraphModel.ts`에 `cluster_ghosts` 정의부에 `collapsed: true` 강제 주입.
  2. `canvas-engine.js`의 `computeVisibleBounds` 함수 내에 **Telescope LOD(System B) Hierarchy Check** 로직을 도입. 현재 순회 중인 클러스터의 `parentNode`가 접혀있다면(`!expandedClusters.has(parentNode.id)`), 해당 자식 클러스터는 Bounds 계산에서 완전히 배제(`continue`)하도록 수정.
- (완료) `canvas-engine.js`에 `computeVisibleBounds()` 함수 추가 및 `fitView` 로직 변경.
  - `computeWorldBounds()` 유지 (Layout=Reality 보존).
  - UI 상수에 맞춘 `COLLAPSED_CLUSTER_WIDTH = 250`, `COLLAPSED_CLUSTER_HEIGHT = 80` 도입.
- (완료) `GhostExpander.ts`에서 도메인 하위 클러스터 할당 로직 구현 (v0.3.35).
  - 3-Tier 계층 생성: `cluster_ghosts` -> `cluster_ghost_${domain}` -> 노드.

- (완료) `ui/canvas-engine.js`의 `requestContextData` 내부 Virtual Debug 추출 로직 수정.
  - 기존의 단편적인 `c.collapsed !== true` (System A) 검색 로직을 버리고, 렌더링 측면의 **Telescope LOD (System B)** 규칙(`engine.expandedClusters` 및 부모 상태 검사)을 엄격히 적용하여 백엔드로 전달될 클러스터 범위 필터링 동기화.
  - 이로 인해 Simulation Debug 수행 시 접혀 있는 유령 노드 69,226개가 AAE 파이프라인으로 전송되어 13,254라인의 거대 리포트를 생성하던 버그(OOM 및 병목) 완벽 해결.

- (완료) `VirtualDebugger.ts` 및 `CanvasPanel.ts`를 리팩토링하여 `Architecture Surgery Pipeline` 직접 연결 (v0.3.34.17)
  - **문제**: 실험실(Laboratory) 환경(`b5_validation_layer.ts`)은 정적 JSON 파일을 보고, 라이브 캔버스는 동적 상태를 보면서 결과 리포트 체계(`LOGIC_REPORT.md` vs `ASR_EV.md`)가 분리되어 있던 아키텍처 부채 해결.
  - **해결**: `VirtualDebugger.ts`에서 웹뷰로부터 전달받은 `targetState`를 `report/temp_target_state.json`으로 덤프한 후, `child_process.execSync`를 통해 `b5_validation_layer.ts`와 `generate_surgery_report.ts`를 직접 실행하도록 파이프라인 통합.
  - 생성된 `ASR_EV-LIVE.md` 파일을 `LOGIC_REPORT.md` 대신 VSCode 마크다운 프리뷰(`markdown.showPreview`)로 자동 오픈하도록 `CanvasPanel.ts` 수정.
  - 향후 v0.4.x에서는 이 임시 JSON 덤프 및 CLI 호출 방식을 **메모리 기반 Library 호출(`import { runValidationLayer }`)**로 구조 전환할 예정 (Phase 2).
  
- (완료) `filterSnapshot.ts` 리팩토링 및 "Roots Only / Cluster State Mismatch" 버그 완벽 수정 (v0.3.34.18)
  - **문제**: 캔버스에서 "Roots Only" 버튼 클릭 시 수천 개의 폴더가 닫히지 않고 오직 10개의 폴더만 접히는 `collapsedClusters: 10` 버그 발생. 
  - **원인**: 백엔드의 `filterSnapshot.ts`가 중간 단계의 빈 폴더(Intermediate empty folders)들을 스냅샷에서 필터링하여 완전히 제거해버림. 이로 인해 리프 폴더(Leaf folders)들이 부모를 잃어버렸고, 프론트엔드의 `buildHierarchy` 복구 로직이 부모를 찾다 실패하여 리프 폴더들의 `parent_id`를 `null`로 할당함. 그 결과 2900개가 넘는 리프 폴더들이 "최상위 루트(True Root)"로 인식되어 Roots Only 상태에서 닫히지 않음.
  - **해결**: `filterSnapshot.ts`에서 하위 노드가 존재하는 클러스터의 모든 조상(Ancestor) 폴더들을 역추적하여 보존(Keep)하도록 O(N) 알고리즘 재설계. 이로써 부모-자식 관계가 단절되지 않으며 프론트엔드에서 수천 개의 폴더를 올바른 레벨(Depth)로 인식하여 "Roots Only" 모드가 정상 작동함.
