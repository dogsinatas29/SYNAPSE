# 🚀 Milestone v0.3.34.17 - ASR 3.0 Evidence Layer (Formatting & Ghost Restoration)

## 📅 작업 정보
- **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.34.17
- **목표:** ASR 3.0 레이아웃 전면 리팩토링 및 Ghost Evidence 타겟 복원

## 🛠️ 기술적 변경 사항
- **Ghost Evidence Restoration (isGhost Flag):**
  - 원본 심볼명(`originalTo`/`originalFrom`) 복원 패치 이후, 타겟 문자열에 `unknown`이 사라지면서 Ghost Evidence 필터링이 누락되던 현상을 해결.
  - `VirtualDebugger.ts`의 Edge Aggregator에서 `originalFrom` 또는 `originalTo`에 기반하여 `AGGREGATE_` 태그를 가지고 있던 본래 엣지를 식별하고, `isGhost: true` 플래그를 부착.
  - `ValidationEngine.ts` 필터에서 문자열 매칭(이름 기반)이 아닌 `e.isGhost` 플래그를 최우선으로 검사하도록 아키텍처 개선.
- **ASR 3.0 Layout Refactoring (HTML/MD):**
  - 아키텍트의 논리적 독해 흐름에 맞춰 `ValidationReportBuilder.ts`의 레이아웃 엔진 전면 개편.
  - 기존 `생태계 통계 -> 증거` 흐름에서 `상태 판정(Executive Summary) -> 수술 대상 지목(Impact Files) -> 원시 증거(Evidence Layer) -> 수술 기대 효과 -> 세부 통계(Raw Metrics)` 순서로 재배치 완수.
  - HTML 및 Markdown 렌더러에 100% 동일한 구조 적용 완료.
- **Data Quality Fixes:**
  - `Top Impact Files`가 정상적으로 Top 10을 추출하여 렌더링되도록 수정.
  - VSCode URI(`vscode://file/`)의 호스트 의존적인 절대 경로(PII)를 제거하고 워크스페이스 기준 상대 경로로 치환.

## ⚠️ 예외 처리 및 주의 사항
- `Evidence Count`: 개별 심볼 단위의 원시 엣지는 Java 스캐너 특성상 중복 관계를 1개의 엣지로 압축 방출하므로 `Count: 1` 표기가 기본 동작(정상)임. 대신 `Top Impact Files` 단위의 `Total External Edges` 집계치로 모듈 간 통신량 지표를 대체 활용.
- 터미널 쉘 다운(`connection reset by peer`)으로 인해 제 쪽에서 컴파일 덤프 확인 불가, 사용자 측에서 직접 릴리즈 빌드 후 덤프 출력 검증 필요.

### 추가 패치 (데이터 품질 및 기술 부채 해소)
- **Impact Files 전체 엣지 기반 집계**: 기존에 Top 50으로 슬라이싱된 `boundaryEvidence`만 합산하던 치명적 오류를 수정. 전체 `intentEdges`를 순회하며 `externalEdges`를 합산한 후 Top 10을 추출하도록 픽스.
- **VSCode 링크 버그 픽스**: `vscode://file/...` 스키마가 절대 경로를 요구함에도 상대 경로를 맵핑하여 OS에서 파일을 열지 못하던 문제 해결. (표시되는 텍스트는 PII 제거, 숨겨진 URL은 절대 경로로 분리)
- **상수 승격 (Magic Number 제거)**: `slice(0, 10)` -> `TOP_IMPACT_LIMIT`, `slice(0, 50)` -> `EVIDENCE_LIMIT`로 교체하여 하드코딩 제거.
- **가중치 방어 로직**: `VirtualDebugger.ts`에서 `e.weight || 1`을 `e.weight ?? 1`로 교체하여 `weight=0` 유실 방지.
- **문자열 기반 Ghost 판정 삭제**: `ValidationEngine.ts` 내의 `.includes('ghost')` 같은 하드코딩 필터를 제거하고 `isGhost` 메타데이터만을 신뢰하도록 정비.
