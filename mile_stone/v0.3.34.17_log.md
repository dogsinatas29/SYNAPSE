# 🚀 Milestone v0.3.34.17_log - Virtual Debug Scope Synchronization (System B Alignment)

## 📅 작업 정보 - **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.34.16
- **목표:** Simulation Debug(Runtime Architecture Analysis) 시 발생하는 OOM 및 초대형 리포트(13,254 라인) 생성 버그 수정. 검색 및 추출 로직을 Telescope LOD 렌더링 가시성 규칙과 완벽히 동기화.

## 🧠 상세 설계 및 로직
- **근본 원인 분석 (Root Cause):** 
  - 프론트엔드(`canvas-engine.js`)에서 노드를 화면에 그릴 때는 `engine.expandedClusters`(System B)의 상태와 부모-자식 계층(Telescope LOD)을 참조하여 가시성을 엄격히 통제함.
  - 그러나, 사용자가 "Runtime Simulation Debug" 버튼을 눌렀을 때 백엔드로 전송되는 `visibleClusterIds`를 추출하는 검색 로직은 단순히 정적 속성인 `c.collapsed !== true` (System A)만을 검사하고 있었음.
  - 이로 인해, 부모인 `cluster_ghosts`가 축소(Collapse) 상태라도 자식 계층인 `cluster_ghost_linux` 등의 노드 69,226개가 필터링 없이 그대로 `VirtualDebugger.ts`로 전송되어, AAE(Architecture Analysis Engine) 파이프라인에서 33,583개의 Findings를 포함한 예전 포맷의 13,254라인 리포트를 뱉어내는 병목이 발생함.

- **해결책 (The Brake Applied):**
  - `requestContextData` 인터셉터 로직을 전면 수정.
  - 단순히 `c.collapsed`를 읽지 않고, 렌더링 최적화와 동일하게 `engine.expandedClusters.has(c.id)` 및 부모 클러스터의 `expanded` 상태를 검사하여 `visibleClusterIds`를 산출.
  - 화면에 안 보이는(Telescope LOD 상 접혀 있는) 노드들은 100% 백엔드 분석 대상에서 제외됨.
