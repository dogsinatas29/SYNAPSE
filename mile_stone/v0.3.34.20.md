## 🎯 목표

현재 SYNAPSE는 "참조가 존재한다"는 안다. 하지만 "어떤 종류의 참조인가"는 모른다.

```
interface / type / enum / function / runtime logic
```

전부 동일한 Edge로 계산 → 순수 Contract Hub와 실제 Runtime Hub를 구분 불가.

AST는 **Evidence Verification Layer**다. Graph Generator가 아니다.

## 🧠 상세 설계

### 파이프라인 변경

```
Before:
  Regex Scanner → Graph → Boundary → FanOut → Impact Ranking → Report

After:
  Regex Scanner → Graph → Boundary → FanOut → Impact Ranking
    → Top Impact Files 선정
    → AST Evidence Verification   ← NEW
    → Re-Ranking                  ← NEW
    → Report
```

### AST 역할 정의

| 역할 | 설명 |
|------|------|
| ✅ 하는 것 | Top Impact Files의 참조 종류 재판정 |
| ✅ 하는 것 | adjustedImpactScore 계산 (원본 보존) |
| ✅ 하는 것 | Human Translation 텍스트 생성 |
| ❌ 안 하는 것 | Graph/Edge/Boundary/FanOut/Layout 수정 |
| ❌ 안 하는 것 | 전체 프로젝트 AST 생성 |
| ❌ 안 하는 것 | AST Resolver / Symbol Registry / Kconfig / Makefile |

## 🛠️ 기술적 변경 사항

### [NEW] `src/cli/ast_verification_engine.ts`

**입력**: `filePath: string`

**사용 API**: `ts.createSourceFile(...)`

**출력**:
```ts
{
  type: "TYPE_ONLY" | "BARREL_EXPORT" | "HEADER_CONTRACT" |
        "TEST_ARTIFACT" | "HEALTHY_CONTRACT" | "RUNTIME_HUB",
  interfaceRatio: number,  // 0~100
  typeRatio: number,
  runtimeRatio: number
}
```

**비율 계산**:
```
nodeCount 기준
interfaceRatio = interfaceCount / totalNodes
typeRatio      = typeCount / totalNodes
runtimeRatio   = (functionCount + statementCount) / totalNodes
```

**분류 체계**:

| 분류 | 조건 |
|------|------|
| `TYPE_ONLY` | interface+type > 90%, runtime < 5% |
| `BARREL_EXPORT` | export * > 90%, runtime statement 없음 |
| `HEADER_CONTRACT` | declaration 중심, runtime logic 없음 |
| `TEST_ARTIFACT` | describe/it/test 패턴 중심 |
| `HEALTHY_CONTRACT` | 계약 + 일부 구현 혼재 |
| `RUNTIME_HUB` | function/statement 비율 높음 |

**캐시**: `filePath + mtime` 키. 히트 시 AST 재파싱 생략.

**Degraded Mode**: AST 실패 시 기존 보고서 유지, AST 섹션만 생략. 분석 중단 금지.

### [MODIFY] `src/core/validation/ValidationEngine.ts`

Impact Ranking 이후 AST Verification 삽입:

```ts
// candidate 확장
candidate.astVerification = {
  type: "TYPE_ONLY",
  interfaceRatio: 91,
  typeRatio: 7,
  runtimeRatio: 2
};

// Re-Ranking multiplier
const multiplier: Record<string, number> = {
  TYPE_ONLY: 0.2,
  BARREL_EXPORT: 0.3,
  HEADER_CONTRACT: 0.4,
  TEST_ARTIFACT: 0.1,
  HEALTHY_CONTRACT: 0.8,
  RUNTIME_HUB: 1.0
};
candidate.adjustedImpactScore =
  candidate.impactScore * (multiplier[candidate.astVerification.type] ?? 1.0);
// candidate.impactScore 원본 보존
```

### [MODIFY] `src/core/validation/ValidationReportBuilder.ts`

Top Impact Files 섹션에 AST 결과 추가:

```
[TYPE_ONLY]
interface 91% | type 7% | runtime 2%
→ 이 파일은 주로 타입과 인터페이스 정의를 담당한다.

[RUNTIME_HUB]
function 68% | statement 22% | type 10%
→ 변경 시 직접 실행 로직을 포함하며 높은 영향도를 가진다.
```

**Human Translation Layer**:

| 원본 | 번역 |
|------|------|
| `Boundary Crossing 127` | 이 파일은 127개의 모듈 경계를 넘는 의존성을 가진다. |
| `FanOut 130` | 변경 시 130개 이상의 파일에 영향을 줄 수 있다. |
| `TYPE_ONLY` | 이 파일은 주로 타입과 인터페이스 정의를 담당한다. |
| `BARREL_EXPORT` | 이 파일은 하위 모듈을 일괄 재수출하는 배럴 파일이다. |
| `RUNTIME_HUB` | 이 파일은 실제 실행 로직을 포함하는 런타임 허브이다. |

## ⚠️ 예외 처리 및 주의 사항

1. **Top N 제한 엄수**: Top 100 초과 AST 금지. 13,544개 전체 AST 절대 금지.
2. **원본 impactScore 보존**: `adjustedImpactScore`는 보고서 출력용. 내부 Graph 데이터 오염 금지.
3. **TypeScript API만 사용**: `ts.createSourceFile` — `typescript` 패키지는 이미 devDependency에 있음. 신규 의존성 추가 금지.
4. **Linux Kernel 범위**: Type Reference, Struct Usage, Function, Macro Usage, Header Contract만 지원. AST Resolver / Kconfig / Makefile은 v0.3.34 범위 밖으로 명시적 제외.
5. **Degraded Mode 필수**: AST parse 실패 시 해당 파일 결과 null로 처리 후 계속 진행.
