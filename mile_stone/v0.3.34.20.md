# 🚀 Milestone v0.3.34.20 - AST Evidence Verification Layer

## 📅 작업 정보

* **상태:** 🏗️ Planned
* **관련 마일스톤:** v0.3.34.19a
* **목표:** 정규식 기반 그래프 분석 결과의 상위 위험 파일(Top Impact Files)에 대해 AST 기반 증거 검증(Evidence Verification)을 수행하여 Contract Hub, Barrel Export, Header Contract 등의 오탐을 제거하고 보고서 신뢰도를 향상시킨다.

---

# 🧠 설계 배경

## 현재 SYNAPSE 분석 구조

```text
Regex Scanner
    ↓
Graph 생성
    ↓
Boundary 계산
    ↓
FanOut 계산
    ↓
Impact Ranking
    ↓
Report 생성
```

현재 SYNAPSE는 다음을 매우 빠르게 찾아낸다.

```text
어떤 파일이
어떤 파일을 참조하는가
```

하지만 아직은 알 수 없다.

```text
그 참조가
실제 런타임 의존성인지
단순 타입 의존성인지
```

예:

```ts
import type { Session } from './types';
```

```ts
import { SessionManager } from './sessionManager';
```

현재는 둘 다

```text
Dependency 1
```

로 동일하게 취급된다.

# 🎯 AST 위치 결정

초기 설계 당시 AST를 전면 도입하는 방안도 검토되었다.

예:

```text
13,544 파일
82,452 Boundary Edges
```

규모의 프로젝트에 대해

```text
전체 AST 생성
```

을 수행하면

```text
분석 시간 증가
메모리 증가
캐시 관리 복잡도 증가
```

문제가 발생한다.

따라서 AST는 그래프 생성기가 아니다.

AST는

```text
Evidence Verification Layer
```

로 사용한다.

# 🌍 Human Translation Layer

AST 검증 이후 바로 수행

---

현재:

```text
Boundary Crossing: 127
FanOut: 130
```

---

변환 후:

```text
이 파일은 127개의 모듈 경계를 넘나드는 핵심 연결점이다.

변경 시 130개 이상의 파일에 영향을 줄 수 있다.
```

---

현재:

```text
TYPE_ONLY
```

---

변환 후:

```text
이 파일은 주로 타입과 인터페이스 정의를 담당한다.

시스템 전반에서 널리 참조되지만
실제 런타임 로직은 거의 포함하지 않는다.
```

---

목표:

```text
아키텍트가
Raw Metric 없이도
의미를 이해할 수 있게 만든다.
```

# 🚫 AST의 역할 제한

AST는

```text
증거 검증
오탐 제거
랭킹 보정
보고서 설명 강화
```

만 수행한다.

---

절대 수정 금지

```text
Boundary
FanOut
Layout
Graph
```

---

AST는

```text
Graph Generator
```

가 아니다.
