# 🚀 Milestone v0.3.34.21 - [ASR Edge Type & Ghost Classification]

## 📅 작업 정보 
- **상태:** 🏗️ Planned 
- **관련 마일스톤:** v0.3.34.20
- **목표:** 단순 연결(Count: 1)을 넘어서, Edge Type을 세분화하여 Ghost와 아키텍처 메트릭의 품질을 획기적으로 끌어올린다. Kconfig 같은 오버엔지니어링(Compiler Frontend)은 과감히 버리고, 가장 ROI가 높은 Edge Type 분류에 집중한다.

## 🧠 핵심 과제 (The 3 Pillars of Semantic Analysis)

### 1. Node Role Classification (노드 역할 분류)
- **현상:** 파일이 실제 운영(Core) 코드인지, 테스트(Test) 코드인지 구분 없이 엣지 수(Fan-In/Out)만으로 중요도를 평가함. 이로 인해 `tools/testing/selftests/.../verifier.c` 같은 단순 테스트 허브가 커널 전체의 핵심 런타임 허브로 오탐됨.
- **계획:** 파일 경로 및 내부 메타데이터를 기반으로 노드 역할을 부여.
  - `CORE_RUNTIME` / `TEST` / `BENCHMARK` / `SAMPLE` / `TOOLING` / `DOCUMENTATION`
  - **효과:** `TEST`나 `SAMPLE` 노드를 중요 아키텍처 허브(Runtime Hub) 평가 후보에서 원천 배제하여 치명적인 오탐 해결.

### 2. Edge Type Classification (의미론적 엣지 분류)
- **현상:** `#include`, 심볼 참조, 호출 등이 모두 단순 `Edge Count +1`로 뭉뚱그려져 의존성 노이즈 발생 및 가짜 고스트(`xterm`, `zod` 등 외부 패키지) 양산.
- **계획:** 스캐너 레이어에 다음 Edge Type 도입 및 가중치 분리:
  - `CALL` / `INCLUDE` / `IMPORT` / `TYPE_REF` / `EXTERNAL_PACKAGE`
  - **효과:** 순수 유실 심볼(Ghost)과 정상 패키지(EXTERNAL_PACKAGE)를 분리하고, 실제 런타임 영향도(CALL)와 단순 헤더 참조(INCLUDE)를 구분하여 분석 신뢰도 대폭 상승.

### 3. Assembly Pattern Detection (진입점 탐지 패턴)
- **현상:** 통계 기반(가장 많이 연결된 노드)으로 어셈블리 포인트를 찾으려다 보니, 정작 실제 진입점(`main`, `start_kernel` 등)은 의존성이 적어 놓치고 엉뚱한 테스트 파일이 잡힘.
- **계획:** 단순히 연결 수가 많은 놈이 아니라, 실제 Entry Point를 식별하는 패턴 매칭 도입.
  - 예: `int main()`, `start_kernel()`, `module_init()`, `initcall` 
  - **효과:** 시스템의 실제 부트/초기화 체인을 정확히 식별하여 Assembly Point 출력의 신뢰성 회복.

## ⛔ 버려진 과제 (Rejected)
- **Kconfig / Build Graph 인식:**
  - 사유: 커널 분석용 `#ifdef CONFIG_*` 파싱 및 `.config` 해석은 아키텍처 스캐너(Scanner)의 영역을 벗어난 컴파일러 프론트엔드(Compiler Frontend)의 영역임. 이를 구현하려다가는 Makefile, Device Tree 지옥이 열리며 개발/유지보수 비용(ROI)이 극도로 낮음. (YAGNI 원칙에 따라 폐기)
