# v0.3.34.22 Acceptance Validation Rules

This document defines the strict criteria for what constitutes a "PASS" in SYNAPSE's Final Acceptance Validation. Emitting a finding is not enough; the finding must align with architectural ground truth and be mathematically/logically explainable.

## 1. Ground Truth Validation (The "Creator's Test")
A feature only passes if its output matches the human architect's mental model of the system.

### Q1: 어디서 시작해야 하나? (Entry Points)
- **Engine Output:** List of top entry nodes.
- **Ground Truth (SYNAPSE):** e.g., `Extension.ts`, `CanvasEngine`, `RuleEngine`, `GraphModel`.
- **Validation Rule:** The engine's top 5 must contain at least 3 of the human-defined ground truth entry points.
- **Fail Condition:** Outputting generic utilities or leaf nodes (e.g., `Logger`, `ThemeManager`) as primary entry points.

### Q2: 누가 시스템을 지배하는가? (Authority Ranking)
- **Engine Output:** Ranked list of `DOMINANT_AUTHORITY` / `MAJOR_AUTHORITY`.
- **Ground Truth (SYNAPSE):** `GraphModel`, `CanvasEngine`, `RuleEngine` must be at the very top.
- **Validation Rule:** The top 10 list must accurately reflect the system's centers of gravity. Ranking `ThemeManager` higher than `GraphModel` is an immediate FAIL, even if the math technically produced a score.

### Q7 & Q8: 데이터/제어권은 어떻게 흐르는가? (Known Flow Validation)
- **Engine Output:** `DATA_PIPELINE` and `CONTROL_PIPELINE` paths.
- **Ground Truth (SYNAPSE):** 
  - Data: `FileScanner` -> `DataPipeline` -> `LayoutEngine` -> `Canvas`
  - Control: `WebviewInterceptor` -> `CommandDispatcher` -> `RuleEngine`
- **Validation Rule:** The engine must independently discover and accurately trace these known corridors.
- **Fail Condition:** Emitting garbage paths (e.g., `A -> import -> B`) as Data/Control pipelines, or failing to identify the primary known pipelines.

## 2. Explainability Validation (The "Why" Test)
An answer is only acceptable if SYNAPSE can defend it using evidence.

- **Requirement:** Every top-level answer MUST include a human-readable explanation derived from evidence.
- **Example Pass (Q2):** "GraphModel (Authority Score: 91). Evidence: State Owner (Role), Reachability 52, Fan-In 120, Fan-Out 84."
- **Example Fail:** "GraphModel (Authority Score: 91). Evidence: [ev-101, ev-102]." (Opaque IDs are unacceptable for final acceptance).

## 3. Revised Phase Priorities
To answer the most critical architect questions first, future phases are reprioritized:

1. **Phase 5: Boundary Layer (Q6)** - Finding the edges (UI vs Logic).
2. **Phase 6: Criticality Layer (Q3)** - Core vs Supporting vs Utility (Addresses "What is essential?").
3. **Phase 7: Extension Point Layer (Q4)** - Identifying where to plug in.
4. **Phase 8: Blast Radius Layer (Q5)** - Predicting collapse points based on Authority + Flow.
