# v0.3.34.22 Answer Acceptance Harness

This document defines the exact Input, Expected Output, and Validation Rules for testing the `AnswerEngine` (Phase 9). The `AnswerEngine` must pass these tests in `test/answer_engine_validation.test.ts` to be considered successful.

## Q1 Entry Point Acceptance
- **Input:** `CONTROL_PIPELINE` and `DOMINANT_AUTHORITY` findings.
- **Expected:** Top Entry Points Ranking.
- **Validation Rules:**
  1. Root nodes of high-confidence control pipelines reaching dominant authorities are returned.
  2. The explanation must state *why* it is an entry point (e.g., "Originates 3 control pipelines").
  3. `supportingFindings` array must contain the IDs of the pipelines and authorities used.

## Q2 Authority Acceptance
- **Input:** `DOMINANT_AUTHORITY` and `MAJOR_AUTHORITY` findings.
- **Expected:** Top 10 Authority Ranking.
- **Validation Rules:**
  1. `GraphModel` must be in the Top 3.
  2. `ThemeManager` (a high-fan-in utility, if it exists in the test graph) must NOT rank higher than `GraphModel`.
  3. Explanation string must contain semantic translations of Evidence: must mention "Role", "Reachability", and "Dependency".
  4. Outputting raw `ev-xyz` IDs in the human-readable explanation is a strict FAIL. `supportingFindings` is where IDs belong.

## Q7 Data Flow Acceptance
- **Input:** `DATA_PIPELINE` findings.
- **Expected:** Primary Data Corridors.
- **Validation Rules:**
  1. Must trace known data pipelines (e.g., `FileScanner -> DataPipeline -> Canvas`).
  2. Output must be deduplicated.
  3. Confidence score of the pipeline must be exposed.

## Q8 Control Flow Acceptance
- **Input:** `CONTROL_PIPELINE` findings.
- **Expected:** Primary Control Corridors.
- **Validation Rules:**
  1. Must trace known control pipelines (e.g., `Button -> CommandDispatcher -> RuleEngine`).
  2. Output must be deduplicated.
  3. Confidence score of the pipeline must be exposed.
