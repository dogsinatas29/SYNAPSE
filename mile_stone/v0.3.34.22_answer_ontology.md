# v0.3.34.22 Answer Ontology

SYNAPSE is an **Architect Answer Engine**. Generating `Finding` objects is merely the intermediate step; the ultimate output must be a human-readable, evidence-backed `Answer` to one of the 8 core architectural questions.

This ontology maps how raw findings are aggregated and transformed into Answers.

## The Transformation Pipeline
`Evidence -> Rule -> Finding -> AnswerAggregator -> Answer`

## Question Mapping & Templates

### Q1: 어디서 시작해야 하나? (Where to start?)
- **Required Findings:** `CONTROL_PIPELINE` (roots), `DOMINANT_AUTHORITY`.
- **Answer Logic:** Find nodes that act as the starting point (source) of Control Pipelines that eventually touch Dominant Authorities.
- **Answer Template:**
  ```text
  Top Entry Points:
  1. [Node] - [Reason: e.g., "Originates 3 control pipelines reaching the core engine."]
  ```

### Q2: 누가 시스템을 지배하는가? (Who dominates?)
- **Required Findings:** `DOMINANT_AUTHORITY`, `MAJOR_AUTHORITY`.
- **Answer Logic:** Rank by confidence/score. Aggregate underlying evidence into human-readable points.
- **Answer Template:**
  ```text
  1. [Node] (Authority Score: [X])
     근거:
     - [Role] (e.g., State Owner)
     - Reachability: [X]
     - Fan-In / Fan-Out: [X] / [Y]
  ```

### Q3: 무엇이 핵심이고 무엇이 부수적인가? (Core vs Utility)
- **Required Findings:** `CORE`, `SUPPORTING`, `UTILITY` (Pending Phase 6).
- **Answer Logic:** Group the system into three distinct buckets to separate domain logic from infrastructure noise.
- **Answer Template:**
  ```text
  Core Pillars: [Nodes]
  Supporting Logic: [Nodes]
  Utilities (High reuse, low logic): [Nodes]
  ```

### Q4: 어디서 확장해야 하나? (Where to extend?)
- **Required Findings:** `EXTENSION_POINT` (Pending Phase 7).
- **Answer Logic:** List interfaces or abstract classes that the system depends on but expect external implementation.
- **Answer Template:**
  ```text
  Designed Extension Points:
  1. [Interface Node] - [Reason: e.g., "Injected into 5 Core controllers."]
  ```

### Q5: 어디를 건드리면 무너지는가? (Blast Radius)
- **Required Findings:** `BLAST_RADIUS` (Pending Phase 8), `AUTHORITY`, `DATA_PIPELINE`.
- **Answer Logic:** Identify nodes whose mutation breaks the most critical data and control pipelines.
- **Answer Template:**
  ```text
  Critical Chokepoints (High Blast Radius):
  1. [Node] - [Reason: e.g., "Modifying this alters state read by 4 Dominant Authorities."]
  ```

### Q6: 시스템 경계는 어디인가? (Boundaries)
- **Required Findings:** `BOUNDARY`, `BOUNDARY_CROSSER` (Pending Phase 5).
- **Answer Logic:** Group nodes by isolated islands or explicit layer borders (e.g., UI vs Domain).
- **Answer Template:**
  ```text
  System Boundaries:
  - Boundary: [Layer A] <-> [Layer B]
  - Crosser: [Adapter Node] handles [N] cross-layer calls.
  ```

### Q7: 데이터는 어떻게 흐르는가? (Data Flow)
- **Required Findings:** `DATA_PIPELINE`.
- **Answer Logic:** Present the most confident state-transfer paths.
- **Answer Template:**
  ```text
  Primary Data Corridors:
  1. [A] -> [B] -> [C] (Confidence: [X])
  ```

### Q8: 제어권은 어떻게 흐르는가? (Control Flow)
- **Required Findings:** `CONTROL_PIPELINE`.
- **Answer Logic:** Present the highest-confidence orchestration paths.
- **Answer Template:**
  ```text
  Primary Control Corridors:
  1. [A] -> [B] -> [C] (Confidence: [X])
  ```
