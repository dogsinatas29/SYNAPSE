# v0.3.34.22 Extension Point Ontology

The Extension Point Layer (Phase 7) defines where the architecture is intentionally left open for modification without modifying core source code (Open/Closed Principle). 

## The Prime Directive
> An Extension Point is NOT merely a code abstraction or an interface. It is a "structural opening" intentionally designed to absorb future variation.

## Core Distinction
- `interface ILogger` with `ConsoleLogger` is an **Abstraction**. It decouples logging implementation but is not structurally designed for widespread external extension.
- `interface IRule` with 15 implementations, a `RuleRegistry`, and a `RuleEngine` that iterates over them is an **Extension Point**. The system is structurally designed to consume an infinite number of rules without modifying the engine.

## Findings Ontology

To avoid Finding Type Explosion (e.g., `PLUGIN_POINT`, `STRATEGY_POINT`), this layer strictly emits ONE finding type:

### 1. `EXTENSION_POINT`
A structural seam in the architecture designed for polymorphic injection or registry-based discovery.
- **Criteria:** 
  1. Multiple implementations exist.
  2. The interface is injected into or consumed by a Core/Supporting component (usually via a collection or registry).
  3. Often crosses Boundaries (Implementation lives in a different boundary than the Interface/Engine).
