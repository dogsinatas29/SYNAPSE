# v0.3.34.22 Flow Ontology

Before implementing the Flow Layer, we must strictly define what constitutes "Flow". Flow is the transmission of power (data or control) across boundaries.

## 1. Flow Types

### 1.1 Data Flow
Data flow represents the physical movement of state, payloads, or models through the system.
- **Evidence Markers:** `return` edges, data object passing, state injection.
- **Ontology Definition:** Movement of `State`, `DTO`, `Model`, `Payload`.
- **Example:** `GraphModel` -> `DataPipeline` -> `CanvasEngine` (State flows to Render).

### 1.2 Control Flow
Control flow represents the delegation of execution authority or orchestration of actions.
- **Evidence Markers:** `call` edges, event dispatching, callbacks, interface invocation.
- **Ontology Definition:** Movement of `Command`, `Dispatch`, `Event`, `Callback`, `Invocation`.
- **Example:** `WebviewInterceptor` -> `CommandDispatcher` -> `RuleEngine` (Command triggers Execution).

## 2. Flow Topologies

### 2.1 Flow Segment
A single hop between two nodes.
- **Notation:** `A -> B`
- **Meaning:** Direct coupling where A passes data or control to B.

### 2.2 Flow Path
A transitive sequence of segments representing a complete pipeline.
- **Notation:** `A -> B -> C -> D`
- **Meaning:** A macroscopic corridor of power. The ultimate origin (A) and ultimate destination (D) are connected.

## 3. Boundary Crossing (Future Phase Setup)
Flows that cross architectural boundaries (e.g., UI to Core) are critical security and architectural chokepoints.
- **UI → Core:** Translating user intent to system commands.
- **Core → Transport:** Serializing state for external systems.
- **Transport → External:** Crossing the system edge.

## 4. Extraction Rules
- **Extractor Phase:** Recognizes physical edges (`call`, `dispatch`, `return`) and emits `IDataFlowSegmentEvidence` and `IControlFlowSegmentEvidence`.
- **Analyzer Phase (`FlowAnalyzer`):** Stitches segments together to form `IDataPathEvidence` and `IControlPathEvidence`.
## 5. Flow Constraints (Path Explosion & Cycle Prevention)
To prevent O(2^N) path explosion in large graphs, the `FlowAnalyzer` MUST adhere to these strict limits:

### 5.1 Maximum Depth
- **Limit:** `MAX_FLOW_DEPTH = 5`
- **Rule:** A path traversal must terminate if it reaches 5 segments. Any path longer than this is too diffuse to be considered a strong architectural corridor.

### 5.2 Maximum Paths Per Source
- **Limit:** `MAX_PATHS_PER_SOURCE = 10`
- **Rule:** If a single node originates more than 10 distinct paths, it is a utility broadcaster. The analyzer should stop discovering paths from this node.

### 5.3 Cycle Resolution
- **Rule:** Cyclic dependencies (`A -> B -> C -> A`) are extremely common in Control Flow.
- **Handling:** If a node is encountered that is already in the current traversal path, the path terminates immediately as a valid sequence up to that point. The duplicate node is NOT appended.

## 6. Flow Confidence Accumulation
A Flow Path is only as strong as its weakest link.
- **Segment Confidence:** `dispatch` (0.9), `call` (0.7), `import` (0.3).
- **Pipeline Confidence:** The total confidence of a `PathEvidence` is the product (or weighted average) of its segment confidences. Low-confidence edges degrade the validity of the entire pipeline.
