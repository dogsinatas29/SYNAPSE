# v0.3.34.22 Phase 1 Validation Plan

To ensure Phase 1 meets the strict requirements of `v0.3.34.22_bootstrap.md`, the following validations must pass before moving to Phase 2 (Role Classification).

## 1. EvidenceExtractor Purity Validation
**Goal:** Prove `EvidenceExtractor` is strictly an observer.
- **Check:** Ensure it only outputs raw counts and facts (e.g., `inDegree: 5`).
- **Check:** Ensure it contains ZERO strings or enums related to `Authority`, `Role`, `Boundary`, or `Critical`.
- **Action:** Add explicit code review and automated lint/grep checks against the extractor.

## 2. RuleEngine Traceability Validation
**Goal:** Prove a `Finding` can explain exactly why it exists.
- **Check:** A Dummy Rule (`R-000 Dummy Structural Rule`) must be created.
- **Check:** The `Finding` produced must include `evidenceIds` linking to specific extracted evidence, and an `explanation` that uses the evidence data.
- **Action:** Write an End-to-End test to output and verify a Finding.

## 3. ReasoningSnapshot Immutability
**Goal:** Prevent rules from mutating the observed state and affecting subsequent rules.
- **Action:** Refactor `ReasoningSnapshot.ts`.
- **Action:** Implement `freeze()` or use `readonly` arrays that cannot be mutated once extraction is complete.

## 4. RuleRegistry Robustness
**Goal:** Ensure the registry can safely handle hundreds of rules.
- **Action:** Refactor `RuleRegistry` to throw on duplicate rule IDs.
- **Action:** Add support to enable/disable specific rules.

## 5. End-to-End Execution Test
**Goal:** Prove the pipeline works without the `GraphModel` leaking into the reasoning logic.
- **Action:** Create `test/phase1_validation_e2e.ts`.
- **Flow:** `Mock Graph` -> `Extractor` -> `Snapshot.freeze()` -> `RuleRegistry(DummyRule)` -> `Finding`.
