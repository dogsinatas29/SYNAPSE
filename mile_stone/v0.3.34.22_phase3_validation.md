# v0.3.34.22 Phase 3 Validation Plan

To ensure the "Authority" concept is not diluted into mere "Centrality" or "Role Count", Phase 3 must pass the following semantic and structural validations before we can proceed to Phase 4 (Flow Layer).

## 1. Authority vs Centrality Validation
**Goal:** Prove that a high number of connections does not automatically grant Authority status.
- **Test Case (UtilityHub):**
  - `fanIn` = 500
  - `fanOut` = 300
  - `RoleDensity` = 0
  - `DecisionReach` = 0
- **Expected Result:** `AUTHORITY_CANDIDATE` or lower.
- **Forbidden Result:** `DOMINANT_AUTHORITY`

## 2. Role Density Inflation Validation
**Goal:** Prove that having many roles does not automatically grant Authority status if influence is missing.
- **Test Case (TinyManager):**
  - Roles: `STATE_OWNER`, `POLICY_OWNER`, `CONTROLLER` (Density = 3)
  - `fanIn` = 1
  - Reach = 1
- **Expected Result:** Not an Authority.

## 3. Reachability Consistency Validation
**Goal:** Fix the definition of Reachability to prevent inconsistent scoring.
- **Definition:** For Phase 3, Reachability is defined as **N-hop transitive reach**. 
  *(A -> B -> C -> D means A has a reach of 3).*

## 4. Authority Threshold Validation
**Goal:** Verify exact threshold boundaries for Authority classification.
- **Test Cases:**
  - Score 0 ~ 39: None
  - Score 40 ~ 59: `AUTHORITY_CANDIDATE`
  - Score 60 ~ 79: `MAJOR_AUTHORITY`
  - Score 80+: `DOMINANT_AUTHORITY`

## 5. Explainability Validation
**Goal:** Ensure every Authority Finding can explain itself completely.
- **Check:** Every `AUTHORITY_CANDIDATE`, `MAJOR_AUTHORITY`, and `DOMINANT_AUTHORITY` Finding MUST include an array of `AuthorityContribution` (or equivalent formatted output) detailing exact points for State Ownership, Dependency Centrality, etc.
- **Forbidden:** Finding a score without a breakdown.

## 6. Ontology Compliance Validation
**Goal:** Prove the strict separation of concerns.
- **Check:** `AuthorityRule` must ONLY read `Influence Evidence` (like `IRoleDensityEvidence`, `IDependencyEvidence`, `IReachabilityEvidence`).
- **Forbidden:** `AuthorityRule` reading `Role Findings` directly.
