# v0.3.34.22 Phase 4 Validation Plan

To ensure the "Flow" concept correctly identifies architectural pipelines without suffering from path explosion or ontology contamination, Phase 4 must pass the following structural and logic validations before proceeding.

## 1. Data vs Control Separation Validation
**Goal:** Prove that Data Flow and Control Flow paths do not cross-contaminate unless explicitly merged.
- **Test Case 1 (Data):** `GraphModel` ->(return)-> `DataPipeline` ->(return)-> `Canvas`
  - Expected: `DATA_PIPELINE`
- **Test Case 2 (Control):** `Button` ->(dispatch)-> `CommandBus` ->(call)-> `RuleEngine`
  - Expected: `CONTROL_PIPELINE`
- **Forbidden:** A single path classifying as both Data and Control without semantic justification.

## 2. Path Explosion Validation
**Goal:** Prevent O(2^N) combinatorial explosion in wide graphs.
- **Test Case:** Node A connects to 20 children (B1..B20), which connect to more. 
- **Expected:** `FlowAnalyzer` must enforce `MAX_PATHS_PER_SOURCE = 10`. It should stop exploring from A after emitting 10 distinct paths.

## 3. Depth Cutoff Validation
**Goal:** Prevent infinitely deep or uselessly diffuse pipelines.
- **Test Case:** A -> B -> C -> D -> E -> F -> G
- **Expected:** `MAX_FLOW_DEPTH = 5`. The `FlowAnalyzer` emits a path `A -> B -> C -> D -> E` (5 nodes / 4 edges) and stops tracing further.

## 4. Cycle Validation
**Goal:** Terminate tracing when encountering cycles.
- **Test Case:** A -> B -> C -> A
- **Expected:** Emits `A -> B -> C`. Tracing stops instead of hanging in an infinite loop.

## 5. Confidence Propagation Validation
**Goal:** Verify that a pipeline's confidence degrades based on weak links.
- **Test Case:** `dispatch` (0.9) -> `call` (0.7) -> `import` (0.3)
- **Expected:** The Pipeline confidence is a mathematical combination (e.g., product = 0.189). Weak links accurately reduce trust in the pipeline.

## 6. Path Deduplication Validation
**Goal:** Prevent redundant work and noisy output.
- **Test Case:** The path `A -> B -> C` is discovered via multiple traversals.
- **Expected:** The `ReasoningSnapshot V3` contains only ONE instance of `A -> B -> C` `PathEvidence`.

## 7. Finding Compatibility Validation
**Goal:** Prove the `targetType` schema upgrade cleanly supports both node and path reasoning.
- **Test Case (Authority):** Rule output must specify `targetType: 'NODE'` and `targetIds: ['GraphModel']`.
- **Test Case (Flow):** Rule output must specify `targetType: 'PATH'` and `targetIds: ['GraphModel', 'DataPipeline', 'Canvas']`.
