# v0.3.34.22 Phase 5 Validation (Boundary Layer)

This document defines the strict validation criteria for the Boundary Layer. It ensures that the engine distinguishes between raw "Communities" and architectural "Boundaries", and completely ignores the file system directory structure.

## Core Validation Philosophy
> Community Detection Success ≠ Boundary Detection Success

A mathematical clustering algorithm (like Louvain) might group tightly coupled layers into one giant community, or split a cohesive domain into tiny fragments. The `BoundaryRule` and `BoundaryAnalyzer` must process these raw communities into meaningful architectural boundaries.

---

## Required Validation Tests (`test/phase5_validation.test.ts`)

### 1. Boundary ≠ Folder Test
- **Scenario:** A mock graph where nodes are named `ui/A`, `ui/B`, `core/C`, `infra/D`. The structural edges tightly couple `ui/B` and `core/C` into a single logical domain, while leaving `ui/A` separate.
- **Expected Result:** The `BOUNDARY` findings must group `ui/B` and `core/C` together based on edge evidence.
- **Fail Condition:** If the engine groups `ui/A` and `ui/B` just because of the "ui/" prefix, it fails.

### 2. Bridge Detection Test (Adapter Pattern)
- **Scenario:** `UI Community` and `Core Community` exist. They do not communicate directly. Instead, 100% of their cross-community edges go through a single node: `Adapter`.
- **Expected Result:** `Adapter` is emitted as a `BOUNDARY_CROSSER`.
- **Fail Condition:** `Adapter` is just absorbed into one of the boundaries without being highlighted as the critical structural bridge.

### 3. Island Detection Test (Decoupled Utility)
- **Scenario:** A subgraph of 5 nodes (`UtilityPackage`) has high internal connectivity, but only 1 edge connecting it to the `Main System`.
- **Expected Result:** The `UtilityPackage` is emitted as a `BOUNDARY_ISLAND`.
- **Fail Condition:** The utility package is merged into the main system's boundary, or is just labeled a normal `BOUNDARY` without noting its isolation.

### 4. Giant Community Regression Test (Monolith)
- **Scenario:** `UI`, `Core`, and `Transport` nodes are highly coupled, creating a "Giant Ball of Mud".
- **Expected Result:** The engine must still be able to identify internal fracture planes (e.g., by the Analyzer tuning the Louvain resolution, or the Rule identifying sub-boundaries). If the engine returns 1 single giant `BOUNDARY` and says "I couldn't find any boundaries", the test FAILS. The system must find the boundaries.
