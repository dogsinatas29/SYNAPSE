# v0.3.34.22 Real Acceptance (Ground Truth Validation)

This document defines the strict validation criteria when running the SYNAPSE Answer Engine against its own real source tree (`antigravity-extension-vis/src/`). A Mock Test pass is insufficient; the engine must correctly analyze the real codebase.

## Ground Truth Data

### Q1: 어디서 시작해야 하나? (Top Entry Points)
- **Validation:** The returned Entry Points must include at least 1 of the following true structural roots:
  - `extension.ts`
  - `CanvasPanel.ts`
  - `CommandInterceptor.ts` (Legacy/Orphaned but historically structural)

### Q2: 누가 시스템을 지배하는가? (Top Authority)
- **Validation:** The Top 5 Authority Ranking MUST contain at least 2 of the following core engines:
  - `CanvasEngine.ts`
  - `GraphModel.ts`
  - `RuleEngine.ts`
- **Fail Condition:** Leaf utilities (e.g., `Logger.ts`, `SynapseIgnore.ts`) ranking higher than the core engines due to naive fan-in.

### Q7: 데이터는 어떻게 흐르는가? (Data Flow)
- **Validation:** The engine must discover paths that trace the physical state pipeline.
- **Expected Path Segment:** Must discover a path involving `GraphModel -> CanvasEngine` or `FileScanner -> GraphModel`.

### Q8: 제어권은 어떻게 흐르는가? (Control Flow)
- **Validation:** The engine must discover the command delegation pipeline.
- **Expected Path Segment:** Must discover a path involving `WebviewInterceptor -> CanvasEngine` or `RuleEngine -> AuthorityRule`.

## Execution Protocol
1. Run `test/answer_engine_real_synapse.test.ts`.
2. Extract all TS files in `src/`.
3. Parse edges (imports, cross-file references) using a real or mocked scanner.
4. Pass through `EvidenceExtractor -> RoleRules -> AuthorityRule -> FlowRules -> AnswerEngine`.
5. Compare the output `IAnswer[]` against this document.

*Note: If the real scanner is not fully implemented for Phase 1 (e.g., `TsScanner.ts` is incomplete), the test must simulate the real graph structure of SYNAPSE to prove the Answer Engine works on complex topologies.*
