# v0.3.34.22 Rule Specification
## SYNAPSE Architectural Reasoning Rules

---

# Purpose

This document defines the reasoning rules used by SYNAPSE.

Ontology defines:

```text
What exists.
```

Rules define:

```text
How conclusions are produced.
```

Ontology without Rules:

```text
Vocabulary
```

Rules without Ontology:

```text
Guesswork
```

Architectural reasoning requires both.

---

# Core Reasoning Model

All findings must follow:

```text
Evidence
↓
Rule
↓
Finding
↓
Confidence
↓
Validation
```

Direct transitions are prohibited.

Invalid:

```text
Evidence
↓
Conclusion
```

Invalid:

```text
Graph
↓
AI Guess
↓
Conclusion
```

---

# Rule Structure

Every rule must define:

```text
Rule ID

Rule Name

Purpose

Input Evidence

Conditions

Thresholds

Output Findings

Confidence Formula

Termination Conditions
```

---

# Confidence Model

All findings must produce confidence.

---

## Confirmed

```text
Multiple direct evidence sources exist.
```

Confidence:

```text
80-100
```

---

## Probable

```text
Strong supporting evidence exists.
```

Confidence:

```text
50-79
```

---

## Speculative

```text
Weak or indirect evidence.
```

Confidence:

```text
0-49
```

# Rule Execution Order

Rules must execute in the following order:

```text
Role Classification
↓
Authority
↓
Boundary
↓
Extension
↓
Data Flow
↓
Control Flow
↓
Criticality
↓
Health
↓
Recommendation
```

Execution outside this order requires explicit justification.

---

# Termination Conditions

Reasoning must stop when:

```text
No new evidence exists
```

OR

```text
Confidence decreases below threshold
```

OR

```text
No applicable rules remain
```

OR

```text
Architectural boundary reached
```

---

# Final Rule

SYNAPSE does not discover architecture by intuition.

SYNAPSE discovers architecture through:

Evidence → Rule → Finding → Validation

Every architectural conclusion must be traceable to one or more reasoning rules defined in this document.

Any conclusion that cannot be traced to a rule is invalid.
