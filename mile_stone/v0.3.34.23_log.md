# v0.3.34.23 작업 로그

## 1. Data Pipeline 및 Ground Truth 엣지 추출 디버깅
- **문제점**: 기존 Data Pipeline 실행 시 `IMPLEMENTS` 및 `EXTENDS` 구문이 추출되지 않고 엣지 개수가 0으로 나오는 현상 발생.
- **원인**: `update_project_state.ts` 스크립트 실행 시 `ScannerRegistry`가 초기화되지 않아(기본 파서 작동), `JsTsScanner`의 커스텀 상속 구문 추출 로직이 동작하지 않음.
- **조치**: 
  - `update_project_state.ts` 스크립트에 `ScannerRegistry.getInstance().register(new JsTsScanner())` 명시적 등록 로직 추가.
  - `EdgeBuilder.ts`에 `IMPLEMENTS`, `EXTENDS` 엣지 타입이 정상 매핑되도록 추가.
- **결과**: `project_state.json` 상에 63개의 `IMPLEMENTS` 엣지와 1개의 `EXTENDS` 엣지 정상 추출 완료 (Ground Truth 확보).

## 2. Extension Point Discovery Engine 설계 (아키텍처 축 발견)
- **개념 전환**: ExtensionCandidate(구현체 중심) -> ExtensionPointCandidate(확장 축 중심)으로 시스템 철학 변경.
- **IS_EXTENSION_POINT 메타데이터**: Self-loop 엣지로 인한 향후 그래프 연산 노이즈를 방지하기 위해 엣지가 아닌 `ISemanticNodeFact` (Node Fact) 형태로 `IS_EXTENSION_POINT`를 정의하기로 결정.
- **후보군 필터링 (Threshold)**: 단일 구현체만 있는 인터페이스 배제를 위해, `incoming IMPLEMENTS/EXTENDS >= 2` 인 노드만 Candidate로 승격하도록 기준 수립.
- **가중치 (Evidence Tier)**:
  - Tier 1: Extension Density (단순 확장 구현체 수)
  - Tier 1.5: Cross-cluster Density (구현체가 여러 클러스터/대륙에 걸쳐 있는지 여부 - 강력한 아키텍처 축의 증거)
- **목표 검증 기준 (Acceptance Criteria)**:
  - Top 5 확장 축 도출 목표: `IRule`, `LanguageScanner`, `ArchitectureAnalyzer`, `IAnswerAggregator`, `ChatAdapter`

## 3. 추론 파이프라인(Reasoning Pipeline) 디버깅 및 완전한 데이터 연결
- **문제점**: 보고서에 Q4 Extension Points 정보가 출력되지 않음. `ArchitectureIrBuilder`가 `UI_COMPONENT`로 잘못 매칭됨.
- **원인 1 (Role Misclassification)**: `ArchitectureAuditor.ts`에서 `.includes('ui')`라는 단순 문자열 매칭을 사용하여 `ArchitectureIrBuilder`가 오탐됨.
- **원인 2 (Reasoning Pipeline 단절)**: `Q4ExtensionAggregator`가 ReasoningSnapshot에서 추출한 Evidence가 아닌, 존재하지 않는 `findings` 배열을 필터링(`f.type === 'EXTENSION_POINT'`)하여 데이터를 읽으려 함.
- **원인 3 (아키텍처 혼재)**: 추론 로직이 분리되어 호출되지 않고 기존 진단 로직(`ValidationEngine`)에 파편화될 위험.
- **조치**:
  - `ArchitectureAuditor.ts`: 정규식을 활용하여 정확한 단어 경계(`/(^|\/|_|-)ui($|\/|_|-)/i`)로 매칭하도록 개선하여 오탐 방지.
  - `ReasoningPipelineRunner.ts`: 진단(`ValidationEngine`)과 독립적인 추론 전용 파이프라인 런너 신설.
  - `Q4ExtensionAggregator.ts`: `snapshot.getEvidenceByCategory<IExtensionEvidence>(EvidenceCategory.EXTENSION)`를 사용하여 ReasoningSnapshot에 담긴 Evidence를 직접 읽고, AnswerBundle 객체로 가공하도록 수정.
  - `VirtualDebugger.ts`: Validation 엔진 종료 후 `ReasoningPipelineRunner`를 실행하고 결과를 Context에 삽입.
  - `ValidationReportBuilder.ts`: 결과 AnswerBundle에서 추출된 Q4 항목들을 마크다운 리포트 `## 7. Architectural Reasoning` 섹션에 반영하도록 렌더링 로직 추가.
- **결과**:
  - `ExtensionAnalyzer` 생성 -> `ReasoningSnapshot` 적재 -> `Q4ExtensionAggregator` 판독 -> `ValidationReportBuilder` 출력에 이르는 데이터 흐름이 단절 없이 완벽하게 복구됨.
