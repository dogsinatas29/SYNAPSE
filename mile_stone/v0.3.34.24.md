# 🚀 Milestone v0.3.34.24 - Node Lifecycle FSM (Architecture State Model)

## 📅 작업 정보
- **상태:** 🏗️ Planned (Discovery 60% / Implementation 0%)
- **관련 마일스톤:** v0.3.34.23 (Q4 Extension Point Engine)
- **목표:** 그래프 내 노드의 생애주기(Lifecycle)를 상태 머신(FSM)으로 모델링하여, `UNKNOWN` 쓰레기통을 분해하고 아키텍처 이상 상태를 정량적으로 추적하는 **Architectural Anomaly Report** 를 도출한다.

## 🧠 설계 배경 및 발견 근거

### v0.3.34.23 디버깅에서 발견된 사실
```text
[AGGREGATE_NO_CLUSTER] { collapsedNodeId: "telemetryReporter.ts", nodeFound: false }
[AGGREGATE_NO_CLUSTER] { collapsedNodeId: "README.md", nodeFound: false }
```

- `nodeFound: false` = 노드가 GraphModel에 **존재하지만** 현재 `rawStateNodes`(뷰)에 없음
- 이는 분류 실패(Bug)가 아니라 **View Scope 이탈** — 유효한 상태(Valid State)
- 기존 코드는 이 두 상태를 구분하지 않고 모두 `AGGREGATE_unknown`으로 처리

### 핵심 통찰
> **"UNKNOWN은 버그가 아니라 상태를 정의하지 못한 결과다."**

현재 `UNKNOWN` 쓰레기통에 혼재하는 실제 상태:
1. `OUT_OF_SCOPE` — View Scope 이탈 (정상, ViewState)
2. `UNCLUSTERED` — cluster_id 미배정 (소프트 버그, NodeState)
3. `UNCLASSIFIED` — role 분류 실패 (소프트 버그, NodeState)
4. `CORRUPTED_NODE` — 데이터 구조 손상 (하드 버그, NodeState)

## 🛠️ 상세 설계

### 핵심 원칙: NodeState ↔ ViewState 분리

`telemetryReporter.ts` 사례:
```text
NodeState  = REGISTERED   (GraphModel에 존재)
ViewState  = OUT_OF_SCOPE (rawStateNodes에 없음)
```
노드가 OUT_OF_SCOPE인 게 아니다. **뷰 기준으로** OUT_OF_SCOPE다.

### NodeState (그래프 기준)
```typescript
enum NodeState {
    DISCOVERED,     // 파일 발견
    PARSED,         // AST 파싱 완료
    REGISTERED,     // GraphModel에 등록
    CLUSTERED,      // cluster_id 배정
    CLASSIFIED,     // role 분류 완료

    // 실패 전이
    UNCLUSTERED,    // REGISTERED → cluster_id 배정 실패
    UNCLASSIFIED,   // CLUSTERED → role 분류 실패
    GHOST,          // 참조는 있으나 파일 없음
    CORRUPTED,      // 데이터 구조 손상 (하드 버그)
}
```

### ViewState (뷰 기준)
```typescript
enum ViewState {
    VISIBLE,        // 현재 뷰에 표시
    COLLAPSED,      // 상위 클러스터로 접힘
    FILTERED,       // 사용자 필터에 의해 숨김
    OUT_OF_SCOPE,   // 현재 rawStateNodes 범위 밖
}
```

### NodeEvent (전이 트리거)
```typescript
enum NodeEvent {
    // 정상 전이
    FILE_DISCOVERED,
    AST_PARSED,
    GRAPH_REGISTERED,
    CLUSTER_ASSIGNED,
    ROLE_CLASSIFIED,

    // 실패 전이
    CLUSTER_ASSIGN_FAILED,
    ROLE_CLASSIFY_FAILED,
    DATA_CORRUPTED,
    GHOST_DETECTED,

    // View 전이
    NODE_COLLAPSED,
    NODE_FILTERED,
    VIEW_SCOPE_EXITED,
}
```

### 상태 전이표
| 현재 상태      | 이벤트                    | 다음 상태       |
|-------------|--------------------------|---------------|
| –           | FILE_DISCOVERED          | DISCOVERED     |
| DISCOVERED  | AST_PARSED               | PARSED         |
| PARSED      | GRAPH_REGISTERED         | REGISTERED     |
| REGISTERED  | CLUSTER_ASSIGNED         | CLUSTERED      |
| REGISTERED  | CLUSTER_ASSIGN_FAILED    | UNCLUSTERED    |
| REGISTERED  | GHOST_DETECTED           | GHOST          |
| CLUSTERED   | ROLE_CLASSIFIED          | CLASSIFIED     |
| CLUSTERED   | ROLE_CLASSIFY_FAILED     | UNCLASSIFIED   |
| any         | DATA_CORRUPTED           | CORRUPTED      |
| CLASSIFIED  | NODE_COLLAPSED           | ViewState: COLLAPSED    |
| CLASSIFIED  | NODE_FILTERED            | ViewState: FILTERED     |
| CLASSIFIED  | VIEW_SCOPE_EXITED        | ViewState: OUT_OF_SCOPE |

## ✅ Acceptance Criteria

1. **NodeState / ViewState 분리**: `AGGREGATE_unknown`이 `AGGREGATE_out_of_scope` / `AGGREGATE_unclustered` 등으로 분리 출력
2. **Anomaly Report 추가**: 보고서 신규 섹션에 상태별 수량 및 판정(정상/버그) 집계 출력
3. **UNKNOWN 설명 가능성**: 최종 `UNKNOWN` 수가 0이 목표가 아니라, **남아있는 UNKNOWN이 전부 설명 가능**해야 함
   ```text
   UNKNOWN Count = 7
   → UNCLASSIFIED_ROLE: 4
   → UNCLUSTERED: 2
   → CORRUPTED: 1
   ```
4. **VSCode Main 검증**: Q4 Extension Points에 `AGGREGATE_unknown` 미출력 (실제 out_of_scope로 재분류됨으로써)

### StateTransitionRecord (v0.3.34.25+ 시뮬레이션 기반)
이번 마일스톤에서 **설계만 확정**. 구현은 다음 단계.
```typescript
interface StateTransitionRecord {
    nodeId: string;
    from: NodeState | ViewState;
    to: NodeState | ViewState;
    event: NodeEvent;
    reason: string;
    timestamp?: number;
}
```
이 레코드가 쌓이면:
- `Topology Mutation Replay` — 상태 전이 재생
- `Failure Propagation` — 특정 노드 제거 시 cascading 계산
- `Architectural Impact Simulation` — "PlaybackService 제거 시 영향" 예측
