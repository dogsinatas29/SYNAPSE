# 🚀 Milestone v0.3.34.24 - Architecture State Model (Current-State Analysis FSM)

## 📅 작업 정보

- **상태:** ✅ Completed (2026-08-20)
- **관련 마일스톤:** v0.3.34.23 (Q4 Extension Point Engine)

### 목표

> **UNKNOWN은 버그가 아니다.**
> **UNKNOWN은 상태 머신 관점에서 노드의 상태 또는 상태 전이가 명시적으로 기록되지 않았음을 의미한다.**

따라서 본 마일스톤의 목표는

```text
UNKNOWN 제거
```

가 아니다. 목표는

```text
모든 노드와 참조를
설명 가능한 State 또는 State Transition으로 귀속
```

이다. `UNKNOWN`은 이 과정의 결과로 자연 소멸한다.

---

### 핵심 문장

```text
UNKNOWN = Transition Missing

데이터 품질 문제 ❌
State Machine Completeness 문제 ✅
```

---

### 정의

```text
UNKNOWN은 분류 실패가 아니다.

UNKNOWN은 상태 전이 이력이 존재하지 않는 노드다.

즉, DISCOVERED / PARSED / REGISTERED / CLUSTERED / CLASSIFIED
중 어디에도 속하지 않거나

HealthState / ViewState / ReferenceState
중 어디에도 매핑되지 않은 상태다.
```

---

### 마일스톤 정의

```text
v0.3.34.24 =
```

# 🧠 설계 철학

## SYNAPSE는 고고학 도구가 아니다

SYNAPSE는 과거 설계자의 의도를 복원하려 하지 않는다.

다음 질문들은 대부분의 실제 프로젝트에서 객관적으로 증명할 수 없다.

```text
왜 이 컴포넌트가 만들어졌는가?

왜 이 구조를 선택했는가?

왜 MVC를 사용했는가?

왜 Service Locator를 채택했는가?

왜 이 의존성이 존재하는가?
```

특히 다음과 같은 프로젝트에서는 더욱 그렇다.

- 설계자가 이미 퇴사한 경우
- 수년 이상 유지보수된 장기 프로젝트
- 여러 세대의 개발자가 교체된 프로젝트
- 당시의 기술 제약이 사라진 프로젝트

현재 남아 있는 것은 코드와 구조뿐이며,
원래의 설계 의도는 이미 소실되었을 수 있다.

이 영역은 분석의 영역이 아니라 해석의 영역이다.

---

## SYNAPSE가 답하려는 질문

SYNAPSE는 Why를 복원하지 않는다.

대신 다음 질문에 답한다.

```text
현재 시스템에서 무엇이 존재하는가?

무엇이 핵심 허브인가?

무엇이 가장 큰 영향력을 가지는가?

어디서 결합이 발생하는가?

어디서 경계를 침범하는가?

어디가 위험한가?

어디를 먼저 조사해야 하는가?
```

즉,

```text
Historical Meaning
↓

Current Architectural Significance
```

를 분석한다.

---

## 현재 의미(Current Meaning)의 정의

SYNAPSE에서 의미(Meaning)는

```text
설계자의 의도
```

가 아니다.

의미는 다음과 같이 정의된다.

```text
현재 구조에서의 역할

현재 구조에서의 영향력

현재 구조에서의 위험도

현재 구조에서의 결합도

현재 구조에서의 중요성
```

예를 들어,

```text
kernel/fork.c
```

가 왜 그렇게 설계되었는지는 알 수 없다.

그러나

```text
현재 커널에서 높은 Fan-In을 가지며
광범위한 영향력을 행사한다
```

는 것은 증명할 수 있다.

SYNAPSE는 후자를 다룬다.

는 노드가 존재하지 않는다는 의미가 아니었다.

즉,


```text

```

## 핵심 통찰

> UNKNOWN은 버그가 아니다.
>
> UNKNOWN은 상태 전이 머신에서 전이가 기록되지 않은 상태다.

```text
DISCOVERED
    ↓
PARSED
    ↓
REGISTERED
    ↓
???
```

여기서 `???`는 `UNKNOWN`이 아니다. 정확하게는 **Transition Missing**이다.

---

### FSM Completeness 분류

```typescript
enum FSMCompleteness {
    KNOWN,                 // 모든 전이 기록됨
    INCOMPLETE_TRANSITION, // 전이 단계 누락 (예: DISCOVERED→REGISTERED, PARSED 없음)
    INVALID_TRANSITION,    // 불가능한 전이 (예: DISCOVERED→CLASSIFIED)
}
```

| 케이스 | 경로 | 판정 |
|--------|------|------|
| 정상 | DISCOVERED→PARSED→REGISTERED→CLUSTERED→CLASSIFIED | KNOWN |
| 단계 누락 | DISCOVERED→REGISTERED (PARSED 없음) | INCOMPLETE_TRANSITION |
| 불가능 전이 | DISCOVERED→CLASSIFIED | INVALID_TRANSITION |

보고서 출력:

```text
기존: UNKNOWN: 37

신규: FSM Completeness Report
  Missing Transitions : 31
  Invalid Transitions :  6
```

---

## 목표 재정의

본 마일스톤의 목표는

```text
UNKNOWN Role 제거
```

가 아니다.

역할(Role)은 온톨로지의 한계로 인해 아직 미분류 상태일 수 있다.

예를 들어:

```text
Role = UNKNOWN
```

은 허용 가능하다.

그러나

```text
State = UNKNOWN
```

은 허용될 수 없다.

모든 상태는 반드시 설명 가능해야 한다.

즉,

```text
UNKNOWN Role
    → 허용 가능

UNKNOWN State
    → 허용 불가
```

가 본 마일스톤의 철학이다.

# 🛠️ 상세 설계

## 핵심 원칙

### 1. State vs Transition 분리

```text
State     = 현재 노드가 어떤 단계에 있는가
Transition = 어떤 경로로 그 단계에 도달했는가
```

UNKNOWN = 두 정보 중 하나 이상이 기록되지 않음.

### 2. NodeState ↔ ViewState 분리

```text
telemetryReporter.ts

NodeState = REGISTERED
ViewState = OUT_OF_SCOPE
```

노드가 존재하지 않는 것이 아니다. 현재 뷰 기준으로만 보이지 않을 뿐이다.

### 3. NodeState Aggregate 타입

여러 상태를 각각 들고 다니면 상태 폭발 발생. 단일 객체로 집약.

```typescript
interface NodeState {
    lifecycle: LifecycleState;
    health:    HealthState;
    view:      ViewState;
    fsm:       FSMCompleteness;
}
```

---

## LifecycleState

노드 존재 단계

```typescript
enum LifecycleState {
    DISCOVERED,     // 파일 발견
    PARSED,         // AST 파싱 완료
    REGISTERED,     // GraphModel 등록
    CLUSTERED,      // cluster_id 배정
    CLASSIFIED,     // role 분류 완료
}
```

### 특징

- 단방향 진행
- 정상 흐름만 표현
- 실패 상태는 HealthState로 분리

---

## HealthState

노드 건강 상태

```typescript
enum HealthState {
    HEALTHY,
    UNCLUSTERED,
    UNCLASSIFIED,
    CORRUPTED,
}
```

### 의미

| 상태 | 설명 |
|--------|--------|
| HEALTHY | 정상 |
| UNCLUSTERED | cluster_id 미배정 |
| UNCLASSIFIED | 역할 분류 실패 |
| CORRUPTED | 데이터 손상 |

---

## ViewState

현재 View 기준 상태

```typescript
enum ViewState {
    VISIBLE,
    COLLAPSED,
    FILTERED,
    OUT_OF_SCOPE,
}
```

### 의미

| 상태 | 설명 |
|--------|--------|
| VISIBLE | 현재 표시 중 |
| COLLAPSED | 상위 클러스터에 접힘 |
| FILTERED | 필터에 의해 숨김 |
| OUT_OF_SCOPE | 현재 View 범위 밖 |

---

## ReferenceState

참조 상태

```typescript
enum ReferenceState {
    RESOLVED,
    GHOST,
}
```

### 의미

| 상태 | 설명 |
|--------|--------|
| RESOLVED | 대상 존재 |
| GHOST | 참조 대상 없음 |

### 주의

GHOST는 노드 상태가 아니다.

```text
Node State ❌

Reference State ✅
```

이다.

---

## NodeEvent

```typescript
enum NodeEvent {

    // Lifecycle
    NODE_DISCOVERED,
    NODE_RESOLVED,
    NODE_CLASSIFIED,

    // Health
    NODE_UNCLUSTERED,
    NODE_UNCLASSIFIED,
    NODE_CORRUPTED,

    // View
    NODE_HIDDEN,
    NODE_REVEALED,

    // Reference
    REFERENCE_BROKEN,
    REFERENCE_RESOLVED,
}
```
