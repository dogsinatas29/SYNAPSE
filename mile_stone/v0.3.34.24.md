# 🚀 Milestone v0.3.34.24 - Architecture State Model (Current-State Analysis FSM)

## 📅 작업 정보

- **상태:** 🏗️ Planned (Discovery 60% / Implementation 0%)
- **관련 마일스톤:** v0.3.34.23 (Q4 Extension Point Engine)

### 목표

그래프 내 노드의 상태(State)를 FSM(Finite State Machine)으로 모델링하여 설명 불가능한 `UNKNOWN` 상태를 제거한다.

본 마일스톤의 목적은 프로젝트의 과거 설계 의도(Why)를 복원하는 것이 아니다.

대신 현재 시스템이 어떤 구조를 가지고 있으며,

- 무엇이 존재하는가
- 무엇이 영향력을 가지는가
- 어디서 결합이 발생하는가
- 어디가 위험한가
- 무엇을 먼저 조사해야 하는가

를 정량적으로 설명하는 **Architectural Anomaly Report**를 생성한다.

---

# 🧠 설계 철학

## SYNAPSE는 고고학 도구가 아니다

SYNAPSE는 과거 설계자의 의도를 복원하려 하지 않는다.

다음 질문들은 대부분의 실제 프로젝트에서 객관적으로 증명할 수 없다.

```text
왜 이 컴포넌트가 만들어졌는가?

왜 이 구조를 선택했는가?

왜 MVC를 사용했는가?

왜 Service Locator를 채택했는가?

왜 이 의존성이 존재하는가?
```

특히 다음과 같은 프로젝트에서는 더욱 그렇다.

- 설계자가 이미 퇴사한 경우
- 수년 이상 유지보수된 장기 프로젝트
- 여러 세대의 개발자가 교체된 프로젝트
- 당시의 기술 제약이 사라진 프로젝트

현재 남아 있는 것은 코드와 구조뿐이며,
원래의 설계 의도는 이미 소실되었을 수 있다.

이 영역은 분석의 영역이 아니라 해석의 영역이다.

---

## SYNAPSE가 답하려는 질문

SYNAPSE는 Why를 복원하지 않는다.

대신 다음 질문에 답한다.

```text
현재 시스템에서 무엇이 존재하는가?

무엇이 핵심 허브인가?

무엇이 가장 큰 영향력을 가지는가?

어디서 결합이 발생하는가?

어디서 경계를 침범하는가?

어디가 위험한가?

어디를 먼저 조사해야 하는가?
```

즉,

```text
Historical Meaning
↓

Current Architectural Significance
```

를 분석한다.

---

## 현재 의미(Current Meaning)의 정의

SYNAPSE에서 의미(Meaning)는

```text
설계자의 의도
```

가 아니다.

의미는 다음과 같이 정의된다.

```text
현재 구조에서의 역할

현재 구조에서의 영향력

현재 구조에서의 위험도

현재 구조에서의 결합도

현재 구조에서의 중요성
```

예를 들어,

```text
kernel/fork.c
```

가 왜 그렇게 설계되었는지는 알 수 없다.

그러나

```text
현재 커널에서 높은 Fan-In을 가지며
광범위한 영향력을 행사한다
```

는 것은 증명할 수 있다.

SYNAPSE는 후자를 다룬다.

---

## FSM이 필요한 이유

v0.3.34.23 디버깅 과정에서 다음과 같은 사례가 발견되었다.

```text
[AGGREGATE_NO_CLUSTER]
{
    collapsedNodeId: "telemetryReporter.ts",
    nodeFound: false
}

[AGGREGATE_NO_CLUSTER]
{
    collapsedNodeId: "README.md",
    nodeFound: false
}
```

조사 결과:

```text
nodeFound: false
```

는 노드가 존재하지 않는다는 의미가 아니었다.

```text
GraphModel에는 존재

현재 View Scope에는 없음
```

을 의미했다.

즉,

```text
OUT_OF_SCOPE
```

인 정상 상태였음에도 기존 엔진은 이를

```text
AGGREGATE_unknown
```

으로 처리하고 있었다.

---

## 핵심 통찰

> UNKNOWN은 버그가 아니다.
>
> UNKNOWN은 상태 모델의 부재다.

현재 UNKNOWN 쓰레기통에는 다음 상태들이 혼재되어 있다.

```text
OUT_OF_SCOPE
UNCLUSTERED
UNCLASSIFIED
CORRUPTED
```

이들은 모두 서로 다른 의미를 가진다.

하지만 기존 보고서는 이를 모두

```text
UNKNOWN
```

으로 출력한다.

이는 설명 가능한 상태를 설명 불가능한 상태로 만드는 것이다.

---

## 목표 재정의

본 마일스톤의 목표는

```text
UNKNOWN Role 제거
```

가 아니다.

역할(Role)은 온톨로지의 한계로 인해 아직 미분류 상태일 수 있다.

예를 들어:

```text
Role = UNKNOWN
```

은 허용 가능하다.

그러나

```text
State = UNKNOWN
```

은 허용될 수 없다.

모든 상태는 반드시 설명 가능해야 한다.

즉,

```text
UNKNOWN Role
    → 허용 가능

UNKNOWN State
    → 허용 불가
```

가 본 마일스톤의 철학이다.

# 🛠️ 상세 설계

## 핵심 원칙

### NodeState ↔ ViewState 분리

예시:

```text
telemetryReporter.ts

NodeState = REGISTERED
ViewState = OUT_OF_SCOPE
```

노드가 존재하지 않는 것이 아니다.

현재 뷰 기준으로만 보이지 않을 뿐이다.

---

## LifecycleState

노드 존재 단계

```typescript
enum LifecycleState {
    DISCOVERED,     // 파일 발견
    PARSED,         // AST 파싱 완료
    REGISTERED,     // GraphModel 등록
    CLUSTERED,      // cluster_id 배정
    CLASSIFIED,     // role 분류 완료
}
```

### 특징

- 단방향 진행
- 정상 흐름만 표현
- 실패 상태는 HealthState로 분리

---

## HealthState

노드 건강 상태

```typescript
enum HealthState {
    HEALTHY,
    UNCLUSTERED,
    UNCLASSIFIED,
    CORRUPTED,
}
```

### 의미

| 상태 | 설명 |
|--------|--------|
| HEALTHY | 정상 |
| UNCLUSTERED | cluster_id 미배정 |
| UNCLASSIFIED | 역할 분류 실패 |
| CORRUPTED | 데이터 손상 |

---

## ViewState

현재 View 기준 상태

```typescript
enum ViewState {
    VISIBLE,
    COLLAPSED,
    FILTERED,
    OUT_OF_SCOPE,
}
```

### 의미

| 상태 | 설명 |
|--------|--------|
| VISIBLE | 현재 표시 중 |
| COLLAPSED | 상위 클러스터에 접힘 |
| FILTERED | 필터에 의해 숨김 |
| OUT_OF_SCOPE | 현재 View 범위 밖 |

---

## ReferenceState

참조 상태

```typescript
enum ReferenceState {
    RESOLVED,
    GHOST,
}
```

### 의미

| 상태 | 설명 |
|--------|--------|
| RESOLVED | 대상 존재 |
| GHOST | 참조 대상 없음 |

### 주의

GHOST는 노드 상태가 아니다.

```text
Node State ❌

Reference State ✅
```

이다.

## NodeEvent

```typescript
enum NodeEvent {

    // Lifecycle
    NODE_DISCOVERED,
    NODE_RESOLVED,
    NODE_CLASSIFIED,

    // Health
    NODE_UNCLUSTERED,
    NODE_UNCLASSIFIED,
    NODE_CORRUPTED,

    // View
    NODE_HIDDEN,
    NODE_REVEALED,

    // Reference
    REFERENCE_BROKEN,
    REFERENCE_RESOLVED,
}
```

# 상태 전이

## Lifecycle

| 현재 상태 | 이벤트 | 결과 |
|------------|------------|------------|
| - | NODE_DISCOVERED | DISCOVERED |
| DISCOVERED | NODE_RESOLVED | REGISTERED |
| REGISTERED | NODE_CLASSIFIED | CLASSIFIED |

---

## Health

| 현재 상태 | 이벤트 | 결과 |
|------------|------------|------------|
| REGISTERED | NODE_UNCLUSTERED | UNCLUSTERED |
| CLASSIFIED | NODE_UNCLASSIFIED | UNCLASSIFIED |
| ANY | NODE_CORRUPTED | CORRUPTED |

---

## View

| 현재 상태 | 이벤트 | 결과 |
|------------|------------|------------|
| VISIBLE | NODE_HIDDEN | COLLAPSED/FILTERED |
| ANY | VIEW_SCOPE_EXIT | OUT_OF_SCOPE |
| OUT_OF_SCOPE | NODE_REVEALED | VISIBLE |

---

## Reference

| 현재 상태 | 이벤트 | 결과 |
|------------|------------|------------|
| RESOLVED | REFERENCE_BROKEN | GHOST |
| GHOST | REFERENCE_RESOLVED | RESOLVED |
