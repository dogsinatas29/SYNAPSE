# 🚀 Milestone v0.3.34.24 - Node Lifecycle FSM (Architecture State Model)

## 📅 작업 정보
- **상태:** 🏗️ Planned (Discovery 60% / Implementation 0%)
- **관련 마일스톤:** v0.3.34.23 (Q4 Extension Point Engine)
- **목표:** 그래프 내 노드의 생애주기(Lifecycle)를 상태 머신(FSM)으로 모델링하여, `UNKNOWN` 쓰레기통을 분해하고 아키텍처 이상 상태를 정량적으로 추적하는 **Architectural Anomaly Report** 를 도출한다.

## 🧠 설계 배경 및 발견 근거

### v0.3.34.23 디버깅에서 발견된 사실
```text
[AGGREGATE_NO_CLUSTER] { collapsedNodeId: "telemetryReporter.ts", nodeFound: false }
[AGGREGATE_NO_CLUSTER] { collapsedNodeId: "README.md", nodeFound: false }
```

- `nodeFound: false` = 노드가 GraphModel에 **존재하지만** 현재 `rawStateNodes`(뷰)에 없음
- 이는 분류 실패(Bug)가 아니라 **View Scope 이탈** — 유효한 상태(Valid State)
- 기존 코드는 이 두 상태를 구분하지 않고 모두 `AGGREGATE_unknown`으로 처리

### 핵심 통찰
> **"UNKNOWN은 버그가 아니라 상태를 정의하지 못한 결과다."**

현재 `UNKNOWN` 쓰레기통에 혼재하는 실제 상태:
1. `OUT_OF_SCOPE` — View Scope 이탈 (정상, ViewState)
2. `UNCLUSTERED` — cluster_id 미배정 (소프트 버그, NodeState)
3. `UNCLASSIFIED` — role 분류 실패 (소프트 버그, NodeState)
4. `CORRUPTED_NODE` — 데이터 구조 손상 (하드 버그, NodeState)

## 🛠️ 상세 설계

### 핵심 원칙: NodeState ↔ ViewState 분리

`telemetryReporter.ts` 사례:
```text
NodeState  = REGISTERED   (GraphModel에 존재)
ViewState  = OUT_OF_SCOPE (rawStateNodes에 없음)
```
노드가 OUT_OF_SCOPE인 게 아니다. **뷰 기준으로** OUT_OF_SCOPE다.

### LifecycleState (노드 존재 단계 — 단방향 진행)
```typescript
enum LifecycleState {
    DISCOVERED,     // 파일 발견
    PARSED,         // AST 파싱 완료
    REGISTERED,     // GraphModel에 등록
    CLUSTERED,      // cluster_id 배정
    CLASSIFIED,     // role 분류 완료
}
```
> 정상 경로만 존재. 실패는 HealthState로 기록.

### HealthState (분류 실패 판정 — NodeState 이상 상태)
```typescript
enum HealthState {
    HEALTHY,        // 정상 (기본값)
    UNCLUSTERED,    // cluster_id 미배정 (소프트 버그)
    UNCLASSIFIED,   // role 분류 실패 (소프트 버그)
    CORRUPTED,      // 데이터 구조 손상 (하드 버그)
}
```
> `CLASSIFIED` 상태 노드도 `UNCLUSTERED`가 되지 않는다. 두 축이 독립적.

### ViewState (현재 뷰 기준 — 노드 상태 아님)
```typescript
enum ViewState {
    VISIBLE,        // 현재 뷰에 표시
    COLLAPSED,      // 상위 클러스터로 접힘
    FILTERED,       // 사용자 필터에 의해 숨김
    OUT_OF_SCOPE,   // rawStateNodes 범위 밖 (정상 상태)
}
```

### ReferenceState (엣지/참조 기준 — Node 상태 아님)
```typescript
enum ReferenceState {
    RESOLVED,       // 대상 노드 존재 확인
    GHOST,          // 참조는 있으나 대상 파일 없음
}
```
> GHOST는 노드 상태가 아니다. 노드를 가리키는 **참조(Edge)의 상태**다.

### NodeEvent (도메인 이벤트 — 구현 함수명 아님)
```typescript
enum NodeEvent {
    // Lifecycle
    NODE_DISCOVERED,
    NODE_RESOLVED,       // 파싱 + 등록 완료
    NODE_CLASSIFIED,     // 역할 분류 완료

    // Health
    NODE_UNCLUSTERED,    // cluster_id 배정 실패
    NODE_UNCLASSIFIED,   // role 분류 실패
    NODE_CORRUPTED,      // 데이터 손상

    // View
    NODE_HIDDEN,         // COLLAPSED / FILTERED
    NODE_REVEALED,       // 다시 표시

    // Reference
    REFERENCE_BROKEN,    // 대상 노드 소실 → GHOST
    REFERENCE_RESOLVED,  // GHOST → 대상 복구
}
```

### 상태 전이표
| LifecycleState | 이벤트               | 결과                        |
|---------------|---------------------|-----------------------------|
| –             | NODE_DISCOVERED     | DISCOVERED                  |
| DISCOVERED    | NODE_RESOLVED       | REGISTERED                  |
| REGISTERED    | NODE_CLASSIFIED     | CLASSIFIED                  |
| REGISTERED    | NODE_UNCLUSTERED    | HealthState: UNCLUSTERED    |
| CLASSIFIED    | NODE_UNCLASSIFIED   | HealthState: UNCLASSIFIED   |
| any           | NODE_CORRUPTED      | HealthState: CORRUPTED      |

| ViewState (CLASSIFIED 이후) | 이벤트          | 결과              |
|---------------------------|----------------|-------------------|
| VISIBLE                   | NODE_HIDDEN     | COLLAPSED/FILTERED|
| any                       | VIEW_SCOPE_EXIT | OUT_OF_SCOPE      |
| OUT_OF_SCOPE              | NODE_REVEALED   | VISIBLE           |

| ReferenceState | 이벤트              | 결과      |
|---------------|---------------------|-----------|
| RESOLVED      | REFERENCE_BROKEN    | GHOST     |
| GHOST         | REFERENCE_RESOLVED  | RESOLVED  |

## ✅ Acceptance Criteria

1. **상태 4분리**: `AGGREGATE_unknown`이 `AGGREGATE_out_of_scope` / `AGGREGATE_unclustered` 등 명시적 상태명으로 분리 출력
2. **Anomaly Report 추가**: 보고서 신규 섹션에 HealthState / ViewState / ReferenceState 별 수량 집계 출력
3. **UNKNOWN 설명 가능성**: 남은 `UNKNOWN`이 전부 원인 포함하여 설명 가능해야 함
   ```text
   UNKNOWN Count = 7
   → HealthState.UNCLUSTERED: 2
   → HealthState.UNCLASSIFIED: 4
   → HealthState.CORRUPTED: 1
   ```
4. **VSCode Main 검증**: Q4 Extension Points에 `AGGREGATE_unknown` 미출력

### StateTransitionRecord (v0.3.34.25+ 시뮬레이션 기반)
이번 마일스톤에서 **설계만 확정**. 구현은 다음 단계.
```typescript
interface StateTransitionRecord {
    nodeId: string;
    lifecycle: LifecycleState;
    health: HealthState;
    view: ViewState;
    event: NodeEvent;
    reason: string;
    timestamp?: number;
}
```
이 레코드가 쌓이면:
- `Topology Mutation Replay` — 상태 전이 재생
- `Failure Propagation` — 특정 노드 제거 시 cascading 계산
- `Architectural Impact Simulation` — "PlaybackService 제거 시 영향" 예측

## ⚠️ 예외 처리 및 주의 사항

- **이번 범위**: AGGREGATE 상태 분리 + Anomaly Report + StateTransitionRecord 타입 설계
- **다음 범위 (v0.3.34.25+)**: 이벤트 스트림 수집, 시간축, What-If Simulation
