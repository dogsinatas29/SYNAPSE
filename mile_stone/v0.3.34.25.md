## 🧠 상세 설계

### Transition Grammar

상태 전이 규칙을 선언형으로 정의.

```typescript
// 허용 전이 예시
UNCLUSTERED → CLUSTERED      ✅
CLUSTERED   → CORRUPTED      ✅ (데이터 손상)
CLASSIFIED  → UNCLASSIFIED   ✅ (role 제거)

// 금지 전이 예시
OUT_OF_SCOPE → CORE_RUNTIME  ❌ (View 상태 → NodeState 불가)
DISCOVERED   → CLASSIFIED    ❌ (단계 건너뜀)
HEALTHY      → DISCOVERED    ❌ (역방향 불가)
```

### 구현 대상

```typescript
// TransitionRule: 허용/금지 선언 단순 객체 (배열, 런타임 상수)
interface TransitionRule {
    from        : LifecycleState | HealthState | ViewState;
    to          : LifecycleState | HealthState | ViewState;
    allowed     : boolean;
    reason      : string;
}

// TransitionGrammar: Rule 집합 + 검증기
class TransitionGrammar {
    validate(from: NodeState, to: NodeState): TransitionValidation;
    audit(nodes: NodeState[]): FSMAuditSummary;
}

interface FSMAuditSummary {
    validTransitions   : number;
    invalidTransitions : number;
    unknownPaths       : number;
    violations         : TransitionViolation[];
}

interface TransitionViolation {
    nodeId  : string;
    from    : string;
    to      : string;
    reason  : string;
}
```

### AnomalyCollector 연계

`AnomalyCollector`는 현재 단일 스냅샷 기준 상태 판정.
`TransitionGrammar`는 두 상태(이전→현재)의 전이 유효성 판정.

```text
AnomalyCollector.classifyNode(node)  →  NodeState (현재)
TransitionGrammar.validate(prev, cur) →  TransitionValidation
TransitionGrammar.audit(allStates)   →  FSMAuditSummary
```

## ⚠️ 예외 처리 및 주의 사항

### Memory Budget
- TransitionRule 배열: ~50개 이하 규칙 → 수 KB
- FSMAuditSummary: 숫자 카운터 + violations 배열 → 노드 수 비례하나 count 기반이면 O(1)
- violations 배열에 모든 위반 저장 시 메모리 위험 → **상위 N개 cap 필수**

### 역방향 전이 처리
- LifecycleState는 단방향 (DISCOVERED→CLASSIFIED)
- 역방향(CLASSIFIED→DISCOVERED)은 명시적 CORRUPTED 이벤트를 거쳐야 유효
- 직접 역방향은 INVALID

### View State ↔ Node State 혼용 금지
- `OUT_OF_SCOPE → CLASSIFIED` 같은 cross-axis 전이는 문법 자체가 성립 불가
- 축이 다른 전이는 Rule 등록 전에 필터링
