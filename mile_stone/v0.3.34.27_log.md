# v0.3.34.27 작업 기록 (Topology Mutation)

## 📌 작업 요약
- **목표:** Graph Clone 없이 순수 물리 토폴로지 변경 시뮬레이션 환경 구축 (메모리 OOM 방지)
- **작업일:** 2026-08-21
- **관련 마일스톤:** `mile_stone/v0.3.34.27.md`

## 🛠️ 세부 구현 내역

### 1. `TopologyOverlay.ts` 구현
- 70,000개 노드/380,000개 엣지 그래프를 통째로 복사하는 대신, 변경분만 저장하는 `TopologyOverlay` 클래스를 `src/core/simulation/` 에 추가.
- `mutatedStates` (상태 변화) 개념 배제. 오직 `removedNodes`, `removedEdges`, `addedEdges`만 추적함.
- `isNodeAlive`, `isEdgeActive`, `getActiveEdges` 메서드를 제공하여 가상 뷰 형성.

### 2. `SimulationTargetSelector.ts` 분리
- 27버전 엔진이 리포트 계층 심각도 등급(HIGH)에 의존하여 계층 간 침범이 일어나는 문제를 방지.
- `SimulationTargetSelector`를 통해 객관적인 합산 파급력 (Direct + Indirect + Cascade) 기준으로 `Top N Impact Nodes`를 산출하여 시뮬레이션 타겟을 결정.

### 3. `TopologyMutator.ts` 엔진 작성
- 선정된 Top N 노드들에 대해, `TopologyOverlay`를 생성하고 26버전의 `FailurePropagator`를 호출하여 재계산을 수행.
- 반복문 종료 시마다 `overlay` 인스턴스 폐기하여 GC를 유도 (`Compute → Report → Discard` 원칙 철저).

### 4. `FailurePropagator.ts` 및 파이프라인 리팩토링
- `FailurePropagator` 엔진이 선택적 매개변수 `overlay`를 받아 BFS 전파 중 `!overlay.isNodeAlive()` 등을 확인하도록 수정 (26번 엔진 재사용).
- `StateAuditPipeline.ts`에 Mutation 단계를 추가하고 `memoryMetrics`를 단계별로 로깅하도록 추적기 부착.

## 💡 의사결정 기록 (Invariant)
- **State Simulation 금지:** 노드가 교체되거나 지워졌다고 해서 타겟 노드의 상태가 CORRUPTED로 바뀐다고 자의적으로 추정(시뮬레이션)하지 않는다. 27버전은 순수하게 연결망이 끊겼을 때의 물리적 파급 범위 변화만 관찰한다.
- **Topology = Graph Structure:** Graph Clone 금지 원칙을 고수하기 위해 `Overlay` 패턴을 정립하였으며, 테스트 결과 메모리 증분은 0.00MB(가비지 컬렉션 즉각 반영) 수준으로 최적화됨.
