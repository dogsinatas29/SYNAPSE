# 🚀 Milestone v0.3.34.31 - Semantic Hub Recognition & Wrapper Bug Fix

## 📅 작업 정보 
- **상태:** ✅ Completed 
- **관련 마일스톤:** v0.3.34.24
- **목표:** 단순한 Fan-out 횟수 기반의 위험도 판별을 넘어, Semantic Context를 기반으로 의도된 아키텍처 허브(Intended Hub)와 구조적 결함(Structural Defect)을 정확히 구분하는 판독력 확보.

## 🧠 상세 설계 및 로직 
- **Semantic Hub 식별 로직 확립:**
  - `RiskClassifier` 내부의 판별 우선순위를 재조정하여, 높은 Fan-out과 사이클을 가지더라도 Strong Boundary 내부에 존재하는 경우 `STRUCTURAL_DEFECT` (CRITICAL) 대신 `INTENDED_HUB` (INFO)로 분류하도록 수정.
  - 이를 통해 프레임워크의 코어 모듈들이 억울하게 결함으로 잡히는 오탐(False Positive) 제거.
- **Wrapper Resurrection 버그 해결 로직:**
  - `BoundaryGraphBuilder` 단계에서 응집도가 낮아 분할(SPLIT) 처리된 디렉토리들이 나중에 `RootCauseAggregator`의 경로 문자열 처리(추출 깊이 제한)로 인해 인위적인 가짜 허브(Artificial Hub)로 부활하는 현상 차단.
  - SPLIT된 노드 목록을 반환하여 파이프라인 아래로 전달하고, Aggregator가 해당 노드를 만나면 더 깊은 하위 경로(Depth)로 파고들도록 동적 드릴다운 로직 구현.

## 🛠️ 기술적 변경 사항 
- **Node/Edge/File Update:** 
  - `BoundaryGraphBuilder.ts`: SPLIT 판정된 후보군을 추적하는 `splitWrappers` 배열 반환 로직 추가.
  - `BoundaryAnalyzer.ts`: `BoundaryResult`에서 `splitWrappers`를 넘겨받아 `EvidenceType.WRAPPER_NODE` 로 방출.
  - `types.ts`: `EvidenceType` 열거형에 `WRAPPER_NODE` 추가.
  - `SemanticContext.ts`: 전달받은 래퍼 노드들을 Set에 저장하고 `isWrapper()` 인터페이스 제공.
  - `RootCauseAggregator.ts`: `extractTopLevelDir` 헬퍼를 도입하여, 식별된 ownerId가 Wrapper일 경우 Depth를 최대 5까지 증가시키며 하위 모듈로 쪼개어 집계하도록 수정.
  - `InsightEngine.ts`: 리포트 출력 시 Hardcoding되어 있던 `Subsystem: None / Unbounded` 문구를 실제 `boundaryContext.id`에 맞게 동적으로 렌더링하도록 수정.

## ⚠️ 예외 처리 및 주의 사항 
- **Boundary Discovery V2 한계점 (알려진 이슈):**
  - Linux Kernel 테스트 결과, `sound/soc/mediatek` 등 깊은 계층으로 내려갈수록 내부 응집도(Cohesion)와 질량이 승격 기준(Threshold)을 만족하지 못해 `UNKNOWN_HUB`로 잔류하는 현상 발생.
  - 이는 파이프라인의 버그가 아니며, 향후 V2 마일스톤에서 디렉토리 Depth 가중치나 부모 상속 로직을 통해 정밀하게 보완해야 함. 무리한 임계값 완화는 과적합(Overfitting)을 유발하므로 현재 설정 유지.

## 📝 Post-Work Log (작업 후 기록) 
*(Release Note 통합)*

### 🇬🇧 English
Advanced the Semantic Engine to properly distinguish between high fan-out structural defects and intended architectural hubs. Massive core modules (e.g., `src/vs` in VSCode, `core`/`scene`/`servers/rendering` in Godot, `drivers`/`arch` in Linux Kernel) are now correctly classified as `[INFO] INTENDED_HUB` instead of `[CRITICAL] STRUCTURAL_DEFECT`. 

Fixed the "Wrapper Resurrection" bug where `RootCauseAggregator` artificially recreated wrapper hubs (like `extensions/copilot`) that were intentionally split by `BoundaryGraphBuilder`. Added `splitWrappers` tracking, `EvidenceType.WRAPPER_NODE` emission, and dynamic depth drill-down (up to depth 5) to ensure aggregator groupings respect semantic boundaries. 

Validated successfully against VSCode, Godot, and Linux Kernel architectures, proving the generalization of the Semantic Boundary pipeline across different architectural paradigms.

### 🇰🇷 한국어
시맨틱 엔진을 고도화하여 단순한 Fan-out 기반의 구조적 결함과 의도된 아키텍처 허브를 완벽히 구분하도록 개선했습니다. VSCode의 `src/vs`, Godot의 `core`, `scene`, Linux Kernel의 `drivers` 같은 거대 핵심 모듈들이 이제 `[CRITICAL] STRUCTURAL_DEFECT`가 아닌 `[INFO] INTENDED_HUB`로 정확히 분류됩니다. 

`BoundaryGraphBuilder`가 폐기(SPLIT)한 래퍼 디렉토리(예: `extensions/copilot`)를 `RootCauseAggregator`가 가짜 허브로 부활시키던 'Wrapper Resurrection' 버그를 수정했습니다. 이를 위해 `splitWrappers` 추적, `EvidenceType.WRAPPER_NODE` 방출, 그리고 최대 Depth 5까지 파고드는 동적 집계 드릴다운 로직을 구현했습니다. 

VSCode, Godot, Linux Kernel 아키텍처에서 성공적으로 검증을 완료하며, 특정 프레임워크에 종속되지 않은 시맨틱 바운더리 파이프라인의 범용성을 증명했습니다.
