## 🧠 상세 설계 및 로직
- **디렉터리 맹신 타파 (Internal Density 기반 승격):**
  - 무조건 최상위 디렉터리(`src/vs`)를 묶는 기존의 맹점을 피하기 위해, 내부 응집도(Internal Density)와 외부 의존 비율(External Ratio)을 계산.
  - 조건: `internalDensity > 0.3 && externalRatio < 0.2`
  - 위 조건을 만족할 경우, 거대 디렉터리 내부라도 하위 그룹(예: `src/vs/workbench`)을 독립적인 Boundary 후보로 승격시킴.
- **Boundary Explosion 방지:**
  - 노드 2~3개짜리 파일 뭉치가 Boundary로 분류되는 현상을 막기 위해 최소 컷오프(Cut-off) 도입.
  - 조건: `MIN_BOUNDARY_MEMBERS = 5` AND `MIN_INTERNAL_EDGES = 20`.
- **Cohesion / Size 완전 분리 계산:**
  - 기존에는 거대한 Boundary가 높은 Strength 점수를 독식하는 구조였으나, 이를 방지하기 위해 `cohesion`(순수 응집도 비율)과 `size`(규모 보정)를 분리.
  - `boundaryStrength = cohesion * Math.min(1, Math.log10(internalEdges + 1) / 3)`의 정규화 수식 적용.
- **소유권(Ownership) 및 진입점(Entry Point) 배제:**
  - 아직 시스템 통제 흐름(Authority)을 모르기 때문에 "누가 경계를 위반했는가(Leak)"나 "누가 주인인가(Owner)"를 판단할 수 없음.
  - 철저하게 **"시스템의 경계가 무엇인가"**만을 도출하는 데 집중.

## 📝 Post-Work Log (작업 후 기록)
- `BoundaryGraphBuilder`와 `BoundaryAnalyzer`의 초기 작성 및 파이프라인 연동 성공.
- 이후 이 릴리즈를 배포 파일(vsix)로 빌드하여 Godot와 VSCode 프로젝트에서 실제 경계 검증을 진행할 예정.
- **추가 수정 내역 (Calibration 반영):**
  - **밀도(Density)의 함정 발견:** 희소 그래프(Sparse Graph) 특성상 노드 수(N)가 커지면 `possibleEdges(N*(N-1))`가 기하급수적으로 커져 `internalDensity`가 0에 수렴하는 현상(예: 0.011) 확인.
  - **승격 조건 Cohesion으로 변경:** `density > 0.3` 기준을 폐기하고, 순수 내부 의존 비율을 나타내는 `cohesion > 0.7`로 승격 기준 재설정.
  - **Candidate Discovery 뎁스 확장:** 단순 `src` 하나만 후보로 잡히는 맹점을 보완하기 위해 Node/TS 환경에서 `src/xxx` 레벨까지 Boundary 후보로 깊이 탐색하도록 개선.
  - **BoundaryAnalysisReport 덤프 생성기 추가:** 파이프라인 마지막에서 `BoundaryAnalysisReport.md` 파일로 상세 결과가 저장되도록 로직 반영.
  - 관련 프로브(`[BOUNDARY_CANDIDATE]`, `[BOUNDARY_DIAG]`) 추가로 Boundary 승격/탈락 원인 가시화 확보.
  - **Topology 함정 2차 해결 (Pattern Consistency 도입):** `cohesion` 수치(단순 외부 연결 비율)만으로 Boundary를 평가하는 것은 모노레포 구조에서 계층형 레이어를 탈락시키는 치명적 맹점이 있음을 발견.
  - **하위 그룹 자동 승격 (Subgroup Auto-Promotion):** Cohesion 0.45 미만인 경우 탈락(Reject)시키지 않고 재귀적으로 `SPLIT`하여 하위 폴더들을 독립적으로 재평가하는 Queue 기반 Hierarchical Validation 구현.
  - **Target Concentration 공식 투입:** 단순 `cohesion`이 0.2 이상으로 낮더라도, 외부 엣지의 50% 이상(`concentration >= 0.5`)이 단일 타겟 최상위 계층으로 집중되는 경우 "목적 지향형 레이어"로 판단하여 PROMOTED 시키는 일관성 패턴 분석 룰 반영.
  - **Risk Classification 연동 (Topology → Semantic):** Boundary Discovery 결과를 Risk 엔진에 주입. 단순히 Fan-out이 높다는 이유만으로 `ARCHITECTURAL_HUB` (CRITICAL)로 몰아가지 않고, 해당 노드가 의미 있는 Boundary 내에 속해 있을 경우 `INTENDED_HUB` (INFO) 또는 `UNKNOWN_HUB` (WATCH)로 다운그레이드하는 판별 로직 추가.
  - **Boundary Evidence 보존:** 차기 마일스톤(Ownership/Authority)에서 재사용할 수 있도록 `ProblemGroup`에 `boundaryContext(id, strength, size)` 메타데이터 유지.
  - **Massive Subsystem 승격 룰 (Type B Boundary):** Godot의 `scene`이나 `servers`처럼 절대적인 규모(내부 파일 수백 개, 내부 엣지 수천 개)가 큼에도 불구하고 `core` 등 외부 의존도가 높아 Cohesion 비율(예: 30~40%)이나 타겟 집중도에서 탈락하는 맹점을 해결. cohesion 임계값을 계속 낮추는 튜닝의 늪을 피하기 위해, `memberIds.length >= 100 && internalEdges >= 1000`과 같이 cohesion에 독립적인 순수 규모(Volume) 기반 `isMassive` 룰로 확정. 
  - **SemanticContext Layer 구축:** Boundary Evidence가 Reporting 파이프라인 중간에 유실되는 버그를 원천 차단하기 위해 `src/core/analysis/SemanticContext.ts` 신설. Evidence 배열 속성에 숨겨진 데이터를 `nodeId -> boundaryId` 역인덱스 기반의 일급 객체 모델로 분리.
  - **Boundary 단계 완료 및 Ownership 단계(v0.3.34.32) 진입 준비:** `RiskClassifier`, `InsightEngine` 등 리포팅 엔진 전체가 `SemanticContext`를 참조하여 "Subsystem 단위 해석"을 지원하도록 개편. 아키텍트 리포트가 단순 fan-out 수치가 아닌 `INTENDED_HUB`와 서브시스템 맥락을 명확히 리포팅하게 함으로써 Boundary 마일스톤(v0.3.34.31)의 진짜 목적 달성.
  - **Massive Boundary 오탐지 해결 (Type B Strength Override):** Godot `scene` 등 거대 서브시스템이 `isMassive` 룰로 승격되었음에도 낮은 Cohesion 점수 때문에 `Weak` 판정을 받아 `UNKNOWN_HUB`로 강등되는 버그 수정. `isMassive`에 해당하는 경우 그 질량 자체를 근거로 즉시 `Strong` 판정으로 오버라이드하여 `INTENDED_HUB` 보호 적용.
  - **Architect Report Narrative 전면 개편:** `InsightEngine.ts`의 리포트 출력 방식을 단순 메트릭(예: `Contains 446 fan-out issues`)에서 의미론적 구조 설명(`Subsystem`, `Role`, `Architectural Interpretation`)으로 완전히 전환. Boundary와 Semantic Context 기반 추론을 리포트 상에 명확히 서술하도록 변경.
  - **ID Normalization 디버깅 프로브 투입:** VSCode 환경에서 `RootCauseAggregator`와 `BoundaryGraphBuilder` 간의 클러스터 ID 정규화(Normalization) 불일치로 인해 Semantic Context 조회가 `MISS` 처리되는 현상 추적을 위해 `RiskClassifier.ts`에 `[SEMANTIC_LOOKUP]` 및 덤프 프로브 삽입.
