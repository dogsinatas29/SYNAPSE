Phase 13.2: Signal Taxonomy Validation
Phase 13.1에서 확보한 Signal Discovery Core를 활용하여, 실제 프로젝트들(SYNAPSE, AntennaPod, VSCode, Linux)에서 어떤 신호 분포가 나타나는지 '통계(Census)'를 수집합니다. 목적은 Constraint 발견이 아니라, 우리가 정의한 Signal Taxonomy가 여러 프로젝트에서 안정적으로 살아남는가를 검증하는 것입니다. 아직 어떠한 해석이나 클러스터링(Constraint 발견)도 시도하지 않고, 오직 신호의 발생 빈도와 패턴만을 관측합니다.

User Review Required
IMPORTANT

13.2는 기능 추가가 아니라 관측 실험이 목적입니다. 새로운 로직(SignalStatisticsGenerator)을 추가하고, Naming Rule을 극한으로 쪼아 역할(Role) 냄새가 나는 모든 신호(Signal) 이름을 동사형 행동(Action)으로 통제합니다.

Proposed Changes
1. Strict Signal Naming Rule 강화
역할(Role) 해석이 개입될 여지를 원천 차단하기 위해, 명명 규칙을 '관측 가능한 행동(Observable Action)'으로 엄격하게 제한합니다.

[MODIFY] src/core/reasoning/signal/SignalNamingRule.md
Signal must describe an observable action, not an architectural role.

🟢 GOOD (관측 가능한 행동)

state_mutation
write_access
object_creation
dependency_resolution
🔴 BAD (역할, 주관적 해석 포함)

owns_state
controller
authority
coordinator
provider
2. Signal Statistics Generator 추가
어떤 노드가 어떤 신호를 집중적으로 발생시키는지, 그리고 프로젝트 크기에 무관하게 비율(Percent)로 비교할 수 있도록 통계 추출기를 고도화합니다.
