[v0.3.34.33 P0] Analyzer Characterization Implementation
The goal of this implementation phase is to actualize the P0 scope of the v0.3.34.33 Analyzer Characterization (Metrology) specification. We are shifting SYNAPSE from analyzing projects to analyzing the performance and biases of its own extractors.

User Review Required
WARNING

This phase will NOT attempt to modify or fix any existing architectural blind spots or performance bottlenecks. It will purely build the Observatory (Meter) to measure them, enforcing the strict boundary between Characterization (v0.3.34.33) and Re-engineering (v0.3.34.34).

IMPORTANT

The MVP P0 scope is brutally cut down to the "Core 4": Blind Spot Topology Map, Extractor Agreement Matrix, Extractor Property Registry, and Cost & Amplification Profile. Track C (Priority Score calculation) and all other tracking (Trustworthiness, Marginal Cost Curve, Pattern Catalog) are strictly deferred to P1 and v0.3.34.34.

Proposed Changes
We will introduce a new metrology layer inside the src/core/ directory to house these 4 characterization metrics, completely decoupled from the existing extraction logic to prevent the observer effect.

1. Metrology Data Structures
Define the core metrology types in a dedicated src/types/metrology.ts.

[NEW] src/types/metrology.ts
Define ObservabilityClass (Observable, PartiallyObservable, Inferable, Blind, Misleading)
Define RecoverabilityClass (Recoverable, PartiallyRecoverable, Unrecoverable) and RecoverySource
Define SurvivabilityClass (TinyReady, MediumReady, LargeReady, KernelReady)
Define CoverageSource (GROUND_TRUTH, MANUAL_AUDIT, MULTI_EXTRACTOR_CONSENSUS, SYNTHETIC_DATASET)
Define CostType (CPU, IO, Memory, Serialization, StateExplosion)
Define StabilityMetric (sampleCount, mean, variance)
Define PipelinePhase (phase name and count)
Define structures for ExtractorPropertyRegistry (Strength, Weakness, Bias, Metric Confidence) and PropertyAttribution.
[NEW] Define BenchmarkSnapshot to serialize the entire metrology result (Coverage, Amplification, Cost) for version-to-version comparison.
2. Track A: Extractor Characterization Engine (The Core 3)
Build the core measurement instruments for Track A.

[NEW] src/core/metrology/BlindSpotMapper.ts
Implement BlindSpotTopologyMap.
Track Misleading Risk vs Blind Risk by explicitly recording falsePositiveCount (graph pollution) and falseNegativeCount (missing insights).
Use StabilityMetric to store deterministic stability data (do NOT implement automatic multi-run logic in P0).
Output Missing Coverage with basic fields (coverageSource, confidence, recoverySource), pushing mathematical judgment logic to P1.
[NEW] src/core/metrology/AgreementMatrixBuilder.ts
Calculate Extractor Agreement Matrix.
Compute Consensus Illusion Index (CII) by separating Agreement from Ground Truth Match.
[NEW] src/core/metrology/PropertyRegistry.ts
Manage the storage for Extractor Property Registry (output as a simple PropertyRegistry.json snapshot for P0).
Store Property Attribution (Project vs Extractor).
3. Track B: Performance Characterization Engine (The Core 1)
Build the instrumentation to track cost and state explosions.

[NEW] src/core/metrology/CostProfiler.ts
Track Execution Cost Class and Survivability Class.
Record Cost Owner and Cost Type to pinpoint exactly who caused the bottleneck.
[NEW] Differentiate between Self Cost and Inclusive Cost to identify the true culprit in a call chain (e.g., AuthorityBuilder vs ValidationEngine).
Record raw execution data (Input Size, Time, Memory) to build a foundation for later Marginal Cost Curve plotting.
[NEW] src/core/metrology/AmplificationTracker.ts
Monitor State Space Growth Profile (Object/Edge Amplification) by logging PipelinePhase[] (e.g., Input Nodes -> Signal Nodes -> Virtual Edges -> Validation Edges).
Detect non-linear state explosions across pipeline phases.
4. Track 0: Snapshot Engine
[NEW] src/core/metrology/BenchmarkSnapshotter.ts
Aggregate data from Track A and Track B into a BenchmarkSnapshot file.
