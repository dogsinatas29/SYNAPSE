# 🚀 Milestone v0.3.34.34 - Analyzer Re-engineering (Virtual Debugging)

## 📅 작업 정보 - **상태:** 🏗️ Planned
- **관련 마일스톤:** v0.3.34.33 (Analyzer Metrology)
- **목표:** Linux 실험에서 확인된 가상 디버거 마비의 주범인 '객체 폭발(Amplification Explosion)'과 '착시(Misleading)' 현상을 직접 수술(Re-engineering)한다. Governance(우선순위 산출)는 후순위로 미루고, 가장 치명적인 생존 위협(190x 증폭)부터 도려낸다.

## 🧠 상세 설계 및 로직
v0.3.34.33의 관측 데이터를 기반으로 가장 높은 ROI를 주는 구조적 문제부터 외과적 수술을 단행한다.

### Phase 1: Amplification Surgery (객체 폭발 억제)
- **목표:** 190x 증폭률을 20x 이하로 억제
- `Input Nodes → Signal Nodes → Virtual Edges → Validation Edges → Objects` 파이프라인 중 어디서 폭발이 일어나는지(Amplification Attribution) 추적하고 억제한다.
- O(1) 캐싱 전략이나 Lazy Evaluation을 적용하여 객체 폭증 연쇄를 끊어낸다.

### Phase 2: Misleading Edge Surgery (착시 엣지 제거)
- **목표:** 틀린 데이터를 진실이라고 믿는 현상(False Positive) 제거
- `BlindSpotMapper`와 CII 데이터를 기반으로, **False Positive Filter Layer**를 도입한다.
- 예: Regex 기반 Edge 추출 후 AST 검증에 실패하면 즉각 버림(Discard). 탐지(Detection)보다 검증(Validation)을 우선한다.

### Phase 3: Recoverability Layer (맹점 복구)
- **목표:** 가장 저렴한 비용으로 사각지대(Blind Spot) 복구
- 추출 실패 시 `RecoverabilitySource`를 활용한 Fallback 파이프라인 구현 (예: Regex 실패 → AST 시도 → Semantic 시도).

### Phase 4: Governance Engine (우선순위 자동 산출)
- 생존이 확보된 이후, 남은 이슈들을 Coverage Gap, Cost, Frequency 등을 팩터로 자동 스코어링하는 엔진 구축 (v34 후반부 또는 v34.1로 이관 가능).

## ⚠️ 예외 처리 및 주의 사항
- **우선순위의 철저한 엄수:** Amplification Surgery가 완벽히 증명되기 전까지는 다음 Phase로 넘어가지 않는다.
- **Observer Effect 방어 유지:** Re-engineering 과정에서도 Metrology 레이어(v33)는 순수 수집통으로 남아야 한다.
