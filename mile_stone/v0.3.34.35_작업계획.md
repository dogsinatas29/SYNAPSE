[v0.3.34.35] Deterministic Stability Verification
This plan transitions SYNAPSE into the Verification phase to prove that the 18x factor and our coverage targets from v0.3.34.34 are repeatable physical laws rather than probabilistic flukes. Only after proving 100% determinism will we proceed to Governance.

User Review Required
CAUTION

Strict Success Criteria (N=30 Fixed Runs):

Amplification Stability: CV < 1%
Runtime Stability: Execution Time CV < 5%
Coverage Stability: Drift < 1%
CII Stability: Drift < 2%
Deterministic Hash Verification: Hash Match Rate = 100%
Snapshot Drift Analysis: Unexpected Drift = 0
If the hash mismatch triggers or the CV/Drift exceeds the limits across the 30 runs, it indicates underlying non-determinism (Set/Map ordering, async race conditions) which MUST be patched before proceeding.

Proposed Changes
Phase 1: Stability Runner Harness (CV & Drift)
We will build the execution harness capable of running N=30 iterations of the pipeline and collecting the metrics for statistical comparison using Coefficient of Variation and Drift.

[NEW] src/core/metrology/Verification/DeterministicStabilityRunner.ts
Implement a harness that executes the benchmark N times sequentially.
Collects Amplification Factor, Coverage Retention, and CII Reduction for each run.
Calculates the Coefficient of Variation (CV) for amplification and the Max Drift for coverage and CII.
[MODIFY] src/core/benchmark/BenchmarkHarness.ts
Add support for parameterized iterations: number to allow the Stability Runner to drive the loop continuously.
Phase 2: Snapshot Drift & State Hash Analysis
We will build an analyzer to compare the final structural snapshots and canonical hashes across runs.

[NEW] src/core/metrology/Verification/SnapshotDriftAnalyzer.ts
Compares BenchmarkSnapshot outputs between runs.
Flags edges or objects that cause unexpected drift (presence in Run A but absence in Run B).
[NEW] src/core/metrology/Verification/DeterministicHashVerifier.ts
Computes SHA256 hashes of the Canonical JSON representations of project_state.json and validation_context.json at the end of each run.
Canonical JSON Rules:
Object Key Sort (Lexicographic)
Stable Array Ordering
Remove Timestamp
Remove Runtime UUID
UTF-8 normalized stringify
Asserts that Run N Hash === Run 1 Hash.
