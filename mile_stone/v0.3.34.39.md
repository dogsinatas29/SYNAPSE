# Milestone v0.3.34.39 - Boundary Candidate Rejection Audit

## Status

* Phase: Investigation
* Type: Diagnostic / Read-Only Analysis
* Predecessor: v0.3.34.38 (Completed)
* Successor: v0.3.34.40 (Boundary Recovery)

---

# Objective

Identify why BoundaryDetector fails to promote specific subsystems into architectural boundaries.

This milestone does **not** modify promotion criteria, relax thresholds, introduce hardcoded boundaries, or redesign onboarding behavior.

The sole purpose is to expose and classify every rejected boundary candidate so that future fixes are based on evidence rather than assumptions.

---

# Background

v0.3.34.38 successfully eliminated report hallucinations.

The remaining issue is not that reports are incorrect.

The issue is that several expected subsystems never appear inside the Boundary Analysis output.

Observed Boundaries:

* src/core/analysis
* src/core/ir
* src/core/reasoning

Missing Candidates:

* src/server
* src/webview
* src/bootstrap
* src/core/collaboration
* src/core/metrology

At present, the system only reports promoted boundaries.

Rejected candidates disappear from all generated reports.

As a result, root-cause analysis is impossible.

---

# Problem Statement

Current BoundaryGraphBuilder behavior:

```ts
isPromoted =
    !isWrapper &&
    (
        cohesion >= 0.45 ||
        (cohesion >= 0.2 && targetConcentration >= 0.5) ||
        isMassive
    );
```

Candidates can be rejected because they are:

* too small
* weakly cohesive
* classified as wrappers
* otherwise fail promotion criteria

However, none of these reasons are surfaced in reports.

Therefore:

* We do not know why src/server failed.
* We do not know why src/webview failed.
* We do not know why src/bootstrap failed.
* We do not know whether candidates were evaluated at all.

# Phase 1 - Boundary Candidate Audit

## Goal

Expose every evaluated candidate.

### New Audit Structure

```ts
interface BoundaryCandidateAudit {
    id: string;
    members: number;
    internalEdges: number;
    externalEdges: number;
    cohesion: number;
    targetConcentration: number;
    result:
        | 'PROMOTED'
        | 'REJECT_SMALL'
        | 'REJECT_WEAK'
        | 'WRAPPER';
}
```

Every candidate must be recorded regardless of outcome.

---

# Phase 2 - Boundary Analysis Report Expansion

## Goal

Make rejected candidates visible.

New report section:

```text
=== Rejected Boundary Candidates ===
```

Example:

```text
[REJECT_SMALL] src/bootstrap

Members: 4
Internal Edges: 6
External Edges: 12
Cohesion: 0.33
Target Concentration: 0.60
```

Example:

```text
[REJECT_WEAK] src/server

Internal Edges: 18
External Edges: 35
Cohesion: 0.34
Target Concentration: 0.45
```

Example:

```text
[WRAPPER] src/webview

Members: 45
Internal Edges: 12
External Edges: 89
Cohesion: 0.12
Target Concentration: 0.20
```

# Phase 3 - Root Cause Classification

## Goal

Determine why each missing subsystem failed promotion.

Expected classification categories:

### Candidate Missing

Candidate never entered BoundaryGraphBuilder.

### REJECT_SMALL

```text
members < MIN_BOUNDARY_MEMBERS
```

or

```text
internalEdges < MIN_INTERNAL_EDGES
```

### REJECT_WEAK

Candidate evaluated but failed promotion criteria.

### WRAPPER

Candidate classified as container/wrapper and split.
