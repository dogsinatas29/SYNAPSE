# 🚀 Milestone v0.3.34.3 - Architect Intervention Layer (아키텍트 개입 계층)

## 📅 작업 정보
- **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.34.2 (Aggregation Layer 완료)
- **목표:** '왜(Why)'를 찾는 추상적인 리포팅(Reasoning)에서 벗어나, 거대 결합(SCC)을 끊어내기 위해 **'어디를 잘라야 하는가(Intervention Point)'**를 계산하는 실용적인 처방전 탐색 시스템 구현.

## 🧠 상세 설계 및 로직
- **Graph Pipeline 분리 (Read-Only 유지):** 모든 시뮬레이션은 GraphModel 원본을 수정하지 않고 분리된 메모리 가상 상태에서 수행됨.
- **Tarjan SCC 기반 Hub 도출:** 
  - Regex 기반 Logic Node + Logic Edge 그래프를 그대로 사용. (디렉토리/폴더 노드 제외)
  - 거대 순환 참조 군집(SCC)을 추출하고, 그 안에서 Degree Centrality(In + Out 합산)가 가장 높은 Hub 노드를 식별.
- **Single-Cut Intervention Simulation:** 
  - Hub에 연결된 핵심 엣지들을 하나씩 가상 제거(Single-Cut).
  - 제거 후 SCC 크기(노드 수, 사이클 파급력)의 감소량(Impact) 측정.
- **Fact-Based Discovery:** 
  - 가장 파급력이 큰(가장 많이 붕괴하는) 엣지들을 '유망한 절단 후보(Break Candidate)'로 랭킹.
  - "이게 정답이다"라는 오만을 버리고 리팩터링 비용은 `Unknown`, 엣지 성질은 `Regex Hypothesis`로 표기하여 팩트 기반 한계 명시.
