# 🚀 Milestone v0.3.34.4 - Graph Hygiene Layer (노드/그래프 정화 계층)

## 📅 작업 정보
- **상태:** 🏗️ Planned
- **관련 마일스톤:** v0.3.34.3 (Graph Stress Simulator 완료)
- **목표:** Data Pipeline과 GraphModel 간의 입력 품질을 통제하여, `README.md`, 정규식 문자열 찌꺼기(`[^'"]+`), 에셋 파일(`webp`) 등 아키텍처 분석에 무의미한 **가짜 노드(Noise Nodes)**가 그래프에 진입하는 것을 원천 차단한다. (Garbage In, Garbage Out 방지)

## 🧠 상세 설계 및 로직
- **Node Provenance 도입:** 엣지(Edge) 기원 이전에 노드(Node) 자체가 어떤 성격인지(소스 코드, 설정 파일, 문서, 미디어, 고스트 노드 등) 식별하는 메타데이터 필요.
- **Source-Code Only Policy 강화:**
  - 분석 및 Intervention Engine의 대상은 기본적으로 런타임/컴파일 로직에 관여하는 "Source Code"로 제한.
  - 마크다운(`.md`), 이미지(`.webp`, `.png`), 로그 파일(`.log`) 등은 그래프 노드 생성 시점부터 제외하거나 특별한 'Document/Asset' 타입으로 마킹하여 분석(Tarjan SCC 등)에서 무시하도록 격리.
- **File Scope Filtering (정규식 찌꺼기 제거):**
  - 기존 `FileScanner`나 `FlowScanner`에서 추출된 대상 중, 실제 파일 시스템에 존재하지 않고 정규식의 부산물로 생성된 문자열(`[^'"]+`, `) || trimmed` 등)을 철저히 식별.
  - 이러한 가짜 고스트 노드(Ghost Node)는 아예 생성하지 않거나 `Ghost Node Elimination` 파이프라인에서 폐기 처분.

## 🛠️ 기술적 변경 사항
- **Node 스키마 확장:** `src/types/schema.ts`의 Node 타입에 `nodeType` (예: `SOURCE`, `CONFIG`, `DOCUMENT`, `ASSET`, `GHOST_GARBAGE`) 필드 추가.
- **Data Pipeline 및 Scanner 개조:** 
  - `DataPipeline.ts` 및 개별 Scanner(예: MarkdownScanner 등)에서 노드를 생성/등록할 때 해당 노드의 확장자나 성격을 기반으로 `nodeType`을 분류.
  - 정규식 파싱 결과물이 물리적인 경로 스키마나 가상 모듈 스키마에 부합하지 않는 쓰레기 텍스트인 경우 등록을 거부하는 Validator 로직 추가.
- **Reasoning Engine 필터링 연동:**
  - `TarjanSCC.ts` 및 `InterventionEngine.ts` 구동 시, 노드의 타입이 `SOURCE` 또는 `CONFIG` 인 경우만 SCC 계산 및 브리지 후보군 탐색에 포함하도록 필터링 적용.

## ⚠️ 예외 처리 및 주의 사항
- **합법적 고스트 노드 보호:** NPM 패키지(예: `vscode`, `path`, `fs`) 등 실제 로컬 파일은 없으나 아키텍처 적으로 유효한 'External Reference(외부 참조)' 고스트 노드는 `GARBAGE`로 분류되지 않도록 주의. (Node Provenance = `EXTERNAL`)
- **하위 호환성:** 기존 `project_state.json`에 `nodeType` 속성이 없는 경우, 확장자 기반으로 `SOURCE`나 `ASSET`을 자동 추론(Fallback)하는 로직 필요.
