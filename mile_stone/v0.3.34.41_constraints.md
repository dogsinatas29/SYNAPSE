# Purpose

This document defines the architectural boundaries that v0.3.34.41 must never violate.

The goal of these constraints is simple:

```text
Add Simulation

Without Damaging SYNAPSE
```[cite: 21]

---

# Core Principle

It is not a replacement[cite: 21].

+

# Constraint 24
## Non-Blocking Projection Enforcement

### Rule

Monolithic blocking `JSON.parse` operations on large-scale snapshot assets are strictly prohibited.

---

### Required

All projections must leverage non-blocking stream-based chunk slicing or index-driven partial parsing primitives to protect the Node.js single-threaded event loop from locking up.

---

### Forbidden

Synchronous whole-file deserialization of multi-hundred megabyte configuration state files inside the simulation bootstrap path.

---

# Constraint 25
## Baseline Report Fallback Guarantee

### Rule

Reporting builders must never crash or throw runtime exceptions when evaluating execution states lacking simulation payloads.

---

### Required

All legacy and modern reporting layers must process inputs through `SimulationSchemaAdapter`, enforcing safe structural defaults and fallback schemas during non-simulation baseline runs.
