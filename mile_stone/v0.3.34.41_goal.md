# 🎯 v0.3.34.41 Goal

## Scenario-Driven Architecture State Transition Simulation

### Status

Planned

### Purpose

v0.3.34.41의 목적은 새로운 정적 분석기를 만드는 것이 아니다.

또한 기존 Graph Engine, Boundary Detector, Evidence Engine을 교체하는 것도 아니다.

본 마일스톤의 목적은 이미 생성되어 있는 프로젝트 스냅샷(`project_state.json`)을 기반으로 특정 아키텍처 변경 시나리오를 가상 적용하여 시스템의 상태 전이(State Transition)를 계산하는 Simulation Layer를 구축하는 것이다.

---

# Problem Statement

현재 SYNAPSE는 다음을 수행할 수 있다.

* 프로젝트 스캔


* 노드 생성


* 클러스터 생성


* Boundary 탐지


* Evidence 생성


* Architecture Report 생성


* Executive Report 생성


* Onboarding Report 생성



그러나 현재 시스템은 모두 현재 상태(Current State)에 대한 정적 분석이다.

즉,

```text
현재 구조는 어떠한가?

```

는 설명할 수 있지만

```text
이 구조를 변경하면 무슨 일이 발생하는가?

```

는 설명할 수 없다.

---

# Core Goal

Simulation Layer를 추가하여

```text
현재 구조
→ 변경 이벤트 적용
→ 상태 전이 계산
→ 영향 전파 계산
→ 결과 리포트 생성

```

을 수행할 수 있도록 한다.

---

# Scope

Simulation의 대상은 실제 프로젝트가 아니다.

Simulation의 대상은

```text
project_state.json

```

으로부터 생성된

```text
Simulation Snapshot

```

이다.

실제 프로젝트 구조는 절대로 변경되지 않는다.

---

# Single Source Of Truth

SSoT는 계속

```text
project_state.json

```

이다.

그러나 Simulation은 SSoT를 직접 수정하지 않는다.

항상

```text
project_state.json
        ↓
Simulation Snapshot Clone
        ↓
Simulation Engine

```

구조를 유지한다.

---

# Simulation Unit

Simulation의 최소 단위는

```text
Node
=
File

```

이다.

---

Simulation의 핵심 단위는

```text
Cluster
=
Folder

```

이다.

---

즉

일반적인 Graph Theory의 Cluster가 아니라

```text
실제 파일 시스템 폴더

```

가 Simulation의 기본 분석 단위가 된다.

---

# Boundary Unit

Evidence 및 Boundary 분석의 기준은

```text
Cluster (Folder)

```

이다.

Node 단위는 Evidence의 구성 요소이다.

---

예시

```text
drivers/gpu/drm/i915

```

라는 Cluster가 존재하면

Simulation은

```text
i915 폴더
+
내부 파일
+
외부 의존성

```

전체를 하나의 Boundary로 취급한다.

---

# Scenario Driven Simulation

Simulation은 무작위 변경을 수행하지 않는다.

반드시

```text
Scenario

```

를 통해서만 상태를 변경한다.

---

예시

```text
API_CHANGED

CONTRACT_BROKEN

BOUNDARY_SPLIT

BOUNDARY_MERGED

CONTROL_NODE_CHANGED
```[cite: 15]

---

Scenario는 Event를 생성한다[cite: 15].

Event는 State를 변경한다[cite: 15].

State는 Propagation을 발생시킨다[cite: 15].

---

# State Transition Goal

Simulation은 다음 질문에 답할 수 있어야 한다[cite: 15].

```text
이 Boundary가 변경되면
어떤 Boundary가 영향을 받는가?
```[cite: 15]

---

```text
이 Cluster가 분리되면
어떤 Evidence가 깨지는가?
```[cite: 15]

---

```text
이 Control Node가 변경되면
어떤 Cluster가 위험해지는가?
```[cite: 15]

---

```text
이 변경은
Architecture Level에서
어떤 파급 효과를 만드는가?
```[cite: 15]

---
