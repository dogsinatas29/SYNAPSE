# 🚀 SYNAPSE Pattern Coverage Audit (Phase 5)

## 📌 개요
이 문서는 "현재 우리가 확보한 KEEP 패턴(6~7개)만으로 종합 아키텍처 진단이 과연 가능한가?"에 대한 답을 구하는 문서입니다.
Phase 3(Vocabulary)에서 발굴된 '증명 불가' 용어들을 기반으로, SYNAPSE가 현재 어떤 종류의 진단(Architecture Concern)에 눈이 멀어 있는지(Blind Spot) 커버리지를 평가하고, 아키텍트들이 실무에서 쓰는 30대 용어를 완성하기 위해 반드시 추가되어야 하는 **결손 패턴 목록(Missing Pattern Catalog)**을 정의합니다.

---

## 📊 종합 아키텍처 커버리지 현황 (Architecture Coverage Audit)

| Architecture Concern (관심사) | Current Coverage | 비고 (현재 상태) |
| :--- | :--- | :--- |
| **Dependency (의존성)** | 🟢 **YES** | `Fan-In`, `Fan-Out`으로 완벽히 측정 가능 |
| **Coupling (결합도)** | 🟢 **YES** | `Cycle Participation (SCC)`로 파악 가능 |
| **Cohesion (응집도)** | 🟢 **YES** | `Cohesion` 지표 보유 |
| **Change Impact (파급력)** | 🟢 **YES** | `Blast Radius` 보유 |
| **Ownership (소유권)** | 🔴 **NO** | 코드 소유주나 독점도 파악 불가 |
| **Churn (변동성)** | 🔴 **NO** | 어떤 코드가 자주 바뀌고 부패하는지 파악 불가 |
| **Runtime Flow (런타임)** | 🔴 **NO** | 실제 실행 시점의 병목 파악 불가 |
| **Data Flow (데이터 흐름)** | 🔴 **NO** | 데이터베이스나 DTO의 전파 파악 불가 |
| **Extension Contract (확장성)** | 🔴 **NO** | 다형성(Polymorphism) 기반의 플러그인 구조 파악 불가 |
| **Layer Violation (계층 위반)** | 🟡 **PARTIAL** | `Boundary Crossings`로 일부 감지되나, 엄격한 Tier 분류 불가 |
| **Testability (테스트 품질)** | 🔴 **NO** | 파급력 대비 커버리지 사각지대 파악 불가 |
| **Stability Trend (안정성 추세)** | 🔴 **NO** | 시간에 따른 아키텍처 퇴화(Erosion) 추적 불가 |

**결론:** 
- 현재 SYNAPSE의 **Dependency Architecture Coverage는 80~90%**로 매우 훌륭합니다.
- 그러나 **Overall Architecture Coverage는 35~45%** 수준에 머무르고 있습니다. 즉, SYNAPSE는 아직 종합 아키텍처 진단기가 아니라 고성능 **"의존성 진단기"**에 불과합니다.

## 🔍 Missing Pattern Catalog (부족한 패턴 카탈로그)
위의 맹점(Blind Spot)을 채워 넣고 남은 20개의 핵심 Vocabulary를 완성하기 위해 향후 반드시 개발되어야 하는 패턴(스캐너) 목록입니다.

### Missing Pattern #1: Ownership (코드 소유권)
- **증명 가능한 Vocabulary:** `Knowledge Bottleneck`, `Bus Factor Risk`, `Ownership Risk`
- **필요 원시 데이터(Raw Pattern):** `Git Blame`, `Author Count`, `Commit Ownership`
- **필요 스캐너:** Git Metadata Scanner

### Missing Pattern #2: Extension (다형성 및 확장)
- **증명 가능한 Vocabulary:** `Extension Point`, `Plugin Contract`, `Framework Core`, `Over-engineered Abstraction`
- **필요 원시 데이터(Raw Pattern):** `Interface Count`, `Abstract Class Inheritance`, `Trait`, `Implementation Count`
- **필요 스캐너:** AST Hierarchy Scanner (객체지향 메타데이터)

### Missing Pattern #3: Flow (데이터/런타임 흐름)
- **증명 가능한 Vocabulary:** `Request Pipeline`, `Data Pipeline`, `Orchestrator Hub`
- **필요 원시 데이터(Raw Pattern):** `Entry Point`, `Service Node`, `Repository Node`, `Sink (DB/Network)`
- **필요 스캐너:** Semantic Tagging Scanner (프레임워크 어노테이션 기반)

### Missing Pattern #4: Quality & Testability (품질 및 검증)
- **증명 가능한 Vocabulary:** `Test Blind Spot`, `Fragile Target`
- **필요 원시 데이터(Raw Pattern):** `Test Coverage`, `Test File Ratio`, `Assert Count`
- **필요 스캐너:** Coverage Report Parser (LCOV, JaCoCo 등 연동)

### Missing Pattern #5: Churn (변동성)
- **증명 가능한 Vocabulary:** `High Churn Component`, `Technical Debt Hotspot`
- **필요 원시 데이터(Raw Pattern):** `Git Commit Frequency`, `PR Churn Rate`
- **필요 스캐너:** Git History Analyzer

## 🎯 감사 결론 (Final Conclusion)

이 문서를 통해 "우리의 패턴 세트가 충분한가?"에 대한 답은 명백히 **"NO"**임이 증명되었습니다.

우리는 현재 6~7개의 KEEP 패턴(`Fan-In`, `Blast Radius`, `SCC` 등)만 쥐고 있으며, 이 무기만으로는 의존성 세계(Dependency World)만 설명할 수 있습니다. 무리해서 Question Catalog를 작성해봤자, 이 7개의 변수로 표현되는 10여 개의 의존성 관련 대답만 반복될 뿐입니다.

따라서 0.3.34.44의 가장 큰 성과는 억지로 진단 범위를 부풀리지 않고, **SYNAPSE가 아키텍처 진단기로 성장하기 위해 정확히 무엇이 결핍되어 있는지(Missing Patterns)를 공식적으로 발굴해 낸 것**입니다.

이로써 Persistence Layer(Phase 6) 설계로 돌입하여, 현재 확보된 10개의 용어와 3개의 1순위 구출 패턴(`Blast Radius`, `SCC`, `Boundary Crossings`)을 Graph JSON에 안착시킬 준비가 모두 끝났습니다.
