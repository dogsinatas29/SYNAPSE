# 🚀 SYNAPSE Pattern Expansion Roadmap (Phase 5.5)

## 📌 개요
Phase 5(Coverage Audit)를 통해 SYNAPSE가 현재 `Dependency(의존성)` 영역에만 갇혀 있음이 증명되었습니다. 
이 문서는 진정한 아키텍처 진단기가 구사하는 '30대 핵심 Vocabulary'를 완성하기 위해, 앞으로 어떤 **Pattern Family(패턴 군)** 가 확장되어야 하는지 로드맵을 정의합니다. 

또한 이 로드맵을 기반으로, "무엇을 언제 `project_state.json`(Persistence Layer)에 저장할 것인가?"에 대한 영구 보존 전략을 **3가지 Tier**로 공식화합니다.

---

## 🛤️ Future Pattern Families (미래 확장 패턴군)

의존성(Dependency) 외의 사각지대를 밝혀내기 위해 추가되어야 할 스캐너와 패턴들입니다.

| Pattern Family | Missing Pattern (발굴 대상) | 타겟 진단 영역 (Vocabulary) | 구현 난이도 |
| :--- | :--- | :--- | :---: |
| **Ownership** | `Author Count`, `Git Blame Ratio`, `Bus Factor` | 지식 병목, 독점도, 인수인계 리스크 | High (Git 통합) |
| **Evolution** | `Churn Rate`, `Commit Frequency`, `Age` | 격동의 컴포넌트, 기술 부채 생성기 | High (Git 통합) |
| **Extension** | `Interface Impl Count`, `Abstract Extends` | 다형성, 오버엔지니어링, 플러그인 경계 | Med (AST 확장) |
| **Runtime Flow** | `Entry Node`, `Hot Path`, `Call Depth` | 병목 구간, 성능 지뢰밭 | Hard (APM 연동) |
| **Data Flow** | `Data Producer`, `Data Consumer`, `Sink` | 정보 유출, 오염된 파이프라인 | Med (어노테이션) |
| **Quality** | `Coverage`, `Test File Ratio`, `Asserts` | 테스트 사각지대, 깨지기 쉬운 핵심 | Low (LCOV 연동) |

## 💾 Persistence Tier Strategy (영구 보존 등급 전략)

확장 로드맵이 명확해짐에 따라, **"무엇을 그래프 데이터베이스(JSON)에 당장 박제해야 하는가?"**에 대한 명단이 확정되었습니다.

### 🚨 Tier 1: Core Dependency Patterns (즉시 저장 대상)
현재 SYNAPSE가 증명 완료한 10대 Vocabulary의 근간이자, 지금 당장 `In-Memory`에서 구출해 파일 시스템(`Graph JSON`)으로 끌어내려야 할 P0 인프라입니다.
- `Fan-In` (보유)
- `Fan-Out` (보유)
- `Size` (보유)
- `Cohesion` (보유)
- **`Blast Radius` (긴급 구출 요망 - Phase 6 타겟)**
- **`Cycle Participation (SCC)` (긴급 구출 요망 - Phase 6 타겟)**
- **`Boundary Crossings` (긴급 구출 요망 - Phase 6 타겟)**

### ⏳ Tier 2: Future Pattern Families (향후 확장 시 저장 대상)
위의 로드맵에 따라 새로운 스캐너가 개발되면, 그 즉시 Persistence Layer 스키마를 확장하여 저장해야 할 미래의 뼈대들입니다.
- `Ownership` (Author, Bus Factor)
- `Churn` (Commit Frequency)
- `Runtime Flow` (Hot Path)
- `Data Flow` (Producer/Consumer)
- `Extension` (Implementation Count)
- `Quality` (Coverage)

### 🔄 Tier 3: Derived Patterns (절대 저장 불가 - 계산식 강등)
원시(Raw) 데이터나 복잡한 알고리즘 결과물(Aggregate/Analytical)이 아니며, 단순히 Tier 1 데이터를 UI에서 곱하고 섞은 결과물입니다. **Persistence Layer 오염을 막기 위해 영구 저장을 엄격히 금지**하며 런타임 수식(Formula)으로만 취급합니다.
- `Control Score` (산식: `Fan-In × Size`)
- `Authority Reach` (산식: `Blast Radius`의 텍스트 Alias)
- `Concentration` (산식: 실효성 없는 비율 계산)

## 🎯 확장 로드맵 결론 (Roadmap Conclusion)

1. **SYNAPSE의 무지가 완벽히 문서화되었습니다.** 우리는 우리가 모르는 것(Tier 2)이 무엇인지 정확히 인지했으며, 향후 개발 방향성을 확보했습니다.
2. **저장해야 할 것과 버려야 할 것의 경계가 확정되었습니다.** Tier 1은 반드시 지켜내고, Tier 3는 철저히 배제하는 규칙이 마련되었습니다.

이 기반을 바탕으로, 드디어 그동안 애타게 찾았던 **Tier 1 구출 작전(`Blast Radius`, `SCC`, `Boundary Crossings` ➡️ Graph JSON 저장)**을 구체적인 코드 레벨로 설계하는 **Phase 6: Persistence Audit**으로 안전하게 진입할 수 있게 되었습니다.
