# 🚀 SYNAPSE Pattern Dependency Stress Test (Phase 5.7)

## 📌 개요
이 문서는 "우리가 Persistence Layer(저장소)에 넣으려는 패턴들이 정말로 대체 불가능(Irreplaceable)한가?"를 검증하는 최종 반증(Falsification) 테스트입니다.

아무리 Contract에서 자주 쓰인다 하더라도, 만약 그 패턴이 제거되었을 때 다른 패턴들의 조합으로 근사치 계산이 가능하다면, 그것은 굳이 저장 공간을 차지할 필요가 없는 연산식(Formula)에 불과합니다. 따라서 Tier 1 패턴 7개에 대해 극한의 스트레스 테스트를 진행합니다.

---

## 💥 테스트 1: 진단 언어 붕괴도 (Vocabulary Collapse)
해당 패턴이 삭제되었을 때, 10대 핵심 진단 어휘 중 몇 개가 붕괴(정의 불가 상태)하는지 측정합니다.

| 제거된 Pattern | 붕괴하는 Vocabulary 수 | 타격받는 주요 Vocabulary |
| :--- | :---: | :--- |
| **Fan-In** | **7개** | Domain Core, System Dominator, Tangled Core 등 대다수 |
| **Blast Radius** | **5개** | Change Amplifier, System Dominator, Domain Core 등 |
| **Cohesion** | **5개** | Architectural Debt, God Module, Boundary Erosion 등 |
| **Fan-Out** | **4개** | Change Amplifier, God Module, Knowledge Gateway 등 |
| **Cycle Participation (SCC)** | **3개** | Architectural Debt, Tangled Core, Stable Foundation |
| **Boundary Crossings** | **3개** | Boundary Erosion, Architectural Debt, Knowledge Gateway |
| **Size** | **2개** | System Dominator, God Module |

**결과:** 7개의 패턴 중 단 하나라도 제거되면 최소 2개에서 최대 7개의 아키텍처 진단 개념이 즉시 붕괴합니다.

---

## 🧮 테스트 2: 대체 가능성 검증 (Approximation Test)
붕괴는 확인했습니다. 그렇다면 "제거된 패턴을 남은 패턴들의 수학적 조합으로 흉내(Approximation) 낼 수 있는가?"를 검증합니다.

### 1. Blast Radius 대체 테스트
- **가설:** `Blast Radius`를 제거하고, `Fan-Out` + `Fan-In` 의 재귀적 합산으로 근사치를 구할 수 있는가?
- **검증:** **NO (대체 불가).** `Fan-In/Out`은 1 Depth의 직접 의존성만 계산하지만, `Blast Radius`는 N-Depth에 걸친 '영향력 감쇠/증폭(Cascading Impact)'을 그래프 탐색 알고리즘(Graph Traversal)으로 연산한 결과입니다. 1 Depth 엣지 개수만으로는 N-Depth 파급력을 절대 도출할 수 없습니다.

### 2. Cycle Participation (SCC) 대체 테스트
- **가설:** `SCC`를 제거하고, `Fan-In`이 높은 것과 `Fan-Out`이 높은 것을 교차해서 순환 참조를 추측할 수 있는가?
- **검증:** **NO (대체 불가).** 양방향 참조(`A ↔ B`)는 추측할 수 있으나, 3-Depth 이상의 순환(`A → B → C → A`)이나 거대한 컴포넌트 엉킴은 Tarjan 알고리즘 같은 강결합 요소(Strongly Connected Components) 연산 없이는 절대 찾아낼 수 없습니다.

### 3. Boundary Crossings 대체 테스트
- **가설:** `Boundary Crossings`를 제거하고, `Fan-Out` 중 외부 모듈을 가리키는 비율로 계산할 수 있는가?
- **검증:** **NO (대체 불가).** 단순 `Fan-Out`은 의존성의 갯수일 뿐이며, 그 선이 "합법적인 통로(Interface)"를 지났는지 "불법적인 계층 침범(Layer Violation)"인지 판단하는 도메인 룰(Domain Rule) 맥락이 결여되어 있습니다.

### 4. (참고) Control Score 대체 테스트
- **가설:** `Control Score`를 제거하고, `Fan-In` + `Size` 로 대체할 수 있는가?
- **검증:** **YES (대체 완벽).** 애초에 단순 휴리스틱 곱셈 공식이므로 대체율 100%입니다. 따라서 Tier 3로 강등되어 영구 저장 대상에서 탈락한 것이 정당함이 다시 한번 증명되었습니다.

## 🎯 반증 결론 (Falsification Conclusion)

| Pattern | 대체 가능 여부 | 영구 저장(Tier 1) 자격 최종 판정 |
| :--- | :---: | :--- |
| **Fan-In / Fan-Out** | NO | 🟢 **Irreplaceable** (모든 연산의 근원) |
| **Size** | NO | 🟢 **Irreplaceable** (물리적 크기는 추론 불가) |
| **Cohesion** | NO | 🟢 **Irreplaceable** (내부 응집도는 외부 간선으로 추론 불가) |
| **Blast Radius** | **NO** | 🚨 **Irreplaceable (N-Depth 연산은 단순 엣지 합산으로 대체 불가)** |
| **Cycle Participation** | **NO** | 🚨 **Irreplaceable (알고리즘 기반 순환 탐색은 대체 불가)** |
| **Boundary Crossings** | **NO** | 🚨 **Irreplaceable (도메인 룰 맥락은 단순 간선으로 대체 불가)** |

**최종 선언:**
우리가 `Persistence Layer`로 구출하려 했던 **`Blast Radius`, `SCC`, `Boundary Crossings`는 임시 연산식으로 결코 대체할 수 없는 "독립적이고 필수적인 물리량"임이 반증 테스트를 통해 최종 증명되었습니다.**

이로써 이 데이터들을 런타임에 매번 재계산해서 버리지 말고, 그래프 빌드 시점에 1회 연산하여 `project_state.json`에 영구 보존해야 한다는 **Tier 1 자격**이 완벽한 논리적 정당성을 획득했습니다.
