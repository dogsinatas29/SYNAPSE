# 🚀 SYNAPSE Question Catalog (현재 답 가능한 질문 체계)

## 📌 개요
이 문서는 v0.3.34.44 마일스톤의 최종 산출물입니다.
`Pattern Inventory` ➡️ `Survival Audit` ➡️ `Knowledge Audit` ➡️ `Vocabulary Validation` ➡️ `Vocabulary Dependency Audit`을 거쳐, 어휘의 거품(Alias)을 걷어내고 순수한 원형(Archetype)으로 정제된 진단 언어를 기반으로 작성되었습니다.

현재 SYNAPSE는 자신이 가진 지식 체계를 완벽하게 확정했으며, 아래의 질문들에 대해서는 그 어떤 감(Gut feeling)이나 휴리스틱 없이 수학적 패턴과 명확한 계약(Contract)에 기반하여 완벽하게 답할 수 있습니다.

## 🏛️ 진단 가능한 질문 카탈로그 (Question Catalog)

### 1. Archetype 1: The Core (핵심과 관문)
관련 어휘: `Domain Core`, `System Dominator`, `Knowledge Gateway`
- **Q1.** "현재 시스템에서 가장 많은 책임을 지탱하고 있는 도메인 핵심(Domain Core)은 어디인가?"
- **Q2.** "전체 시스템의 생살여탈권을 쥐고 있는 지배적 모듈(System Dominator)은 무엇인가?"
- **Q3.** "다른 컴포넌트들이 외부로 나가기 위해 반드시 거쳐야 하는 지식의 병목(Knowledge Gateway)은 어디인가?"

### 2. Archetype 2: The Spreader (전파자)
관련 어휘: `Change Amplifier`
- **Q4.** "이 컴포넌트를 수정했을 때, 시스템의 어느 범위까지 변경 여파가 도달하는가(Blast Radius)?"
- **Q5.** "가장 파급력이 커서 수정 시 가장 많은 테스트가 요구되는 모듈(Change Amplifier)은 무엇인가?"

### 3. Archetype 3: The Rot (부패와 부채)
관련 어휘: `Tangled Core`, `Boundary Erosion`, `God Module`, `Architectural Debt`
- **Q6.** "어느 모듈들이 서로를 끊임없이 참조하며 거대한 순환의 늪(Tangled Core / SCC)에 빠져 있는가?"
- **Q7.** "UI가 DB를 직접 참조하는 등, 사전에 정의된 아키텍처 계층을 위반(Boundary Erosion)하는 지점은 어디인가?"
- **Q8.** "자신이 덩치가 크면서 동시에 수많은 컴포넌트를 조종하려는 신(God Module)은 누구인가?"
- **Q9.** "위의 부패들이 중첩되어 당장 리팩토링이 시급한 기술 부채(Architectural Debt) 구역은 어디인가?"

### 4. Archetype 4: The Static (정적이고 안정적인 영역)
관련 어휘: `Stable Foundation`, `Isolated Feature`
- **Q10.** "다른 곳을 참조하지 않아 가장 안정적이고 테스트하기 쉬운 기반(Stable Foundation)은 어디인가?"
- **Q11.** "의존성이 완벽히 격리되어 있어 언제든 안전하게 떼어내거나 삭제할 수 있는 기능(Isolated Feature)은 어디인가?"

## 🔗 질문-근거 추적표 (Traceability Matrix)
단순한 질문 리스트가 아닙니다. 사용자가 특정 질문을 던졌을 때, SYNAPSE가 "왜 그렇게 판단했는가?"에 대해 답을 생성하는 근거(Evidence) 추적 맵입니다. 

이 매트릭스를 통해 `Question ➡️ Vocabulary ➡️ Pattern ➡️ Evidence` 로 이어지는 기계적 증명이 가능해집니다.

| Question | Vocabulary | Required Patterns (Cache) |
| :--- | :--- | :--- |
| **Q1. 도메인 핵심은 어디인가?** | `Domain Core` | `Fan-In` + `Authority Reach` + (`SCC` 배제) |
| **Q2. 시스템 지배자는 누구인가?** | `System Dominator` | `Fan-Out` + `Control Score` |
| **Q3. 지식의 관문은 어디인가?** | `Knowledge Gateway` | `Boundary Crossings` + `Authority Reach` |
| **Q4. 변경 여파는 어디까지인가?** | `Change Amplifier` (Scope) | `Blast Radius` |
| **Q5. 가장 파급력이 큰 모듈은?** | `Change Amplifier` (Target) | `Blast Radius` + `Fan-In` |
| **Q6. 엉켜있는 순환의 늪은?** | `Tangled Core` | `SCC (Tarjan)` + `Size` |
| **Q7. 계층을 위반하는 지점은?** | `Boundary Erosion` | `Boundary Crossings` + (Layer Mismatch) |
| **Q8. 거대한 신(God)은 누구인가?** | `God Module` | `Size` + `Fan-Out` + `Authority Reach` |
| **Q9. 기술 부채의 핵심 구역은?** | `Architectural Debt` | `SCC` + `Boundary Crossings` + `Blast Radius` |
| **Q10. 가장 안정적인 기반은?** | `Stable Foundation` | `Fan-Out = 0` + `Fan-In > 0` |
| **Q11. 완벽히 격리된 기능은?** | `Isolated Feature` | `SCC Size = 1` + `Fan-In = 0` + `Fan-Out = 0` |

## 🚫 현재 대답할 수 없는 질문들 (v0.3.34.45 분리 항목)
우리는 이제 우리가 "무엇을 대답할 수 없는지"를 명확히 압니다. 아래의 질문들은 현재의 언어(Dependency/Structure)로는 대답할 수 없으며, **v0.3.34.45 (Missing Language Discovery)** 마일스톤에서 커버리지 감사(Coverage Audit)와 패턴 확장 로드맵을 통해 해결할 영역입니다.

- "이 모듈의 실질적 소유자는 누구인가?" ➡️ (Ownership Pattern 없음)
- "이 파일이 최근 6개월 동안 얼마나 불안정했는가?" ➡️ (Churn Pattern 없음)
- "이 모듈이 런타임에서 실제로 중요한가?" ➡️ (Runtime Pattern 없음)
- "이 컴포넌트는 비즈니스적으로 핵심인가?" ➡️ (Business Tag 없음)
