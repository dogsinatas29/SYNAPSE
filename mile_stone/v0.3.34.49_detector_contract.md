# 🔬 Milestone v0.3.34.49 - Detector Contract Specification

## 목적
이 문서는 아키텍처 사전(Dictionary)의 용어를 생산할 수 있는 유일한 계층인 **Detector**의 권한과 책임, 그리고 엄격한 입출력 규격을 정의한다. "무엇을 절대 하면 안 되는가(Forbidden)"를 계약 수준에서 강제하여 48버전에서 발생했던 마법 숫자(Magic Number)와 권한 남용을 원천 차단한다.

---

## 1. Detector Authority Rule (생산 독점권)
오직 Detector 계층만이 `PatternFinding` 객체를 생성할 수 있다.

* ❌ **Report 계층**: Pattern 생성 및 용어 조합 금지
* ❌ **Analyzer 계층**: Pattern 생성 금지
* ❌ **Metric Engine**: Pattern 생성 금지
* ✅ **Detector 계층**: PatternFinding 생성 권한 독점

---

## 2. Detector Input Contract (입력 규약)
Detector는 어디선가 몰래 원시 데이터를 훔쳐 쓰지 않는다. **오직 `DetectorContext`를 통해서만** 공식적으로 공급받는다.

```typescript
export interface DetectorContext {
    graph: Graph;
    evidence: EvidenceContext;
    metrics: MetricContext;
}
```

* **허용된 정보 흐름:** `Detector ← Metric`, `Detector ← Evidence`
* **엄격히 금지된 흐름:** `Report ← Metric` (Report는 오직 Detector의 출력만 바라봐야 한다)

---

## 3. Detector Output Contract (출력 규약)
Detector의 `detect` 메서드는 **반드시 `PatternFinding[]` 배열만을 반환**해야 한다.

```typescript
export interface PatternDetector {
    detect(context: DetectorContext): PatternFinding[];
}
```

* ❌ `string[]`, `number[]`, `ReportSection[]`, `Markdown` 등 반환 절대 금지.
* 보고서에 찍힐 마크다운이나 문자열 조각은 Detector 내부에서 절대로 생성해선 안 된다.

---

## 4. Evidence Requirement Rule (증거 필수 원칙)
49 버전의 가장 중요한 계약이다. 증거 없는 직관은 폐기한다.

* **Rule:** `evidence.length == 0` → **Finding 생성 절대 금지.**
* 아무리 `confidence` 점수가 높아도, 이를 뒷받침할 구체적 `EvidenceItem`이 하나라도 누락된 `PatternFinding` 객체는 반환할 수 없다.

---

## 5. Gap Handling Rule (패턴 한계 처리)
Registry에 명시된 5가지 Gap(A~E) 상태에 따라 Detector의 구동 방식을 강제한다.

* **A (Sufficient), B (Derivable):** 자유롭게 생성 가능
* **C (Source Gap):** 생성 가능 (단, Missing Signal로 인한 누락 가능성 명시)
* **D (Definition Gap):** **생성 절대 금지**
  * 예: `LEARNING_HUB` → Detector 코드 작성 자체를 금지하며, 어떠한 Finding도 뱉어내선 안 됨.
* **E (Dynamic Gap):** 생성 가능 (단, Static Approximation(정적 추정)임을 명시)

---

## 6. Confidence Rule (신뢰도 규약)
과거 `score += 10000` 같은 마법 숫자를 전면 금지하고, 정규화된 확률 분포 스케일을 강제한다.

* **0.9 ~ 1.0**: Strong Evidence (결정적 증거 다수 존재)
* **0.7 ~ 0.9**: Moderate Evidence (복수의 정황 증거 확보)
* **0.5 ~ 0.7**: Weak Evidence (약한 추정 단계)
* **< 0.5**: **Do Not Emit** (출력 금지. 아예 `PatternFinding` 배열에 담지 말고 누락시킬 것)

---

## 7. Detector Traceability Rule (역추적성 원칙)

> "Detector가 생성한 모든 `PatternFinding`은 최소 1개 이상의 `EvidenceItem`을 포함해야 하며, 해당 `EvidenceItem`은 반드시 하위 계층인 Graph Node 또는 Source Code 파일 경로까지 역추적(Traceback) 가능해야 한다."

이는 v0.3.34.49 **Success Gate KPI 5 (Evidence Traceability = 100%)** 달성을 위한 최상위 설계 헌법이다.
