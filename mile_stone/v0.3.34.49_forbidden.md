# 🚫 Milestone v0.3.34.49 - Forbidden List & Architectural Guardrails

## 목적

v0.3.34.48 감사(Audit)를 통해 확인된 실패 사례를 재발 방지하기 위한 규칙이다.

본 문서는 기능 명세가 아니라 **설계 금지 목록(Forbidden List)** 이다.

새로운 코드 작성, Detector 구현, AST 도입, Pattern 추가 이전에 반드시 준수해야 한다.

---

# Rule 1. Report는 Metric을 직접 읽어서는 안 된다

## 금지

```text
Report
 └─ fanIn
 └─ fanOut
 └─ degree
 └─ blastRadius
 └─ topImpactFiles
```

직접 접근 금지.

## 이유

48 감사 결과:

```text
Report
  → Metric 직접 참조
  → Magic Formula 적용
  → Architect Vocabulary 출력
```

구조가 발견됨.

이는

```text
Question
 → Vocabulary
 → Pattern
 → Detector
 → Finding
 → Report
```

계약을 파괴한다.

## 허용

```text
Report
 └─ PatternFinding[]
```

오직 이것만 소비 가능.

---

# Rule 2. Detector 없이 Architect 용어를 사용하지 않는다

## 금지

다음 용어를 Detector 없이 Report에 출력하는 행위

* Hub
* Core
* Boundary
* Fortress
* Chokepoint
* Amplifier
* Entry Point
* Cascade Failure

## 이유

아키텍처 용어는 데이터가 아니라 해석이다.

해석은 반드시 Detector를 통해 생성되어야 한다.

## 허용

```text
PatternFinding {
    pattern: SYSTEM_CORE
}
```

가 존재할 때만

```text
System Core
```

표현 가능.

---

# Rule 3. Magic Number 금지

## 금지

예시

```ts
consumers.length * 2
```

```ts
score += 10000
```

```ts
if (name === "main.ts")
```

```ts
if (name === "extension.ts")
```

## 이유

근거가 없는 숫자는 Architect Dictionary에 존재하지 않는다.

설명할 수 없는 점수는 폐기 대상이다.

---

# Rule 4. Definition 없는 Pattern 구현 금지

## 금지

다음 순서

```text
Metric 발견
 ↓
Pattern 이름 붙임
 ↓
Report 출력
```

## 이유

48 감사에서 발견된 핵심 실패 원인.

실제 순서는

```text
Question
 ↓
Definition
 ↓
Evidence
 ↓
Detector
 ↓
Metric
```

이어야 한다.

---

# Rule 5. AST 도입 금지 (조건 충족 전)

## 금지

다음 주장

```text
AST 넣으면 해결된다
```

## 이유

48 감사 결과

패턴 문제는

* Definition Gap
* Wiring Gap
* Detector Gap

이 대부분이었다.

AST는 일부 Signal Gap만 해결한다.

## 조건

아래가 모두 완료되기 전까지 AST 작업 금지

* Dictionary 확정
* Pattern 정의 확정
* Detector 계약 확정
* Report Wiring 복구

---

# Rule 6. Evidence 없는 Pattern 금지

Pattern은 반드시 증거를 가져야 한다.

## 금지

```text
Core 같다
Boundary 같다
Hub 같다
```

## 허용

```text
Evidence
 ↓
Detector
 ↓
Finding
 ↓
Pattern
```

추적 가능할 때만 허용.

---

# Rule 7. Orphan Detector 생성 금지

## 금지

```text
Detector 작성
```

후

```text
아무도 호출하지 않음
```

상태.

## 이유

48 감사 결과

* SystemCoreDetector
* ChangeAmplifierDetector
* CascadeFailureDetector

가 실제 파이프라인에서 사용되지 않았음.

존재하는 코드와 작동하는 코드는 다르다.

---

# Rule 8. Contract First

모든 구현은 다음 질문부터 시작한다.

```text
이 Pattern은 무엇을 증명하는가?
```

그 다음

```text
어떤 Evidence가 필요한가?
```

그 다음

```text
현재 Resolver가 제공하는가?
```

그 다음

```text
Detector가 계산 가능한가?
```

마지막에만

```text
구현
```

을 시작한다.

---

# Rule 9. Evidence Preservation 유지

어떤 Finding도 반드시 역추적 가능해야 한다.

```text
Report
 ↓
Finding
 ↓
Detector
 ↓
Evidence
 ↓
Graph
 ↓
Source
```

체인이 끊어지면 실패.

---

# Rule 10. SYNAPSE는 Architecture Diagnostic Platform이다

SYNAPSE의 목적은

```text
예쁜 그래프
```

도 아니고

```text
복잡한 메트릭
```

도 아니다.

목적은

```text
Architectural Question
 ↓
Evidence
 ↓
Answer
```

이다.

모든 기능은 이 흐름을 강화해야 하며,
이 흐름을 우회하는 기능은 추가하지 않는다.
