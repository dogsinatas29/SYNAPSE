# 🧩 Milestone v0.3.34.49 - PatternFinding Contract Specification

## 목적
이 문서는 `Detector` 계층이 출력하고 `Report` 계층이 유일하게 소비해야 하는 핵심 데이터 객체인 `PatternFinding`의 공식 스펙을 정의한다.
Detector마다 중구난방으로 출력되는 포맷을 막고, **권위 체계를 통과하는 유일한 단일 데이터 규격**을 강제한다.

---

## 🛑 핵심 결정 사항 (Design Decisions)

### 1. Scope (Finding의 적용 범위)
**Q. Finding 하나는 Node 수준인가? Cluster 수준인가? Project 수준인가?**
**A. 모든 수준(Multi-level) 가능.**
Finding은 특정한 분석 대상(Target Entity)을 가리켜야 한다. 따라서 `TargetScope`(`NODE`, `CLUSTER`, `EDGE`, `PROJECT`)와 해당 대상의 고유 `targetId`를 분리하여 명시해야 한다.

### 2. Evidence (증거의 강제성)
**Q. Evidence는 필수인가?**
**A. 절대적 필수(Mandatory).**
증거 없는 추측(Guess)은 금지된다(Rule 6). 증거는 단순한 문자열이 아니라, 도출 근거가 되는 `EvidenceItem[]` 형태의 구조화된 데이터여야 한다.

### 3. Confidence (신뢰도)
**Q. Confidence는 필수인가?**
**A. 필수(Mandatory).**
정적 분석만으로는 증명할 수 없는 Dynamic Gap(E)이 존재하므로, Detector는 자신의 결론에 대한 신뢰도 점수(0.0 ~ 1.0)를 반드시 제공해야 한다.

### 4. Report Visibility (보고서 계층의 접근 권한)
**Q. Report는 Finding의 어떤 필드만 읽을 수 있는가?**
**A. 읽기 전용으로 제한.**
Report는 `patternId`, `targetId`, `confidence`만 읽어 아키텍처 사전(Dictionary)을 통해 텍스트로 번역(Render)해야 한다. Report가 Finding 내부의 원시 데이터(Evidence)를 직접 까보고 2차 계산을 하거나 독자적인 용어를 생성하는 것은 100% 금지된다.

### 5. Arbitrary Text (임의 텍스트 삽입)
**Q. Detector가 임의 텍스트(문장)를 넣어도 되는가?**
**A. 엄격히 불가(Forbidden).**
Detector는 문장을 만드는 곳이 아니다. 오직 `patternId` 식별자만 반환한다. "이 모듈은 시스템 코어입니다" 같은 문장은 최종적으로 Report 계층이 `patternId`를 매핑하여 조립한다.

### 6. Dictionary Mapping (아키텍처 사전 저장소)
**Q. Dictionary 용어("System Core")는 어디에 저장되는가?**
**A. Finding 객체 내부에 저장되지 않는다.**
Finding에는 오직 Enum 성격의 `patternId`(`"SYSTEM_CORE"`)만 저장된다. 실제 용어, 설명, 번역은 중앙 집중화된 `PatternRegistry`가 독점적으로 제공하며, Report는 이 Registry를 조회하여 출력한다.

## 📜 PatternFinding Interface (Official Code Contract)

```typescript
export type TargetScope = 'NODE' | 'CLUSTER' | 'EDGE' | 'PROJECT';

export interface EvidenceItem {
    type: string;
    value: number | string | string[];
    sourceNode?: string; // 증거가 발생한 진원지
}

export interface PatternFinding {
    // 1. Dictionary 권위 (반드시 Registry에 존재하는 ID여야 함)
    patternId: string; // ex: "SYSTEM_CORE"

    // 2. 적용 대상
    targetScope: TargetScope;
    targetId: string | string[]; // 배열은 묶음 대상일 경우 (예: 순환 참조 엣지들)

    // 3. 증거 및 신뢰성 (생략 절대 불가)
    confidence: number;       // 0.0 ~ 1.0
    evidence: EvidenceItem[]; 

    // 4. 컨텍스트 메타데이터 (Report가 문자열 렌더링 시 템플릿에 넣을 변수들)
    context?: Record<string, any>;
}
```
