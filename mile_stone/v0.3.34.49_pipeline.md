# 🏗️ Milestone v0.3.34.49

## Architecture Diagnostic Pipeline Contract

---

# 목적

SYNAPSE는 단순한 그래프 분석기가 아니다.

SYNAPSE의 최종 목표는 다음 질문에 답하는 것이다.

```text
아키텍트의 질문에
증거 기반으로 답한다.
```

따라서 모든 파이프라인은

```text
Question
 ↓
Answer
```

를 연결하기 위해 존재한다.

---

# 현재 발견된 문제

v0.3.34.48 Audit 결과

현재 구조는 사실상 다음과 같았다.

```text
Source
 ↓
Resolver
 ↓
Graph
 ↓
Metric
 ↓
Report
```

Report가 직접 Metric을 읽고

```text
degree
fanIn
fanOut
consumers.length * 2
```

등을 이용하여

아키텍트 용어를 생성하고 있었다.

이것은

```text
Question
 ↓
Dictionary
 ↓
Pattern
 ↓
Detector
```

계층을 완전히 우회(Bypass)하는 구조이다.

---

# 목표 구조

v0.3.34.49의 목표 구조는 다음과 같다.

```text
Question
 ↓
Dictionary
 ↓
Pattern Definition

────────────────────

Source
 ↓
Resolver
 ↓
Graph
 ↓
Metric
 ↓
Evidence

────────────────────

Detector
 ↓
PatternFinding
 ↓
Report
```

---

# Layer 1

## Question Layer

---

### 역할

아키텍트가 실제로 묻는 질문

예:

```text
어디가 진입점인가?

어디가 코어인가?

어디가 경계인가?

어디가 병목인가?

어디가 위험한가?
```

---

### 출력

Question Definition

---

# Layer 2

## Dictionary Layer

---

### 역할

질문을 아키텍처 용어로 정의

예:

```text
Root Entry Point

System Core

Boundary Fortress

Change Amplifier

Cascade Failure Point
```

---

### 출력

Pattern Vocabulary

---

# Layer 3

## Pattern Definition Layer

---

### 역할

패턴의 공식 정의

예:

```text
System Core란 무엇인가?

Boundary Fortress란 무엇인가?
```

---

### 포함

```text
Definition

Required Evidence

Detector Contract
```

---

### 출력

Pattern Contract

---

# Layer 4

## Source Layer

---

### 역할

실제 코드

---

### 입력

```text
.ts
.js
.cpp
.h
.java
.kt
...
```

---

### 출력

Raw Source

---

# Layer 5

## Resolver Layer

---

### 역할

소스에서 구조 정보 추출

---

### 예

```text
import

require

include

use
```

---

### 출력

```text
Dependency Relations
```

---

### 중요

Resolver는 의미를 해석하지 않는다.

Resolver는 사실만 수집한다.

---

# Layer 6

## Graph Layer

---

### 역할

의존성 네트워크 생성

---

### 출력

```text
Nodes

Edges

Clusters
```

---

### 특징

Evidence Preservation 시작점

---

# Layer 7

## Metric Layer

---

### 역할

Graph 기반 계산

---

### 예

```text
fanIn

fanOut

degree

authorityReach

blastRadius

clusterTraffic
```

---

### 특징

Metric은 의미가 아니다.

Metric은 숫자일 뿐이다.

---

# Layer 8

## Evidence Layer

---

### 역할

Metric을 Detector가 소비 가능한 증거로 변환

---

### 중요

49 버전에서 가장 중요한 계층

---

현재

```text
Metric
 ↓
Report
```

직결

---

목표

```text
Metric
 ↓
Evidence
 ↓
Detector
```

---

### 예시

Boundary Evidence

```json
{
  "type": "BOUNDARY_NODE",
  "nodeId": "...",
  "crossClusterTraffic": 42,
  "strength": 0.81
}
```

---

Simulation Evidence

```json
{
  "type": "CASCADE",
  "affectedNodeCount": 18,
  "propagationDepth": 4
}
```

---

Entry Evidence

```json
{
  "type": "ENTRY_POINT",
  "fanIn": 0,
  "fanOut": 12,
  "filename": "extension.ts"
}
```

---

### 책임

Evidence Layer는

```text
Graph + Metric
```

을

```text
Pattern이 이해할 수 있는 언어
```

로 변환한다.

---

# Layer 9

## Detector Layer

---

### 역할

Evidence를 Pattern으로 해석

---

### 입력

```typescript
Evidence[]
```

---

### 출력

```typescript
PatternFinding[]
```

---

### 금지

```text
Graph 직접 접근

Report 직접 생성

Metric 직접 출력
```

---

Detector는

```text
Evidence → Finding
```

만 수행한다.

---

# Layer 10

## Finding Layer

---

### 역할

---

### 표준 계약

```typescript
PatternFinding
{
    pattern
    entity
    score
    confidence
    evidence
}
```

---

### 특징

Report의 유일한 입력

---

## Report Layer

---

### 역할

---

### 입력

```typescript
PatternFinding[]
```

---

### 금지

```text
fanIn

fanOut

degree

blastRadius

topImpactFiles
```

---

### 허용

```text
SYSTEM_CORE

CHANGE_AMPLIFIER

BOUNDARY_FORTRESS
```

Finding 소비

# 핵심 계약

---

## Contract 1

Resolver는 사실만 수집한다.

---

## Contract 2

Metric은 숫자만 계산한다.

---

## Contract 3

Evidence는 Detector의 입력이다.

---

## Contract 4

Detector만 Architect Vocabulary를 생성할 수 있다.

---

## Contract 5

Report는 PatternFinding만 소비한다.

---

# Evidence Preservation Chain

```text
Report
 ↓
Finding
 ↓
Detector
 ↓
Evidence
 ↓
Metric
 ↓
Graph
 ↓
Source
```
