# 🚀 Milestone v0.3.34.4 - Graph Hygiene Layer (노드/그래프 정화 계층)

## 📅 작업 정보
- **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.34.3 (Graph Stress Simulator 완료)
- **목표:** Data Pipeline과 GraphModel 간의 입력 품질을 통제하여, 아키텍처 분석에 무의미한 가짜 노드(Noise Nodes)가 그래프에 진입하는 것을 차단하고 Intervention Engine의 입력을 `RUNTIME` 전용으로 정제한다.

## 🧠 상세 설계 및 로직
- **NodeRole 도입:** 단순 파일 출처(Provenance)가 아닌 아키텍처적 역할(Role) 분류.
  - `RUNTIME`, `DOMAIN_MODEL`, `TEST`, `TOOLING`, `CONFIG`, `DOCUMENT`, `ASSET`, `EXTERNAL`, `GHOST`
  - 계층화 확장성을 고려하여 `category` 속성 추가 (예: UI, Service, Domain 등).
- **Early Ghost Rejection:** 정규식 찌꺼기(`[^'"]+`, `||` 등)를 GraphBuilder 이전에 Scanner/Extractor 단계에서 즉시 폐기.
- **Strict RUNTIME Analysis:** 
  - `TarjanSCC` 및 `InterventionEngine` 입력은 **`RUNTIME` ONLY**로 제한.
  - `DOMAIN_MODEL`, `EXTERNAL`, `CONFIG` 등은 Storage(GraphModel)에는 유지하되, SCC 연산(Analysis)에서는 철저히 배제하여 빌드/설정/구조체 그래프가 런타임 결합도를 오염시키는 현상(거짓 허브 생성)을 방지.

## 🛠️ 기술적 변경 사항

- **[PLANNED] `src/core/DataPipeline.ts`:** NodeRole 할당 및 GHOST 배제.
- **[PLANNED] `src/core/analysis/reasoning/TarjanSCC.ts`:** `RUNTIME` ONLY 필터링.
- **[PLANNED] `src/core/analysis/reasoning/InterventionEngine.ts`:** 대상 후보군을 `RUNTIME` 노드로 한정.

## ⚠️ 예외 처리 및 주의 사항
- `DOMAIN_MODEL`(`schema.ts`, `types.ts` 등)과 `EXTERNAL`(`vscode` 등)을 삭제(Drop)하는 것이 아니라, "분석 엔진에서만 제외"하는 것이 핵심.
- **Hygiene 검증의 성공 기준:** 단순히 노드 수나 SCC 크기 감소가 아니라, 분석 결과의 **Top Hub Identity**가 `README.md`, `package.json`, `types.ts`에서 `CanvasPanel`, `BootstrapEngine` 같은 진짜 런타임 코어로 교체되었는지를 확인해야 함.
