# 🚀 Milestone v0.3.34.5 - Edge Provenance System (엣지 기원 추적 시스템)

## 📅 작업 정보
- **상태:** 🏗️ Planned
- **관련 마일스톤:** v0.3.34.4 (Graph Hygiene Layer 완료)
- **목표:** 단순 문자열(정규식) 매칭이나 단일 파서(AST)에 의존하지 않고, 엣지가 생성된 **기원(Provenance)**을 다각도로 분류하여, Intervention Engine이 "의미 있는 아키텍처 결합"과 "무해한 참조"를 구분할 수 있는 메타데이터 기반을 마련한다. 단순 AST 의존 시 발생할 수 있는 동적 의존성(플러그인, 리플렉션, DI 컨테이너) 유실 문제를 해결하는 것이 핵심이다.

## 🧠 상세 설계 및 로직
- **Paradigm Shift:** `AST Only` 접근의 위험성을 회피하기 위해 다양한 소스(Regex, Config, AST 등)에서 수집된 엣지에 태그(Provenance)를 달아 관리.
- **Edge Provenance Types (열거형 후보):**
  1. `CALL_EDGE` : 실제 런타임 함수/메서드 호출 (Runtime Coupling: High)
  2. `TYPE_EDGE` : 순수 타입 참조 (`import type`, 인터페이스 구현 등) (Runtime Coupling: Low/Zero)
  3. `IMPORT_EDGE` : 일반 모듈 임포트
  4. `EXPORT_EDGE` / `REEXPORT_EDGE` : 배럴 파일 등의 내보내기 릴레이
  5. `STRING_REFERENCE` : 정규식 리터럴, 주석 등에서 발견된 문자열 매칭 (신뢰도 낮음)
  6. `CONFIG_REFERENCE` : JSON, YAML 등 설정 파일에서의 명시적 참조
  7. `DYNAMIC_REFERENCE` : DI 컨테이너, 팩토리, 리플렉션 등을 통한 동적 결합
- **Confidence Level (확신도):**
  - 각 Provenance마다 `HIGH`, `MEDIUM`, `LOW` 등의 신뢰도를 부여하여, 엔진이 가짜 노이즈 엣지를 필터링하거나 가중치를 제어할 수 있도록 설계.

## 🛠️ 기술적 변경 사항
- **Node/Edge 스키마 확장:** `src/types/schema.ts`의 Edge 타입에 `provenance` 및 `confidence` 필드 추가.
- **Data Pipeline 1차 수정:** 기존 Scanner 로직들을 수정하여 엣지 생성 시 정규식 기반 참조(`STRING_REFERENCE`) 및 설정 기반 참조(`CONFIG_REFERENCE`) 등 초기 Provenance를 할당. (이후 AST를 통해 정밀하게 CALL / TYPE 등을 분류 및 검증)
- **Intervention Engine 필터링:** Provenance가 `STRING_REFERENCE` 중 신뢰도가 낮거나, 명백한 무해 파일(예: `README.md`, 정규식 찌꺼기 등)을 필터링 및 가중치 조정 로직 반영.

## ⚠️ 예외 처리 및 주의 사항
- **호환성 및 마이그레이션:** 기존에 수집된 `project_state.json` 상의 엣지들은 `provenance`가 없으므로 `UNKNOWN_REFERENCE` 등 기본값을 주어 호환성을 유지해야 한다.
- **오버헤드 관리:** 엣지 객체에 메타데이터가 추가되므로, 직렬화 시 성능 저하(OOM)가 발생하지 않도록 메타데이터 구조를 최대한 평탄하고 경량화한다.
