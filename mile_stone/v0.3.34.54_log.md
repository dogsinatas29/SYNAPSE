### Q1. `.41` 문서가 `simulation_evidence.json`에 PROPAGATION/CASCADE schema를 명세했는가?

### Q2. `SimulationEvidenceType`의 `STRUCTURAL/BEHAVIORAL/...`이 현재 정식 Evidence taxonomy인가?

### Q3. `CascadeFailureDetector`의 `PROPAGATION/CASCADE` 요구는 어디서 유래했는가?

## 🔬 Step 2~4 조사 결과

### Step 2 — PROPAGATION vs CASCADE 의미 정의 (FACT)

**`src/types/schema.ts` L630~632:**
```ts
export interface FailureImpact {
    directImpact   : number; // depth=1
    indirectImpact : number; // depth=2
    cascadeImpact  : number; // depth>=3
}
export const MAX_PROPAGATION_DEPTH = 3;
```

**의미 확정:**

| Evidence type | 의미 | 소스 |
|---|---|---|
| `PROPAGATION` | BFS depth=1~2 (직접/간접) 전파 경로 | `FailurePropagator.directImpact + indirectImpact` |
| `CASCADE` | BFS depth≥3 (깊은 연쇄) 전파 | `FailurePropagator.cascadeImpact` |

`.49` 샘플의 `propagationDepth`는 최대 BFS depth, `affectedNodeCount`는 `impactedNodes.length`에 대응.
`PROPAGATION` 별도 schema는 `.49` 문서에 없음 — Detector의 `f.evidenceType === 'PROPAGATION'` 조건은 **선제적 필터(guard)** 이며, 실제 입력 구조는 `CASCADE` 단일 타입임.

### Step 3 — Metric → Evidence 변환 책임자 (FACT)

**경로:**
```text
StateAuditPipeline.run()
  → FailurePropagator.propagate()  ← cascadeImpact 생성
  → StateAuditResult.failurePropagation (FailurePropagationReport)
  → TopologyMutator.simulateNodeRemovals() ← cascadeImpact 소비
```

**VirtualDebugger와의 연결:**
```text
VirtualDebugger → StateAuditPipeline: 연결 없음 (grep 확인)
VirtualDebugger → FailurePropagator:  연결 없음
```

**결론:** `FailurePropagator`는 `cascadeImpact` Metric의 **원체(Source)**임이 확인됨.
그러나 그것이 곳 **Evidence Layer의 책임자**라는 보장은 없음.
`FailurePropagationReport → evidenceBundle.findings` 변환 주체(Adapter) 및 **연결 위치(Orchestration)**는 여전히 설계 결정 대상.

### Step 4 — SimulationEvidenceType과의 관계 (FACT)

```text
SimulationEvidenceType (src/core/simulation/evidence/)
  STRUCTURAL / BEHAVIORAL / CONTROL / STATE / POLICY
  → Simulation 시나리오 내부 전환 증거 (시나리오 재현 단계 분류용)
  → VirtualDebugger에 연결되지 않음

Pattern Evidence taxonomy (CascadeFailureDetector 입력)
  CASCADE / PROPAGATION
  → FailurePropagator 계산 결과 기반
  → 현재 evidenceBundle.findings에 없음
```

**판정: 두 taxonomy는 현재 증거 범위에서 통합을 요구하는 연결이 발견되지 않음. 병렬 유지 여부는 `.55` Evidence Contract 설계에서 확정.**
