`.49` 마일스톤의 P0-13 Trace Audit 결과, 11개 패턴 중 2개의 패턴이 "No Findings (탐지결과 0건)" 상태로 남았다.
- `CASCADE_FAILURE_POINT` (원인 규명 완료 및 이관 됨 - `.56`)
- `BOUNDARY_FORTRESS` (**본 마일스톤 조사 대상**)

"왜 안 나오는가?"를 규명하는 것이 목적이며, 억지로 Fortress를 만들어내는(기능 추가) 작업이 아니다. 기존 검증 패턴(Audit)의 연장선이다.

---

### Step 1. Detector 실행 경로 확인
- 등록 → 실행 → 결과 소비 → 리포트 출력까지의 파이프라인 배선이 정상적으로 연결되어 있는지 코드 레벨에서 확인한다.

### Step 2. Mock 데이터로 강제 발화 검증
- Fortress 후보 조건을 강제로 만족시키는 Mock 데이터를 주입했을 때, Finding이 정상적으로 생성(발화)되는지 확인한다.

### Step 3. 실데이터 분석 (project_state.json)
- 현재 대상 프로젝트(VS Code 확장)의 실제 그래프 상태에 Fortress 조건을 만족할 만한 잠재적 후보가 존재하는지 검토한다.

### Step 4. 최종 판정
조사 결과에 따라 다음 4가지 시나리오 중 하나로 상태를 확정한다.
- **A. Detector 정상 + 후보 없음:** 현재 프로젝트의 그래프 특성 (정상)
- **B. Detector 정상 + Threshold 과도:** 임계값이 비현실적으로 높아 발화되지 않음
- **C. Contract Void:** 필수 데이터나 필드가 누락되어 로직이 무효화됨 (CASCADE 사례와 동일)
- **D. 구현 버그:** 로직 자체에 결함 존재
- **E. 정의-현실 불일치:** 로직은 정상이나, 특정 프로젝트(예: VSCode)의 아키텍처 특성과 패턴 정의(Contract)가 맞지 않아 발생하는 의도된(정상적인) 0건 현상

## 📊 최종 분포 증거 (Distribution Proof)

VSCode의 대형 스냅샷(7,536 노드)과 SYNAPSE(641 노드)를 대상으로 모든 후보(Candidate)가 **어떤 조건에서 탈락했는지**를 전수조사한 통계입니다.

### 1. VSCode 대형 그래프 (7,536 nodes, 579 후보 평가)
- **전체 후보 수:** 579개
- **탈락 (크기/구조 미달 - REJECT_SMALL/LEAF):** 297개 (51.2%)
- **탈락 (응집도 부족 - REJECT_WEAK):** 187개 (32.2%)
- **통과 (PROMOTED):** 95개
  - └─ **BOUNDARY_FORTRESS (Strong): 27개** (전체의 약 4.6%)
  - └─ BOUNDARY_CANDIDATE (Moderate): 29개
  - └─ WEAK_BOUNDARY (Weak): 39개

**[분포 특성]**
- **Cohesion:** 579개 후보 중 415개(71%)가 `0.0 ~ 0.2` 사이의 매우 낮은 응집도를 기록함. 
- **Size:** 362개(62%)가 멤버 수 4개 이하의 초소형 찌꺼기(Fragment) 모듈.
- **결론:** 거대한 프로젝트라도 대부분의 폴더는 파편화되어 있거나, 응집도가 매우 낮아 Fortress 임계값(`cohesion >= 0.75` 또는 `fanIn >= 100`) 근처에도 가지 못하고 탈락(REJECT)합니다.

### 2. SYNAPSE 본체 그래프 (641 nodes, 45 후보 평가)
- **전체 후보 수:** 45개
- **탈락 (크기/구조 미달):** 32개
- **탈락 (응집도 부족):** 3개
- **통과 (PROMOTED):** 10개
  - └─ **BOUNDARY_FORTRESS (Strong): 5개**

### 3. 최종 판정 (Category E: 정의-현실 불일치)
위 분포 증거를 통해, `.49` 당시 646개 노드로 축소된 VSCode 서브셋 그래프에서 0건이 나온 이유가 완벽히 수학적으로 입증되었습니다.
- 해당 서브셋 내에서는 구조적으로 `Size >= 5`를 만족하면서 동시에 `Cohesion >= 0.75`를 달성하거나, `Fan-In >= 100`을 충족하는 폴더가 **단 하나도 없었기 때문**입니다.
- **Contract Void(파이프라인 누락)**나 **버그**가 아니며, 순수하게 데이터의 분포가 Fortress 계약(Contract) 조건을 만족하지 못한 "정의-현실 불일치(E)" 상태입니다.
