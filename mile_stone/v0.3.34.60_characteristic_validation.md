# 🚀 Milestone v0.3.34.60 - Characteristic Validation & Metric Design (ARCHITECTURAL_CHOKEPOINT)

## 📅 작업 정보
- **상태:** 🚧 In-Progress
- **관련 마일스톤:** v0.3.34.59 (Characteristic Audit)
- **목표:** `.59`에서 도출된 관측 특성들을 검증하고, 이를 측정할 수 있는 Metric을 도출합니다. 단, 특정 파일(`CanvasEngine`)에 결과를 맞추는 순환 논리를 피하기 위해 **Synthetic Graph 검증을 최우선**으로 수행합니다.

## 🧠 설계 원칙 (Design Principles)
메트릭 설계를 위해 다음 4가지 검증을 반드시 통과해야 합니다.
1. **Characteristic Fidelity:** Metric이 정의된 현상을 정확히 측정하는가?
2. **Discrimination:** True Chokepoint와 단순 High-Connectivity 노드를 구조적으로 구별하는가?
3. **Robustness:** 그래프나 클러스터의 규모가 변해도 의미가 유지되는가?
4. **Non-Circularity (순환 논리 방지):** 우리가 Chokepoint라고 미리 지정한 파일을 Metric이 다시 Chokepoint로 만드는 구조가 아닌가? (정답에 끼워 맞추기 금지)

## 🛠️ Step 1: Synthetic Graph Test Suite (.60-A)
먼저 아래 5가지 Synthetic Graph 모델을 만들어, 우리가 정의한 6가지 특성(Cross-Boundary Connectivity, Directional Asymmetry 등)이 각 그래프에서 어떻게 판독되어야 하는지 "정답(Expected Observation)"을 세웁니다.

이 G1~G5는 특정 단일 메트릭이 단독으로 Chokepoint를 정의할 수 없음을 증명하는 **False Positive 필터** 역할을 합니다. 

| Graph | 구조 요약 (Cluster 포함) | 제거하려는 오판 (Negative Control) |
| :--- | :--- | :--- |
| **G1 (True Chokepoint)** | [C_A] A,C,E → [C_X] X → [C_B] B,D,F | 우리가 찾으려는 실제 구조 |
| **G2 (High Connectivity)** | [C_A] A → [C_X] X,Y,Z → [C_B] B | 단순 연결이 많다고 Chokepoint가 아님 (우회로 다수) |
| **G3 (Cut Vertex)** | [C_A] A → [C_X] X → [C_B] B | 끊을 수 있다고 모두 Chokepoint가 아님 (단순 병목) |
| **G4 (Bidirectional Coupling)** | [C_A] A ↔ [C_X] X ↔ [C_B] B | 단순 양방향 결합은 Chokepoint가 아님 |
| **G5 (High Fan-In, Local)** | [C_A] A,B,C,D → X | 클러스터 내부의 높은 결합도는 Chokepoint가 아님 |

## 🔬 Step 2: Characteristic Observation (.60-A Phase 2)
스코어나 메트릭 공식을 만들기 전에, 5개의 그래프에 대해 6가지 현상이 어떻게 관측되는지(High/Low)를 있는 그대로 판독합니다.

| Characteristic | 질문 (관측 포인트) |
| :--- | :--- |
| **Cross-Boundary Connectivity** | 서로 다른 영역을 물리적으로 연결하는가? |
| **Directional Asymmetry** | 특정 방향으로 흐름이 집중되는가? |
| **Alternative Path Availability** | 제거 시 다른 우회 경로가 얼마나 존재하는가? |
| **Structural Reach** | 시작된 의존성이 얼마나 넓은 영역(클러스터)에 닿는가? |
| **Dependency Concentration** | 여러 영역의 관계가 한 노드에 몰려 있는가? |
| **Change Propagation Potential** | 변경 시 얼마나 넓은 구조로 퍼져나가는가? |

> **⚠️ 기대 효과:** 이 실험을 통해 특정 특성(Characteristic) 하나만으로는 G1~G5를 구별할 수 없으며, 결국 특성들의 조합(Composite)이 필수적임을 수학적으로 발견하게 될 것입니다.

## 📐 Step 3: Metric Candidate Evaluation (.60-B)
Step 2에서 생성된 `Characteristic Observation Table`을 만족시키는 수학적 수식(Metric)들을 찾아내고 조합합니다.

### 3-1. Alternative Path Availability
**정의:** 노드 X를 제거했을 때, X가 연결하던 Source Domain과 Target Domain 사이에 독립적인 대체 경로가 남아 있는가?
* **선정 후보:** `Directed Node-Disjoint Paths` (또는 `Minimum Node Cut` - 둘은 동치)
* **Precondition (측정 전제조건):**
  1. `Source Domain ≠ Target Domain` (양방향 결합 그래프에서 Source와 Target이 겹치는 경우, X 제거 후 남은 0-depth 경로를 우회로로 오판하는 버그 방지)
  2. 우회 경로는 반드시 1개 이상의 directed edge를 포함하여 다른 영역으로 이동해야 함.

### 3-2. Structural Reach
**정의:** X가 연결하는 논리적/구조적 영역의 범위.
* **선정 후보:** `SR2 - Cluster Reach` (X에서 도달 가능한 distinct clusters 수)
* **특징:** 단순 노드 수가 많은 것(SR1 Node Reach)보다, 독립적인 구조 단위를 얼마나 많이 아우르는지를 측정. 반드시 Forward / Reverse 방향을 각각 측정하여, X가 모으는지(Fan-in 집중) 퍼뜨리는지(Blast Radius)를 구별해야 함.

### 3-3. Dependency Concentration
**정의:** 여러 구조 영역 간의 dependency relationship이 특정 노드 하나에 얼마나 집중되어 있는가?
* **DC1 (Raw Betweenness):** Rejected. Graph 규모에 지나치게 민감하며, Local Hub(G5)를 높게 평가하여 Architectural Chokepoint 정의와 불일치함.
* **DC2 (Boundary-aware Betweenness):** Partial Candidate. Cross-boundary 관계만 필터링한 것은 유효하나 여전히 Node Count에 민감함 (G6 과대평가).
* **DC3 (Cross-Boundary Dependency Concentration):** Strong Candidate.
  * **측정 방식:** 노드 X를 포함하는 Directed Dependency Paths 중, Source Cluster($C_s$)와 Target Cluster($C_t$)가 서로 다른 **Distinct Ordered Cluster-Pair**의 수.
  * **특징:** 규모 독립적(Scale-independent). 로컬 내부 결합 배제(G5=0). 방향성 유지. 단순히 연결된 노드 수가 아닌, 구조 영역 간의 관계 자체를 카운트함.

### 3-4. Directional Asymmetry
Candidate Metrics:
- DA1 Raw Asymmetry
- DA2 Cross-Boundary Asymmetry
- DA3 Structural Reach Asymmetry

Result:
- All three can measure directional imbalance.
- None discriminates G1 from G4.
- G1 (True Chokepoint) can be perfectly symmetric at the node level.
- Therefore directional asymmetry is NOT a necessary condition for ARCHITECTURAL_CHOKEPOINT.

Disposition:
- Demoted from essential characteristic.
- Retained as a secondary topology descriptor.
- Must not be used as a hard exclusion criterion.

Important:
Directional Asymmetry describes the shape/direction of a dependency structure; it does not establish Chokepoint identity.

### 3-5. Change Propagation Potential

Initial Definition:
Change Propagation Potential describes the downstream structural impact that may result from changing node X.

Redundancy Analysis:
Under the current static dependency-graph model, measuring CPP requires directed downstream reachability from X. When the affected scope is measured as reachable clusters, this operation is equivalent to the Forward component of Structural Reach.

Result:
CPP does not currently provide an independent observable beyond Forward Structural Reach.

Disposition:
MERGED into Structural Reach.

Current representation:

Structural Reach
├── Forward Cluster Reach
│   └── downstream structural scope / propagation potential
└── Reverse Cluster Reach
    └── upstream dependency footprint

Important:
This is a model-level redundancy finding, not a universal statement that change propagation is mathematically identical to structural reach. A future change-sensitive propagation model may justify CPP as an independent characteristic.

## 📐 Step 4: Metric Design & Composite (.60-C)

가장 먼저 개별 특성(Characteristic)이 Synthetic Graph 5종(G1~G5)에서 어떻게 판독되는지 Boolean/Qualitative 교차 검증(Raw Matrix)을 수행합니다. 이를 통해 각 특성이 오판(False Positive)을 어떻게 걸러내는지 역할을 확인합니다.

### 4-1. Raw Characteristic Matrix (Qualitative Intersection)

| Graph | Description | Cross-Boundary | Dependency Concentration (DC3) | Alternative Path | Structural Reach (SR2) | Expected Result |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |
| **G1** | True Chokepoint | Yes | 1 | Low | Meaningful | **Candidate** |
| **G2** | Redundant Connectivity | Yes | 1 | High | Meaningful | **Reject** |
| **G3** | Cut Vertex (Single path) | Yes | 1 | Low | Meaningful | **Reject** |
| **G4** | Bidirectional Coupling | Yes | 2 | Low | Meaningful | **Reject** |
| **G5** | Local Hub | No | 0 | N/A | None | **Reject** |

### 4-2. 특성별 필터링 역할 (Role Analysis)

1. **Cross-Boundary Connectivity & Structural Reach**:
   - 역할: 로컬 노드 필터링.
   - 결과: G5(Local Hub)가 탈락합니다.
2. **Dependency Concentration (DC3)**:
   - 발견: DC3는 G1(True Chokepoint)과 G3(Cut Vertex)를 분리하지 못합니다 (둘 다 1). 
   - 의의: 이는 문제가 아니라 "의존성 집중도 자체만으로는 진정한 아키텍처 초크포인트와 단순 컷 버텍스를 구분할 수 없다"는 중요한 사실을 뒷받침합니다. G1과 G3의 궁극적인 차이는 Alternative Path와 Structural Reach의 정량적 규모에서 찾아야 합니다.
3. **Alternative Path (우회 경로)**:
   - 역할: 우회 가능한 일반 경로 필터링.
   - 결과: G2가 명확히 탈락합니다.
   
*(※) G4 (Bidirectional Coupling) 분석*:
- **Observed:** 현재 최소 단위의 Synthetic G4에서는 Alternative Path가 `Low`로 나타납니다.
- **Observed:** G4의 DC3는 2, G1의 DC3는 1로 관측됩니다.
- **Hypothesis:** 실제 코드베이스의 거대한 양방향 강결합(Coupling) 구조에서는 의존성이 여러 경로로 얽혀 있어 Alternative Path가 실질적으로 높아질 수 있습니다.
- **Validation:** 실제 데이터에서 Alternative Path 점수가 G4를 어떻게 평가하는지 검증합니다. G4 전용 예외 로직(Detector)은 만들지 않습니다.

### 4-3. Independence Check (상호 배타성 및 독립성 검증)

특성 합성(Composite) 전에 각 Metric이 독립적인 정보를 제공하는지 확인합니다.

1. **Cross-Boundary vs Dependency Concentration (DC3)**
   - DC3는 `Cs != Ct`인 Ordered Cluster-Pair를 세는 방식이므로, **DC3 > 0 이면 자동으로 Cross-Boundary = Yes**가 성립합니다.
   - 따라서 Cross-Boundary는 독립적인 Metric이라기보다 DC3의 하위 표현(내재된 특성)으로 흡수 가능합니다.
2. **Alternative Path vs Dependency Concentration**
   - DC3는 "어떤 경계(Domain)들을 잇는가"를 봅니다.
   - Alternative Path는 "그 두 경계 사이에 X 외에 다른 길이 있는가"를 봅니다. 둘은 독립적입니다.
3. **Structural Reach (SR2) Forward vs Reverse**
   - 시스템의 단방향 흐름 성향에 따라 특정 노드는 Forward가 길고 Reverse가 짧거나 그 반대일 수 있으므로 독립적인 정보를 제공합니다.
4. **SR2 vs DC3**
   - DC3는 X를 직접 지나는 *쌍(Pair)의 수*를 세고, SR2는 X에서 뻗어나가는 *영향력의 깊이와 넓이(Clusters)*를 셉니다. 서로 다른 현상을 측정합니다.

## 🏁 Step 5: Real Data Validation (.60-D)
설계된 특성 지표(Metric)들을 실제 SYNAPSE 그래프에 적용하여 관측성(Observability)을 검증합니다. 

이 단계의 1차 목표는 **가중치(Weight)나 점수(Score) 합성을 설계하는 것이 아닙니다.** 각 Metric의 스케일, 중복성, 실제 데이터 분포, 노드/클러스터 크기 민감도(Sensitivity)가 완전히 확인되지 않았기 때문입니다. 

대신, Synthetic에서 도출한 **각 Metric의 구조적 의미가 실제 그래프에서도 일관되게 관측되는지** 검증합니다.

- **Representative Candidate:** `CanvasEngine`, `BootstrapEngine`
- **Representative Control:** `types.ts`, `TarjanSCC.ts`
