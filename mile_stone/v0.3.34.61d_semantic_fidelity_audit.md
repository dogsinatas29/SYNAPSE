# 🚀 Milestone v0.3.34.61d - Metric Semantic Fidelity Audit (Candidate Selection)

## 📅 작업 정보
- **상태:** 🏗️ Planned / 🚧 In-Progress
- **목표:** `DC3`와 `AP_count`의 구현 후보군(Candidates)을 Synthetic Graph(G1~G5, G2b)에 대입하여, 각 후보가 원래 의도한 의미론적 계약(Semantic Definition)을 훼손 없이 만족하는지(Fidelity)를 검증한다.
- **핵심 철학:** 이 실험의 진정한 목적은 단순한 승자 선택이 아니라, **"구현 방식이 바뀌면 사실상 이름만 같은 완전히 다른 Metric이 되어버림(Semantic Drift)"**을 증명하는 것이다. (예: `AP_local`이 FAIL을 받는다면, 그것은 `AP_count`의 틀린 구현이 아니라 `Local Neighbor Robustness`라는 별개의 Metric임을 입증하는 것).

---

## 1. Metric Candidates (평가 대상)

### 1.1. DC3 (Dependency Concentration)
- **`DC3_path`**: 실제 노드 X를 관통하는 명시적인 경로 탐색 기반
- **`DC3_reachability`**: $Reverse Reachable Clusters \times Forward Reachable Clusters$ 기반 (순환 구조 시 과대평가 위험 존재)

### 1.2. AP_count (Alternative Path Availability)
- **`AP_global`**: 전역 BFS 탐색 기반 대체 경로(Reachability in $G \setminus \{X\}$) 검사
- **`AP_boundary`**: 경계 노드 간의 우회로 검사
- **`AP_local`**: X의 1-hop 직접 이웃 클러스터 간의 우회로 검사
- **`AP_sampled`**: 샘플링 기반 경로 검사

## 2. Validation Suite: Synthetic Graph Oracles (정량적 정답지)
각 메트릭 후보는 아래의 5가지 합성 그래프 모델을 통과하며 **정확한 정량적 기댓값(Oracle)**을 산출해야 합니다. 단 하나의 오차라도 발생할 경우(Fail) 해당 후보는 최종 Contract에서 영구 탈락합니다. 속도(Cost)는 Fidelity 통과 후 2차 고려 대상입니다.

### [G1] Single Path (기본 병목)
- **Topology**: `A -> X -> B`
- **Clusters**: `C_A`, `C_X`, `C_B` (각 노드는 별도 클러스터)
- **Oracle (정답)**:
  - `DC3(X) = 1` (Pair: C_A $\rightarrow$ C_B)
  - `AP_count(X) = 0` (대체 경로 없음)
  - `SR_F(X) = 1`, `SR_R(X) = 1`

### [G2] Redundant Connectivity (단일 우회로 존재)
- **Topology**: `A -> X -> B`, `A -> Y -> B`
- **Clusters**: `C_A`, `C_X`, `C_B`, `C_Y`
- **Oracle (정답)**:
  - `DC3(X) = 1` (Pair: C_A $\rightarrow$ C_B)
  - `AP_count(X) = 1` (Y를 통한 완벽한 우회로가 존재하여 해당 쌍 유지됨)

### [G2b] Multi-hop Bypass (다단계 간접 우회로 존재)
- **Topology**: `A -> X -> B`, `A -> Y -> Z -> B`
- **Clusters**: `C_A`, `C_X`, `C_B`, `C_Y`, `C_Z`
- **Oracle (정답)**:
  - `DC3(X) = 1` (Pair: C_A $\rightarrow$ C_B)
  - `AP_count(X) = 1` (Y$\rightarrow$Z를 통한 다단계 우회로 존재)

### [G2c] Remote Bypass (원격 우회로 존재)
- **Topology**: `A1 -> A2 -> X -> B1 -> B2`, 우회로 `A1 -> Y -> B2`
- **Clusters**: 각각 개별 클러스터
- **Oracle (정답)**:
  - `DC3(X) = 4` (모든 교차 쌍)
  - `AP_count(X) \ge 1` (최소한 `A1 -> B2` 쌍에 대해서는 Y를 통한 우회로 존재)
  - *해석*: X의 직접 이웃(`A2`, `B1`) 간에는 우회로가 없지만, 더 먼 조상/후손 간에는 우회로가 있음. `AP_local`이 이 쌍을 놓친다면(0을 반환), 그것은 `AP_count`가 아니라 `Local Neighbor Robustness`임을 증명함.

### [G3] Cyclic Dependency (순환 참조 인플레이션)
- **Topology**: `A -> X -> B`, `B -> A`
- **Clusters**: `C_A`, `C_X`, `C_B`
- **Oracle (정답)**:
  - `DC3(X) = 1` (Pair: C_A $\rightarrow$ C_B)
  - *해석*: B에서 A로 돌아가는 순환 경로가 존재하더라도, 단순 경로(Simple path) 관점에서 X를 매개로 하는 새로운 유효 교차 쌍은 창출되지 않음. `DC3_reachability`가 2 (C_A$\rightarrow$C_B, C_B$\rightarrow$C_A)를 반환하면 **FAIL**.

### [G4] Bypassable Hub (우회 가능한 거대 허브)
- **Topology**: `A1, A2 -> X -> B1, B2` 및 `A1, A2 -> Y -> B1, B2`
- **Clusters**: `C_A1`, `C_A2`, `C_X`, `C_Y`, `C_B1`, `C_B2`
- **Oracle (정답)**:
  - `DC3(X) = 4` (Pairs: 2 $\times$ 2)
  - `AP_count(X) = 4` (모든 쌍에 대해 Y라는 우회로 존재)
  - *해석*: 거대한 트래픽이 집중되는 Hub이지만, `AP_count`가 높으므로 Chokepoint가 아님.

### [G5] Strict Cut Vertex (절대적 병목)
- **Topology**: `A1, A2 -> X -> B1, B2` (오직 X만을 통해서 교차 가능)
- **Clusters**: `C_A1`, `C_A2`, `C_X`, `C_B1`, `C_B2`
- **Oracle (정답)**:
  - `DC3(X) = 4` (Pairs: 2 $\times$ 2)
  - `AP_count(X) = 0` (대체 경로 절대 없음)
  - *해석*: 완벽한 형태의 Architectural Chokepoint.

## 3. PASS / FAIL Matrix 및 Selection
후보군(`DC3_path`, `DC3_reachability`, `AP_global`, `AP_local` 등)을 위 G1~G5 오라클에 대입하고 다음과 같은 매트릭스로 평가합니다.

| Candidate | G1 | G2 | G2b | G2c | G3 | G4 | G5 | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `DC3_path` | PASS | PASS | PASS | PASS | PASS | PASS | PASS | **PASSED** (완벽한 의미 보존) |
| `DC3_reachability` | PASS | PASS | PASS | PASS | **FAIL** | PASS | PASS | **FAILED** (순환 구조 시 인플레이션) |
| `AP_global` | PASS | PASS | PASS | PASS | PASS | PASS | PASS | **PASSED** (완벽한 의미 보존) |
| `AP_local` | PASS | PASS | PASS | **FAIL** | PASS | PASS | PASS | **FAILED** (원격 우회로 누락, 이웃 검사로 의미 훼손) |

- **Selection Rule**: 정량적 Oracle(정답)과 값이 일치하지 않는(FAIL) 후보는 "해당 메트릭의 의미를 완벽히 대변하는 구현체가 아님"을 선언받고 가차 없이 폐기됩니다.
- **Cost Evaluation**: 정답을 맞힌(PASS) 후보들만을 대상으로, 연산 비용(Runtime Cost)을 평가하여 최종 `Frozen Contract`로 승격시킵니다.
