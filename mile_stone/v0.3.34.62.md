## 🧠 상세 설계 및 로직

최적화(Caching, O(logN))부터 시작하지 않고, **정확성 검증을 위한 순차적(Incremental) 5단계 파이프라인**을 준수합니다.

### Phase 1: Naive Reference Implementation
수학적 계약을 코드로 1:1 직역한 "느리지만 무조건 맞는" 실행 가능 명세서(Executable Specification)를 작성합니다.
1. Candidate 필터링: $X$가 Singleton SCC인지 검사.
2. SCC-Cluster Attribution: 다중 클러스터에 걸친 SCC는 제외.
3. $P_X$ 및 `DC3` 계산: $G_{scc}$에서 단순 순회를 통한 Cluster-pair 수집.
4. `RetainedPairs` 계산: 각 쌍에 대해 $G_{scc} \setminus \{X\}$ 에서의 도달 가능성 검증.
5. `CriticalPairs` 산출 및 `SR` 결합.

### Phase 2: Oracle G1~G7 Exact Verification
작성된 Naive Reference를 G1~G7 Synthetic Graph에 주입하여 DC3, RetainedPairs, CriticalPairs 값이 Oracle Table과 정확히 일치하는지 검증합니다. 특히 G4(Hub)와 G5(Chokepoint)가 완벽히 분리되는지 확인합니다.

### Phase 3: SYNAPSE Scale Profiling
110k-node / 3k-cluster 규모의 실제 데이터셋에 Naive Reference를 돌려 메모리 및 연산 시간(Performance / Memory footprint)을 측정합니다.

### Phase 4 & 5: Optimization & Equivalence Test
Profiling을 통해 파악된 병목(Transitive Reachability 등)을 개선하는 최적화 알고리즘을 설계하고, 그 결과가 Naive Reference와 100% 동일함(Equivalence)을 입증합니다.
