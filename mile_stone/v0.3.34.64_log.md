## 1. A4 (Boundary Leakage) 관측 파이프라인 분석 및 설계 결론

### A4 Adapter Validation — Cross-Boundary Reference

- **Existing Raw Observation**:
  `BoundaryAnalyzer`가 생성하는 `CROSS_BOUNDARY_DEPENDENCY`를 A4의 Raw Observation으로 사용한다.

- **Observation Semantics**:
  `BoundaryGraphBuilder`는 실제 Graph Edge를 순회하여 `sourceBoundary → targetBoundary` 방향별로 `dependencyCount`를 집계한다.

- **Cardinality**:
  동일 `sourceBoundary → targetBoundary` 관계는 `boundaryEdgesMap`의 단일 Key로 병합되어 하나의 Observation으로 생성된다. (중복 집계 방지를 위한 Raw Observation cardinality 확인 완료)

- **Adapter**:
  `CrossBoundaryReferenceDetector`는 기존 Observation만 소비하며 Graph를 재탐색하거나 Edge를 재계산하지 않는다.

- **Boundary Qualification**:
  `(Unpromoted)` Boundary가 포함된 관계는 A4 Candidate에서 제외한다.
  따라서 A4의 현재 Observation 범위는 실제 Promoted Boundary 간 관계로 제한된다.

- **Evidence**:
  `Source Boundary`, `Target Boundary`, `Dependency Count`를 기존 Observation에서 그대로 추출한다.

- **Classification**:
  현재 A4는 `Cross-Boundary Reference`만 관측하며, `Boundary Leakage`, `Architecture Violation`, `Layer Violation` 등의 Policy 판단은 수행하지 않는다.

- **Fixture Validation**:
  `src/core → src/ui (3)`, `src/core → src/utils (2)`, `src/api → src/core (4)`는 A4 Evidence로 생성되었고, `src/core → src/legacy (Unpromoted, 7)`은 Candidate에서 제외되었다.
