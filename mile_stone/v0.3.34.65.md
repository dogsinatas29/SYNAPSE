# 🚀 Milestone v0.3.34.65 - Contact Point Taxonomy Audit (T1~T5)

## 📅 작업 정보
- **상태:** 🏗️ Planned
- **관련 마일스톤:** v0.3.34.64 (A2 Core Semantic VERIFIED)
- **목표:** A2가 찾아낸 Contact Point에 2차 Annotation(분류)을 부여하기 위한 Taxonomy Audit 수행. (Detector 코딩이 목적이 아니며, Evidence 기반의 분류 체계를 정립하는 것이 목적임)

## 🧠 상세 설계 및 로직
본 마일스톤은 새로운 Metric이나 Semantic Fact를 생성하지 않습니다. 기존 SYNAPSE 시스템이 이미 보유하고 있는 Evidence만을 조합하여 Taxonomy(Structural, Infrastructure, Execution, Unclassified)를 정의합니다. 철저히 **"Evidence → Classification"** 방향만 허용하며, 분류 결과로 Candidate를 제거하는 행위는 엄격히 금지됩니다.

### Audit Pipeline (T1~T5)

- **[T1] Taxonomy Evidence Inventory**
  - **(현재 단계)** "현재 SYNAPSE가 실제로 무엇을 알고 있는가?"만을 조사.
  - 쓸 수 있을 것 같은 것을 상상하는 것이 아니라, `v64 snapshot` 및 코드베이스에 실제로 존재하는 Evidence(NodeRole, Pattern, Boundary Pair Set, Fan-In/Out 등)의 종류, 출처, Schema, Semantic Contract를 인벤토리화.

- **[T2] Taxonomy Evidence Matrix**
  - T1에서 수집된 실제 Evidence만을 기반으로 Matrix(Strong/Supporting/Weak/?/-) 구성.
  - **T2 Semantic Safety Rules (핵심 원칙):**
    1. **Strong**은 Evidence의 Semantic Contract가 Taxonomy 정의를 직접 함의할 때만 허용.
    2. Evidence 이름의 lexical similarity만으로 Strong/Supporting을 부여하지 않음.
    3. Pattern → Taxonomy mapping은 Pattern의 이름이 아니라 underlying evidence contract를 근거로 함.
    4. Metric magnitude(Fan-In/Out 등)만으로 taxonomy를 결정하지 않음.
    5. Boundary Pair Set은 Contact Point identity를 증명하지만 taxonomy를 결정하지 않음.
    6. Ownership은 classification filter가 아니라 annotation임.
    7. **Unclassified는 정상적인 결과임.**
    8. Taxonomy가 A2 Candidate Count / Pair Set / Density / Ownership을 변경하면 실패.
    9. 분류되지 않은 후보를 억지로 분류하지 않음.
    10. **Taxonomy coverage보다 semantic defensibility를 우선시함.**
    11. **Combination Rule은 기존 Semantic Contract에서만 파생됨.** (새로운 조합/휴리스틱 발명 금지)
    12. **Supporting Evidence의 개수는 판정 근거가 아님.** (Supporting × 3 ≠ Strong)

- **[T3] Sample Classification Audit**
  - `Gateway.ts`, `Logger.ts`, `ValidationContext.ts` 등이 의도한 Taxonomy로 분류될 뿐만 아니라, 그 분류 결과가 **"오직 T2 Evidence만으로 완벽히 설명되는가?"**를 검증. 설명 불가능하면 실패.

- **[T4] Negative / Unknown Audit (The Most Important Gate)**
  - `shared.ts`, `helper.ts`, `service.ts` 등 단서가 부족한 노드들이 강제로 3분류 중 하나로 배정되지 않고, **`Unclassified`**로 남는지 검증.
  - Taxonomy는 Recall을 높이는 시스템이 아니라, 충분한 Evidence가 있을 때만 Annotation을 부여하는 시스템. **"Unknown은 실패가 아니라 정상적인 결과다."**

- **[T5] Taxonomy Semantic Sufficiency Audit**
  - 기존 SYNAPSE Evidence만으로 Structural / Infrastructure / Execution이라는 Taxonomy의 의미적 정의와 판정 조건을 정당화할 수 있는지 조사.
  - 기존 문서/코드/Pattern contract에서 각 분류의 직접적 의미를 도출할 수 없다면 `UNRESOLVED` 상태로 종료. (억지로 판정 연산을 발명하지 않음).

- **[T6] Taxonomy Non-Interference Audit**
  - Taxonomy 적용 유무와 상관없이 A2 Core 데이터셋(A2 Candidate Count, Boundary Pair Set, Density, Ownership 등)이 **한 치의 오차도 없이 동일하게 유지**되는지 증명.
  - Taxonomy는 필터가 아니라 **Secondary Annotation Layer**임을 실제 코드로 증명하는 최종 게이트.
