### 🚨 발견된 Semantic Gap (T1/T2/T3 결론)

1. **`bothPairCount` (Module Level)의 착시**
   - 현재 데이터는 **Contact Breadth (몇 개의 Boundary Pair인가?)**는 잘 표현하지만, **Contact Distribution (몇 개의 Node에 분포하는가?)**은 표현하지 않습니다.
   - 단일 Node에 Contact Pair가 집중된 모듈과 다수 Node에 분산된 모듈이 동일한 Module-level `bothPairCount`를 가질 수 있으며, 현재 Core 결과만으로는 두 접촉 구조를 구별할 수 없습니다.

2. **Node = Module Promotion의 한계**
   - 서로 다른 Node에서 발생한 Contact Point 관측을 하나의 Module-level aggregate로 합치는 과정에서, **Contact Contribution의 분포 정보가 사라진다**는 것이 확인되었습니다.

**👉 Next Step:**
T1~T3를 통해 Contact Breadth와 Contact Distribution을 분리해야 한다는 확실한 Semantic Gap을 발견했습니다. 이를 메우기 위해 당장 코드를 수정하기보다는, T4(Boundary Pair Topology)와 T5(Claim Boundary) 감사를 이어가며 전체적인 Gap의 지도를 먼저 완성하겠습니다.

## T4: Boundary Pair Topology Boundary Audit

**T4-A: Directionality (`bothPairs`의 의미)**
- 현재 `extract_a2_phase2.ts`의 로직은 단일 Edge `A → B`가 관측되면, 이를 Source Module과 Target Module 양쪽 모두의 `bothPairs` Set에 추가합니다.
- 즉, **A2 Core의 현재 aggregation은 직접 Boundary Pair 접촉을 undirected meeting relation으로 표현합니다.**
- Raw evidence 자체는 여전히 `A → B`라는 물리적 방향성을 보존하고 있습니다. 방향성이 데이터에서 사라진 것이 아니라, A2의 특정 semantic projection 단계에서 방향성을 배제하고 "만났다(Meeting)"는 사실 자체에 집중하는 것입니다.

**T4-B: Transitive Path (중간 전달자의 위상)**
- `A → B → C` 구조에서 B는 A2 관점에서 "경로상 중간에 있는 노드(Chokepoint)"로 취급되지 않습니다.
- A2는 엄격하게 `A → B`라는 직접 접촉의 Target Endpoint로서의 B와, `B → C`라는 직접 접촉의 Source Endpoint로서의 B라는 독립된 두 개의 관측 사실만을 수집합니다.
- 따라서 A2는 B가 "중간에 있기 때문에 중요하다"는 Chokepoint 의미론으로 미끄러지지 않으며, 철저히 **직접 Boundary Pair Endpoint**만 관측하는 경계(Boundary)를 완벽하게 고수하고 있습니다.

## T5: Claim Boundary Audit (A2 Core 증명 한계 표)

T1~T4 감사를 종합하여, 현재 A2 Core의 증거(Evidence)가 무엇을 증명(Proven Claim)하고 무엇을 증명하지 않는지(Not Proven) 확정합니다.

| Evidence (증거) | Proven Claim (증명된 사실) | Not Proven (증명되지 않은 사실) |
|---|---|---|
| Boundary Pair Set | 이 Node/Module에 특정 외부 경계와의 직접적인 접촉(Contact)이 관측됨 | Chokepoint / Gateway 등 아키텍처적 병목 역할 |
| `bothPairCount` (Module) | 해당 모듈이 접촉한 고유(Unique) Boundary Pair의 총개수 (Contact Breadth) | 접촉이 특정 노드에 집중되었는지 분산되었는지 (Contact Distribution) |
| Node → Module aggregation | 모듈 내부 노드들의 접촉 관측 사실을 모듈 단위로 단순 집계함 | 모듈 자체가 독립적인 단일 거대 Contact Point라는 실체적 의미 |
| Raw source/target | 접촉을 발생시킨 실제 의존성의 물리적 방향 (코드 레벨) | Undirected Meeting Topology를 넘어서는 상위 의미론 자체 |
| Node concentration | 모듈 내 특정 Node에 접촉 쌍(Pair)이 얼마나 모였는지 (분포) | 그 노드가 의도된 Architectural Gateway인지 여부 |
| Ownership (Annotation) | Contact Identity의 물리적 소속 위치 (Node-Owned vs Boundary-Owned 등) | Structural / Infrastructure / Execution 등 기능적 분류(Taxonomy) |

## T6: Core Semantic Gap Decision

- **최종 판단:** 현재 A2 Core 데이터 구조(Node/Edge) 업데이트는 **DEFERRED**.
- **이유:** A2 Core는 `Contact Breadth`와 `Meeting Topology`를 증명합니다. 하지만 `Contact Distribution(분포)` 정보가 Module-level 결과에서 유실된다는 갭(Gap)이 발견되었습니다.
- **보류 사유:** 이 갭이 Core Data Model의 결함인지, 아니면 Report Representation Layer에서의 요구사항인지는 아직 결정할 수 없습니다. 따라서 섣불리 `Contact Concentration`이나 `Contact Area` 등의 새 Metric을 발명(구현)하지 않고 판단을 유보합니다.
