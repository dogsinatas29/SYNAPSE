# SYNAPSE 파이프라인 무결성 종합 리포트 (Phase 1~5)

## 📌 개요
본 리포트는 SYNAPSE 아키텍처 분석 파이프라인의 데이터 흐름, 구조 정확성, 패턴 탐지, 증거 추적성 및 결정성을 5단계에 걸쳐 검증한 결과를 담고 있습니다. 
무결성 검증은 "동일한 입력의 재현성"과 "원본 소스코드 대비 정확성"을 철저히 분리하여, 증명된 사실과 남아있는 결함을 동결(Freeze)하기 위해 작성되었습니다.

| 검증 축 | 현재 판단 | 상태 |
| :--- | :--- | :--- |
| **동일 입력의 재현성** | 보고된 테스트 범위(단일 프로젝트)에서 통과 | ✅ PASS |
| **노드·엣지의 원본 정확성** | 누락(Missing) 및 오연결(Unexpected)이 일부 남아 있음 | ⚠️ PARTIAL |
| **Finding 메타데이터 정확성** | A1/A3/A5 확인 범위 통과, A2(`CROSS_BOUNDARY_REFERENCE`) ID 연결 문제 | ⚠️ PARTIAL |

## 🔍 Phase 1 ~ 5 상세 검증 리포트

### Phase 1: Pipeline Data Integrity (데이터 무결성)
- **상태**: ✅ **PASS**
- **검증 대상**: `BootstrapEngine` -> `DataPipeline` -> `GraphModel`로 이어지는 노드/엣지 데이터의 기본 카운트 손실 여부
- **독립 검증 방법**: `project_state.json`의 raw 노드 개수와 `getFinalSnapshot()`의 반환 개수 비교 (스크립트 기반 대조)
- **결과**: `NODE_COUNT`, `EDGE_COUNT` 모두 유실 없이 100% 보존됨. 고스트 노드 비정상 급증이나 중복(Duplicate) 노드 0건 확인.
- **한계**: 데이터가 "유실되지 않았다"는 증명일 뿐, 최초로 수집된 데이터 자체가 "정확하다"는 증명이 아님.
- **재현 스크립트**: `scratch/audit_graph_source_accuracy.ts` (Phase 1 파트)

### Phase 2: Code to Graph Accuracy (AST 추출 정확성)
- **상태**: ⚠️ **PARTIAL**
- **검증 대상**: `ts_ast_extractor.js`가 소스코드의 물리적 Import/Export 구문을 정확히 파싱하여 Graph Edge로 생성하는가
- **독립 검증 방법**: 원본 `.ts` 파일을 정규식 기반으로 독립 파싱(`import ... from`)하여 추출된 경로 집합과, 그래프 엣지 집합을 교차 검증.
- **결과**: 다수의 일반적인 Import는 정확히 매핑되나, 특정 조건(`export *`, Dynamic Import) 등에서 추출 실패 발생.
- **한계**: 정규식 기반의 독립 검증 스크립트 자체도 복잡한 Aliasing 패턴을 완벽히 커버하지 못할 수 있음.

### Phase 3: Graph Structural Accuracy (그래프 토폴로지 정확성)
- **상태**: ❌ **FAIL**
- **검증 대상**: AST로 추출된 Raw Edge가 `ReferenceResolver`를 거쳐 올바른 타겟으로 연결(Resolve)되는가
- **독립 검증 방법**: Source-Target 해시맵 비교를 통해 누락 및 잉여 엣지 수치화.
- **결과**: 
  - **MISSING (6건)**: 물리적 연결은 있으나 그래프에서 누락.
  - **UNEXPECTED (12건)**: 잘못된 SymbolIndex 매핑 등으로 인한 과잉/오인 연결.
  - **UNRESOLVED (227건)**: 타겟 파일을 찾지 못해 Fallback/Ghost 노드로 처리됨.
- **한계**: 위 수치는 소규모 워크스페이스 기준이며, 대규모 프로젝트에서는 이 오차가 누적되어 Centrality/Authority 점수를 크게 오염시킬 수 있음.
- **재현 스크립트**: `scratch/audit_graph_source_accuracy.ts`

### Phase 4: Evidence Lineage Audit (증거 추적성 검증)
- **상태**: ⚠️ **PARTIAL**
- **검증 대상**: Report 본문 → Evidence Viewer (HTML) → `allFindings.json` 원본 JSON 레코드의 식별자(ID) 유지 및 수치 보존 여부
- **독립 검증 방법**: `EVIDENCE_VIEWER.html` 내의 DOM Data 속성값과 JSON 파일의 필드를 파싱하여 1:1 대조.
- **결과**: 
  - A1(System Core), A3(Boundary), A5(Chokepoint) 등 34건은 수치 위조나 소실 없이 100% 매칭됨 (PASS).
  - A2(`CROSS_BOUNDARY_REFERENCE`) 8건은 뷰어에 값은 나오나 원본 JSON에 `findingId`, `evidenceId`가 누락됨 (FAIL - BROKEN LINK).
- **한계**: 특정 프로젝트 패턴 조합에서만 발생하는 누락일 가능성 존재.
- **재현 스크립트**: `scratch/audit_evidence_lineage.ts`

### Phase 5: Determinism Audit (결정성 검증)
- **상태**: ✅ **PASS**
- **검증 대상**: 동일 소스, 동일 분석 설정 시 매번 동일한 Topology와 Metric(점수/순위)이 산출되는가
- **독립 검증 방법**: `BootstrapEngine.autoDiscover`부터 `InsightEngine`까지 3회 반복 실행하며 UUID와 타임스탬프를 제외한 핵심 메타데이터의 해시값(SHA-256) 비교.
- **결과**: 노드(665개), 엣지(1,257개), 생성된 패턴(20개) 모두 3회 연속 정확히 일치함. 
- **한계**: 검증 스크립트 내에서 Deep Clone으로 객체 불변성을 흉내내어 검증한 것으로, 실제 Extension Host 런타임 환경의 동시성 접근 및 캐시 오염 가능성까지 완벽히 차단했음을 의미하지 않음.
- **재현 스크립트**: `scratch/audit_determinism.ts`

## 🎯 향후 수정 과제 (우선순위)

1. **[P0] Finding ID 및 Evidence ID 연결 복구**: 
   - 대상: `CROSS_BOUNDARY_REFERENCE` (A2)
   - 작업: Detector 수준에서 식별자 할당 로직 복구 및 중간 직렬화 과정 점검.
2. **[P1] 엣지 누락(MISSING) 및 오연결(UNEXPECTED) 수정**:
   - 대상: `ts_ast_extractor.js` 및 `ReferenceResolver`
   - 작업: `export *` 누락 및 잘못된 SymbolIndex 매핑 로직 수정 후, 재현 테스트를 통한 출발점/도착점/타입 검증.
3. **[P2] 대규모 프로젝트 런타임 안정성 검증**:
   - 대상: `BootstrapEngine` 및 Extension Host
   - 작업: Chromium 규모에서의 응답 정지, V8 OOM 등 안정성 문제 해결 로직 구현 및 검증.
