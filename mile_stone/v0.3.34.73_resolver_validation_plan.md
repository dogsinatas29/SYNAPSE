# SYNAPSE 리졸버 검증 계획 v1.0

목표는 Ghost 비율을 무조건 낮추는 것이 아니다. 실제 소스에 존재하는 내부 참조가 그래프에 정확히 매핑되는지 검증하고, Ghost로 남는 이유를 증거로 분류하는 것이다.

## 1. 검증 원칙
- 기존 탐지 규칙과 메트릭을 임의로 변경하지 않는다.
- Ghost 승격 기준을 먼저 완화하지 않는다.
- 실제 관측값, 파생값, 추론을 구분한다.
- 모든 실패 사례를 원본 참조부터 최종 그래프 상태까지 역추적할 수 있어야 한다.
- Ghost 비율 감소와 매핑 정확도 개선을 별개의 지표로 관리한다.

## 2. 검증 단계

### P0 — 현재 구현과 기준선 고정 (완료)
기존 P0 메트릭·패턴 계약 수정을 완료하고 회귀 검증 완료.

### P1 — Ghost 분류 체계 확립
Ghost를 원인별로 분류한다.
- 내부 대상 파일 존재
- 내부 대상 파일 미발견
- 외부 의존성 또는 시스템 헤더
- 생성 파일·조건부 빌드 관련
- 추출 또는 매핑 단계에서 원인 불명
*산출물: Ghost 원인별 개수와 근거가 포함된 감사 결과.*

### P2 — 내부 참조 매핑 정확도 검증
저장소 내부에 실제 존재하는 대상을 가리키는 참조 표본 추출 및 추적.
*산출물: 내부 참조의 매핑 성공률, 실패 유형, 재현 가능한 사례.*

### P3 — 언어·빌드 시스템별 원인 분리
C/C++, Rust, TS/JS 등 실패 사례가 집중되는 지점부터 언어별 조사.
*산출물: 원인별 재현 테스트와 수정 후보.*

### P4 — 수정 검증과 아키텍처 영향 평가
수정 전후 동일 프로젝트/범위로 재분석 비교.
*산출물: 수정 전후 차이, 개선된 실패 유형, 새로 발생한 오매핑 여부.*

## 3. 완료 게이트
- Ghost 분류 규칙과 승격 경로 코드로 확인.
- 내부 미매핑과 외부 의존성 구분.
- 매핑 성공률/오매핑률 측정.
- 아키텍처 패턴 변화가 실제 연결 변경으로 설명 가능.
