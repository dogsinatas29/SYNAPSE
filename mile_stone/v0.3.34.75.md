## 🧠 거버넌스 및 설계 원칙

### 1. 4-Tier Scope Exclusion 처리 모델 (Reality vs Presentation)
분석 범위 제외는 원본 그래프를 변조하지 않고 Presentation/Reporting 계층의 뷰에서만 제어된다:
```
[ Tier 1: Source Graph ] (project_state.json 원본 보존, 1바이트도 수정 금지)
  ▼
[ Tier 2: Measurement Graph ] (V_measure = V_source, E_measure = E_source 원본 동일 측정)
  ▼
[ Tier 3: Candidate Eligibility ] (탐지기별 후보 필터링)
  │  - 3.1 Base Qualification (기존 필터 유지)
  │  - 3.2 Declared Scope Exclusion (선언된 Glob 패턴 매칭 제외)
  ▼
[ Tier 4: Report Selection ] (P90 컷오프 및 결정론적 리포트 렌더링)
```

### 2. No Heuristic 원칙 및 과도기적 예외 (Zero-Diff Guard)
- 특정 프로젝트 경로명을 엔진이 자의적으로 서드파티로 추정하지 않으며, 범위 통제는 오직 **사용자의 명시적 선언(`scopeExclusions`)**으로만 결정된다.
- **과도기적 예외 (Zero-Diff 유지)**: 기존 컴포넌트 테스트 비율 필터(`testRatio < 0.8`)는 v0.3.34.74 기준선과의 바이트 일치(Zero-Diff) 보존을 위해 **Phase A 기간 동안 필수적으로 보존**한다.
