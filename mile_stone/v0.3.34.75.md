## 🧠 거버넌스 및 설계 원칙

### 1. 4-Tier Scope Exclusion 처리 모델 (Reality vs Presentation)
분석 범위 제외는 원본 그래프를 변조하지 않고 Presentation/Reporting 계층의 뷰에서만 제어된다:
```
[ Tier 1: Source Graph ] (project_state.json 원본 보존, 1바이트도 수정 금지)
  ▼
[ Tier 2: Measurement Graph ] (V_measure = V_source, E_measure = E_source 원본 동일 측정)
  ▼
[ Tier 3: Candidate Eligibility ] (탐지기별 후보 필터링)
  │  - 3.1 Base Qualification (기존 필터 유지)
  │  - 3.2 Declared Scope Exclusion (선언된 Glob 패턴 매칭 제외)
  ▼
[ Tier 4: Report Selection ] (P90 컷오프 및 결정론적 리포트 렌더링)
```

### 2. No Heuristic 원칙 및 과도기적 예외 (Zero-Diff Guard)
- 특정 프로젝트 경로명을 엔진이 자의적으로 서드파티로 추정하지 않으며, 범위 통제는 오직 **사용자의 명시적 선언(`scopeExclusions`)**으로만 결정된다.
- **과도기적 예외 (Zero-Diff 유지)**: 기존 컴포넌트 테스트 비율 필터(`testRatio < 0.8`)는 v0.3.34.74 기준선과의 바이트 일치(Zero-Diff) 보존을 위해 **Phase A 기간 동안 필수적으로 보존**한다.

### 3. KISS 원칙에 입각한 project_state.json 원본 불변 보존 및 재생성 배제 규약 (Immutable SSoT & Working Copy Architecture)
- **적용 범위 한정 (`project_state.json`)**:
  - 본 규약의 재생성 배제는 **기존 SSoT(`project_state.json`)의 손상이나 분석 실패를 복구하기 위한 자동 재생성을 금지**하는 것에 엄격히 한정한다.
  - Bootstrap에 의한 최초 생성과 명시적으로 승인된 재수집(Re-harvesting)은 분석 중 복구 목적의 재생성과 완전히 분리된 별도 작업이다.
- **KISS 원칙 확립 (Keep It Simple, Stupid)**:
  - **"기존 SSoT 복구 목적의 자동 재생성은 없앤다."** 복잡한 크래시 롤백, 저널링, 상태 머신 복구 등 과도한 엔지니어링을 전면 배제한다.
  - 검증의 기준선이 되는 원본 데이터(`project_state.json`)는 디스크 상에서 절대 임의 수정·변조하거나 복구 목적으로 자동 재생성하지 않고 **영구 불변(Immutable)**으로 보존한다.
- **파생 산출물 단방향 원칙 (Derived Artifact Rule)**:
  - "수정된 복사본은 파생 산출물일 뿐 SSoT를 대체하지 않는다. SSoT는 오직 수집기만 만든다."
  - 수정된 복사본이 다시 SSoT로 승격(Promotion)되는 경로를 원천 차단하여 복잡한 트랜잭션 롤백 문제를 원천 소멸시킨다.
- **복사본 기반 분석 (Working Copy / In-Memory Read-Only Parsing)**:
  - 모든 분석, 시뮬레이션, 범위 제외, 리포트 검증 작업은 불변 원본의 복사본(인메모리 객체 또는 격리된 복사본)에서 수행한다.
  - 대규모 SSoT(VS Code 60MB, Godot 31MB)의 물리 파일 복사 비용을 방지하기 위해, 평소에는 **메모리상 읽기 전용 파싱(In-Memory Read-Only Parsing) 객체**에서 분석을 수행한다.
  - 작업 도중 실패한 복사본은 즉시 폐기하고 원본에서 다시 생성한다. 원본이 1바이트도 훼손되지 않으므로 복잡한 롤백이나 재작업이 일체 불필요하다.
- **사용자 레이아웃 분리 결정 (Option B: layout.json 분리)**:
  - SSoT(`project_state.json`)는 수집기 소유의 순수 구조 데이터(노드, 엣지, 파일경로, 역할)로 영구 불변 보존한다.
  - 사용자의 캔버스 노드 좌표(`position`), 클러스터 수동 접힘(`collapsed`) 등 사용자 정의 레이아웃은 별도 파일(`layout.json`)로 분리 저장하여 SSoT 해시 변조를 원천 차단한다. (개인 뷰포트 줌/오프셋은 로컬 `workspaceState`로 분리).
- **재구성 및 복구 불필요 (No Reconstruction)**:
  - 원본 데이터를 직접 수정하지 않으므로, 데이터 파손을 가정한 복구·재구성(Reconstruction) 메커니즘을 복잡하게 설계할 필요가 없다.
  - **"재생성 불가능한 데이터(`project_state.json`)는 원본 보존, 복사본 작업, 재구성은 불필요"** 원칙을 시스템 최상위 불변식으로 영구 고정한다.
