### 1.1 공식 계약 및 레지스트리 정합성
- **리포트 계약 ([ReportContract.ts](file:///home/dogsinatas/TypeScript_project/antigravity-extension-vis/src/core/reporting/ReportContract.ts#L105-L114)):**
  - 질문 ID `O2` (`ONBOARDING`, `OBSERVATION`), 지원 패턴 `["DEPENDENCY_ROOT"]`, 허용 지표 `["inDegree", "outDegree"]`.

### 1.3 `VERIFIED_FUNCTION_CALL`과 `dependency-root` 의미 경계
- `provenance`는 엣지의 구조적 의미 유형(`EdgeType`: `INCLUDE`, `CALL` 등) 자체가 아니라 [ReferenceResolver.ts](file:///home/dogsinatas/TypeScript_project/antigravity-extension-vis/src/core/ReferenceResolver.ts#L522-L566) 등의 **해석 결과에 부여되는 메타데이터**이며, **특정 단일 `EdgeType`에 1:1로 고정되지 않는다.**
- 실제로 Godot 및 VS Code 실측에서 `VERIFIED_FUNCTION_CALL` provenance는 서로 다른 `EdgeType` 위에서 관측되었다(고정 매핑이 아닌 관측 사례):
  1. **Godot 관측 사례 (`type === 'CALL' && provenance === 'VERIFIED_FUNCTION_CALL'`, `29,801`건):** `CppScanner`가 추출한 함수 호출(`FUNCTION_CALL`)을 `SymbolIndex.lookupSymbol()`이 `.cpp`/`.c` 정의 파일로 해석하면서 생성되었다. 이는 파일 간 함수 호출 관계이지 `#include`/`import` 기반의 `dependency` 관계가 아니다.
  2. **VS Code 관측 사례 (`type === 'INCLUDE' && provenance === 'VERIFIED_FUNCTION_CALL'`, `716`건 및 `CALL::VERIFIED_FUNCTION_CALL`, `13`건):** `JsTsScanner`가 추출한 정적 `import` 의존 관계(`type: 'dependency'` → `'INCLUDE'`)에 `TypeScriptResolver`가 호출 사용처 기반 `FUNCTION_CALL` provenance를 부여하면서 `INCLUDE` 엣지에도 `VERIFIED_FUNCTION_CALL`이 부여되었다.
- **`type`과 `provenance` 동시 검사(Policy C)의 필연성:** `VERIFIED_FUNCTION_CALL`이 단일 `EdgeType`에 고정되지 않고 `INCLUDE`와 `CALL` 양쪽 모두에서 관측되므로, O2는 `provenance` 단독 필터(`Policy B`)를 사용할 수 없으며 반드시 `edge.type === 'CALL'`과 `edge.provenance === 'VERIFIED_FUNCTION_CALL'` **두 필드를 동시에 검사**하여 정상 `INCLUDE` 의존 엣지를 보존해야 한다.

## §2. 제외 조건의 정확한 정의 (Policy C — DEFERRED / Semantic Review Required)

### 2.1 정확한 제외 판정식
O2(`EntryPointDetector`) 차수 집계에서 제외하는 후보 정책 **Policy C**의 판정식은 아래와 같이 정확히 두 필드의 논리곱(`&&`)으로 정의한다.

```ts
const isExcludedO2Edge = (edge: any): boolean =>
    edge?.type === 'CALL' && edge?.provenance === 'VERIFIED_FUNCTION_CALL';
```

### 2.2 Fail-Safe 보존 규칙
- `edge`가 null/undefined이거나, `edge.type` 또는 `edge.provenance`가 누락(`undefined`/`null`)되거나, 둘 중 어느 한 조건이라도 정확히 일치하지 않으면 **제외하지 않고 보존**한다.
- 임의의 추론, 파일 확장자 기반 조건 분기, 또는 유사 문자열 정규화(소문자 변환 등)로 제외 범위를 확장하지 않는다.

### 2.3 차수 집계 필터 범위의 엄격한 한정 (Strict Scoping Invariant)
1. **단일 적용 지점:** 위 제외 조건은 **오직 [EntryPointDetector.ts](file:///home/dogsinatas/TypeScript_project/antigravity-extension-vis/src/core/analysis/patterns/detectors/EntryPointDetector.ts#L33-L38) 내부의 `inDegreeMap` / `outDegreeMap` 집계 루프에만 적용**한다.
2. **비전파 불변식 (Non-Propagation):**
   - `context.snapshot.edges` 원본 배열을 필터링·변조·교체하지 않는다.
   - 디스크 상의 `project_state.json`, 인메모리 `GraphSnapshot`, 다른 Detector(`SystemCoreDetector`, `ChangeAmplifierDetector`, `SafeRefactoringZoneDetector` 등), 다른 리포트/분석 파이프라인으로 해당 필터를 전파하지 않는다.
3. **유입·유출 대칭 적용:** O2 내부의 `inDegree`와 `outDegree`는 동일한 비-제외 엣지 뷰에서 대칭 집계한다(한 파일의 O2 `outDegree`가 제외된 함수 호출까지 포함해 과대 산정되지 않도록 일관성 유지).

### 2.4 금지된 단순화
- **`edge.type === 'CALL'` 단독 제외 금지:** JS/TS(`api|http|fetch|axios` 경로)와 Python(`api|http|fetch|request` 경로)의 import 기반 의존 엣지가 `type === 'CALL'`(`provenance: 'UNKNOWN_RUNTIME'`)로 매핑되므로 전역 제외 시 비-C/C++ 의존 그래프가 훼손된다.
- **`edge.provenance === 'VERIFIED_FUNCTION_CALL'` 단독 제외 금지 (Policy B 폐기):** VS Code 실측에서 확인된 정상 TypeScript 모듈 의존 엣지 `INCLUDE::VERIFIED_FUNCTION_CALL` `716`건을 함께 제거하여 Baseline 모수(`589 → 586`) 회귀를 유발한다.
