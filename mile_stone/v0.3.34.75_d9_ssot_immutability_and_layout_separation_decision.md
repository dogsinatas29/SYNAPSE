## 1. 결정 배경 및 문제 정의 (Context & Problem Statement)

### 1.1 오버엔지니어링의 근본 원인
v0.3.34.75 Phase B 준비 과정에서 작성된 10차례의 Verification Supplement는 **"공식 SSoT(`project_state.json`)를 디스크 상에서 직접 인플레이스로 수정하고, 크래시 시 롤백·복구해야 한다"**는 잘못된 전제에서 출발했습니다.  
이로 인해 2단계 저널, 복구 락, Stale Lock 세대 판독, 14개 분기의 복구 매트릭스 등 극단적인 오버엔지니어링(YAGNI 위반)과 지속적인 감사 결함이 발생했습니다.

### 1.2 Reality(구조)와 Presentation(레이아웃)의 충돌
실제 코드베이스 감사 결과, `src/webview/CanvasPanel.ts`가 사용자의 UI 노드 드래그 좌표(`position`), 줌/오프셋(`canvas_state`), 클러스터 접힘(`collapsed`) 상태를 `project_state.json`에 통째로 덮어쓰고 있었습니다.  
이로 인해 사용자가 캔버스를 조작할 때마다 SSoT의 SHA-256 해시가 변조되어, Phase A 기준선 검증과 SSoT 불변 보존 원칙이 정면으로 충돌하는 구조적 결함이 확인되었습니다.

## 2. 5대 핵심 아키텍처 결정 사항 (Core Decisions)

### [결정 1] SSoT 불변 및 파생 산출물 단방향 원칙 (Derived Artifact Rule)
> **"수정된 복사본은 파생 산출물(Derived Artifact)일 뿐 SSoT를 대체하지 않는다. SSoT는 오직 수집기(Collector)에 의해서만 생성·갱신된다."**

1. 분석, 시뮬레이션, 정규화 과정에서 수정된 복사본이 다시 SSoT로 승격(Promotion)되는 경로를 전면 차단합니다.
2. 기존 SSoT의 손상이나 분석 실패를 복구하기 위한 자동 재생성 메커니즘을 전면 금지합니다.
3. 분석 작업은 불변 원본의 복사본(Working Copy)에서 수행하며, 실패한 복사본은 즉시 폐기하고 원본에서 다시 생성합니다.
4. Bootstrap에 의한 최초 생성과 사용자가 명시적으로 승인한 재수집(Re-harvesting)은 분석 중 복구 목적의 재생성과 완전히 분리된 별도 작업으로 정의합니다.

### [결정 2] Phase B 처리 모델: 리포트 계층 파생 뷰(Option 2) 채택
경로 정규화 및 `NodeRole.TEST` 재분류에 대해 다음 2번 방안을 공식 채택합니다:
- **채택: (2) 리포트 계층의 파생 뷰(인메모리 복사본)에서 정규화·재분류 수행**
  - 수집기(`NodeBuilder.ts`)는 D7 동결을 엄격히 유지(0줄 수정).
  - Phase A의 선언 기반 제외(`scopeExclusions: ["tests/**"]`)로 테스트 노이즈 격리가 이미 완벽히 달성되었으므로, D7 동결을 해제할 긴급성이 전혀 없음.
  - SSoT 원본은 1바이트도 수정하지 않으며, 리포트 생성 시 파생 뷰에서만 인메모리로 정규화를 적용하여 Zero-Diff 기준선을 영구 보존.

### [결정 3] 큰 파일 비용 최적화 (In-Memory Read-Only Parsing)
- VS Code(60MB), Godot(31MB) 등 대규모 SSoT 파일에 대해 매 실행마다 디스크 물리 복사(`cp`)를 수행하지 않습니다.
- **평소 분석 및 검증은 메모리상 읽기 전용 파싱(In-Memory Read-Only Parsing) 객체에서 수행**합니다.
- 파생 산출물을 디스크에 영구 보존해야 할 명시적 요구가 있을 때만 파생 파일(예: `report_derived.json`)로 Export합니다.

### [결정 4] UI 레이아웃 분리: Option B 채택 (`layout.json`)
사용자 레이아웃을 일급 데이터로 인정하면서 SSoT 불변성을 지키기 위해 **Option B (전용 레이아웃 파일 분리)**를 공식 채택합니다:
1. **`project_state.json` (순수 구조 SSoT - 수집기 소유)**:
   - 노드, 엣지, 파일경로, 역할, 의존성 관계만 포함.
   - 수집기(Bootstrap/Scanner)만 기록하며, UI 조작으로 인한 수정 일체 금지 (Read-Only).
   - 영구 불변 해시(Godot: `ddd7aa29...`, VSCode: `2524c6da...`) 유지.
2. **`layout.json` (사용자 정의 레이아웃 - 사용자 소유)**:
   - 노드의 캔버스 좌표(`position: { x, y }`), 클러스터 수동 배치 및 접힘(`collapsed`) 상태 보존.
   - 프로젝트 구조 파악을 위한 의미 있는 사용자 정의 레이아웃으로서 저장소 공유 및 형상 관리 가능.
   - 수 MB 단위의 SSoT 전체 재기록 없이, 수십 KB 단위의 경량 파일로 원자적 저장.
   - 재수집(Re-harvesting) 시에도 사용자 레이아웃이 덮어쓰여 지워지지 않고 노드 ID 기준으로 안전하게 계승.
3. **개인 뷰포트 상태 (Local Memento)**:
   - 줌 레벨(`zoom_level`) 및 오프셋(`offset`)은 협업 공유 파일이 아닌 사용자 로컬 작업영역 상태(VSCode `workspaceState` / Memento)로 분리 관리.

### [결정 5] 이전 보완 문서(rev1~10) 전면 폐기 (Superseded)
- `mile_stone/v0.3.34.75_phase_b_verification_supplement_v1.0.6.md` 및 `review_revision1~10.md`에 수록된 모든 C2 트랜잭션 저널, Recovery Lock, 복구 상태 매트릭스는 **공식 폐기(SUPERSEDED)** 처리합니다.
- 본 D9 결정을 통해 향후 아키텍처 및 마일스톤 추적성을 명확히 분리 고정합니다.
