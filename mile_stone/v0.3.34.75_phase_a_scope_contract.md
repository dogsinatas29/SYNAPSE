## 2. 선언의 입력 경로, 스키마 및 채택 출처 로깅

### 2.1 설정 파일 탐색 우선순위 (First-Win, Merge 없음)
분석 대상 프로젝트 저장소의 오염 및 읽기 전용 환경을 방지하고 스크립트 실행 경로를 지원하기 위해 다음 **단일 우선순위(First-Win)**로 단일 활성 설정을 채택한다:
1. **1순위 (CLI 플래그 / 환경 변수 / 스크립트 인자)**:
   - CLI 인자 `--scope-exclusions` 또는 환경 변수 `SYNAPSE_SCOPE_EXCLUSIONS` (JSON 문자열)
   - *용도: `generate_surgery_report.ts` 등 비-VSCode 스크립트 환경의 자동화 파이프라인*
2. **2순위 (VSCode 워크스페이스 설정)**:
   - VSCode 설정 `synapse.analysis.scopeExclusions` (또는 `.vscode/settings.json`)
3. **3순위 (프로젝트 루트 설정 파일)**:
   - 프로젝트 루트의 `synapse.config.json` 내 `scopeExclusions`
4. **우선순위 및 기본값 규칙**:
   - 상위 순위에서 키가 발견되면(값이 `[]`인 경우 포함), **하위 순위 설정으로 내려가지 않고 상위 순위의 설정을 최종 확정**한다 (설정 병합 없음).
   - 모든 순위에서 설정이 없거나 필드가 누락된 경우 **기본값은 빈 목록 `[]`**이다.
   - 스키마: `scopeExclusions: string[]`.

### 2.2 채택 출처 로깅 및 `INVALID_CONFIG` 거부 정책
1. **채택 출처 로깅**:
   - 환경 변수가 설정을 조용히 덮어쓰는 등의 혼선을 방지하기 위해, 엔진 시작 시 **채택된 설정 출처를 콘솔 로그에 반드시 기록**한다:
     `[SCOPE_CONFIG] Loaded scopeExclusions from: <CLI_FLAG | ENV_VAR | VSCODE_SETTINGS | PROJECT_CONFIG | DEFAULT_EMPTY> (count: N)`
   - 헤더 변경을 방지하기 위해 이 출처 정보는 리포트 헤더에는 기록하지 않고 오직 런타임 로그에만 남긴다.
2. **`INVALID_CONFIG` 동작 명세 (Fail-Closed)**:
   - 환경 변수의 JSON 파싱 실패 또는 `scopeExclusions`가 `string[]` 타입이 아닌 경우(비문자열 원소 포함):
     **`[FATAL] INVALID_CONFIG: scopeExclusions must be a valid array of strings`** 오류 메시지를 출력하고, **분석 파이프라인 전체를 즉시 안전 중단(Fail-Closed)**한다.

## 3. 핵심 불변식 (Invariants) & 검증 기준선 팩트

### 3.1 빈 선언 시 3종 리포트 바이트 동일성 불변식 (Zero-Diff Invariant)
$$\text{StrictRoots} \ge 1 \land \text{scopeExclusions} = [] \implies \text{Report}_{\text{v0.3.34.75}} \equiv \text{Report}_{\text{v0.3.34.74}} \quad (\text{3종 .md 리포트 SHA-256 Byte-Identical})$$
- **대상 범위 한정**: 본 불변식의 대상은 **엄격 루트가 1개 이상 존재하는 유효 프로젝트 그래프**에서 **3종 마크다운 리포트(`ONBOARDING_REPORT.md`, `ARCHITECT_REPORT.md`, `SIMULATION_DEBUG.md`)**에 한정한다. (엄격 루트가 0개인 순환 그래프 등 특수 환경의 경우, 커밋 `4b135e6`의 degraded Fallback 대신 빈 결과를 반환하는 것은 의도된 단일 동작 변경으로 명시함. 타임스탬프를 포함하는 `allFindings.json` 및 증거 뷰어 HTML은 별도 평가).
- **헤더 조건부 출력 불변식**: `scopeExclusions`가 빈 배열(`[]`)이거나 미설정된 경우, 리포트 헤더에 **Declared Scope Exclusions 및 Accounting 관련 줄을 일체 출력하지 않는다.**
- **Finding 요약 문구 조건부 불변식**:
  - `scopeExclusions`가 빈 선언(`[]`)인 경우: 기존 v0.3.34.74와 100% 동일한 **`({selectedCount} selected / {totalCount} candidates)`** 문구를 유지한다. Selection Basis 역시 **`of {totalCount} candidates`**를 유지한다.
  - `scopeExclusions`가 1개 이상 유효 선언된 경우에 한해서만: **`({selectedCount} selected / {eligibleCount} eligible candidates)`** 및 **`of {eligibleCount} eligible candidates`**로 표기한다.
- **검증 기준선 고정 팩트 (Baseline Ground Truth)**:
  - **Git 조상 증명**: `git merge-base --is-ancestor 0fb520a 4b135e6` $\to$ **PASS** (`0fb520a is ancestor of 4b135e6`). 즉, 커밋 `4b135e6`은 리포트 개선 커밋 `0fb520a`를 온전히 포함함.
  - **검증 입력 데이터**: Godot `project_state.json` (`SHA-256: ddd7aa2982b591f881c95692bbb26f9adde521366742a36a40b49a3b5e56174b`)
  - **기준 리포트 3종 SHA-256 해시값 (Zero-Diff 비교 대상)**:
    - `ONBOARDING_REPORT.md`: `e5706b0d4ae6518b94a63d7bc50142793fe27c8d28fbfc0a4e7ce9ede447663b`
    - `ARCHITECT_REPORT.md`: `1885bcbccbc4a7a8a58c69cd453a9f70c111275aeb4144764349361eb3118cd2`
    - `SIMULATION_DEBUG.md`: `14424cdef43c6817b93830e69bb03db781dd583a5dab64eca8b2ae67a8ed0ae2`

## 4. 실제 데이터 기반 경로 전제 및 가상 노드 처리

### 4.1 실제 `project_state.json` 실측 근거 (Fact)

- **VSCode (14,748개 노드)**: 99.96% 순수 상대 경로. (절대 경로 1건, 역슬래시 5건).

### 4.2 실용적 경로 정규화 및 가상 노드 면제 규칙
1. **가상 노드 면제**:
   - `node.filePath`가 없거나 빈 문자열인 노드, 또는 가상/외부 스키마 접두사(`ghost://`, `external://`, `stdlib://`, `AGGREGATE_*`)를 가진 노드는 Scope 매칭 대상이 아니며, **절대 제외되지 않고 원본 보존**된다.
2. **단순 역슬래시 정규화**:
   - 물리 상대 경로 노드는 `node.filePath.replace(/\\/g, '/')`로 역슬래시만 슬래시로 변환하여 Glob 매칭을 수행한다. (실제 벤치마크 데이터셋의 물리 노드는 대부분 슬래시를 사용하며, 역슬래시 물리 노드 매칭은 단위 테스트를 통해 보증됨).
3. **선행 슬래시(`/`) 경로 안전 처리**:
   - 선행 슬래시가 있는 드문 노드는 슬래시를 떼지 않고 **매칭을 건너뛰며 `[WARN] Absolute path node skipped` 진단 로그만 남긴다**.

## 5. 허용 Glob 문법 및 일반화 규칙

모든 패턴 매칭은 **대소문자 엄격 구분(Case-sensitive)**을 강제한다:
- **일반화 정의**:
  - **`**` (재귀 와일드카드)**: **반드시 세그먼트 전체(`/` 사이 또는 시작/끝)일 때만 허용**되며, 0개 이상의 연속된 디렉터리 세그먼트와 매칭된다. (예: `platform/android/java/**/apksig/**`, `thirdparty/**`, `**` 단독 전수 매칭 모두 동일 원리로 포섭).
  - **`*` (단일 세그먼트 와일드카드)**: 세그먼트 내부에서만 매칭되며 경로 구분자(`/`)를 절대 넘지 않는다.
- **금지 패턴 (Fail-Closed `INVALID_PATTERN`)**:
  - 세그먼트 내부 연속 별표(`foo**bar`, `***`), 연속 재귀 세그먼트(`**/**`), 선행 슬래시(`/`), 후행 슬래시(`foo/`), 빈 문자열(`""`)은 즉시 거부.

## 6. 4-Tier 처리 모델 및 실제 코드 100% 일치 정렬 계약

### 6.1 처리 파이프라인
```
[ Tier 1: Source Graph ] (project_state.json 원본 보존, 1바이트도 수정 금지)
  ▼
[ Tier 2: Measurement Graph ] (V_measure = V_source, E_measure = E_source 원본 동일 측정)
  ▼
[ Tier 3: Candidate Eligibility ] (탐지기별 후보 필터링)
  │
  ├─ [3.1 기본 후보 선정 및 기존 필터 (Base Qualification)]
  │   - O2: fanIn === 0 && fanOut > 0 && role !== NodeRole.TEST (Strict Root만 인정, Fallback 삭제)
  │         * O2 후보 풀: Strict Root 조건을 만족하는 전체 노드 집합
  │         * O2 Scope 제외 적용 시점: Top 5 슬라이스 '이전'에 Scope 매칭 제외를 먼저 적용!
  │   - A1 / E2: Semantic Boundary Node finding 기반 (score > 0 및 기존 testRatio < 0.8 통과 대상)
  │   - Universe 정의:
  │       * members(C): 컴포넌트 C의 고유 노드 ID 집합 (finding.metadata.members)
  │       * C_scopeUniverse^d: Base Qualification을 통과한 기본 후보 컴포넌트 집합
  │       * V_scopeUniverse^d: C_scopeUniverse^d에 속한 모든 컴포넌트들의 members(C) 합집합
  │
  ├─ [3.2 Declared Scope Exclusion (선언 기반 범위 제외)]
  │   - V_matched: scopeExclusions 패턴과 매칭되는 물리 상대 경로 노드 집합
  │   - V_scopeExcluded^d = V_scopeUniverse^d ∩ V_matched
  │   - C_scopeExcluded^d = { C ∈ C_scopeUniverse^d | members(C) ⊆ V_scopeExcluded^d } (Full Match)
  │   - 적격 후보 확정:
  │       * V_scopeEligible^d = V_scopeUniverse^d - V_scopeExcluded^d
  │       * C_scopeEligible^d = C_scopeUniverse^d - C_scopeExcluded^d
  ▼
[ Tier 4: Report Selection ]
  - P90 모수: C_scopeEligible^d 기준 (선택 수 = ceil(0.1 × |C_scopeEligible^d|))
  - 정렬 계약: 현재 실제 코드와 100% 일치 (Zero-Diff 보장)

      * E2: ChangeAmplifierDetector.ts#L94에 따라 complexityScore (score) 내림차순 → targetId 오름차순 (<)
```

## 8. 계약의 한계 명시 (Scope Boundary & Known Limitations)

- **적용 대상 탐지기**: O2 (`EntryPointDetector`), A1 (`SystemCoreDetector`), E2 (`ChangeAmplifierDetector`) 3종에 한정 적용.
- **A2 / A3 / A5 계약 제외 한계**:
  - **A2 (Module Contact Points), A3 (Structural Boundaries), A5 (Structural Control Chokepoints / CONTROL_BRIDGE)**는 본 계약의 적용 대상이 아니다.
  - A1에서는 `thirdparty/**`가 제외되어 시스템 코어에서 빠지더라도, A3 경계 목록이나 A2 접점 목록에는 서드파티 모듈이 그대로 잔존한다.
- **C/C++ O2 진입점 품질 한계 (가설 상태)**:
  - 본 선언 기반 Scope Exclusion은 서드파티/테스트 노이즈를 제거하지만, C/C++ 프로젝트에서 모든 `.cpp`가 inDegree=0으로 진입점에 오르고 `main/main.cpp`가 5위 안에 없는 원인은 **아직 미확인(가설 상태)**이며, 본 계약의 해결 범위 밖(Out of Scope)으로 명시한다.
- **O2 정렬 동점 한계 및 outDegree 계측 속성**:
  - 현재 구현(`EntryPointDetector.ts#L70`)은 `outDegree` 단일 정렬만을 수행하므로 동점 구간은 노드 입력 순서(V8 stable sort)에 의존한다. Zero-Diff 보존을 위해 임의의 타이 브레이커를 추가하지 않는다.
  - O2의 outDegree는 유효한 물리 코드 확장자(`isRealFile`)를 갖는 대상 노드로 향하는 엣지만을 계측한다.

## 9. 3대 검증 계약 및 실행 거버넌스 규정

### 9.1 3대 검증 계약 (Verification Protocol)
