2. **원자적 임시 파일 기록 및 교체**:

     `mv synapse_data/project_state.json.tmp_c2 synapse_data/project_state.json`
3. **사후 검증 실패 시 원자적 복구 절차**:

   - 복구 후 해시가 불일치할 경우, 자동 프로세스를 즉시 영구 정지하고 `EMERGENCY_MANUAL_LOCK` 상태로 전환.

### 3.1. `auditNormalize` 입력 계약 및 8단계 결정적 알고리즘

#### 1) 엄격한 입력 계약 (Fail-Closed Input Contract)

#### 2) 8단계 결정적 정규화 알고리즘
```typescript
export function auditNormalize(rawPath: string): string {
    // 1. Input Validation
    if (rawPath === null || rawPath === undefined) {
        throw new Error("NULL_OR_UNDEFINED_PATH_REJECTED");
    }
    if (typeof rawPath !== 'string') {
        throw new Error("INVALID_PATH_TYPE");
    }
    if (rawPath === '') return '';

    // 2. Virtual URI Bypass Check (대소문자 무관, 원본 100% 보존)
    if (/^(ghost|external|builtin):\/\//i.test(rawPath)) {
        return rawPath;
    }
    // file:// 스킴은 접두어 제거 후 로컬 경로로 변환
    let p = rawPath.replace(/^file:\/\//i, '');

    // 3. Separator Normalization
    p = p.replace(/\\/g, '/');

    // 4. Windows Drive Relative Error Check
    if (/^[a-zA-Z]:[^/]/.test(p)) {
        throw new Error("UNSUPPORTED_DRIVE_RELATIVE_PATH: " + rawPath);
    }

    // 5. Prefix Extraction & UNC Detection
    let prefix = '';
    // Strict UNC: 정확히 2개의 선행 슬래시와 유효한 서버명/공유명 세그먼트
    if (/^\/\/[^\/\s]+\/[^\/\s]+/.test(p) && !p.startsWith('///')) {
        prefix = '//';
        p = p.substring(2);
    } else if (p.startsWith('/')) {
        prefix = '/';
        p = p.replace(/^\/+/, '');
    }

    // 6. Windows Drive Letter Normalization
    if (/^[a-zA-Z]:/.test(p)) {
        prefix = p.substring(0, 2);
        p = p.substring(2).replace(/^\/+/, '/');
    }

    // 7. Consecutive Slash Collapse
    p = p.replace(/\/+/g, '/');

    // 8. Segment Filtering & Parent Directory Preservation
    const parts = p.split('/');
    const resolvedParts: string[] = [];
    for (const part of parts) {
        if (part === '' || part === '.') {
            continue; // 빈 세그먼트 및 현재 디렉터리 축약
        }
        resolvedParts.push(part); // ".."를 포함한 모든 유의미 세그먼트 순서 보존
    }
    p = resolvedParts.join('/');

    if (prefix === '/' && p === '') return '/';
    if (prefix === '//' && p === '') return '/';
    return prefix + p;
}
```

#### 3) 세그먼트 깊이 추적 기반 워크스페이스 경로 이탈(Path Traversal) 검증 알고리즘
선두 `..`뿐 아니라 경로 중간의 `foo/../../outside`와 같은 모든 워크스페이스 이탈을 완전히 차단하기 위해 세그먼트 깊이 스택 검증을 수행합니다:

```typescript
export function validateNoWorkspaceEscape(p_rel: string): void {
    // 가상 URI 및 빈 경로는 워크스페이스 탈출 검증 면제
    if (p_rel === '' || /^(ghost|external|builtin):\/\//i.test(p_rel)) {
        return;
    }

    const segments = p_rel.split('/');
    let depth = 0;
    for (const seg of segments) {
        if (seg === '' || seg === '.') continue;
        if (seg === '..') {
            depth--;
            if (depth < 0) {
                throw new Error("WORKSPACE_ESCAPE_DETECTED: Path escapes workspace root via '..': " + p_rel);
            }
        } else {
            depth++;
        }
    }
}
```

### 3.2. Oracle 입력 경로의 Lexical 경계 및 외부 절대 경로 단일 정책 (`REJECT`)

- **Lexical 경로 기준 (No Symlink Resolution)**:
  정적 그래프 스냅샷 분석의 재현성을 위해 경로 경계 검사는 심볼릭 링크를 추적하지 않는 **순수 렉시컬(Lexical) 정규화 기준**으로 수행합니다.
- **워크스페이스 루트($W_{\text{root}}$)와의 경계 판정 규약**:
  1. **가상 URI 스키마**: `ghost://`, `external://`, `builtin://` $\to$ 워크스페이스 경로 검사를 면제하고 스키마 Role로 직행.
  2. **루트 자체 ($p === W_{\text{root}}$)**: 디렉터리 노드이거나 파일이 아니므로 물리 파일 Role 분류 대상에서 제외 (`NOT_A_FILE_NODE`).
  3. **내부 상대화**:
     - `p.startsWith(W_root + '/')`인 경우: $p_{\text{rel}} = p.\text{substring}(W_{\text{root}}.\text{length} + 1)$.
     - `p`가 이미 상대 경로인 경우: $p_{\text{rel}} = p$.
     - 도출된 $p_{\text{rel}}$에 대해 §3.1의 `validateNoWorkspaceEscape(p_rel)` 실행.
  4. **외부 절대 경로 단일 정책: `REJECT`**:
     - `p`가 절대 경로이면서 `p !== W_root && !p.startsWith(W_root + '/')`인 경우(예: `/home/project-other/file.ts`, 다른 드라이브 `D:/...`, 다른 UNC), 모호함 없이 **즉시 거부 (`throw Error("EXTERNAL_ABSOLUTE_PATH_REJECTED")`)**.

### 3.4. `filePath` 1/2단계 검증의 완전 연결

1. **Stage 1: 입력 무결성 전수 검증 (Input Validation)**:
   - `typeof id !== 'string' || id.trim() === ""` $\to$ 에러 (`EMPTY_OR_NON_STRING_ID`).
   - `filePath === null` $\to$ 에러 (`NULL_FILE_PATH_REJECTED`).
   - `filePath !== undefined && typeof filePath !== 'string'` $\to$ 에러 (`INVALID_FILE_PATH_TYPE`).
   - `typeof filePath === 'string' && id !== filePath` $\to$ 에러 (`ID_FILE_PATH_MISMATCH`).
2. **Stage 2: 출력 불변식 검증 (Output Invariant Verification)**:
   변환 대상 노드 $u \in V_{\text{target}}$에 대해:
   - **원본에 `filePath`가 존재했던 경우**:
     $filePath' \equiv \text{auditNormalize}(filePath) \land id' \equiv \text{auditNormalize}(id) \land filePath' \equiv id'$.
   - **원본에 `filePath === undefined`였던 경우**:
     - **필수 생성 불변식**: 변환 노드 $u'$에 **반드시 `filePath` 필드가 생성되어야 함** (`u'.filePath !== undefined`).
     - **값 불변식**: $u'.filePath \equiv \text{auditNormalize}(u.id) \land u'.id \equiv \text{auditNormalize}(u.id)$.
   - **비대상 노드 ($u \in V \setminus V_{\text{target}}$)**:
     원본 객체 100% 보존 (`deepEqualJSON`).

## 5. P1: 전체 사상 $M^*$ 전역 단사성 및 Edge 실제 스키마 보존

### 5.1. $M^*(x)$의 완전한 수학적 정의 및 5단계 전역 단사성 검증 절차
$$M^*(x) \triangleq \begin{cases} 
M_{\text{id}}(x), & \text{if } x \in V_{\text{target}} \\ 
x, & \text{if } x \in V \setminus V_{\text{target}} 
\end{cases}$$

검증기는 다음 5단계 전역 단사성 검증 절차를 수행합니다:
- **Step 1 (대상 내부 단사성)**: $|M_{\text{id}}(V_{\text{target}})| \equiv |V_{\text{target}}|$, 충돌 0건.
- **Step 2 (전역 배타성, Global Disjointness)**:
  $$M_{\text{id}}(V_{\text{target}}) \cap (V \setminus V_{\text{target}}) = \varnothing$$
  변환된 새 노드 ID가 기존 비대상 노드 ID와 단 1건도 교집합을 갖지 않음을 증명.
- **Step 3 (비대상 항등 사상)**: $\forall u \in V \setminus V_{\text{target}}, M^*(u) \equiv u$.
- **Step 4 (전체 노드 기수 보존)**: $|M^*(V)| \equiv |V|$.
- **Step 5 (Fail-Closed)**: 교집합 발생 또는 기수 불일치 시 즉시 검증 중단 (`GLOBAL_INJECTIVITY_VIOLATION`).

### 5.2. 실제 Edge 스키마 및 양방향 집합 일치

1. **SSoT 실제 Edge 스키마 확정**:
   SYNAPSE SSoT의 엣지는 정확히 다음 필드로 구성됩니다:
   ```typescript
   interface Edge {
       id: string;      // 고유 엣지 식별자 (필수)
       from: string;    // 출발 노드 ID (필수)
       to: string;      // 도착 노드 ID (필수)
       type?: string;   // 엣지 유형
       data?: Record<string, any>; // 메타데이터
   }
   ```
   *(끝점 필드명은 정확히 `from`, `to`이며 `source`/`target`이 아님을 확정)*
2. **Edge 보존 불변식**:
   - 원본 Edge ID 유일성 선행 조건: $\forall e_1 \neq e_2 \in E \implies e_1.\text{id} \neq e_2.\text{id}$.
   - 양방향 ID 일치: $\text{IDs}(E') \equiv \text{IDs}(E) \land |E'| \equiv |E|$.
   - Endpoint 사상 일치: $\forall e \in E, e'.\text{from} \equiv M^*(e.\text{from}) \land e'.\text{to} \equiv M^*(e.\text{to})$.
   - Endpoint 존재성: $\forall e' \in E', e'.\text{from} \in V' \land e'.\text{to} \in V'$.
   - 비-endpoint 메타데이터 Deep-Equal 보존 (`originatingId === undefined` 명시적 부재 검사).
