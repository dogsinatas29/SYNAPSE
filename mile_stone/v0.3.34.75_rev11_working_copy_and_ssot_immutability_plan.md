## 1. 개요 및 설계 철학 (Core Philosophy: KISS & Zero-Regeneration)

### 1.1 오버엔지니어링의 근본 원인 및 완전한 제거
과거 rev1~10 보완 문서는 **"공식 SSoT(`project_state.json`)를 디스크 상에서 인플레이스로 수정하고 크래시 시 이를 복구해야 한다"**는 잘못된 전제에서 출발했습니다.  
이로 인해 파일 시스템의 원자성 한계를 메우기 위해 2단계 저널, 복구 락, Stale Lock 세대 판독, 14개 분기 복구 매트릭스라는 극단적인 복잡성에 빠졌습니다.

### 1.2 "최고의 복구는 복구할 필요 자체를 만들지 않는 것"
사용자의 명확한 KISS 원칙에 따라, 문제를 아키텍처 수준에서 원천 차단합니다:
> **"재생성 불가능한 데이터는 원본 보존, 복사본 작업, 재구성은 불필요 (KISS)"**
1. **SSoT 영구 불변**: 수집기(Bootstrap)가 생성한 세대별 SSoT는 읽기 전용 불변 원본으로 박제합니다.
2. **Working Copy 격리 분석**: 분석·검증 파이프라인은 원본에서 독립적으로 파싱된 일회용 인메모리 객체(Working Copy)에서 실행되며, 실패 시 해당 복사본을 즉시 폐기하고 원본에서 다시 로드합니다. 롤백 저널과 복구 매트릭스는 완전히 불필요합니다.
3. **데이터 소유권 분리**: 캔버스 프레젠테이션과 사용자 편집 데이터는 SSoT 원본에서 완전히 분리된 전용 오버레이 파일(`layout.json`, `user_graph.json`)로 영속화합니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        SYNAPSE Data Architecture                       │
├────────────────────────────────┬───────────────────────────────────────┤
│ ① generations/project_state.vN │ ② Disposable Working Copy             │
│    [Immutable SSoT]            │    [Isolated In-Memory Parse]         │
│    - 수집기(Bootstrap) 전용     │    - 원본에서 독립 파싱하여 분석 수행 │
│    - 노드, 엣지, 클러스터      │    - 실패 시 즉시 폐기 (롤백 불필요)  │
│    - 분석 중 읽기 전용 (RO)    │    - 분석 산출물은 리포트로 저장      │
├────────────────────────────────┼───────────────────────────────────────┤
│ ③ layout.json                  │ ④ user_graph.json                     │
│    [User Layout Overlay]       │    [User Graph Overlay]               │
│    - 사용자 드래그 좌표(position)│    - 사용자 추가/수정/삭제 노드       │
│    - 뷰포트(zoom, offset)      │    - 사용자 확정/수정/삭제 엣지       │
│    - 클러스터 접힘(collapsed)  │    - 캔버스 프레젠테이션 시 병합      │
└────────────────────────────────┴───────────────────────────────────────┘
```

## 3. 다중 Host 동시성 및 단일 Writer 강제 계약 (P0-1 완결)

### 3.1 단일 Writer 원칙 및 다중 Host 쓰기 명시적 차단
TOCTOU 경쟁 조건을 원천 차단하기 위해, 모호한 디스크 재확인이 아닌 **"Workspace 당 단일 Writer 강제 및 다중 창 쓰기 거부"** 계약을 확립합니다:

1. **단일 Writer 식별자 (Host Session Epoch):**
   - Extension Host 활성화 시 고유 세션 식별자(`hostSessionId: string = UUID`)를 생성합니다.
   - `synapse_data/.active_host` 파일에 현재 활성 Host의 `hostSessionId`, `pid`, `timestamp`를 기록합니다.
2. **다중 창(Multiple Workspace Window) 동시 쓰기 거부:**
   - 웹뷰 저장 요청 시, 대상 워크스페이스의 활성 Host가 자신(`hostSessionId`)과 일치하지 않는 경우 **저장 요청을 즉시 거부(`REJECTED_MULTIPLE_HOSTS_READ_ONLY`)**하고 사용자에게 읽기 전용 모드 경고 알림을 표시합니다.
3. **단일 Host 내부 OCC 검증:**
   - 단일 Writer가 보장된 상태에서 Extension Host 직렬 큐(Serial Queue)를 통해 `expectedRevision === currentRevision`을 단언 검사하여 저장을 수행합니다.

## 4. `user_graph.json` 노드·엣지 완전 표현 스키마 및 병합 계약 (P0-2 완결)

사용자의 그래프 편집 동작(노드 및 엣지의 추가·수정·삭제)을 누락 없이 표현하는 완전한 스키마입니다:

```typescript
export interface UserGraphData {
    revision: number;
    // 1. 노드 변경 사항
    customNodes: Record<string, Node>;                 // 사용자 추가 노드 (ID: user::{uuid})
    modifiedNodes: Record<string, Partial<NodeData>>;  // 기존 노드 라벨/메타데이터 수정본
    deletedNodeIds: string[];                          // 노드 삭제 Tombstone (Canvas 숨김용)
    
    // 2. 엣지 변경 사항 (누락 결함 P0-2 완결)
    customEdges: Edge[];                               // 사용자 추가 엣지
    modifiedEdges: Record<string, Partial<EdgeData>>;  // 엣지 라벨/가중치/타입/상태(confirmed) 수정
    deletedEdgeIds: string[];                          // 엣지 삭제 Tombstone (Canvas 숨김용)
}
```

### 4.1 병합 규칙 (Canvas Presentation Overlay Rules)
1. **Tombstone 우선 적용:** `deletedNodeIds` 및 `deletedEdgeIds`에 포함된 ID는 SSoT에 존재하더라도 화면에서 완전히 숨깁니다 (SSoT 원본 변조 0바이트). 노드가 삭제되면 해당 노드에 연결된 모든 엣지도 화면에서 함께 숨깁니다.
2. **수정본 오버레이:** `modifiedNodes[id]` 및 `modifiedEdges[id]`가 존재하면 SSoT 원본의 해당 필드를 덮어써서 렌더링합니다.
3. **사용자 신규 생성분 주입:** `customNodes`와 `customEdges`를 그래프 객체에 추가합니다.
4. **분석 파이프라인과의 격리:** 본 `UserGraphData`는 오직 캔버스 화면 렌더링 시에만 오버레이되며, 정적 아키텍처 분석 파이프라인에는 단 1건도 주입되지 않습니다 (방식 A 엄수).

## 5. SSoT 세대 포인터 내구성 및 동시 Bootstrap 방지 계약 (P0-3, P0-4 완결)

### 5.1 세대 파일 및 활성 포인터의 완전한 내구성 시퀀스 (P0-3)
활성 포인터(`active_generation.json`)와 세대 파일(`generations/project_state.v{N}.json`)에 대해 §4.1과 동일한 완전한 내구성 시퀀스를 적용합니다:

```
[1. tmp 파일 기록] ──> [2. tmp fsync] ──> [3. 부모 디렉터리 fsync (POSIX)]
                                                  │
                         ┌────────────────────────┘
                         ▼
                [4. fs.renameSync] ──(성공)──> [5. 부모 디렉터리 fsync (2차)]
                         │                                    │
                      (실패)                                (실패)
                         ▼                                    ▼
               [기존 활성 포인터 보존,                 [전환 완료 상태 간주,
                tmp 파일 즉시 unlink]                  디렉터리 내구성 미확인 경고]
```

- **Windows 폴백:** Windows 환경(`process.platform === 'win32'`)에서는 파일 수준 FD fsync만 수행하며, 디렉터리 엔트리 내구성은 지원 가능한 파일 수준 내구성으로 한정함을 명시.

### 5.2 세대 포인터 읽기 검증 (Validation on Read) (P0-4)
소비자(Extension Host, 분석기)가 `active_generation.json`을 읽을 때 다음 3단계 유효성 검증을 필수로 수행합니다:
1. **경로 검증:** `activeFilePath`가 `generations/` 디렉터리 내부를 가리키는지 확인 (Path Traversal 차단).
2. **파일 존재 및 해시 검증:** 실제 대상 파일이 존재하며, 파일의 SHA-256이 포인터의 `sha256` 필드와 일치하는지 확인.
3. **폴백 정책:** 포인터가 손상되었거나 세대 파일이 부재한 경우, 직전 유효 세대(`v{N-1}`)를 자동 탐색하여 안전 복구하며, 복구 불가 시 치명적 오류 로깅 후 재수집 가이드 제공.

### 5.3 동시 Bootstrap 방지 (Bootstrap Mutual Exclusion)
- 재수집(Re-harvesting) 시작 전 `synapse_data/.bootstrap.lock`을 독점 생성하여 다른 Bootstrap이나 분석과의 동시 실행을 차단합니다.
- 신규 세대 번호는 `active_generation.json`의 `activeGeneration + 1`로 결정론적으로 할당되며, 중간에 실패하면 신규 세대 파일은 unlink되고 활성 포인터는 기존 세대를 영구 유지합니다.

## 6. `handleRollback`의 복원 일관성 및 원자성 계약 (P0-5 완결)

1. **세대 파일 보존 원칙:**
   - 과거 세대 파일(`generations/project_state.v{N}.json`)은 **영구 보존**되며, 롤백 명령어로 인해 삭제되지 않습니다.
2. **트랜잭션 복원 시퀀스:**
   - 스냅샷 복원 시 `active_generation.json`, `user_graph.json`, `layout.json`의 3개 파일 갱신이 필요합니다.
   - **복원 순서:**
     ① `active_generation.json`을 스냅샷의 세대 번호로 원자적 전환.  
     ② `user_graph.json`을 스냅샷의 사용자 그래프 데이터로 원자적 복원.  
     ③ `layout.json`을 스냅샷의 레이아웃 좌표/뷰포트로 원자적 복원.
3. **중간 실패 처리:**
   - 3개 파일 복원 중 실패가 발생하면, `handleRollback` 시작 시 생성한 `Auto Backup` 스냅샷으로 롤백하여 일관되지 않은 중간 복원 상태의 노출을 차단합니다.
