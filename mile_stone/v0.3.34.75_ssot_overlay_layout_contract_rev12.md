## 1. 개요 및 배경 (Context & Problem Statement)

### 1.1 오버엔지니어링(rev1~11)의 폐기 및 KISS 원칙 확립
과거 rev1~11 보완 문서는 `project_state.json`을 디스크 상에서 인플레이스로 수정하고 크래시 시 이를 복구하려던 잘못된 전제로 인해 14개 복구 매트릭스, 2단계 롤백 저널, 복구 락 등 극단적인 복잡성에 빠졌습니다.  
사용자의 명확한 KISS 원칙(**"재생성 불가능한 데이터는 원본 보존, 복사본 작업, 재구성은 불필요"**)에 따라 인플레이스 수정 및 자동 재생성 메커니즘을 전면 폐기하고, **"SSoT 불변 보존 + `layout.json` 오버레이 분리"**를 단일 아키텍처로 확정합니다.

### 1.2 실측 검증을 통해 확인된 핵심 사실 (Ground Truths)
1. **SSoT 크기와 레이아웃 크기의 극단적 비대칭 (1,000배 차이)**:
   - `project_state.json` 용량의 70~80%는 의존성 그래프의 엣지(`edges`) 및 메타데이터입니다.
   - VS Code 기준 파일 전체는 **61.6 MB** (노드당 4,177 B)인 반면, 전체 노드 좌표는 **1.14 MB** (노드당 80.7 B)이며, 사용자가 수동 배치한 5% 노드 델타는 **64.1 KB** (전체의 0.1%)에 불과합니다.
2. **SSoT 내 초기 좌표의 존재**:
   - 기존 SSoT 파일(Godot 9,876 노드, VS Code 14,748 노드)에는 이미 100% `position: { x, y }` 객체가 포함되어 있습니다.
   - 이를 물리적으로 발라내어 삭제하는 마이그레이션을 수행하면 Phase A 기준선 해시(`ddd7aa29...`)가 즉시 파괴되므로, **기존 파일 마이그레이션은 절대 수행하지 않고 초기값으로 보존**합니다.

## 5. 오버레이 병합 및 생명주기 규칙 (Overlay Merging Protocol)

### 5.1 파일 역할 분리
1. **`project_state.json` (불변 SSoT - 수집기 소유)**:
   - 구조 데이터(노드, 엣지, 클러스터, 파일경로, 역할).
   - 수집 직후 계산된 "초기 기본 좌표" 보존.
2. **`layout.json` (가변 오버레이 - 사용자 소유)**:
   - 사용자가 명시적으로 이동한 노드 좌표 (`positions: Record<NodeId, [x, y]>`).
   - 사용자가 조작한 뷰포트 상태 (`view: { zoom: number, offset: [x, y] }`).
   - 클러스터 접힘/펼침 오버레이 (`clusters: Record<ClusterId, { collapsed: boolean }>`).
   - 트랜잭션 충돌 방지용 모노토닉 버전 (`revision: number`).

### 5.2 병합(Merge) 및 통신 규칙
1. **단방향 오버레이 병합 (Extension Host 담당)**:
   - 캔버스 로드 시 Extension Host가 `project_state.json`을 읽고, `layout.json`이 존재하면 그 위에 좌표를 덮어씁니다:
     $$\text{FinalNode.position} = \text{layout.positions}[id] \;\;?\?\;\; \text{SSoT.node.position}$$
     $$\text{FinalView} = \text{layout.view} \;\;?\?\;\; \text{SSoT.canvas\_state}$$
   - **웹뷰(UI)는 항상 Extension Host가 병합 완료한 완전한 그래프 객체만 전달받으며**, 웹뷰 내부에서 분기 처리나 복잡한 병합 로직을 수행하지 않습니다.
2. **동시성 및 Revision 규칙**:
   - `layout.json`에는 파일 저장 시마다 1씩 증가하는 `revision: number`가 포함됩니다.
   - 웹뷰가 전송한 revision이 디스크의 최신 revision보다 낮은 경우(Stale State), 저장을 거부하고 최신 레이아웃을 다시 웹뷰로 푸시하여 동기화합니다 (Snap-back 완벽 방지).

### 5.3 "레이아웃 초기화"의 명확한 정의
- **`layout.json` 삭제 시 동작**: SSoT(`project_state.json`)에 박혀 있는 초기 스냅샷 좌표로 복귀합니다.
- **"자동 배치(Auto-Layout) 재계산"과의 분리**:
  - 기존 SSoT의 초기 좌표가 만족스럽지 않거나 과거 드래그가 혼입되어 있을 수 있으므로, **"레이아웃 초기화 (초기 SSoT 복귀)"**와 **"엔진 자동 배치 재계산 (ELK/Dagre 백엔드 실행)"**을 독립된 UI 명령어로 명확히 분리합니다.

### 5.4 구조 해시(Structural Hash) 메모
- SSoT 파일의 SHA-256 해시에는 백엔드 레이아웃 엔진의 초기 출력이 포함되어 있으므로, ELK/Dagre 엔진 버전이나 설정 변경 시 바이트가 달라질 수 있습니다.
- 향후 완전한 입력 정체성이 요구될 경우, `position`과 `canvas_state`를 제외한 노드/엣지 토폴로지만 정규화 직렬화한 **`structural_sha256`**을 메타데이터로 병행 기록하는 방식을 권장합니다.
