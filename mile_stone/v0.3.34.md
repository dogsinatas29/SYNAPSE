# 🚀 Milestone v0.3.34 - Heatmap Ghost Cache & Data Mutation Fixes

## 📅 작업 정보 - **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.33
- **목표:** 그래프 내 노드, 엣지, 클러스터의 구조적 변화(Mutation) 발생 시, 2D Canvas 및 WebGL Renderer의 캐시가 즉시 동기화되지 않아 발생하는 Ghost Node/Edge(잔상) 버그 수정. 특히 Heatmap 모드 토글 시 발생하는 오작동 해결.

## 🧠 상세 설계 및 로직
- **문제 원인 파악:** 
  - `canvas-engine.js`에서 그래프 요소가 변경될 때 `isGraphDataDirty` 플래그를 누락하여 캐시(`_visibleNodesCache`, `_visibleEdgesCache`, `spatialIndex`)가 최신화되지 않는 문제가 있었습니다.
  - Heatmap 모드의 Traffic은 `clusterFlows`에 의존하며, 캐시가 무효화되지 않으면 이전 구조의 Traffic 데이터로 계산되어 시각적 오류가 발생했습니다.
- **해결 방안:** 모든 그래프 돌연변이 지점(Graph Data Mutation Points)에서 명시적으로 캐시 무효화 및 LOD 트리 갱신을 수행하도록 변경.

## 🛠️ 기술적 변경 사항
- **File Changes: `ui/canvas-engine.js`**
  - **Cluster 생성 (`createCluster`):** 클러스터 생성 시 `initLODState()` 호출 및 `isGraphDataDirty = true` 추가.
  - **선택된 노드 그룹화/해제 (`groupSelection`, `ungroupSelection`):** 그룹화 및 해제 동작 후 `isGraphDataDirty = true` 및 `initLODState()` 호출 추가.
  - **IPC 상태 동기화 (`updateNode`, `edgeDeletedSource`):** 클라이언트가 전송한 노드 업데이트 및 엣지 삭제 이벤트 처리 후 `isGraphDataDirty = true` 추가.
  - **노드 수동 삭제 (`deleteNode`, `deleteSelectedNodes`):** 노드 삭제 로직 수행 후 `initLODState()` 호출 및 `isGraphDataDirty = true` 처리 추가.

## ⚠️ 예외 처리 및 주의 사항
- `initLODState()`는 LOD 트리를 전부 재구축하므로 호출 빈도가 과도하면 멈춤이 발생할 수 있으나, 위와 같은 구조적 파괴/생성 시점에는 필수적으로 한 번씩 호출되도록 보장했습니다.

## 📝 Post-Work Log (작업 후 기록)
- `createCluster`, `groupSelection`, `ungroupSelection`, `deleteNode`, `deleteSelectedNodes`, `updateNode(IPC)`, `edgeDeletedSource(IPC)` 에서 캐시 무효화가 누락된 점을 보완 완료.
- 이를 통해 Heatmap 토글 시 기존 잔상(Ghost nodes/edges)이 나타나지 않도록 `spatialIndex`와 WebGL 상태 동기화를 보장하게 됨.
