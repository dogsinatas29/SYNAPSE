## 🧠 상세 설계 및 로직
- **God Object 방지:** 엔진 단일 거대 클래스를 피하고 각 분석기를 `ArchitectureAnalyzer` 인터페이스를 구현하는 플러그인(Necrosis, Fracture)으로 분리.
- **if 지옥 방지:** 제네릭 `Finding` 하나에 모든 속성을 욱여넣는 대신, `BaseFinding`에서 상속받는 `Discriminated Union` (태그된 유니온) 방식을 채택 (`NecrosisFinding`, `FractureFinding` 등). 공통되지 않은 `score` 등은 제외하여 확장성 확보.
- **컨텍스트(Context) 활용:** `AnalysisContext`에 `nodeMap`, `edgeMap`, `diagnostics`를 초기 1회 주입하여, 각 플러그인이 `O(N^2)` 크로스 체크를 하지 않도록 O(1) 탐색 최적화 적용.
- **누적 파이프라인(Accumulation Pipeline):** 순차 실행 흐름을 통해 선행 분석기(`NecrosisAnalyzer`)의 결과를 후행 분석기(`FractureAnalyzer`)가 온전히 참조 가능하도록 구조화.
- **Facade 패턴 보존:** 연쇄적인 API 파편화 및 렌더러 오작동을 막기 위해 `VirtualDebugger.ts`를 완전 삭제하지 않고 엔진 위임 계층(Facade)으로 활용.
- **Read-Only Rule 적용:** 분석 결과가 `ProjectState` 원본을 훼손(Mutation)하지 않고, EvidenceBundle 규격으로 묶여 Canvas Overlay 렌더링에만 관여하도록 아키텍처 격리.
