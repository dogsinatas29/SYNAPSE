# v0.3.34 Virtual Debug — Architecture

---

## Goal

Virtual Debug answers four questions about any codebase:

```
What exists?
What is connected?
What is affected?
What is dangerous?
```

It operates entirely on the static graph already loaded in SYNAPSE.
It requires no network, no realtime sync, no event streaming.

---

## Architecture Principle: Deterministic Analysis Engine

### Purpose

Virtual Debug is not a rendering system.
Virtual Debug is not a realtime synchronization system.
Virtual Debug is not a network service.

Virtual Debug is:

```
CPU-Bound Architecture Analysis
```

### Core Rule

All analysis engines execute:

```
Synchronously
Deterministically
Single-Pass
```

whenever possible.

### Allowed Async Operations

Only the following may use `async`, `await`, or `Promise`:

```
File Loading
File Saving
Worker Communication
User Events
```

### Forbidden Async Operations

The following systems must remain synchronous:

```
Architecture Radar
Blast Radius Analysis
Infection Analysis
Boundary Analysis
Cluster Health Analysis
Threat Analysis
```

### Forbidden Patterns

The following patterns are prohibited inside analysis engines:

```js
await analyzeNode();
await analyzeCluster();
await calculateThreat();
await calculateBlastRadius();

setTimeout(...)
queueMicrotask(...)
Promise.resolve(...)
```

### Required Pattern

Analysis engines must be implemented as pure functions:

```js
function analyzeCluster(...) {
    // Read → Analyze → Return
}

function calculateBlastRadius(...) {
    // Read → Analyze → Return
}
```

## Traversal Architecture Constraint

Virtual Debug relies heavily on graph traversal.

### Forbidden

```js
queue.shift()          // O(N) array shift per iteration
visited.includes(...)  // O(N) linear scan per check
```

### Required

```js
// Queue traversal — index pointer pattern
const queue = [];
let head = 0;

while (head < queue.length) {
    const current = queue[head++];
}

// Visited tracking — O(1) hash lookup
const visited = new Set();
```

Applies to:

```
Blast Radius
Infection Analysis
Threat Analysis
Dependency Traversal
```

---

## Complexity Constraint

| Preferred | Avoid |
| :--- | :--- |
| O(N) | O(N²) |
| O(E) | O(N³) |

O(N²) or higher is permitted only when explicitly justified with a written comment explaining why no linear alternative exists.

---

## Linux Kernel Validation Target

All analysis systems must remain operational on repositories of at least:

```
68,000+ Nodes
378,000+ Edges
```

without traversal collapse, memory explosion, or Extension Host freeze.

This is the minimum acceptance criterion for every analysis engine in v0.3.34.

## Analysis Engine Architecture

### Zero-Overhead Graph Access

Virtual Debug does not copy, wrap, or virtualize the graph.

All analysis engines read directly from the live graph structures
already loaded in memory by the main SYNAPSE engine:

```
engine.nodes       — Map<id, Node>
engine.edges       — Map<id, Edge>
engine.clusters    — Map<id, Cluster>
engine.nodeIndex   — adjacency lookup (outgoing)
engine.reverseIndex — adjacency lookup (incoming)
```

**Forbidden:**

```js
const debugNodes = JSON.parse(JSON.stringify(engine.nodes)); // deep copy — forbidden
const snapshot = cloneGraph(engine);                         // virtualization — forbidden
```

**Required:**

```js
const node = engine.nodes.get(id);   // direct read — O(1)
const edges = engine.nodeIndex.get(id); // direct lookup — O(1)
```

Rationale: SYNAPSE already paid the cost to load 68K+ nodes into
memory. Virtual Debug must not pay it again. Any copying or
virtualization layer is overhead that does not exist in this design.

### DebugSession

Owns the lifecycle of a single debug run.
Created on demand, destroyed when the user exits debug mode.
Does not persist between sessions.
Holds no copy of graph data — references only.

```
DebugSession
  ├── ArchitectureRadar       (scan: what exists, what is unhealthy)
  ├── BlastRadiusAnalyzer     (given a node: what does it affect)
  ├── InfectionAnalyzer       (given a node: what infected it)
  ├── BoundaryAnalyzer        (cluster isolation and coupling)
  ├── ClusterHealthAnalyzer   (per-cluster diagnostic scoring)
  └── ThreatAnalyzer          (severity ranking across the graph)
```

### DebugOverlayRenderer

Separate from the main Canvas and WebGL renderers.
Reads DebugSession output and draws overlays on top of the existing graph.
Never modifies node or edge data.

```
DebugOverlayRenderer
  ├── SeverityOverlay         (node color: INFO / WARN / ERROR / CRITICAL)
  ├── PropagationPathOverlay  (animated edge highlight: infection path)
  └── BlastRadiusOverlay      (cluster highlight: affected zone)
```

### Severity Levels

| Level | Color | Meaning |
| :--- | :--- | :--- |
| INFO | blue | Observation only, no action required |
| WARN | yellow | Potential structural issue |
| ERROR | orange | Active architectural violation |
| CRITICAL | red | Propagating failure, immediate attention |

## Data Flow

```
User triggers debug
        ↓
DebugSession.run(graph)
        ↓
ArchitectureRadar.scan()        → NodeDiagnosticMap
        ↓
ClusterHealthAnalyzer.score()   → ClusterHealthMap
        ↓
ThreatAnalyzer.rank()           → ThreatList (sorted by severity)
        ↓
[User selects a node]
        ↓
BlastRadiusAnalyzer.calculate() → AffectedNodeSet
InfectionAnalyzer.trace()       → OriginPath
        ↓
DebugOverlayRenderer.render()   → Visual overlay on canvas
```

All steps from `ArchitectureRadar` through `ThreatAnalyzer` are synchronous.
`DebugOverlayRenderer.render()` is called from the existing render loop.

---

## Architectural Reasoning

Virtual Debug exists to answer structural questions, not to monitor runtime behavior.

It does not require:

```
Realtime processing
Network synchronization
Event streaming
Task scheduling
```

Therefore:

```
Synchronous execution is the default.
Asynchronous execution is the exception.
```

This keeps the analysis deterministic, testable, and safe to run on the Extension Host without introducing new async failure modes.
