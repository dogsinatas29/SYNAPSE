## R-01 — BFS Traversal Collapse on Large Graphs

**Scenario:** BlastRadiusAnalyzer or InfectionAnalyzer enters an infinite loop or collapses on a graph with cycles.

**Linux Kernel exposure:** 378,000 edges, dense cross-cluster dependencies, guaranteed cycles.

**Mitigation:**
- `visited` Set checked before every enqueue
- No node enqueued twice
- Queue bounded by total node count

```js
// Required pattern
const visited = new Set();
const queue = [startId];
let head = 0;

while (head < queue.length) {
    const id = queue[head++];
    if (visited.has(id)) continue;
    visited.add(id);
    // process
}
```

## R-02 — O(N²) Traversal Regression

**Scenario:** A developer introduces `queue.shift()` or `array.includes()` inside a traversal loop, collapsing performance from O(N) to O(N²).

**Linux Kernel exposure:** 68,000 nodes × 68,000 iterations = 4.6 billion operations. Instant freeze.

**Mitigation:**
- Architecture document explicitly forbids `queue.shift()` and `visited.includes()`
- Plan document requires grep audit before each phase sign-off
- Code review checklist includes traversal pattern check

**Detection:**
```bash
grep -r "queue\.shift" src/debug/
grep -r "\.includes(" src/debug/
```
Both must return zero results.

## R-03 — DebugOverlayRenderer Touches Main Pipeline

**Scenario:** DebugOverlayRenderer accidentally modifies `engine.nodes`, `engine.edges`, or calls layout functions.

**Impact:** Graph state corruption, layout shift, user data loss.

**Mitigation:**
- DebugOverlayRenderer receives `DebugEvidenceBundle` only (plain data)
- DebugOverlayRenderer has no reference to engine internals
- Overlay is drawn to a separate canvas layer or via z-index separation

---

## R-04 — DebugSession Copies Graph Data

**Scenario:** DebugSession stores `JSON.parse(JSON.stringify(engine.nodes))` or equivalent deep copy.

**Impact:** 68K nodes × copy overhead = OOM on Linux Kernel.

**Mitigation:**
- Architecture document explicitly forbids deep copy and virtualization
- DebugSession stores `Map` references only, never values

**Detection:**
```bash
grep -r "JSON.stringify" src/debug/
grep -r "JSON.parse" src/debug/
grep -r "cloneGraph\|deepCopy\|structuredClone" src/debug/
```
All must return zero results inside analysis engines.

---

## R-05 — Severity Scoring Non-Deterministic

**Scenario:** ThreatAnalyzer produces different rankings on identical graphs due to Map iteration order or floating-point instability.

**Impact:** Unreliable debug output. Users cannot reproduce results.

**Mitigation:**
- ThreatList sorted by numeric severity score (descending), then by node ID (lexicographic) as tiebreaker
- No random sampling in scoring logic
- No Date.now() or Math.random() inside analysis engines

---

## R-06 — Extension Host OOM on Linux Kernel

**Scenario:** DebugEvidenceBundle for 68K nodes exceeds Extension Host memory limit.

**Mitigation:**
- DebugEvidenceBundle stores severity per node as `Map<id, SeverityLevel>` (integer enum)
- No string duplication per node
- Bundle estimated size: 68K × ~50 bytes = ~3.4MB (acceptable)

**Monitoring:** Log bundle size after Evidence Generation phase.

## R-07A — BFS Structure Failure

**Scenario:** BFS implementation uses incorrect data structure, causing silent result truncation or incorrect traversal order on graphs with complex topology.

**Specific failure modes:**

1. **Stack overflow via recursion** — recursive DFS on 68K depth path
2. **Incomplete traversal** — BFS terminates early due to incorrect termination condition
3. **Wrong direction** — BlastRadius uses incoming edges instead of outgoing (or vice versa)

**Linux Kernel exposure:** High. Linux kernel has long dependency chains (e.g., `include/linux/types.h` → hundreds of transitive dependents).

**Mitigation:**
- BlastRadius: traverses `engine.nodeIndex` (outgoing edges only)
- InfectionTrace: traverses `engine.reverseIndex` (incoming edges only)
- No recursion — iterative BFS only
- Termination: `head >= queue.length`, not queue empty check on shift

**Validation:**
- Unit test: known graph with 5 nodes, verify full traversal
- Unit test: graph with cycle, verify no infinite loop
- Linux Kernel: BlastRadius from a leaf node vs. a hub node, verify different sizes

## R-07B — Async Abuse in Analysis Engines

**Scenario:** A developer wraps a synchronous analysis function in `async`/`await`, introducing microtask scheduling, non-deterministic execution order, or hidden Promise chains inside the analysis pipeline.

**Why this matters:**

```
Synchronous analysis:
  scan() → result available immediately
  deterministic, testable, reproducible

Async analysis:
  scan() → Promise → microtask queue → result available... when?
  non-deterministic ordering if multiple analyses run
  error propagation becomes complex
  Extension Host async failure modes introduced
```

**Specific failure modes:**

1. `await analyzeCluster()` inside a loop — introduces microtask gaps between iterations, making results dependent on event loop state
2. `Promise.all(nodes.map(n => analyzeNode(n)))` — appears parallel, but on single-threaded Extension Host it just adds overhead
3. `setTimeout(() => scan(), 0)` — defers analysis past current frame, breaking "trigger debug → see result" synchrony

**Mitigation:**
- Architecture document lists forbidden patterns explicitly
- Plan document requires async grep audit before each phase sign-off
- All analysis engine functions must have `function` signature, not `async function`

**Detection (run before every phase sign-off):**
```bash
grep -rn "async function\|await \|Promise\.\|setTimeout\|queueMicrotask" src/debug/
```
Any result inside an analysis engine (`ArchitectureRadar`, `BlastRadiusAnalyzer`, `InfectionAnalyzer`, `BoundaryAnalyzer`, `ClusterHealthAnalyzer`, `ThreatAnalyzer`) is a violation.

**Exception:** `DebugSession.loadFromFile()` and `DebugSession.saveToFile()` may use async — file I/O only.
