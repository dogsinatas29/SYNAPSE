# 🚀 Milestone v0.3.35 - [ASR 4.0: Semantic Graph & Build Context]

## 📅 작업 정보 
- **상태:** 🏗️ Planned 
- **관련 마일스톤:** v0.3.34.20
- **목표:** 단순 파일 그래프(File Graph) 스캐너를 넘어, 빌드 컨텍스트(Build Graph)와 의미론적 엣지(Semantic Edge)를 이해하는 진정한 아키텍처 스캐너로의 진화.

## 🧠 핵심 과제 (The 4 Pillars)

### 1. Ghost vs External Package 분리
- **현상:** 현재 스캐너는 로컬 디스크에 없는 모든 참조를 'Ghost'라는 하나의 버킷에 욱여넣고 있음. 이로 인해 `zod`, `xterm` 같은 정상적인 NPM 패키지와, 진짜 유실된(Unknown) 심볼이 섞여 Ghost 품질이 하락함.
- **계획:** `package.json` (또는 언어별 의존성 매니저)를 파싱하여, 식별된 External Package와 순수 Unknown Symbol을 분리 격리.

### 2. CONTRACT_HUB 연결 버그 수정
- **현상:** AST 엔진이 `extHost.protocol.ts`를 완벽하게 `[HEALTHY_CONTRACT]` 및 `CONTRACT_HUB`로 분류했음에도, 리포트 생성기(`ValidationReportBuilder.ts`)가 이 AST 결과를 무시하고 Graph Analyzer의 텅 빈 결과를 참조하여 "No candidates found"를 출력함.
- **계획:** 분류기(AST)의 결과가 감사기(Report/Audit)로 직접 파이프라이닝되도록 데이터 플로우 교체. (이전 버전에서 임시 삭제한 해당 섹션을 AST 기반으로 재건축)

### 3. Edge 타입 분류 (include / symbol / runtime)
- **현상:** C/C++ 및 커널 분석 시 `#include`를 통한 단순 헤더 참조와, 실제 런타임 심볼 호출이 모두 `Count: 1`짜리 동일한 엣지로 취급됨. 이로 인해 거대한 의존성 노이즈(과장된 Blast Radius) 발생.
- **계획:** Scanner 레이어에서 정규식/AST 횡단 시 엣지에 `EdgeType (INCLUDE | SYMBOL | RUNTIME | TYPE_REF)` 메타데이터 부여.

### 4. Kconfig / Build Graph 인식 (Kernel-scale 대응)
- **현상:** `#ifdef CONFIG_ARM64` 처럼 빌드 타임에 잘려나가는 데드 코드(Dead Code)를 스캐너가 물리적 파일 단위로 모조리 긁어와 의존성으로 엮어버림.
- **계획:** C/C++ 프로젝트 스캔 시 Kconfig, Makefile, `compile_commands.json` 등의 빌드 컨텍스트를 주입받아, 비활성화된 분기를 스캔 대상에서 가지치기(Pruning)하는 전처리 레이어 도입.

## 📝 비고
- 해당 마일스톤은 단순한 버그 픽스가 아닌, **"대규모 코드베이스 구조 스캐너"에서 "정확한 아키텍처 분석기"로 넘어가는 패러다임 전환**임.
- 폰테일(Ponytail) 원칙에 따라, 4번(Kconfig)과 같은 거대 작업은 가장 가벼운 정규식 프루닝(Regex Pruning)부터 점진적으로 도입할 것.
