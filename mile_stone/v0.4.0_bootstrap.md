# Mandatory Development Principles

## Principle 1: Think Before Coding

추측해서 구현하지 않는다.

명세가 불명확하면:

1. 구현 중단
2. 모호성 식별
3. 해결안 제시
4. 결정 후 구현

---

## Principle 2: Validation First

모든 구현은 검증 방법이 먼저 존재해야 한다.

순서:

Goal
→ Validation
→ Implementation

금지:

Implementation
→ Validation

---

## Principle 3: Small Increment Rule

한 번에 하나의 Gate만 통과한다.

Phase N Validation이 통과하기 전까지
Phase N+1 구현 금지.

---

## Principle 4: Disposable Cache Rule

다음은 언제든 삭제 가능해야 한다.

* projection.snapshot
* structural.cache
* architectural.cache

삭제 후 시스템은 정상 복구되어야 한다.

---

## Principle 5: Historical Truth Protection

RawFact와 Referenced Blob은 영구 보존 대상이다.

다음은 절대 수행하면 안 된다.

* RawFact 수정
* RawFact 삭제
* Referenced Blob 삭제
* Referenced Blob 변경

# Additional Clarifications

## Clarification 1: Deterministic State Definition

HARNESS-003의 State는 다음을 의미한다.

```typescript
interface TopologyState {
    nodes: Node[];
    edges: Edge[];
    clusters: Cluster[];
}
```

검증:

```typescript
assert.deepEqual(
    topologyA,
    topologyB
);
```

---

## Clarification 2: Drift Reconciliation Rule

Workspace Drift 발견 시

최소 이벤트 집합을 생성한다.

예시:

파일 존재
+
해시 변경

↓

FILE_MODIFIED

파일 신규 발견

↓

FILE_CREATED

파일 제거

↓

FILE_DELETED

복합 이벤트 생성 금지.

---

## Clarification 3: Blob Garbage Collection Rule

GC는 Reachability 기반으로 동작한다.

Root Set:

```text
RawFact.beforeHash
RawFact.afterHash
```

Reachable:

```text
KEEP
```

Unreachable:

```text
DELETE 가능
```

RawFact가 참조하는 Blob은 영구 보존된다.

---

## Clarification 4: Projection Corruption Recovery

projection.snapshot 손상은 정상 장애 시나리오다.

복구 절차:

1. Projection Load 실패
2. Empty Projection 생성
3. Workspace Scan
4. AST Build
5. Evolution Engine 실행
6. Projection 재생성

시스템은 종료되면 안 된다.

# Success Criteria

SYNAPSE v0.4.0은 다음 조건을 모두 만족해야 한다.

1. Workspace만으로 현재 상태 복구 가능
2. Projection 없이 부팅 가능
3. RawFact + CAS만으로 과거 복구 가능
4. Drift 자동 감지 가능
5. Referenced Blob 영구 보존
6. Animator 완전 읽기 전용
7. Deterministic Evolution 보장
8. Projection 손상 복구 가능
9. Cold Boot 성능 목표 달성

모든 HARNESS를 통과하기 전까지 v0.4.0은 완료된 것으로 간주하지 않는다.
