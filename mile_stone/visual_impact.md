# 🧠 Visual Impact - 에러 트레이서 및 논리 테스트 아키텍처

---

## 🏛️ 논리테스트 강화 및 에러 판별기: 시각적 타격 로직 (Visual Impact)
에러의 종류를 일일이 아이콘으로 구분하지 마라. 대신 **'논리의 상태'**로 조져버리는 거다.

### 1. "논리 집합체(Node)의 오염" - [LSP / Syntax / Import]
- **원인**: 오타, 잘못된 임포트, 존재하지 않는 함수명.
- **시각화**: 노드 내부의 보라색 코어(Core)가 '검은색'으로 괴사하거나, 노드 전체가 **'노이즈(Static)'**로 뒤덮이게 해라.
- **느낌**: "이 논리는 읽을 수 없다(Unreadable)"는 강렬한 거부감을 준다.

### 2. "논리 흐름(Edge)의 단절" - [Type Mismatch / Logic Gap]
- **원인**: 논리 흐름은 살아있으나 데이터 전달 방식이 틀린 경우.
- **시각화**: 엣지가 목적지 노드에 닿지 못하고 **'중간에 꺾여서 바닥으로 추락'**하거나, 선이 **'날카로운 지그재그(Z-shape)'**로 변하게 해라.
- **느낌**: "데이터가 길을 잃었다"는 걸 단번에 알 수 있다.

### 3. "시스템의 한계(Pressure)" - [Memory / Resource / Crash]
- **원인**: 메모리 부족, 무한 루프, 하드웨어 임계치 도달.
- **시각화**: 화면 전체의 **'보라색 글로(Glow)가 붉게 점멸(Red Pulse)'**하며, 상태바의 인퍼런스 압력이 **'99%+'**에서 멈추게 해라.
- **느낌**: "지금 당장 멈추지 않으면 시스템이 죽는다"는 경고다.

## 🛠️ DTR: 에러 시각화 표준 (Error Viz Standard)
- **Node Necrosis**: LSP 에러 시 노드 중심부 흑화 처리 (Black-out).
- **Edge Fracture**: 논리 불일치 시 엣지 굴절 및 단절 렌더링.
- **System Red-out**: 리소스 임계치 도달 시 전체 UI 붉은색 펄스(Pulse) 적용.
- **Action**: 에러 노드 클릭 시에만 상세 LSP 메시지 팝업 (평상시 시각 오염 방지).

> ⚠️ **시니어의 한마디**
> "최고의 디버깅 툴은 에러를 설명하는 게 아니라, 에러를 느끼게 하는 거다."

## 🧠 논리 테스트 및 리포트 자동 생성 로직 (v0.x.x)

### 1. 실행 단계 (Execution)
- **인터셉터**: 논리 테스트 실행 시 `edgeHandler.ts`가 모든 데이터 흐름을 캡처한다.
- **실시간 감시**: '노드 괴사(LSP)', '엣지 굴절(Logic Gap)', '시스템 레드아웃(Resource)' 시각화가 실시간으로 화면에 뿌려진다.

### 2. 에러 판별 및 분류 (Discrimination)
- 테스트가 종료되거나 중단되는 시점의 모든 **'시각적 상태값'**을 JSON 데이터로 파싱한다.
  - *예시*: `{"node_id": "auth_logic", "status": "NECROSIS", "reason": "LSP_MISSING_IMPORT"}`

### 3. 리포트 생성 (Report Generation)
- **포맷**: 마일스톤 문서 표준 템플릿을 활용한 `LOGIC_REPORT.md` 자동 생성.
- **내용**: 
  - `[Fail Node]`: 어떤 논리 집합체가 터졌나.
  - `[Broken Edge]`: 어디서 흐름이 끊겼나.
  - `[Pressure Log]`: 인퍼런스 압력이 최고조였던 지점.
  - `[Turbo Mode Feedback]`: 터보 모드(고밀도 추론)가 에러 해결에 도움이 되었는지 여부.

## 📝 Post-Work Log (논리 테스트 결과 템플릿)
- **Test Status**: ✅ Pass / ❌ Fail (Visual Indicator: Red-out)
- **Necrosis Nodes**: [LSP 에러 노드 목록]
- **Fractured Edges**: [데이터 흐름 단절 지점]
- **Inference Efficiency**: 터보 모드 사용 시 추론 정확도 향상률 기록.
- **Refinement**: 다음 설계 시 수정해야 할 논리 병목 지점 제안.

> ⚠️ **시니어의 잔소리**
> "리포트는 반성문이 아니라, 다음 설계의 설계도다. 리포트에 그냥 "에러 났음"이라고 적지 말고, "보라색 추론 밀도를 80%로 올렸더니 이 노드에서 엣지 단절이 해결됨" 같은 유의미한 상관관계를 기록하게 설계해라. 그게 '바이브 코딩'의 핵심 데이터가 될 거다."
