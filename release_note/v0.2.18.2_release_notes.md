# 🚀 Release Notes - Milestone v0.2.18.2 (The Iron Guard Patch)

## 📌 Features & Updates

**Architecture Guardrail Validation Engine (`LogicAnalyzer.ts`)**
- Added the 4-step Validation Loop ensuring constraints strictly align with `synapse.config.json`.
- **Layer Gravity Enforcement:** Disallowed node connections from a lower-layer component backward up the stack (e.g., from Layer 2 `api` back to Layer 1 `frontend`).
- **Inter-Cluster Restrictions (enforce_bridge):** Connections jumping between clusters are checked to ensure proper bridge nodes are utilized.
- **Same Layer Adjustments:** Integrated the capability to allow/disallow intra-layer node connections globally.

**Visual UI Updates (`CanvasPanel.ts`, `canvas-engine.js` & `index.html`)**
- Edge validation results dynamically affect styling, turning invalid paths a **Gruvbox Yellow** (Warnings) or a solid **Gruvbox Red** (Criticals).
- Semantic Zooming automatically abstracts smaller nodes out of view at wider zoom levels to reduce visual impact.
- **Layer Visibility Interface:** Added a toggle UI (`[Base Logic (AI)]`, `[User Custom]`) to the bottom-left of the canvas. This allows users to instantly filter the view to display only system-generated logic or manually-created architecture without performance loss.

**IDE Diagnostics Hook-in (`extension.ts`)**
- Enabled VS Code IDE background validations. Upon saving a workspace text document, a 1-second debounced background check triggers `LogicAnalyzer.ts`.
- Detected violations are published to VS Code's internal Diagnostics system, allowing the user to view structural issues in real-time in the `Problems` Context.

**Supported Language Exceptions**
- Analyzers now reference the `"supported_languages": [".ts", ".js", ".py", ".md"]` array within `synapse.config.json`. Unsupported files attempted to be wired to the architecture log a warning.
