## 🇰🇷 한국어 릴리즈 노트

### 개요

v0.2.21-fix는 WebGL GPU 가속 렌더러의 구조적 결함을 전면 수정한 핫픽스 릴리즈입니다.  
이번 릴리즈 이후 🚀 Accel 버튼이 정상 동작하며, WebGL + Canvas 2D 하이브리드 렌더링이 안정적으로 작동합니다.

---

### 🔴 치명적 버그 수정

#### 1. `webgl-renderer.js` 403 Forbidden 차단 (`CanvasPanel.ts`)
- **원인:** `_getHtmlForWebview()`에서 `canvas-engine.js`만 `asWebviewUri()` 변환하고 `webgl-renderer.js`는 원시 상대 경로 그대로 방치
- **결과:** VS Code Webview CSP가 `webgl-renderer.js` 로드를 **403 Forbidden**으로 차단 → `WebGLRenderer` 클래스 미정의 → 버튼 클릭 시 `ReferenceError`
- **수정:** `webgl-renderer.js`도 `webview.asWebviewUri()`로 올바르게 변환

```typescript
// 수정 후 (CanvasPanel.ts)
const webglRendererUri = webview.asWebviewUri(
    vscode.Uri.joinPath(this._extensionUri, 'ui', 'webgl-renderer.js')
);
html = html.replace('src="webgl-renderer.js"', `src="${webglRendererUri}"`);
```

---

#### 2. WebGL + Canvas 2D Context 충돌 (`webgl-renderer.js`)
- **원인:** 브라우저 규칙 — 하나의 `<canvas>`에는 렌더링 context 1종만 허용
  - `getContext('2d')` 호출 후 동일 canvas에서 `getContext('webgl')` → `null` 반환
  - 에러 메시지 `"WebGL not supported"` 는 오해의 소지가 있었음 (지원 여부가 아니라 context 충돌)
- **수정:** `WebGLRenderer`가 **독립 오버레이 canvas를 동적 생성**

```
변경 전:                     변경 후:
<canvas id="canvas">        container (position: relative)
 └─ 2D context               ├─ <canvas id="webgl-overlay-canvas">  ← WebGL
                             │     (pointer-events: none, z-index: 0)
                             └─ <canvas id="canvas">                 ← Canvas 2D
```

- **레이어 구조 (Sigma.js / Cytoscape.js와 동일한 하이브리드 패턴):**
  - WebGL canvas (하단): stars, nodes — GPU 가속
  - Canvas 2D (상단): edges, labels, HUD, 선택 UI

---

#### 3. Overlay Canvas 생애주기 최적화 (`index.html`)
- **이전 (나쁜 방식):** Toggle OFF 시 `overlay.remove()` + `webglRenderer = null` → ON 시 매번 새로 생성 (DOM 삽입 + GL context 재초기화 반복)
- **수정 (올바른 방식):** Overlay canvas는 **최초 1회만 생성**, 이후 토글은 `display: block/none`만 사용

```javascript
// ON: 최초 1회만 생성
if (!eng.webglRenderer) {
    eng.webglRenderer = new WebGLRenderer(eng.canvas);
}
overlay.style.display = 'block';

// OFF: GL context 유지, 화면만 숨김
overlay.style.display = 'none';
```

---

#### 4. Accel 버튼 클릭 무응답 (`index.html`, `canvas-engine.js`)
- **원인 체인:**
  1. 버튼이 View 드롭다운 내부에 있어 클릭 시 `document click` 이벤트로 드롭다운 닫힘 → 이벤트 경쟁
  2. `setupToolbarListeners()`의 `this` 컨텍스트 바인딩 불확실성
- **수정:**
  1. `btn-webgl`을 드롭다운 밖 독립 툴바 버튼으로 이동
  2. 리스너를 `index.html` `DOMContentLoaded` 블록으로 이전, `window.engine` lazy 참조

---

#### 5. `TypeError: Assignment to constant variable` (`canvas-engine.js:1977`)
- **원인:** `const clickedClusterHeader` 선언 후 동일 스코프 하위에서 재할당 시도
- **수정:** `const` → `let` 변경

---

#### 6. `ReferenceError: isPromoting is not defined` (`canvas-engine.js:5173`)
- **원인:** `renderNode()` 내에서 `isPromoting` 변수를 선언 없이 사용 (`this.promotingNodeIds` Set은 초기화되어 있었으나 로컬 변수 선언 누락)
- **수정:** 함수 상단에 변수 선언 추가

```javascript
// 추가됨
const isPromoting = this.promotingNodeIds && this.promotingNodeIds.has(node.id);
```

### ⚡ 성능 최적화

#### 7. Pan/Zoom 시 GPU 버퍼 재업로드 제거 (`webgl-renderer.js`)
- `isDataDirty` 플래그 도입: `gl.bufferData()` 는 노드 이동 /데이터 변경 시에만 호출
- Pan/Zoom 시 projection `uniform` 행렬만 갱신 → CPU→GPU 전송 비용 제거

#### 8. GL 상태 초기화 위치 최적화 (`webgl-renderer.js`)
- `gl.disable(DEPTH_TEST)`, `gl.enable(BLEND)`, `gl.blendFunc()` → 생성자에서 1회만 설정

#### 9. `render()` 시그니처 정직화 (`webgl-renderer.js`)
- 미사용 `edges` 파라미터 제거: `render(nodes, edges, transform)` → `render(nodes, transform, isDataDirty)`

#### 10. DEBUG 콘솔 로그 노이즈 제거 (`canvas-engine.js`)
- 매 이벤트마다 찍히던 로그 전량 제거:
  - `[DEBUG] Wheel event detected`
  - `[DEBUG] zoom called`
  - `[DEBUG] New transform`
  - `[DEBUG] MouseDown on`
  - `[DEBUG] fitView calculated`

## 🇺🇸 English Release Notes

### Overview

v0.2.21-fix is a hotfix release that completely resolves all structural defects in the WebGL GPU-accelerated renderer. After this release, the 🚀 Accel button works correctly and the WebGL + Canvas 2D hybrid rendering pipeline is stable.

---

### 🔴 Critical Bug Fixes

#### 1. `webgl-renderer.js` Blocked with 403 Forbidden (`CanvasPanel.ts`)
- **Cause:** `_getHtmlForWebview()` converted `canvas-engine.js` with `asWebviewUri()` but left `webgl-renderer.js` as a raw relative path
- **Result:** VS Code Webview CSP blocked `webgl-renderer.js` with **403 Forbidden** → `WebGLRenderer` never defined → `ReferenceError` on button click
- **Fix:** Register `webgl-renderer.js` with `webview.asWebviewUri()` just like `canvas-engine.js`

```typescript
const webglRendererUri = webview.asWebviewUri(
    vscode.Uri.joinPath(this._extensionUri, 'ui', 'webgl-renderer.js')
);
html = html.replace('src="webgl-renderer.js"', `src="${webglRendererUri}"`);
```

---

#### 2. WebGL + Canvas 2D Context Conflict (`webgl-renderer.js`)
- **Cause:** Browser rule — a single `<canvas>` supports only ONE rendering context type
  - Calling `getContext('webgl')` after `getContext('2d')` on the same canvas returns `null`
  - Error message said "WebGL not supported" but was misleading — the GPU supports WebGL, it was a context conflict
- **Fix:** `WebGLRenderer` now creates its own dedicated **overlay canvas**

```
Before:                      After:
<canvas id="canvas">         container (position: relative)
 └─ 2D context                ├─ <canvas id="webgl-overlay-canvas">  ← WebGL
                              │     (pointer-events: none, z-index: 0)
                              └─ <canvas id="canvas">                 ← Canvas 2D
```

- **Layer architecture (same hybrid pattern as Sigma.js / Cytoscape.js):**
  - WebGL canvas (below): stars, nodes — GPU accelerated
  - Canvas 2D (above): edges, labels, HUD, selection UI

---

#### 3. Overlay Canvas Lifecycle Optimization (`index.html`)
- **Before (bad):** Toggle OFF called `overlay.remove()` + `webglRenderer = null` → recreated from scratch on every ON (repeated DOM insertion + GL context re-initialization)
- **Fixed (correct):** Overlay canvas created **exactly once** on first ON, subsequent toggles use only `display: block/none`

```javascript
// ON: create once only
if (!eng.webglRenderer) {
    eng.webglRenderer = new WebGLRenderer(eng.canvas);
}
overlay.style.display = 'block';

// OFF: GL context preserved, just hidden
overlay.style.display = 'none';
```

---

#### 4. Acceleration Button Click Not Registering (`index.html`, `canvas-engine.js`)
- **Root cause chain:**
  1. Button was inside View dropdown — clicks triggered `document click` → dropdown closed → event race condition
  2. `this` binding uncertainty in `setupToolbarListeners()`
- **Fix:**
  1. Moved `btn-webgl` out of dropdown to standalone toolbar button
  2. Listener moved to `index.html` `DOMContentLoaded` with lazy `window.engine` reference

---

#### 5. `TypeError: Assignment to constant variable` (`canvas-engine.js:1977`)
- **Cause:** `clickedClusterHeader` declared as `const` but reassigned later in the same scope
- **Fix:** `const` → `let`

---

#### 6. `ReferenceError: isPromoting is not defined` (`canvas-engine.js:5173`)
- **Cause:** `isPromoting` used in `renderNode()` without being declared (`this.promotingNodeIds` Set existed but local variable declaration was missing)
- **Fix:** Added variable declaration at top of function

```javascript
const isPromoting = this.promotingNodeIds && this.promotingNodeIds.has(node.id);
```

---

### ⚡ Performance Optimizations

#### 7. Eliminated GPU Buffer Re-upload on Pan/Zoom (`webgl-renderer.js`)
- `isDataDirty` flag: `gl.bufferData()` called only on node data changes
- Pan/Zoom updates only the projection `uniform` matrix — zero CPU→GPU transfer

#### 8. GL State Initialization Out of Render Loop (`webgl-renderer.js`)
- `gl.disable(DEPTH_TEST)`, `gl.enable(BLEND)`, `gl.blendFunc()` → set once in constructor

#### 9. Honest `render()` Signature (`webgl-renderer.js`)
- Removed unused `edges` param: `render(nodes, edges, transform)` → `render(nodes, transform, isDataDirty)`

#### 10. Removed DEBUG Console Log Noise (`canvas-engine.js`)
- Removed per-event debug logs that flooded the console:
  - `[DEBUG] Wheel event detected`
  - `[DEBUG] zoom called`
  - `[DEBUG] New transform`
  - `[DEBUG] MouseDown on`
  - `[DEBUG] fitView calculated`
