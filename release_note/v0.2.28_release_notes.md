## [EN] v0.2.28 — Rendering Parity & Stability Patch

### Overview
This release focuses on eliminating visual inconsistencies between 2D (Canvas) and 3D (WebGL Accelerated) rendering modes and resolving several UX friction points that accumulated during the v0.2.27 debug cycle.

---

### 🎨 Rendering Fixes

#### 1. Conditional Node Color Parity (`webgl-renderer.js`)
- **Problem**: Decision-type nodes (`valid_*`, `checker`, `validator`, `router`, `is_*`) were rendered with a light background (`#ebdbb2`) in 3D accelerated mode, while the canonical 2D renderer (`getNodeStyle` in `canvas-engine.js`) correctly used a dark background (`#3c3836`) with a yellow border (`#fabd2f`).
- **Fix**: 3D renderer now mirrors 2D behavior exactly. Decision nodes use `bgColor: #3c3836`. Only true `isDeterministicFracture` violation nodes retain the `#ebdbb2` light background to distinguish them as active constraint violations.
- **Impact**: Visual output is now consistent when switching between 2D and 3D modes.

#### 2. Node Render-Order Over Edges (3D mode)
- Nodes continue to be rendered after edges in the WebGL pipeline to ensure they are always drawn on top, preventing edge lines from visually piercing node bodies.

---

### 💾 Snapshot & Camera View Persistence

#### `canvas-engine.js` — Camera State in `saveState()`
- The `saveState()` method now includes `view: this.transform` in the serialized `projectState` payload sent to the extension backend.

#### `CanvasPanel.ts` — `handleSaveState()` View Merge
- The `handleSaveState` handler now reads `newState.view` and merges it into `currentState.view` before writing to `project_state.json`.
- **Effect**: Camera position (pan offset + zoom level) is now fully persisted across sessions and snapshot rollbacks.

#### `canvas-engine.js` — `loadProjectState()` View Restore
- On state load, `transform.zoom`, `transform.offsetX`, and `transform.offsetY` are restored from the saved view, unless `preserveView` is explicitly set.

---

### 🗂️ File Handling Improvements (`CanvasPanel.ts`)

#### Extensionless File Open Guard (`openFile`)
- Clicking a node whose file path has no extension (e.g., `README`, `Makefile`, virtual nodes) now triggers a Korean-language warning message before attempting to open.
- Error messages now include the specific error reason (e.g., `ENOENT: no such file or directory`) instead of a generic "Failed to open file" string.

---

### 🧹 Code Quality

#### `handleUngroup` Corruption Fix (`CanvasPanel.ts`)
- A previous automated edit had injected ~200 lines of stray comment text into the `handleUngroup` function body, corrupting its control flow. The function has been fully restored to its canonical state using `git stash`.
- `sendProjectState()` call after ungroup was also restored.

## [KO] v0.2.28 — 렌더링 일치 및 안정성 패치

### 개요
이번 릴리즈는 2D(캔버스)와 3D(WebGL 가속) 렌더링 모드 간의 시각적 불일치를 제거하고, v0.2.27 디버그 사이클에서 누적된 UX 불편사항들을 해결하는 데 집중합니다.

---

### 🎨 렌더링 수정

#### 1. 조건 노드 색상 일치 (`webgl-renderer.js`)
- **문제점**: `valid_*`, `checker`, `validator`, `router`, `is_*` 같은 결정 노드들이 3D 가속 모드에서는 밝은 배경(`#ebdbb2`)으로 렌더링되었으나, 2D 렌더러(`canvas-engine.js`의 `getNodeStyle`)에서는 어두운 배경(`#3c3836`)에 노란 테두리(`#fabd2f`)로 렌더링되어 불일치가 발생했습니다.
- **수정**: 3D 렌더러가 2D 동작을 정확히 미러링합니다. 결정 노드는 `bgColor: #3c3836`을 사용합니다. 실제 `isDeterministicFracture`(결정론적 제약 위반) 노드만 활성 위반을 명시하기 위해 `#ebdbb2` 밝은 배경을 유지합니다.
- **효과**: 2D↔3D 전환 시 시각적 출력이 일관되게 유지됩니다.

#### 2. 3D 모드에서 노드가 엣지 위에 렌더링 보장
- WebGL 파이프라인에서 노드는 엣지 이후에 렌더링되어 항상 엣지 위에 그려집니다. 이로써 엣지 선이 노드 바디를 시각적으로 관통하는 현상을 방지합니다.

---

### 💾 스냅샷 및 카메라 뷰 영속성

#### `canvas-engine.js` — `saveState()`에 카메라 상태 포함
- `saveState()` 메서드가 익스텐션 백엔드로 전송하는 `projectState` 페이로드에 `view: this.transform`을 포함합니다.

#### `CanvasPanel.ts` — `handleSaveState()` 뷰 병합
- `handleSaveState` 핸들러가 `newState.view`를 읽어 `project_state.json`에 쓰기 전 `currentState.view`에 병합합니다.
- **효과**: 카메라 위치(패닝 오프셋 + 줌 레벨)가 세션과 스냅샷 롤백 전반에 걸쳐 완전히 영속됩니다.

#### `canvas-engine.js` — `loadProjectState()` 뷰 복원
- 상태 로드 시 `preserveView`가 명시적으로 설정되지 않은 경우, 저장된 뷰에서 `transform.zoom`, `transform.offsetX`, `transform.offsetY`를 복원합니다.

---

### 🗂️ 파일 처리 개선 (`CanvasPanel.ts`)

#### 확장자 없는 파일 열기 가드 (`openFile`)
- 확장자가 없는 파일 경로를 가진 노드(예: `README`, `Makefile`, 가상 노드)를 클릭하면 열기 시도 전에 한국어 경고 메시지를 표시합니다.
- 오류 메시지에 일반적인 "Failed to open file" 문자열 대신 구체적인 오류 원인(예: `ENOENT: no such file or directory`)이 포함됩니다.

---

### 🧹 코드 품질

#### `handleUngroup` 오염 코드 복구 (`CanvasPanel.ts`)
- 이전 자동화된 편집으로 인해 `handleUngroup` 함수 본문에 ~200줄의 불필요한 주석 텍스트가 삽입되어 제어 흐름이 손상되었습니다. `git stash`를 사용하여 함수를 정규 상태로 완전히 복원했습니다.
- 언그룹 후 `sendProjectState()` 호출도 함께 복원되었습니다.
