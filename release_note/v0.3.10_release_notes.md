# 🚀 v0.3.10 Release Notes - Hard Lock Protocol & Click Resilience

## 📅 Released: 2026-04-07

---

### [English] 🛡️ Key Changes

#### 1. Hard Lock Protocol (Reality-First Implementation)
- **Atomic File Creation & Verification:** Physical file creation via `fs.writeFile` is now immediately followed by `fs.stat` verification to ensure file existence before the UI is updated.
- **Partial Confirmation Loop:** Instead of a full-state rebroadcast, the system now sends partial updates (`updateNode`) to the webview. This preserves the local UI layout and prevents the 'Ghost Wipe' caused by stale project states.
- **Host Sync Pressure:** Executed `vscode.commands.executeCommand('saveAll')` upon file creation to force the VS Code Explorer to recognize new files immediately.

#### 2. Click Interaction & Path Resilience
- **Intelligent Path Fallback:** Implemented a multi-level fallback for the double-click handler (`data.path` -> `data.file` -> `file` -> `data.label`). This ensures that even newly created nodes (with system-generated IDs like `node_manual_...`) can open the associated file using their displayed filename (`test.py`).
- **Metadata Synchronization:** Enforced root-level (`node.file`) and nested (`node.data.file`) metadata alignment in the `updateNode` handler to guarantee click eligibility for manual nodes.

#### 3. Visual & System Stability
- **Edge Count Normalization:** Synchronized the UI info display with the actual rendered edges by filtering out orphaned connections (Matching 12 visible edges).
- **Boot-time Hardening:** Resolved the 403 Forbidden security error for `engine-core.js` and applied exhaustive null-safety guards throughout the rendering loop.

---

### [한국어] 🇰🇷 주요 변경 사항

#### 1. 하드 락 프로토콜 (현실 우선 구현)
- **원자적 파일 생성 및 검증:** `fs.writeFile` 호출 직후 `fs.stat` 검증을 수행하여, 파일이 물리적으로 존재함을 확신한 뒤에만 UI의 노드 상태를 'Solid'로 확정합니다.
- **부분 확정 루프:** 전체 상태를 재전송(Re-broadcast)하지 않고, 확정된 노드 정보만 부분 업데이트(`updateNode`)하여 웹뷰의 레이아웃을 보존하고 '유령 노드' 현상을 박멸했습니다.
- **호스트 동기화 압박:** 파일 생성 즉시 `saveAll` 명령을 실행하여 VS Code 탐색기 탭이 새로운 파일을 지체 없이 인지하도록 강제했습니다.

#### 2. 클릭 상호작용 및 경로 해석 복구
- **지능형 경로 폴백:** 더블클릭 핸들러에 다중 폴백 로직을 적용했습니다. 시스템 생성 ID(`node_manual_...`) 대신 사용자가 입력한 **라벨(`test.py`)**을 최후의 수단으로 활용하여, 생성 직후에도 파일을 즉시 열 수 있게 수복했습니다.
- **메타데이터 정밀 동기화:** `updateNode` 수신 시 노드의 최상위(`file`)와 하위(`data.file`) 경로 정보를 모두 각인하여, 신규 노드의 클릭 '자격'을 즉각 활성화했습니다.

#### 3. 시각 및 시스템 안정성
- **엣지 통계 정밀화:** 유효하지 않은 엣지를 카운트에서 제외하여, 화면에 보이는 12개의 엣지와 정보창의 수치를 1:1로 일치시켰습니다.
- **부팅 안정화 (Hardening):** `engine-core.js`의 403 Forbidden 보안 오류를 해결하고, 렌더링 루프 전체에 Null-Safety 가드를 설치하여 초기화 중 크래시를 방지했습니다.
