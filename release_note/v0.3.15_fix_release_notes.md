# 🚀 SYNAPSE v0.3.15 (Fix) Release Notes

## 🔧 Bug Fixes (버그 수정)

### [KR] 문서 노드(Documentation Shelf) 오분류 버그 수정
* **이슈**: `README.md` 내 링크 등으로 파싱된 파생 노드들(예: `synapse-visual-architecture-v0.2.20`, `synapse_tree_v0.2.16` 등)이 제대로 📚 Documentation Shelf에 분류되지 못하고 ☁️ External Ghosts(외부 유령) 클러스터로 잘못 분류되는 현상 발생.
* **원인**: 파이프라인의 Semantic Routing(의미 기반 분기) 로직 내에서, 파싱된 이름의 버전명(`v0.`)이 파일명 제일 앞(`startsWith`)에 위치했는지만을 검사했습니다. 이 때문에 버전명이 파일명 중간 단어에 나타나는 경우 문서 아티팩트로 식별되지 못한 채 일반 외부 모듈 기호(Symbol)로 취급되었습니다. 결국 디스크상에 파일이 존재하지 않는 것으로 판단한 StateManager에 의해 유령 처리되었습니다.
* **해결책**: `DataPipeline.ts`와 `StateManager.ts`의 판별 로직에서 `startsWith('v0.')`를 `includes('v0.')`로 포괄적으로 개선하여, 식별자 내 어디에든 버전명이 존재하는 문서 연관 파생 노드들이 정확히 📚 Documentation Shelf로 이동하도록 로직을 수정 완료했습니다.

### [EN] Fixed Misclassification of Documentation Entities
* **Issue**: Specific nodes parsed from `README.md` and related documents (e.g., `synapse-visual-architecture-v0.2.20`) were misrouted to the ☁️ External Ghosts cluster instead of being systematically placed onto the 📚 Documentation Shelf.
* **Cause**: The semantic routing pipeline narrowly checked if target strings explicitly started with version prefixes (`startsWith('v0.')`). Since typical artifact names encapsulate the version number in the middle or suffix, they were mistakenly filtered completely out of the documentation category, treated simply as generic symbols, and subsequently dumped as "ghosts" lacking physical system counterparts.
* **Resolution**: Replaced the strict `startsWith('v0.')` clause with the universally applicable `includes('v0.')` function within both `DataPipeline.ts` and `StateManager.ts`. Versioned architectural artifacts will rightfully be recognized and curated onto the 📚 Documentation Shelf.
