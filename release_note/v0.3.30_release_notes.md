# Synapse Visual Architecture - v0.3.30 Release Notes

[Status: Verified by Commander]

## 📝 Summary / 요약

This release transforms SYNAPSE from a standalone visualization tool into a **Submission-based Collaborative Harvest System**. A role-based permission system (Lead/Member) is introduced with a complete pipeline: Project Boundary → Identity & Session → Submission Snapshot → Remote Layer Projection → Architecture Index → Reference Verification → Harvest → Boundary Enforcement. All 9 phases verified with 106/106 tests passing.

이번 릴리즈는 SYNAPSE를 단독 시각화 도구에서 **Submission 기반 협업 Harvest 시스템**으로 전환합니다. 역할 기반 권한 체계(Lead/Member)와 완전한 파이프라인(프로젝트 경계 → ID/세션 → 제출 스냅샷 → 원격 레이어 투영 → 아키텍처 인덱스 → 참조 검증 → 수확 → 경계 강제)이 도입되었습니다. 9개 Phase 모두 106/106 테스트 통과로 검증 완료.

## 🚀 Changes / 상세 수정 내역

### Phase 1 — Project Boundary Foundation (`src/core/ProjectMetadata.ts`, `src/core/SymbolIndex.ts`)
- **ProjectMetadata** singleton: server-owned project boundary manager with `validatePath()` security enforcement
- **SymbolIndex** singleton: cross-file registry with FolderTree + FileRegistry + FunctionCatalog
- **SnapshotSystem** upgrade: versioning, SHA-256 checksum, metadata embedding
- **DataPipeline** security integration: path validation at file processing entry
- 10/10 validation tests passing

### Phase 2 — Identity & Session Foundation (`src/core/collaboration/IdentityManager.ts`, `SessionManager.ts`, `RuntimeInitializer.ts`)
- **IdentityManager**: Identity + Role + Permission 체계 (Lead: CreateSession/Verify/Harvest/RemoteEdit 등, Member: JoinSession/SubmitChanges 등)
- **SessionManager**: Full session lifecycle (Created → Open → Active → Closing → Closed) + Join/Leave/Security
- **RuntimeInitializer**: 4-step startup flow (ProjectMetadata → SymbolIndex → Identity → Session) → ready
- 14/14 validation tests passing

### Phase 3 — SSH Transport / Submission Boundary (`src/core/collaboration/SubmissionManager.ts`)
- **SubmissionSnapshot**: Collaboration-only artifact, immutable, with ReviewState (pending → review → approved/rejected)
- **Member Frozen**: Post-submission write authority revocation
- **Remote Edit**: Lead review correction with `RemoteEditAction` audit trail
- **Schema**: SubmissionFile, SubmissionSnapshot, ReviewState, RemoteEditAction types added
- 12/12 validation tests passing

### Phase 4 — Remote Layer Visualization (`src/core/collaboration/RemoteLayerProjector.ts`)
- **Stateless Projector**: SubmissionSnapshot → ProjectionResult with Layer classification (AI/User/External)
- Node/Cluster classification rules with visibility model (showBaseLayer/showUserLayer/showExternalLayer)
- Edges have no layer — visibility = Visible(From) AND Visible(To)
- 14/14 validation tests passing

### Phase 5 — Architecture Index Generation (`src/core/collaboration/ArchitectureIndexBuilder.ts`)
- **ArchitectureIndex**: ProjectTree + FolderTree + SourceFileRegistry + FunctionCatalog
- Source-only file registry (excludes .md .txt .log .report, external://, ghost://)
- Multi-language function extraction (Python, TS, JS, Rust, Go, Java, Kotlin, C, C++, Swift)
- Excludes layer info, user clusters, external ghosts, visualization metadata
- 14/14 validation tests passing

### Phase 6 — Reference Verification Layer (`src/core/collaboration/ReferenceVerifier.ts`)
- **ReferenceVerifier**: ArchitectureIndex → ReferenceGraph + VerificationReport + HarvestCandidateSet
- Multi-language reference discovery + resolution (direct/extension/module path match)
- Ghost Projection: external:// (known packages) / ghost:// (unresolved internal)
- 8 edge categories + Findings (EXTERNAL_DEPENDENCY, GHOST_PROJECTION, DISCONNECTED_COMPONENT)
- 14/14 validation tests passing

### Phase 7 — Harvest Engine (`src/core/collaboration/HarvestEngine.ts`)

- Files/folders copied exactly as approved — no rename, no normalization
- Original snapshot preserved to `.synapse/snapshots/{id}/`
- Skips external:// and ghost:// visualization artifacts
- 10/10 validation tests passing

### Phase 8 — Boundary Enforcement (`src/core/collaboration/BoundaryGuard.ts`)
- **BoundaryGuard** singleton: 8 boundary checks (Project/Session/Workspace/Submission/RemoteEdit/Harvest/Auth/CacheCleanup)
- Centralized security enforcement for all collaboration boundaries
- 8/8 validation tests passing (all denial + cleanup success)

### Phase 9 — Acceptance Test (`src/test/phase9_acceptance.test.ts`)
- End-to-End validation: Runtime → Session → Join → Submit → Remote Layer → Index → Verify → Remote Edit → Harvest → Session Close
- 10 scenarios, 106 total tests across all 9 suites
- **Collaborative Harvest MVP Complete** 🎉

## ⚠️ Notes / 참고 사항

- All collaboration systems are built on the **No Database principle** — SubmissionSnapshot is the only authoritative source.
- Layer = Visibility Classification Group (not a render surface). Layers are recomputed every load.
- The collaboration layer is fully isolated from the existing graph/flow/file views via Phase 8 Boundary Guard.
- 106 tests across 9 phases all validated with `jest` and `tsc --noEmit`.
- This is the **Collaborative Harvest MVP** — subsequent releases will build on this foundation.

## 🌟 Final Architecture Update (2026-06-22)

**1. Client Isolation Structure (User Root) / 다중 클라이언트 격리 보관**
- **[EN]** Replaced the single `.synapse/master` directory with a robust client-isolated structure. Gathered files are now strictly isolated into `.synapse/clients/{clientUsername}/harvest/` to maintain absolute ownership and prevent "Who created this?" ambiguity. Prepared future extensions by creating placeholder directories for `snapshots` and `cache`.
- **[KO]** 단일 `.synapse/master` 구조를 폐기하고, 누가 만든 파일인지 식별할 수 있도록 클라이언트별 완벽 격리 구조를 도입했습니다. 수확된 파일은 `.synapse/clients/{clientUsername}/harvest/` 경로로 안전하게 복사되며, 향후 확장을 대비해 `snapshots`, `cache` 등의 예약 폴더를 자동 생성합니다.

**2. Harvest vs Sync Philosophy / 수집과 통합의 분리**
- **[EN]** **Harvest (Data Collection)** is an explicit one-way pipeline: Client → Server. **Sync (Data Integration)**, which entails overwriting, conflict resolution, and rollback management, introduces enormous complexity and has been officially deferred to v0.4+.
- **[KO]** **Harvest(데이터 수집)**를 Client → Server 단방향 수집 프로세스로 정의했습니다. 덮어쓰기 정책 및 충돌 관리를 수반하는 **Sync(데이터 통합)** 과정은 복잡성을 덜어내기 위해 v0.4+ 백로그(연구 항목)로 공식 이관했습니다.

**3. Virtual Debugger Boundary / 가상 디버깅 책임 한정 (Host Only)**
- **[EN]** The Virtual Debugger relies on the local file system and VS Code Diagnostics. Analyzing outdated harvested files would lead to false positives compared to the client's live working copy. Thus, virtual debugging is strictly restricted to the **Host (Architect) Workspace**. Remote debugging capabilities will be introduced in v0.4+ via a "Diagnostics Push" model.
- **[KO]** 현재 Virtual Debugger는 로컬 파일 시스템과 VS Code Diagnostics에 의존하므로, 그 책임을 오직 **Host(Architect) Workspace**로 한정했습니다. 수확된 옛날 사본을 디버깅하여 발생하는 신뢰성 붕괴(False Positive)를 방지하며, 클라이언트 디버깅은 v0.4+에서 'Diagnostics Push' 방식으로 이관됩니다.

**4. UX & Report Enhancements / 사용자 경험 및 리포트 강화**
- **[EN]** **Checkbox UI:** Added a dynamic checkbox UI in the Canvas for per-file approval or rejection during the harvest process.
- **[EN]** **Auto-Reporting:** Immediately after harvest, timestamped `.json` and `.md` reports are generated in `.synapse/reports/` including a list of `harvestedClients` and explicit failure reasons.
- **[EN]** **OS Explorer Integration:** A pop-up allows the Architect to instantly open the most neutral root folder (`.synapse/clients/`) via `vscode.env.openExternal`.
- **[KO]** **파일 단위 승인:** 캔버스 UI 내에 동적 체크박스를 추가하여 아키텍트가 개별 파일 단위로 수확 승인/거절을 선택할 수 있도록 개선했습니다.
- **[KO]** **리포트 자동 생성:** 수확 완료 직후 `.synapse/reports/` 폴더에 타임스탬프 기반 `.json`, `.md` 리포트를 자동 덤프하며, 참여한 클라이언트 목록과 실패 사유(Path Traversal 등)를 기록합니다.
- **[KO]** **OS 탐색기 연동:** 수확 완료 직후 정보 알림의 [폴더 열기] 버튼을 클릭하면, 가장 중립적인 최상위 폴더(`.synapse/clients/`)가 OS 기본 탐색기(노틸러스 등)를 통해 즉시 열립니다.

**5. Ghost Data Cleanup on Disconnect / 네트워크 단절 시 잔여 데이터(Ghost) 완벽 제거**
- **[EN]** Resolved an issue where temporary live edits (clientPushData) from disconnected clients remained on the master canvas. The SSoT for active states was shifted from persistent login sessions to real-time SSE connections (`sseClients.keys()`). Additionally, `stateVersion` is immediately incremented upon connection drop, triggering an instant refresh across all clients to ensure no residual ghost nodes remain.
- **[KO]** 네트워크가 끊어지거나 브라우저를 닫은 클라이언트의 실시간 편집 데이터(clientPushData)가 캔버스에 유령(Ghost)처럼 남는 현상을 해결했습니다. `/api/state`의 활성 유저 판별 기준을 세션(Session)에서 실시간 소켓 연결(`sseClients`)로 교체하였고, 연결 종료 시 즉각적으로 전체 클라이언트의 강제 새로고침(`stateVersion++`)을 유도하여 찌꺼기가 즉시 증발하도록 개선했습니다.

**6. Harvest Documentation / Harvest 모델 문서화**
- **[EN]** Added comprehensive documentation to `README.md` and `README.ko.md` clarifying the Uni-directional Harvest Model vs Bi-directional Sync, explaining Client Isolation and Harvest Lock.
- **[KO]** 양방향 동기화(Sync)와의 차별점, 단방향 수집 모델(Harvest), Client Isolation 및 Harvest Lock의 개념을 설명하는 문서를 `README.md` 및 `README.ko.md`에 공식 추가했습니다.
