# SYNAPSE v0.3.31 Release Notes

## 🚀 주요 변경 사항 (Key Updates)

### 1. 전역 블랙리스트 강제화 – Ghost Node 버그 수정
### 1. Global Blacklist Enforcement – Ghost Node Bug Fix

- **[KO]** 타 클라이언트 소스를 수집한 하베스트 데이터(`.synapse/clients/...`)가 로컬 프로젝트 렌더링에 무차별적으로 편입되는 심각한 오염 발생. 네트워크 연결이 끊긴 오프라인 상태에서도 폴백 캐시(`project_state.json`)를 통해 유령 노드들이 부활하는 문제 확인.  
  **해결:** `src/core/RuleEngine.ts`의 `ignoreFolders`에 `.synapse`를 명시적으로 등록하여 데이터 파이프라인 원천 차단.
- **[EN]** Harvest data (`.synapse/clients/...`) collected from other clients was indiscriminately merged into local project rendering, causing serious graph contamination. Ghost nodes were also resurrecting via fallback cache (`project_state.json`) when offline.  
  **Fix:** Explicitly registered `.synapse` in `ignoreFolders` of `src/core/RuleEngine.ts` to block at the data pipeline level.

---

### 2. 아키텍처 정렬 물리 엔진 안정화 – Role-based Alignment
### 2. Role-Based Alignment Physics Stabilization

- **[KO]** 캔버스에서 `Align Architecture` 실행 시 노드가 우주로 튕겨나가거나 겹치는 충돌 발생.  
  **해결:** 클러스터 기준점 산출을 시뮬레이션 진입 전 1회 고정, 동적 공간 할당 및 O(1) 프레임 연산으로 교체.
- **[EN]** Clicking `Align Architecture` caused nodes to explode outward or collapse into each other.  
  **Fix:** Target coordinates are now computed once before simulation entry. Dynamic column spacing replaces hardcoded offsets. Frame loop reduced to O(1) by moving sort/grouping logic out of the render path.

---

### 3. 스키마 검증 허용 타입 확장 – False Positive Necrosis 방지
### 3. Schema Validation Whitelist Expansion – False Positive Necrosis Prevention

- **[KO]** 클라이언트가 업로드한 `doc`, `file`, `folder` 타입 노드들이 LLM 환각(Hallucination)으로 오분류되어 Necrosis 노드로 잘못 시각화되는 문제 수정. 동일 타입을 로직 디버깅 대상(`nonLogicTypes`)에서도 제외.
- **[EN]** Nodes of type `doc`, `file`, `folder` uploaded by clients were misclassified as LLM hallucinations and rendered as Necrosis nodes. Fixed by adding these types to the schema whitelist and excluding them from logic analysis (`nonLogicTypes`).

---

### 4. Ghost Cluster 의존성 폭주 방지
### 4. Ghost Cluster Dependency Flood Prevention

- **[KO]** `folder_x → cluster_ghosts` 패턴이 수십 개 발생하여 Strong Dependency 힌트를 폭주시키던 문제 수정. `cluster_ghosts`, `doc_shelf`를 의존성 검사 대상에서 제외.
- **[EN]** Dozens of `folder_x → cluster_ghosts` patterns were flooding the architectural hints with false Strong Dependency warnings. Fixed by skipping `cluster_ghosts` and `doc_shelf` as dependency targets.

---

### 5. Pressure 계산식 정규화
### 5. Pressure Calculation Normalization

- **[KO]** 기존 절대값 기반(`criticalIssues * 15`) 계산식은 노드 수 증가 시 무조건 100%로 도달. 노드 수 비례 정규화(`criticalIssues / totalNodes`)로 교체하여 프로젝트 규모와 무관하게 일관된 척도 제공.
- **[EN]** The old absolute formula (`criticalIssues * 15`) always hit 100% as project size grew. Replaced with a normalized ratio (`criticalIssues / totalNodes`) for scale-invariant pressure measurement.
- 🟢 0–10% Stable | 🟡 10–30% Caution | 🟠 30–60% Warning | 🔥 60%+ Critical

---

### 6. clientTimestamp + 다중 클라이언트 메타 전파
### 6. clientTimestamp & Multi-Client Metadata Propagation

- **[KO]** 원격 클라이언트 노드에 `clientTimestamp`, `clientUsername`, `sessionId`를 주입. 향후 멀티클라이언트 구성에서 툴팁에 `"Bob – Updated 7m ago"` 형태로 즉시 표시 가능.
- **[EN]** Remote client nodes now carry `clientTimestamp`, `clientUsername`, and `sessionId`. In multi-client setups (Alice/Bob/Charlie), the node tooltip will immediately show `"Bob – Updated 7m ago"`.

---

### 7. Stale Diagnostics 시각화 (Opacity 기반)
### 7. Stale Diagnostics Visualization (Opacity-Based)

- **[KO]** 클라이언트 노드의 마지막 업데이트 시간을 기준으로 투명도를 자동 적용.  
  `0–5분 Active (1.0)` / `5–15분 Stale (0.7)` / `15분+ Offline Candidate (0.4)`  
  툴팁에 `👤 [username] Updated Xm ago` 표시.
- **[EN]** Opacity is automatically applied to remote client nodes based on elapsed time since last update.  
  `0–5m Active (1.0)` / `5–15m Stale (0.7)` / `15m+ Offline Candidate (0.4)`  
  Tooltip shows `👤 [username] Updated Xm ago`.

---

### 8. Soft Disconnect – 15분 캐시 보존
### 8. Soft Disconnect – 15-Minute Cache Retention

- **[KO]** SSE 연결 해제 시 즉시 삭제하지 않고 15분간 캐시 보존 후 Hard Purge. 클라이언트 크래시 발생 시 Architect가 "방금 죽은 이유"를 디버깅할 단서 보존. 재접속 시 기존 타이머 취소 및 캐시 자동 복원.
- **[EN]** On SSE disconnect, client data (`clientPushData`, `clientDiagnostics`) is retained for 15 minutes instead of being immediately deleted. This preserves debugging evidence (Necrosis nodes, diagnostics) for the Architect after a client crash. Reconnection cancels the pending purge timer.
