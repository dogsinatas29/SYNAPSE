# Release Notes — SYNAPSE v0.3.32.3
# Viewport Culling & LOD Optimization

---

## Summary (English)

v0.3.32.3 introduces O(1) viewport culling and Level-of-Detail (LOD) rendering across all major canvas draw paths in the SYNAPSE engine. The primary goal was to eliminate unnecessary Canvas API calls for off-screen elements under large-scale graph loads.

---

## Changes

### `ui/canvas-engine.js`

- **`renderEdges2D()`**: Viewport Culling applied. Edges whose AABB falls entirely outside the viewport are skipped before any Canvas API call. Fallback LOD added: when zoom ≤ 0.35 and physical edge count exceeds 2,000 with no bundle edges, edge rendering is skipped entirely.
- **`renderNodes2D()`**: Viewport Culling applied. Uses `canvas.width / dpr` for accurate viewport size calculation (fixed `clientWidth` bug).
- **`renderClusters()`**: Cluster Bounding Box-based Culling applied.
- **`renderGhostNodes()`**: Ghost Node Viewport Culling applied.
- **`renderNode()` LOD — Satellite View**: When zoom < 0.2, nodes are rendered as colored arc dots instead of grey 120×60 rectangles.

### `src/core/benchmark/BenchmarkHarness.ts`

- Benchmark pass count reduced: **5 → 2**.
- Reason: For regression detection purposes, 2 passes provide sufficient statistical confidence. 5 passes increased webview memory pressure by 2.5×, causing unnecessary OOM (webview restart) risk.
- Maximum benchmark config capped at 5,000 nodes (removed 10K / 15K / 20K configs).

### Long Duration Profiling (138 seconds)

| Metric | Value |
|---|---|
| Main Thread Active Time | **4.37 seconds** |
| CPU Utilization | **3.2%** |
| Scripting | 818 ms |
| Rendering | 822 ms |
| Painting | 203 ms |

> The renderer spent 96.8% of its lifetime idle during 138 seconds of continuous benchmark execution and user interaction.

### Grey Screen Root Cause

Not a rendering bug or memory leak. Pattern: `4 configs × 5 passes = 20` consecutive large graph IPC payloads → GC pressure → IPC queue backlog → Webview restart. Resolved by reducing pass count and capping max config size.

## 요약 (한국어)

v0.3.32.3은 SYNAPSE 캔버스 엔진의 주요 렌더링 경로 전체에 O(1) 뷰포트 컬링과 LOD(Level of Detail) 렌더링을 도입합니다. 핵심 목표는 대규모 그래프 환경에서 화면 밖 요소에 대한 불필요한 Canvas API 호출을 원천 차단하는 것입니다.

### 변경 사항

- **`renderEdges2D()`**: 뷰포트 컬링 적용. 엣지의 AABB가 화면 밖이면 즉시 스킵. Fallback LOD 추가(zoom ≤ 0.35 + 개별 엣지 2,000개 초과 시 렌더링 생략).
- **`renderNodes2D()`**: 뷰포트 컬링 적용. `canvas.width/dpr` 기반 정확한 화면 크기 산출(`clientWidth` 버그 수정).
- **`renderClusters()`**: 클러스터 Bounding Box 기반 컬링 적용.
- **`renderGhostNodes()`**: Ghost Node 뷰포트 컬링 적용.
- **LOD 위성 뷰 개선**: zoom < 0.2 진입 시 노드를 회색 사각형 대신 색상 원형 도트로 렌더링.
- **벤치마크 하네스 조정**: pass 수 5 → 2. 이유: 회귀 탐지 목적에는 2 pass면 충분하며, 5 pass는 웹뷰 메모리 압력을 2.5배 증가시켜 OOM 위험을 초래.

### 성능 검증 결과 (138초 DevTools 프로파일링)

| 항목 | 값 |
|---|---|
| Main Thread 점유 시간 | **4.37초** |
| CPU 사용률 | **3.2%** |
| Scripting | 818ms |
| Rendering | 822ms |
| Painting | 203ms |

**핵심:** 138초 동안 CPU를 3.2%밖에 사용하지 않았다. 현재 병목은 SYNAPSE 렌더링 알고리즘이 아니라 벤치마크의 반복적 대용량 IPC 전송(GC 압박)이다.

### 회색 화면 원인

렌더링 버그·메모리 누수가 아닌, `4 configs × 5 passes = 20회` 연속 대용량 IPC 전송 → GC 압박 → 웹뷰 재시작 패턴. pass 수 감소 및 최대 설정 크기 제한으로 해소.
