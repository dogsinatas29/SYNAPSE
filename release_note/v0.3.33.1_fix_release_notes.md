# Release Notes - v0.3.33.1_fix

## 🌟 Highlights (주요 변경 사항)

### 🚀 Edge Rendering Pipeline Optimization (엣지 렌더링 파이프라인 최적화)
- **[EN]** Removed the hard limit of 50,000 edges that was prematurely aborting the rendering pipeline. The renderer now intelligently culls edges using Spatial Hashing, enabling full architecture exploration even for massive monorepos like VSCode-main (66,000+ edges) without silent rendering failures.
- **[KR]** 렌더링 파이프라인 최상단에서 동작을 강제 중단시키던 50,000개 엣지 방어 로직(Hard Limit)을 제거했습니다. 이제 공간 해싱(Spatial Hashing) 기반의 뷰포트 컬링을 통해 화면에 보이는 엣지만 스마트하게 그려내며, VSCode-main과 같이 엣지가 66,000개 이상인 거대 모노레포에서도 엣지가 증발하는 현상 없이 완벽한 렌더링을 지원합니다.

### 🔍 Edge Visibility Modes & Diagnostics (엣지 렌더링 모드 및 진단 도구 추가)
- **[EN]** Restored the `LINES (No Badges)` mode in the UI, allowing users to view physical edges without the clutter of edge labels.
- **[KR]** UI 메뉴에 엣지 라벨(뱃지) 없이 선만 깔끔하게 보여주는 `LINES (No Badges)` 가시성 모드를 성공적으로 부활시켰습니다.
- **[EN]** Injected critical telemetry probes (`[EDGE_STATS]`, `[BUNDLE_STATS]`, `[EDGE_MODE]`, `[ARC_DRAW]`) deep inside the rendering pipeline to strictly monitor culling efficiency, LOD behavior, line thickness, and dynamic transparency.
- **[KR]** 파이프라인 심층부에 4대 핵심 계측 프로브(`[EDGE_STATS]`, `[BUNDLE_STATS]`, `[EDGE_MODE]`, `[ARC_DRAW]`)를 주입하여 컬링 효율성, LOD 동작, 두께 산정 및 투명도 렌더링을 실시간으로 추적할 수 있도록 개선했습니다.

## 🛠️ Technical Details (기술적 세부 사항)
- **Edge Budget Protection Removed:** The pipeline no longer instantly skips processing for graphs with > 50,000 edges. It now relies completely on dynamic viewport bounds checking.
- **UI State Synchronization:** Re-wired the edge visibility HTML buttons (`btn-edge-vis-nobadge`) to synchronize perfectly with the WebGL & Canvas2D rendering core.
