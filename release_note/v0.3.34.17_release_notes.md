# 🚀 Release Notes: v0.3.34.17

**Date:** 2026-08-09
**Milestone:** v0.3.34.17 - ASR 3.0 (Architecture Scan Report) Stabilization & Data Reliability

## 🇰🇷 한국어 (Korean)

이번 릴리즈는 SYNAPSE의 리포트 시스템이 주관적인 "AI 진단(Diagnosis)"의 늪에서 벗어나, 철저한 팩트 기반의 **"아키텍처 스캔 리포트(ASR 3.0)"**로 거듭나는 중요한 전환점입니다. 우리는 "진단보다 스캔이 먼저다(Scan > Diagnosis)"라는 철학을 확립하고, 리포트의 레이아웃과 데이터 신뢰도를 근본적으로 교정했습니다.

### ✨ 주요 변경 사항 (Key Changes)

#### 1. ASR 3.0 레이아웃 전면 리팩토링 (6-Stage MRI Structure)
아키텍트의 논리적 독해 흐름에 맞춰 리포트 레이아웃을 전면 개편했습니다.
- `상태 판정(Executive Summary)` → `수술 대상 지목(Impact Files)` → `원시 증거(Evidence Layer)` → `수술 기대 효과` → `세부 통계(Raw Metrics)` 순서로 재배치 완수.
- 주관적인 추론(ROI 예측, 프롬프트 자동 생성 등)을 배제하고 사실(Fact)만 렌더링.

#### 2. 데이터 품질 및 신뢰성 확보 (Data Reliability)
단순한 텍스트 렌더링 수정을 넘어 엔진 자체의 집계 로직을 수정했습니다.
- **Impact Files 전체 엣지 집계**: Top 50으로 슬라이싱된 증거만 합산하던 치명적 오류를 수정. 전체 `intentEdges`를 순회하며 `externalEdges`를 합산한 후 Top 10을 추출하도록 변경. (이제 `42`와 같은 묵직한 정상 숫자가 출력됩니다.)
- **고스트 증거 복원 (Ghost Evidence Restoration)**: 타겟 문자열에 의존하던 하드코딩 필터(`.includes('ghost')`)를 전부 삭제하고, 깔끔하게 `e.isGhost === true` 메타데이터 플래그만 신뢰하도록 아키텍처 개선.

#### 3. 기술 부채 및 버그 수정 (Tech Debt & Bug Fixes)
- **VSCode 링크 상대 경로 버그 픽스**: `vscode://file/...` 스키마가 절대 경로를 요구함에도 상대 경로를 맵핑하여 OS에서 파일을 열지 못하던 문제 해결. (표시되는 텍스트는 PII 제거, 숨겨진 URL은 절대 경로로 분리)
- **상수 승격 (Magic Number 제거)**: `slice(0, 10)` → `TOP_IMPACT_LIMIT`, `slice(0, 50)` → `EVIDENCE_LIMIT`로 교체하여 스캐너 규모 확장에 대비.
- **가중치 방어 로직**: `VirtualDebugger.ts`에서 `e.weight || 1`을 `e.weight ?? 1`로 교체하여 `weight=0` 유실 방지.

## 🇺🇸 English

This release marks a critical turning point for SYNAPSE’s reporting system, moving away from the pitfalls of subjective "AI Diagnosis" and establishing a strictly fact-based **"Architecture Scan Report (ASR 3.0)"**. By adopting the philosophy of "Scan > Diagnosis," we have fundamentally overhauled both the layout and data reliability of our reports.

### ✨ Key Changes

#### 1. ASR 3.0 Layout Refactoring (6-Stage MRI Structure)
Completely redesigned the report layout to match a real architect's logical reading flow.
- Reordered into: `Executive Summary` → `Impact Files` (Surgery Targets) → `Evidence Layer` (Raw Proof) → `Expected After Surgery` → `Raw Metrics`.
- Removed subjective interpretations (e.g., ROI predictions, automated AI prompts) to strictly render undeniable facts.

#### 2. Data Quality & Reliability
Patched the core engine's aggregation logic to ensure absolute trust in the numbers.
- **Full-Edge Aggregation for Impact Files**: Fixed a critical flaw where Impact Files were calculated from a truncated list of the top 50 boundary evidence edges. It now correctly traverses ALL `intentEdges` to sum up absolute `externalEdges` before extracting the top 10 God Classes.
- **Ghost Evidence Restoration**: Removed hardcoded string matching filters (`.includes('ghost')`) and upgraded the architecture to strictly trust the `e.isGhost === true` metadata flag.

#### 3. Tech Debt & Bug Fixes
- **VSCode Link Path Bug**: Fixed an issue where the `vscode://file/...` URI schema was incorrectly mapped to relative paths, failing to open files in the OS. Hidden URLs now use absolute paths while the displayed text remains clean and PII-free.
- **Magic Number Promotion**: Replaced hardcoded array slicing limits (`slice(0, 10)`) with constants (`TOP_IMPACT_LIMIT`, `EVIDENCE_LIMIT`) to prepare for massive-scale projects.
- **Defensive Weight Logic**: Replaced `e.weight || 1` with `e.weight ?? 1` in `VirtualDebugger.ts` to prevent the loss of valid `weight=0` values.
