# v0.3.34.23 Release Notes — Architecture IR Builder: Semantic Edge Extraction Layer

---

## 🇺🇸 English

### Overview
v0.3.34.23 establishes the **Architecture IR Builder** pipeline — a multi-stage evidence collection and promotion system that transforms raw AST `include` edges into semantically meaningful architectural relationships. This version focuses on the **Q4 Extension Point Engine**: discovering, evaluating, and reporting the structural extension axes of a codebase.

---

### What's New

#### ✅ Semantic Candidate → Evidence → Promotion Pipeline
- **`ExtensionPointCandidateGenerator`**: Scans `IMPLEMENTS` / `EXTENDS` edges and promotes types with ≥2 implementors as extension point candidates.
- **`ExtensionPointEvidenceEvaluator`**: Collects structural evidence (implementor count, cross-cluster density) for each candidate.
- **`PromotionEngine`**: Applies confidence thresholds to promote or reject candidates. Rejection logs include specific reasons (`INSUFFICIENT_STRUCTURAL_EVIDENCE`, etc.).
- **Q4 Report Rendering**: Q4 Extension Points section now renders promoted results from `answer.items` (field name mismatch `answer.findings` fixed).

#### ✅ Java / Kotlin Inheritance Parser Overhaul
- Rewrote `JavaScanner` regex to handle multi-line and mixed `extends`/`implements` declarations (e.g., `class Foo extends Bar implements Callback`).
- Improved `KotlinScanner` to support constructor override and multiple parent types after `:`.
- Result: `EXTENDS: 174`, `IMPLEMENTS: 98` confirmed on AntennaPod.

#### ✅ ScannerRegistry Class Mangling Fix (Critical)
- Webpack production build minifies all class names to single characters, causing duplicate detection `("" === "")` to reject all scanners after the first.
- Fixed: Changed dedup logic from `s.constructor.name === scanner.constructor.name` to `s.constructor === scanner.constructor` (reference equality, mangling-immune).

#### ✅ Legacy Parser Fallback Elimination
- Added explicit constructor to `FileScanner` that auto-registers all scanners (`JsTsScanner`, `JavaScanner`, `KotlinScanner`, etc.) on instantiation.
- Prevents fallback to legacy `parseJava()` function which only extracted `import` statements, missing inheritance structure entirely.

#### ✅ Framework Noise Filtering
- Added `isFrameworkType()` to `ExtensionPointCandidateGenerator`.
- Filters out Android/Java SDK types by package prefix (`android.`, `androidx.`, `java.`, `kotlin.`, etc.) and class name (`Fragment`, `AppCompatActivity`, `RecyclerView.*`, `Serializable`, etc.).
- Also excludes `AGGREGATE_*` nodes from candidate pool.

#### ✅ AntennaPod Real-Project Validation
- Confirmed end-to-end pipeline on AntennaPod (Android, ~2,400 nodes):
  - Q4 Extension Points: `PodcastSearcher`, `Playable`, `SwipeAction`, `FeedItem` promoted
  - `Role: UNKNOWN` reduced to near-zero
  - `AGGREGATE_unknown` traced to View Scope mismatch (not classification failure)

#### ✅ UNKNOWN State Triage (Design Discovery → v0.3.34.24)
- `[AGGREGATE_NO_CLUSTER]` log confirmed: `nodeFound: false` = node exists in GraphModel but absent from `rawStateNodes` (current view scope).
- Identified 3 distinct UNKNOWN sources:
  - `OUT_OF_SCOPE` — node outside current view (valid state, not a bug)
  - `UNCLUSTERED` — node registered but cluster_id missing (soft bug)
  - `UNCLASSIFIED` — node clustered but role classification failed (soft bug)
- `VirtualDebugger.ts`: `AGGREGATE_unknown` → `AGGREGATE_out_of_scope` split applied.
- `ArchitectureAuditor.ts`: Added `intents`, `commands`, `handlers` to COORDINATOR heuristic keywords (fixes `agentIntent.ts` classification).

## 🇰🇷 한국어

### 개요
v0.3.34.23은 **Architecture IR Builder** 파이프라인을 확립합니다. 이 시스템은 AST의 원시 `include` 엣지를 다단계 증거 수집 및 승격 과정을 거쳐 의미론적 아키텍처 관계로 변환합니다. 이번 버전은 **Q4 Extension Point Engine** — 코드베이스의 구조적 확장 축을 발견, 평가, 보고하는 엔진에 집중합니다.

---

### 주요 변경 사항

#### ✅ Semantic Candidate → Evidence → Promotion 파이프라인
- **`ExtensionPointCandidateGenerator`**: `IMPLEMENTS` / `EXTENDS` 엣지를 스캔하여 구현체가 2개 이상인 타입을 확장 포인트 후보로 승격.
- **`ExtensionPointEvidenceEvaluator`**: 각 후보에 대해 구조적 증거(구현체 수, 클러스터 횡단 밀도) 수집.
- **`PromotionEngine`**: 신뢰도 임계값을 적용하여 후보 승격 또는 기각. 기각 시 사유 로그(`INSUFFICIENT_STRUCTURAL_EVIDENCE` 등) 포함.
- **Q4 보고서 렌더링**: `answer.findings` → `answer.items` 필드명 불일치 수정으로 Q4 Extension Points 섹션 정상 출력.

#### ✅ Java / Kotlin 상속 파서 전면 개선
- `JavaScanner` 정규식을 다중 라인 및 `extends`/`implements` 혼합 선언 처리 가능하도록 재작성.
- `KotlinScanner`가 `:` 이후 생성자 오버라이드 및 다중 부모 타입을 인식하도록 개선.
- 결과: AntennaPod 기준 `EXTENDS: 174`, `IMPLEMENTS: 98` 확인.

#### ✅ ScannerRegistry 클래스 맹글링 버그 수정 (Critical)
- Webpack 프로덕션 빌드 시 클래스 이름이 단일 문자로 압축되어 `"" === ""` 중복 판정으로 첫 번째 이후 모든 스캐너가 등록 거부되는 문제.
- 수정: 중복 검사를 `s.constructor.name === scanner.constructor.name` (문자열 비교)에서 `s.constructor === scanner.constructor` (참조 동등성, 맹글링 면역)으로 교체.

#### ✅ 레거시 파서 폴백 차단
- `FileScanner` 생성자에서 모든 스캐너 자동 등록 로직 추가.
- `import`문만 추출하고 상속 구조를 인식하지 못하는 레거시 `parseJava()` 폴백을 영구 차단.

#### ✅ 프레임워크 노이즈 필터링
- `ExtensionPointCandidateGenerator`에 `isFrameworkType()` 추가.
- Package prefix(`android.`, `androidx.`, `java.`, `kotlin.` 등) 및 클래스명(`Fragment`, `AppCompatActivity`, `RecyclerView.*`, `Serializable` 등)으로 Android/Java SDK 타입 필터링.
- `AGGREGATE_*` 노드도 후보 풀에서 제외.

#### ✅ AntennaPod 실프로젝트 검증
- AntennaPod(Android, ~2,400 노드) 기준 End-to-End 파이프라인 검증:
  - Q4 Extension Points: `PodcastSearcher`, `Playable`, `SwipeAction`, `FeedItem` 승격 확인
  - `Role: UNKNOWN` 거의 제거
  - `AGGREGATE_unknown` → View Scope 이탈(분류 실패 아님)로 원인 확정

#### ✅ UNKNOWN 상태 분류 체계 수립 (설계 발견 → v0.3.34.24)
- `[AGGREGATE_NO_CLUSTER]` 로그 분석: `nodeFound: false` = 노드가 GraphModel에 존재하지만 현재 뷰(`rawStateNodes`)에 없는 정상 상태.
- UNKNOWN의 3가지 실제 원인 식별:
  - `OUT_OF_SCOPE` — 현재 뷰 범위 이탈 (정상 상태, 버그 아님)
  - `UNCLUSTERED` — cluster_id 미배정 (소프트 버그)
  - `UNCLASSIFIED` — role 분류 실패 (소프트 버그)
- `VirtualDebugger.ts`: `AGGREGATE_unknown` → `AGGREGATE_out_of_scope` 분리 적용.
- `ArchitectureAuditor.ts`: COORDINATOR 키워드에 `intents`, `commands`, `handlers` 추가 (`agentIntent.ts` 분류 수정).
