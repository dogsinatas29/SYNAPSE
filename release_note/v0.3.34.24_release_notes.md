# v0.3.34.24 Release Notes — Architecture State Model: Graph → State Graph

---

## 🇺🇸 English

### Overview

v0.3.34.24 redefines the fundamental treatment of `UNKNOWN` in SYNAPSE.

Previously, `UNKNOWN` was treated as a classification failure — a bug to be eliminated.
This milestone reframes it as a **State Machine Completeness problem**:

> **UNKNOWN is not a classification failure.**
> **UNKNOWN means a node's state or state transition has not been explicitly recorded.**

This milestone is the **first implementation milestone of SYNAPSE's Architecture State Model** —
the foundation for transitioning from a static graph analyzer to a state-based architecture simulator.

---

### Core Philosophy

```
Static Graph Analyzer    →    State-Based Architecture Model
UNKNOWN = bug            →    UNKNOWN = Transition Missing
```

SYNAPSE does not attempt to restore past design intent (Why).
It models: **What state is the system in now? What changes when something is removed?**

---

### What's New

#### ✅ Step 1 — Architecture State Model (`src/types/schema.ts`)

FSM-based state model. Additive only — no existing interfaces broken.

| Type | Purpose |
|---|---|
| `LifecycleState` | Node lifecycle stage (DISCOVERED→CLASSIFIED), one-way |
| `HealthState` | Classification failure verdict (HEALTHY / UNCLUSTERED / UNCLASSIFIED / CORRUPTED) |
| `ViewState` | View-scope state — **not** node state (VISIBLE / COLLAPSED / FILTERED / OUT_OF_SCOPE) |
| `ReferenceState` | Edge/reference state — **not** node state (RESOLVED / GHOST) |
| `FSMCompleteness` | Transition completeness (KNOWN / INCOMPLETE_TRANSITION / INVALID_TRANSITION) |
| `NodeState` | `{lifecycle, health, view}` aggregate — three axes as one object |
| `TransitionValidation` | `{completeness, reason?}` — separated from state (validation ≠ state) |
| `NodeEvent` | Domain events (NODE_DISCOVERED, REFERENCE_BROKEN…) — not function names |
| `StateTransitionRecord` | Transition log (foundation for v0.3.34.25+ simulation) |
| `AnomalySummary` | Aggregated counts across all state axes |
| `UNCHARTED_CONTINENT` | `'UNCHARTED' as const` — replaces all `'unknown'` continent hardcoding |

**Key design decision**: `FSMCompleteness` removed from `NodeState`.
State and validation result are different concerns.

#### ✅ Step 2 — AnomalyCollector (`src/core/AnomalyCollector.ts`)

Pure state classifier. No architecture pattern inference. No Why reasoning.

```typescript
class AnomalyCollector {
    classifyNode(node): NodeState
    classifyReference(edge): ReferenceState
    validateTransition(nodeState): TransitionValidation
    summarize(): AnomalySummary
    classifyAll(nodes, edges): void
}
```

Classification rules (data-driven, no hardcoding):
- `!cluster_id` → `HealthState.UNCLUSTERED`
- `!role` → `HealthState.UNCLASSIFIED` **(Soft Anomaly — not a FSM violation)**
- `!rawStateIds.has(node.id)` → `ViewState.OUT_OF_SCOPE`
- `!nodeIndex.has(edge.to)` → `ReferenceState.GHOST`

**UNCLASSIFIED = Soft Anomaly**: Per *"UNKNOWN Role = allowed"* principle,
missing role does not trigger FSM violation. FSM Completeness can PASS even when
role ontology is incomplete.

#### ✅ Step 3 — ValidationEngine Integration

`AnomalyCollector` injected at the end of `ValidationEngine.analyzeState()`.
Wrapped in try/catch — non-breaking.

```typescript
// ValidationContext addition:
anomalySummary?: AnomalySummary;
```

#### ✅ Step 4 — Section 8: Architecture State Report (`ValidationReportBuilder.ts`)

New section in every Architecture Scan Report.
FSM Completeness and Health/View/Reference anomalies rendered separately:

```markdown
## 8. Architecture State Report

### FSM Completeness
| Metric | Count |
| Missing Transitions | 0 |
| Invalid Transitions | 0 |
| State Completeness  | ✅ PASS |

### HealthState
| UNCLUSTERED  | N | Soft Bug |
| UNCLASSIFIED | N | Soft Anomaly (Role ontology gap) |
| CORRUPTED    | N | Hard Bug |

### ViewState
| OUT_OF_SCOPE | N |

### ReferenceState
| GHOST | N |
```

#### ✅ Step 5 — Hardcoding Elimination

All `'unknown'` string literal fallbacks replaced with typed references:

| File | Before | After |
|---|---|---|
| `GraphAnalyzer.ts` | `\|\| 'unknown'` (continent) | `\|\| UNCHARTED_CONTINENT` |
| `VirtualDebugger.ts` | `? 'unknown' : 'out_of_scope'` | `? HealthState.UNCLUSTERED : ViewState.OUT_OF_SCOPE` |
| `VirtualDebugger.ts` | `\|\| 'unknown'` (continent) | `\|\| UNCHARTED_CONTINENT` |

Result: `AGGREGATE_unknown` can no longer be generated at runtime.
`AGGREGATE_UNCLUSTERED` or `AGGREGATE_OUT_OF_SCOPE` appear instead.

### Known Observation: UNCLUSTERED/UNCLASSIFIED = 0

`project_state.json` is a **completed snapshot** — classification has finished before export.
At snapshot time all nodes already have `cluster_id` and `role`.

`UNCLUSTERED/UNCLASSIFIED = 0` is **correct behavior, not a bug**.

Runtime anomaly detection during active graph construction will be addressed in v0.3.34.25+
when `StateTransitionRecord` collection is implemented.

## 🇰🇷 한국어

### 개요

v0.3.34.24는 SYNAPSE에서 `UNKNOWN`을 다루는 근본적인 관점을 재정의합니다.

기존: `UNKNOWN` = 분류 실패 (제거해야 할 버그)
신규: `UNKNOWN` = 상태 머신 완전성(State Machine Completeness) 문제

> **UNKNOWN은 분류 실패가 아니다.**
> **UNKNOWN은 노드의 상태 또는 상태 전이가 명시적으로 기록되지 않았음을 의미한다.**

이 마일스톤은 SYNAPSE의 **Architecture State Model 첫 번째 구현 마일스톤** —
정적 그래프 분석기에서 상태 기반 아키텍처 시뮬레이터로 전환하기 위한 기반입니다.

---

### 핵심 철학

```
정적 그래프 분석기   →   상태 기반 아키텍처 모델
UNKNOWN = 버그       →   UNKNOWN = Transition Missing
역사적 의도(Why) ❌      현재 아키텍처 상태(What) ✅
```

---

### 주요 변경 사항

#### ✅ Step 1 — Architecture State Model (`src/types/schema.ts`)

FSM 기반 상태 모델 전체 도입. 기존 인터페이스에 영향 없는 순수 추가.

| 타입 | 역할 |
|---|---|
| `LifecycleState` | 노드 생애주기 단계 (DISCOVERED→CLASSIFIED), 단방향 |
| `HealthState` | 분류 실패 판정 (HEALTHY / UNCLUSTERED / UNCLASSIFIED / CORRUPTED) |
| `ViewState` | 뷰 기준 상태 — 노드 상태 **아님** (VISIBLE / COLLAPSED / FILTERED / OUT_OF_SCOPE) |
| `ReferenceState` | 엣지/참조 상태 — 노드 상태 **아님** (RESOLVED / GHOST) |
| `FSMCompleteness` | 전이 완전성 판정 (KNOWN / INCOMPLETE_TRANSITION / INVALID_TRANSITION) |
| `NodeState` | `{lifecycle, health, view}` 집약 타입 |
| `TransitionValidation` | `{completeness, reason?}` — 상태에서 분리 (검증 ≠ 상태) |
| `NodeEvent` | 도메인 이벤트 (NODE_DISCOVERED, REFERENCE_BROKEN 등) |
| `StateTransitionRecord` | 전이 기록 (v0.3.34.25+ 시뮬레이션 기반) |
| `AnomalySummary` | 전체 상태 축 집계 결과 |
| `UNCHARTED_CONTINENT` | `'UNCHARTED' as const` — 모든 `'unknown'` continent 하드코딩 대체 |

**핵심 설계 결정**: `FSMCompleteness`를 `NodeState`에서 분리.
상태(State)와 검증 결과(Validation Result)는 다른 개념.

#### ✅ Step 2 — AnomalyCollector (`src/core/AnomalyCollector.ts`)

순수 상태 판정기. 아키텍처 패턴 추론 없음. Why 해석 없음.

판정 규칙 (데이터 기반, 하드코딩 없음):
- `cluster_id` 없음 → `HealthState.UNCLUSTERED`
- `role` 없음 → `HealthState.UNCLASSIFIED` (**Soft Anomaly — FSM 위반 아님**)
- `rawStateIds`에 없음 → `ViewState.OUT_OF_SCOPE`
- `edge.to` 노드 없음 → `ReferenceState.GHOST`

**UNCLASSIFIED = Soft Anomaly**: `"UNKNOWN Role = 허용"` 원칙에 따라
role 미분류는 FSM 전이 완전성 위반으로 취급하지 않음.

#### ✅ Step 3 — ValidationEngine 연결

`AnomalyCollector`를 `ValidationEngine.analyzeState()` 마지막에 주입.
try/catch 래핑 — 기존 파이프라인 무중단.

#### ✅ Step 4 — Section 8: Architecture State Report

모든 Architecture Scan Report에 새 섹션 추가.
FSM Completeness와 Health/View/Reference 이상을 분리 렌더링.

#### ✅ Step 5 — 하드코딩 제거

모든 `'unknown'` 문자열 리터럴을 타입 참조로 교체:

| 파일 | 이전 | 이후 |
|---|---|---|
| `GraphAnalyzer.ts` | `\|\| 'unknown'` (continent) | `\|\| UNCHARTED_CONTINENT` |
| `VirtualDebugger.ts` | `? 'unknown' : 'out_of_scope'` | `? HealthState.UNCLUSTERED : ViewState.OUT_OF_SCOPE` |
| `VirtualDebugger.ts` | `\|\| 'unknown'` (continent) | `\|\| UNCHARTED_CONTINENT` |

결과: `AGGREGATE_unknown`은 런타임에서 더 이상 생성 불가.
대신 `AGGREGATE_UNCLUSTERED` 또는 `AGGREGATE_OUT_OF_SCOPE` 출력.

### Known Observation: UNCLUSTERED/UNCLASSIFIED = 0

`project_state.json`은 분류 완료 후 내보낸 **완성 스냅샷**.
이 시점에서 모든 노드에는 `cluster_id`와 `role` 배정 완료.

런타임 이상 감지(그래프 구축 중 파이프라인 완료 전)는
`StateTransitionRecord` 수집이 구현되는 v0.3.34.25+에서 다룬다.
