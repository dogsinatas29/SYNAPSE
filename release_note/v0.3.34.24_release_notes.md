# v0.3.34.24 Release Notes — Architecture State Model: Graph → State Graph

---

## 🇺🇸 English

### Overview

v0.3.34.24 redefines the fundamental treatment of `UNKNOWN` in SYNAPSE.

Previously, `UNKNOWN` was treated as a classification failure — a bug to be eliminated.
This milestone reframes it as a **State Machine Completeness problem**:

> **UNKNOWN is not a classification failure.**
> **UNKNOWN means a node's state or state transition has not been explicitly recorded.**

As a result, this milestone is not a cleanup task. It is the **first implementation milestone
of SYNAPSE's Architecture State Model** — the foundation for transitioning from a static
graph analyzer to a state-based architecture simulator.

---

### Core Philosophy

```
Historical Meaning (Why)    ❌  — cannot be proven
Current Architecture State  ✅  — observable and measurable
```

SYNAPSE does not attempt to restore past design intent.
It answers: **What state is the system in now? What changes when something is removed?**

---

### What's New

#### ✅ Architecture State Model (`src/types/schema.ts`)

Introduced a complete FSM-based state model. All new types are additive — no existing interfaces broken.

| Type | Purpose |
|---|---|
| `LifecycleState` | Node existence stage (DISCOVERED → CLASSIFIED), one-way, normal path only |
| `HealthState` | Classification failure verdict (HEALTHY / UNCLUSTERED / UNCLASSIFIED / CORRUPTED) |
| `ViewState` | Current view-scope state (VISIBLE / COLLAPSED / FILTERED / OUT_OF_SCOPE) — not a node state |
| `ReferenceState` | Edge/reference state (RESOLVED / GHOST) — not a node state |
| `FSMCompleteness` | Transition completeness verdict (KNOWN / INCOMPLETE_TRANSITION / INVALID_TRANSITION) |
| `NodeState` | Aggregate of `{lifecycle, health, view}` — carries all three axes as a single object |
| `TransitionValidation` | Validation result `{completeness, reason?}` — separated from state (validation ≠ state) |
| `NodeEvent` | Domain events (NODE_DISCOVERED, REFERENCE_BROKEN, etc.) — not implementation function names |
| `StateTransitionRecord` | Transition log record (foundation for v0.3.34.25+ simulation) |
| `AnomalySummary` | Aggregated counts across all state axes |

**Key design decision**: `FSMCompleteness` was intentionally removed from `NodeState`.
State and validation result are different concerns.

#### ✅ AnomalyCollector (`src/core/AnomalyCollector.ts`)

Pure state classifier. No architecture pattern inference. No "Why" reasoning.

```typescript
class AnomalyCollector {
    classifyNode(node): NodeState
    classifyReference(edge): ReferenceState
    validateTransition(nodeState): TransitionValidation
    summarize(): AnomalySummary
    classifyAll(nodes, edges): void
}
```

Classification rules:
- `!cluster_id` → `HealthState.UNCLUSTERED`
- `!role` → `HealthState.UNCLASSIFIED` (**Soft Anomaly** — does not trigger FSM violation)
- `!rawStateIds.has(node.id)` → `ViewState.OUT_OF_SCOPE`
- `!nodeIndex.has(edge.to)` → `ReferenceState.GHOST`

**UNCLASSIFIED is a Soft Anomaly**: Per the principle *"UNKNOWN Role = allowed"*,
missing role classification does NOT count as a FSM transition violation.
This means FSM Completeness can PASS even when role ontology is incomplete.

#### ✅ ValidationEngine Integration (`ValidationEngine.ts`, `ValidationContext.ts`)

`AnomalyCollector` is injected at the end of `ValidationEngine.analyzeState()`.
Wrapped in try/catch — existing pipeline is unaffected on failure.

```typescript
// Added to ValidationContext:
anomalySummary?: AnomalySummary;
```

#### ✅ Section 8: Architecture State Report (`ValidationReportBuilder.ts`)

New section appended to every Architecture Scan Report:

```markdown

```

### Known Observation: UNCLUSTERED/UNCLASSIFIED = 0

All three validation projects returned `UNCLUSTERED = 0` and `UNCLASSIFIED = 0`.

This is **expected behavior**, not a bug.

`project_state.json` is a **completed snapshot** — the classification pipeline has already
finished before export. At snapshot time, all nodes have `cluster_id` and `role` assigned.

Runtime anomaly detection (during active graph construction, before pipeline completion)
will be addressed in future milestones when StateTransitionRecord collection is implemented.

## 🇰🇷 한국어

### 개요

v0.3.34.24는 SYNAPSE에서 `UNKNOWN`을 다루는 근본적인 관점을 재정의합니다.

기존에는 `UNKNOWN`을 분류 실패 — 제거해야 할 버그 — 로 취급했습니다.
이번 마일스톤은 이를 **상태 머신 완전성(State Machine Completeness) 문제**로 재정의합니다:

> **UNKNOWN은 분류 실패가 아니다.**
> **UNKNOWN은 노드의 상태 또는 상태 전이가 명시적으로 기록되지 않았음을 의미한다.**

따라서 이 마일스톤은 단순 정리 작업이 아닙니다. SYNAPSE의 **Architecture State Model 첫 번째 구현 마일스톤** — 정적 그래프 분석기에서 상태 기반 아키텍처 시뮬레이터로 전환하기 위한 기반입니다.

---

### 핵심 철학

```
역사적 의도(Why)      ❌  — 증명 불가
현재 아키텍처 상태     ✅  — 관측 및 측정 가능
```

SYNAPSE는 과거 설계 의도를 복원하지 않습니다.
대신 **현재 시스템이 어떤 상태인가? 무언가를 제거하면 무엇이 변하는가?** 에 답합니다.

---

### 주요 변경 사항

#### ✅ Architecture State Model (`src/types/schema.ts`)

FSM 기반 상태 모델 전체 도입. 기존 인터페이스에 영향 없는 순수 추가.

| 타입 | 역할 |
|---|---|
| `LifecycleState` | 노드 생애주기 단계 (DISCOVERED → CLASSIFIED), 단방향, 정상 경로만 |
| `HealthState` | 분류 실패 판정 (HEALTHY / UNCLUSTERED / UNCLASSIFIED / CORRUPTED) |
| `ViewState` | 현재 뷰 기준 상태 (VISIBLE / COLLAPSED / FILTERED / OUT_OF_SCOPE) — 노드 상태 아님 |
| `ReferenceState` | 엣지/참조 상태 (RESOLVED / GHOST) — 노드 상태 아님 |
| `FSMCompleteness` | 전이 완전성 판정 (KNOWN / INCOMPLETE_TRANSITION / INVALID_TRANSITION) |
| `NodeState` | `{lifecycle, health, view}` 집약 타입 — 세 축을 단일 객체로 |
| `TransitionValidation` | 검증 결과 `{completeness, reason?}` — 상태에서 분리 (검증 ≠ 상태) |
| `NodeEvent` | 도메인 이벤트 (NODE_DISCOVERED, REFERENCE_BROKEN 등) — 구현 함수명 아님 |
| `StateTransitionRecord` | 전이 기록 (v0.3.34.25+ 시뮬레이션 기반) |
| `AnomalySummary` | 전체 상태 축 집계 결과 |

**핵심 설계 결정**: `FSMCompleteness`를 `NodeState`에서 의도적으로 분리.
상태와 검증 결과는 다른 개념이다.

#### ✅ AnomalyCollector (`src/core/AnomalyCollector.ts`)

순수 상태 판정기. 아키텍처 패턴 추론 없음. "왜(Why)" 해석 없음.

판정 규칙:
- `cluster_id` 없음 → `HealthState.UNCLUSTERED`
- `role` 없음 → `HealthState.UNCLASSIFIED` (**Soft Anomaly** — FSM 위반 아님)
- `rawStateIds`에 없음 → `ViewState.OUT_OF_SCOPE`
- `edge.to` 노드 없음 → `ReferenceState.GHOST`

**UNCLASSIFIED = Soft Anomaly**: `"UNKNOWN Role = 허용"` 원칙에 따라,
role 미분류는 FSM 전이 완전성 위반으로 취급하지 않음.
즉 Role Ontology가 미완성이어도 FSM Completeness는 PASS 가능.

#### ✅ ValidationEngine 연결 (`ValidationEngine.ts`, `ValidationContext.ts`)

`ValidationEngine.analyzeState()` 마지막에 `AnomalyCollector` 주입.
try/catch 래핑 — 실패해도 기존 파이프라인 무중단.

#### ✅ Section 8: Architecture State Report (`ValidationReportBuilder.ts`)

모든 Architecture Scan Report에 새 섹션 추가. FSM Completeness와 Health/View/Reference 이상 분리 출력.

### Known Observation: UNCLUSTERED/UNCLASSIFIED = 0

3개 검증 프로젝트 모두 `UNCLUSTERED = 0`, `UNCLASSIFIED = 0` 반환.

**예상된 동작, 버그 아님.**
