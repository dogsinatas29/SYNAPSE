# 🚀 SYNAPSE v0.3.34.25 Release Notes (Transition Grammar Engine)

## 📌 Release Summary
- **Version:** v0.3.34.25
- **Status:** ✅ Completed
- **Core Milestone:** Architecture Simulator v1 (Phase 1: Transition Grammar)

This release focuses on establishing the grammar and validation rules for architectural state transitions (`Transition Grammar Engine`). It strictly defines the logical rules for how node states change over time and validates their consistency, avoiding the memory-intensive approach of recording a complete historical transition archive.

본 릴리스는 아키텍처 상태 전이 규칙을 정의하고 그 정합성을 검증하는 `Transition Grammar Engine` 도입에 중점을 두었습니다. 메모리를 기하급수적으로 소비하는 과거 트랜지션 기록 보관 방식을 배제하고, 현재 상태 자체의 일관성을 검사하는 규칙(Grammar) 기반의 접근 방식을 택했습니다.

---

## 🛠️ Key Architectural Changes

### 1. StateAuditPipeline 도입 (Decoupling Producer & Consumer)
- `AnomalyCollector` (상태 생산자)와 `TransitionGrammar` (상태 소비자) 간의 강결합을 방지하기 위해 얇은 파이프라인 조율자 역할을 하는 `StateAuditPipeline`을 신설했습니다.
- 이를 통해 향후 `FailurePropagation` 등 새로운 로직이 추가될 때 Collector 레이어의 오염 없이 안전하게 확장이 가능해졌습니다. (KISS 및 Observer 철학 준수)

### 2. TransitionGrammar 및 검증 규칙(Rule) 정의
- LifecycleState(수명 주기)와 HealthState(건강 상태) 간의 축 오염(Cross-axis Transition)을 원천 차단했습니다. (예: `ViewState`와 `LifecycleState` 혼용 불가)
- `TransitionChain` 모델을 통해 단순 A→B 전이가 아닌, `DISCOVERED → CLASSIFIED` 와 같이 중간 단계를 뛰어넘거나(MISSING), 역방향으로 흐르는(INVALID) 불법 전이를 논리적으로 적발합니다.

### 3. FSM Audit Summary 보고서 최적화
- `ValidationReportBuilder`에 Section 8 `FSM Audit (v0.3.34.25)` 섹션을 신설했습니다.
- 메모리 폭발과 보고서 가독성 훼손을 막기 위해 **위반(Violation) 내역을 하드 리밋(100개, `MAX_VIOLATIONS`)으로 제한(Cap)하고, 보고서 상에는 요약 수치(Count)와 상세 링크(Link)만 노출**하도록 정책을 바꿨습니다.

## 💡 Developer Note (Invariant)
> **Transition Engine ≠ Transition History System**
>
> Transition Grammar는 현재 상태의 정합성을 논리적으로 검증(Audit)합니다. 
> 메모리와 디스크, 분석 시간을 폭발시키는 **"실제 과거 상태의 저장(Archive) 또는 시간축에 따른 재구성(Replay)"은 이 시스템에서 영구적으로 배제**됩니다.
