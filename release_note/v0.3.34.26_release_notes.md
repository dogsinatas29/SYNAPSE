# 🚀 SYNAPSE v0.3.34.26 Release Notes (Failure Propagation Engine)

## 📌 Release Summary
- **Version:** v0.3.34.26
- **Status:** ✅ Completed
- **Core Milestone:** Architecture Simulator v1 (Phase 2: Failure Propagation)

This release introduces the `Failure Propagation Engine`. It answers the question: **"If that node breaks, what else is affected?"** by analyzing the static dependency graph and the architecture state model. Crucially, it calculates the structural impact of failures without performing any runtime simulation, memory profiling, or dynamic code execution, ensuring alignment with SYNAPSE's `Architecture Only` constraint.

본 릴리스는 결함 전파 엔진(Failure Propagation Engine)을 도입했습니다. "특정 노드가 깨지면 어디까지 파급되는가?"라는 질문에 답하기 위해 정적 의존성 그래프와 상태 모델을 결합했습니다. 런타임 환경을 흉내내는 실행 시뮬레이션이나 메모리 추론 등을 일절 배제하고 오직 아키텍처 관점에서의 연쇄 파급력만 계산합니다.

---

## 🛠️ Key Architectural Changes

### 1. Static Failure Impact Calculation
- 결함(HealthState)이 있을 때 의존성(Edge)을 타고 몇 개의 노드가 영향받는지 BFS를 통해 범위를 탐색합니다.
- 상태(State)를 변경/오염시키는 시뮬레이션은 하지 않습니다. 오직 "누가 영향을 받는가?"(Direct, Indirect, Cascade Impact)와 **Blast Radius Score**만을 산출합니다.
- 동적인 런타임 에러 예측이나 콜스택 추론을 배제하고 철저히 "State + Edge" 기반으로만 계산합니다. (Execution Simulation 금지)

### 2. OOM(Out of Memory) 방지용 하드 스탑(Hard Stop) 적용
- 대규모 그래프(예: 7만 노드의 리눅스 커널)에서 한 노드의 결함이 수만 개의 노드로 번지는 폭발적 전파를 막기 위해 엄격한 제한을 걸었습니다.
- `MAX_PROPAGATION_DEPTH = 3`: 결함 전파는 최대 3단계(Depth)까지만 탐색합니다. 무한 뎁스 순회를 금지합니다.
- `MAX_IMPACT_NODES = 1000`: 하나의 분석에서 전파되는 총 결함 노드 수가 1,000개를 초과하면 탐색을 즉시 중단합니다.

### 3. Compute → Report → Discard 패턴 적용
- 전파 결과물(`Failure Cache`, `Impact Cache` 등)을 상태로 누적하거나 캐싱하지 않습니다.
- 계산 후 보고서(Report)만 생성하고 데이터는 메모리에서 즉시 폐기(Discard)하여 다음 마일스톤인 `Topology Mutation` 대비 OOM 위험을 차단했습니다.

### 4. Validation Report 최적화 (Section 9)
- `ValidationReportBuilder`에 Section 9 `Failure Propagation Report` 서브섹션을 추가했습니다.
- 가독성 보호 및 보고서 크기 폭발 방지를 위해 타격받은 수천 개의 노드 목록을 인라인으로 출력하지 않고, **Direct Impact, Indirect Impact, Cascade Impact**의 요약 수치만을 제공합니다.
- 상세 전파 경로는 `[View Failure Graph]` 명령 링크를 통해서만 접근하도록 제한했습니다.

## 💡 Developer Note (Invariant)
> **Failure Propagation ≠ Execution Simulation & Topology Mutation**
>
> 우리는 "이 노드가 지워지면 누가 컴파일이 안 되거나 동작을 멈출 수 있는가?"를 아키텍처 의존성 관점에서 계산할 뿐, **"실행 시간에 실제로 메모리 누수가 터지거나 스케줄러가 죽는가?"를 예측하지 않습니다.**
>
> 또한 "A가 깨지면 B의 상태가 무엇으로 변하는가?" 역시 계산하지 않습니다. (상태 변화 시뮬레이션은 v0.3.34.27 Topology Mutation의 영역입니다).
>
> 모든 결함 파급력 계산 결과는 캐싱되지 않고 **즉시 폐기(No Snapshot)** 됩니다.
