🚀 Milestone v0.3.34.42 - 47-Second CPU Lockup Fix

## 📅 작업 정보 - **상태:** ✅ Completed
- **관련 마일스톤:** v0.3.34.41 (이전 버전 링크)
- **목표:** 380k 대규모 그래프에서 발생하는 47초 UI 멈춤 현상(mousemove bottleneck)의 근본 원인 제거.

## 🧠 상세 설계 및 로직
- **47초의 진실:** `pick()` 함수는 단 0.017ms에 끝났으나, 바로 뒤에 호출되는 `getClusterAt()`이 문제였다.
- **O(N*C) 지옥:** `cluster._headerBounds`가 없는 렌더링 전 클러스터를 검사할 때, `this.nodes.filter(n => n.cluster_id === cluster.id)`라는 O(N) 탐색을 모든 클러스터(C)에 대해 반복하고 있었다.
- 380,000(노드) * 수천(클러스터) = 매 마우스 이동마다 **수십억 번의 루프** 발생.
- 이전 패치의 `continue` 문이 `if (cluster._headerBounds)` 블록 내부에 갇혀 있어, 정작 브레이크가 필요한 조건에서는 루프를 빠져나가지 못하는 치명적 실수가 있었다.

## 🛠️ 기술적 변경 사항
- **File Changes:** `ui/canvas-engine.js` 수정
- **수정 사항:** 
  - `getClusterAt` 내부의 O(N) 노드 순회 폴백 코드를 완전히 차단(Bypass).
  - 렌더링 바운딩 박스가 없을 경우 레이아웃의 `cluster.bounds`를 대체제로 사용해 무조건 O(1)으로 검사 종료.

## ⚠️ 예외 처리 및 주의 사항
- CPU 프레임 사이클에 `for`와 `filter` 같은 배열 전체 탐색이 숨어 있으면 WebGL이 아무리 빨라도 소용이 없다.
- `visibleNodes`가 380k로 유지되는 이유는 필터가 모두 꺼져 있고 클러스터 LOD가 열려있어 WebGL에게 전체 배열을 넘겨주기 때문이다. WebGL은 380k 포인트를 그리는 데 문제가 없으므로 이는 의도된 Presentation 결과다.
