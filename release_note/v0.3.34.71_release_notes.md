# Release Notes v0.3.34.71

## 🚀 Verified Pattern Rendering Contract (Contract Validation)

**Phase Status:** ✅ Completed

### 🧠 핵심 변경 사항
1. **Contract-Based Report Generation**
   - 모든 Markdown 리포트(`ARCHITECT`, `ONBOARDING`, `SIMULATION_DEBUG`)가 `ReportContract` 기반으로 완전히 전환되었습니다.
   - 보고서(Markdown)에는 "Claim(주장)"과 "Finding(요약 결과)"만을 렌더링하고, 실제 Evidence는 렌더링하지 않도록 격리했습니다.
   - Evidence는 오직 `EVIDENCE_VIEWER.html`에서만 상세 출력되도록 하여 "Report = Navigation, Viewer = Raw Data" 계약을 확립했습니다.

2. **Pipeline Stability & Cross-Project Isolation**
   - Kubernetes, PostgreSQL, Linux Kernel, VSCode, AntennaPod 등 다양한 규모의 프로젝트에서 파이프라인 무결성을 검증했습니다.
   - 프로젝트 간 데이터 혼입(Contamination) 현상을 완벽히 해결했습니다.
   - 중복 렌더링 버그(Evidence Viewer에서의 데이터 중복 표기)를 수정했습니다.

3. **Detector Consistency Verified**
   - `ArchitecturalChokepointDetector` (A5)의 정상 동작을 리눅스 커널(20개 발견)을 통해 증명했습니다.
   - VSCode/PostgreSQL 등에서 A5가 0개로 나오는 것은 버그가 아니라 프로젝트 구조상 Chokepoint 조건(강력한 Betweenness Centrality)을 충족하는 노드가 없었기 때문임이 수치적으로 입증되었습니다 (Deterministic).
   - "A5 Discrepancy" 가설은 폐기되었으며, 파이프라인은 의도대로 정확히 동작하고 있음이 확인되었습니다.

### ⚠️ 인지된 한계 및 다음 마일스톤 과제
- **대규모 프로젝트 생성 실패 (Linux Kernel 등):**
  Linux 커널과 같은 초거대 그래프 환경에서 `ARCHITECT_REPORT` 등 다수의 리포트를 동시 생성할 경우 OOM(Out of Memory) 또는 Timeout이 발생하여 생성 프로세스가 중단되는 증상이 확인되었습니다. 다음 마일스톤에서는 대규모 그래프 처리를 위한 스트리밍 기반 생성기 최적화 또는 Report 병렬 처리 아키텍처가 필요합니다.
