# Milestone v0.3.34.73 Release Notes (EN/KR)

## 🇰🇷 한국어 (Korean)
**버전 요약**: Architecture Evidence Pipeline - 해석 객관성 및 추적성 강화

이번 릴리즈는 프로젝트의 아키텍처를 분석할 때 SYNAPSE 엔진이 제공하는 주장(Claim)과 증거(Evidence) 사이의 인과관계를 명확하게 분리하는 데 집중했습니다. 코드상의 관측값(예: Fan-In, Dependency)을 곧바로 비즈니스나 아키텍처적 의미(예: 핵심 모듈, 실행 진입점)로 단정 짓는 '해석의 비약'을 제거하고, 순수한 정량적/구조적 사실(Fact)만을 보고서에 담도록 파이프라인을 교정했습니다.

### 핵심 변경 사항 (Key Changes)
1. **해석의 비약 및 과장 제거**
   - **O2 (EntryPoint)**: 단순 `inDegree=0`인 노드를 '프로그램의 실행 진입점'으로 무조건 단정하던 로직을 수정. 이제는 "독립적 최상위 노드(Top-level Node)"로만 보고하며 실제 진입점 여부는 사용자가 판단하도록 변경.
   - **E2 (Change Amplifier)**: 높은 `complexityScore`를 가진 노드를 '변경을 증폭시키는 위험 요소'로 해석하던 주장을 제거하고, 복잡도 지표 자체의 관측값만을 명시하도록 교정.

2. **Evidence 추적성 강화 및 명문화**
   - **A1 / A2 (Core vs Boundary)**: 코어 및 경계 모듈을 선정할 때 어떤 기준(선정 Basis)으로 분류했는지에 대한 논리적 근거 누락 문제를 수정.
   - **A3 (Isolated Component)**: 격리성(Strength) 분류 기준을 Fan-In 수치 등 명확한 척도로 명시하여, "왜 이 컴포넌트가 격리되었다고 판단했는지"를 추적 가능하게 함.

3. **Data Pipeline 파싱 버그 원인 규명 (P3 Discovery)**
   - 대규모 프로젝트(예: Chromium) 분석 시 `session_*` 로 시작하는 정상적인 소스 파일 수천 개가 Ghost Node로 처리되던 문제의 Root Cause 규명 완료 (추후 버전에서 수정 예정).

## 🇺🇸 English
**Version Summary**: Architecture Evidence Pipeline - Enhancing Objectivity and Traceability

This release focuses on clearly separating the causal relationship between the Claims and Evidence provided by the SYNAPSE engine when analyzing a project's architecture. We removed 'logical leaps' where raw observational data (e.g., Fan-In, Dependencies) were definitively declared as business or architectural semantics (e.g., Core Module, Execution Entry Point). The pipeline has been corrected to include only pure quantitative/structural facts in the reports.

### Key Changes
1. **Removal of Interpretive Leaps and Exaggeration**
   - **O2 (EntryPoint)**: Corrected the logic that unconditionally declared nodes with `inDegree=0` as the 'execution entry points' of the program. They are now strictly reported as "independent top-level nodes," leaving the final interpretation to the user.
   - **E2 (Change Amplifier)**: Removed the assertion that a high `complexityScore` automatically makes a node a 'change amplifier (risk factor)'. The system now simply reports the observed complexity metrics without speculative interpretation.

2. **Enhanced Evidence Traceability**
   - **A1 / A2 (Core vs Boundary)**: Fixed the omission of the logical basis used when classifying Core and Boundary modules, ensuring the selection criteria are always documented.
   - **A3 (Isolated Component)**: Specified the classification criteria for isolation strength using definitive metrics (such as Fan-In), making it fully traceable *why* a component was deemed isolated.

3. **Data Pipeline Parsing Bug Discovered (P3 Discovery)**
   - Successfully identified the root cause of an issue where thousands of valid source files starting with `session_*` in large projects (e.g., Chromium) were incorrectly processed as Ghost Nodes. (A fix is scheduled for a future version).
