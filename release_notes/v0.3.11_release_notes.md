# v0.3.11 Release Notes - Authoritative Stability

## 🚀 Key Improvements

### 1. Authoritative State Synchronization (Instant Reactivity)
- Fixed a critical regression where the UI would "roll back" to a stale state after user interactions (node creation, deletion, or edge confirmation).
- Implemented an `isAuthoritative` flag that bypasses the WebView's interaction lock, ensuring manual actions are immediate and permanent.
- Eliminated interaction latency by forcing an authoritative backend-to-frontend update cycle for all manual operations.

### 2. Intelligent Node Degree & Clustering Fix
- Resolved the "Vanishing Reserved Cluster" bug. The engine now correctly maps file paths to manual node IDs during graph analysis.
- Manual nodes (with `node_manual_` IDs) now accurately reflect their connection count (degrees), ensuring they remain correctly categorized in the **Reserved Cluster** even when AI re-scans the project.

### 3. Edge Deduplication & Status Sovereignty
- Eliminated the persistent `?` (Pending) badge issue. Edges are now deduplicated by their Node-Pair identity.
- When an AI-scanned edge overlaps with a user-confirmed edge, the **Confirmed Status** now takes absolute priority, cleaning up the UI automatically.

### 4. ID Sovereignty Enforcement
- Solidified the `StateManager` to prevent AI scan results from overwriting user-defined node identities.
- Manual node positions and types are now strictly preserved across re-scans and session reloads.

## 🛠 Technical Changes
- **CanvasPanel.ts**: Added `isAuthoritative` parameter to `sendProjectState` and applied it to node/edge mutations.
- **StateManager.ts**: Refactored `generateMergedState` to build path-to-id alias maps *before* calculating node degrees and clusters.
- **ui/canvas-engine.js**: Updated message handler to respect `isAuthoritative` flag and clear stale `_pendingState` buffers.
